# Noir Engraving Lab — 视觉系统设计

## 1. 这个实验是什么

这是 SSNoir 的长期视觉研究工程，不是第二客户端，也不是一次性效果 Demo。

它只研究一件事：

> 在低模、无纹理或极少纹理、程序化生成和 AI 生成资产都可进入的生产条件下，怎样建立一种具有强烈黑色电影表现力、同时能稳定迁回 Unity 的视觉系统。

因此这里追求的不是 Three.js 特性本身，而是**跨引擎成立的视觉规律**。

## 2. 最终视觉假设

暂定名称：**Noir Engraving / 黑色版画**。

画面由五层共同构成，顺序固定：

1. **形 Shape**  
   大体块、强轮廓、明确比例。资产即使全部涂黑，也应能被认出。

2. **线 Line**  
   线不是“所有边”。它负责选择性揭示结构，并建立信息层级：主体线、环境线、消失的线。

3. **光 Light**  
   少量、有叙事理由的光。光负责决定“什么被看见”，而不是均匀照亮场景。

4. **空气 Atmosphere**  
   雾、雨、烟、光束、湿地反射等，把简单几何变成摄影空间。

5. **印刷 Print**  
   最终屏幕统一：亮度压缩、有限色阶、Bayer dither、固定冷色 ramp、轻微 grain。

生产过程可以复杂，最终视觉语法必须简单。

## 3. 不做什么

- 不默认增加纹理来解决“空”。
- 不默认增加模型细节来解决“廉价”。
- 不把所有几何边都描出来。
- 不用大量彩色灯营造“赛博朋克”。
- 不把复古滤镜、CRT、像素化等效果当作风格本体。
- 不因为 Three.js 能做某个效果就把它加入画面。
- 不为临时截图写不可维护的特殊分支。

## 4. 研究场景

实验长期围绕同一个小街区迭代，避免每轮换内容导致无法比较。

固定构成：

- 一条主街；
- 剧院：视觉主角，代表娱乐、诱惑、上层世界；
- 仓库：工业、码头、沉重体量；
- 两排普通街屋：程序化背景；
- 后巷：压迫、小尺度、犯罪感；
- 消防梯、路灯、招牌、窗光：结构与节奏；
- 湿路面、雨、雾：空气与反射。

以后可以增加“室内酒馆”和“码头”两个 benchmark scene，但必须等当前街区建立稳定基线之后。

## 5. 固定镜头

自由相机用于检查；判断画风以固定镜头为准。

1. **Theater Street**：地面高度、主街纵深、剧院主体。
2. **Warehouse Fog**：工业体量、雾、远近层次。
3. **Alley Mouth**：狭窄空间、遮挡、黑面积。
4. **City Compression**：沿街长焦压缩、前景黑块、地标与街区层级。

重要视觉修改至少检查这四个镜头。

## 6. 工程分层

```
src/
  config/
    visualProfile.js     全局视觉参数；稳定的“画风配置”

  scene/
    city.js              场景构成与程序化建筑语法
    materials.js         无纹理材质系统
    primitives.js        几何原语、描线原语

  systems/
    lighting.js          主光、补光、街灯、光束
    atmosphere.js        雨及后续雾噪声/烟尘

  post/
    noirShader.js        黑色版画最终印刷层
    pipeline.js          后处理顺序

  shots.js               固定基准镜头
  ui.js                  实验控制面板
  main.js                装配，不承载视觉实现
```

规则：一个视觉问题只能有一个主要归属。不要把灯光参数散在 city、main 和 shader 三处。

## 7. 可复现原则

视觉实验必须可比较。

- 程序生成使用固定 seed。
- 固定四个 benchmark shots。
- 每次实验只改变少数变量。
- 重要变量必须可以关闭或恢复 baseline。
- 结论记录在 `RESEARCH_LOG.md`。
- 记录“看起来更好”之外，还要说明**为什么**以及**如何迁回 Unity**。

## 8. 长期研究路线

### Phase 0 — 基线与架构

目标：得到稳定、可复现、可拆解的研究场。

完成条件：

- 模块边界稳定；
- 四个固定镜头；
- 基础参数面板；
- 无纹理程序化街区；
- 可开关线、空气、光束、印刷层；
- 研究记录格式固定。

### Phase 1 — Shape / 构图与黑面积

只研究体块，不研究花哨 shader。

问题：

- 多大比例的画面应该沉入黑色？
- 主体与背景靠什么形成第一阅读层级？
- 建筑细节应该在哪个距离消失？
- “空”是否比“满”更有力量？

输出：适合 SSNoir 的体块密度、建筑比例、镜头高度、负空间规则。

### Phase 2 — Line / 线的层级

研究三类线：

- Hero：叙事主体与交互对象；
- Context：帮助理解空间的结构线；
- Silence：主动不画。

测试：全描线 / 选择性描线 / 极少线。

输出：CityBox 的描线策略和不同距离/语义下的线宽、明度、显隐规则。

### Phase 3 — Light / 黑色电影摄影

不追求更多光源，而追求更明确的光源理由。

研究：

- hard key / soft fill；
- 门光；
- 窗光；
- 路灯；
- 百叶窗式切光；
- 逆光剪影；
- 单一高亮点对构图的控制。

输出：Unity 的灯光数量、方向、强度比例和叙事灯模板。

### Phase 4 — Atmosphere / 空气

研究：

- 指数雾；
- 非均匀低频雾；
- 雨；
- 烟尘；
- 光束；
- 湿地反射。

核心问题：空气对画面提升是否高于模型细节。

输出：Unity Atmosphere 的最小效果集。

### Phase 5 — Print / 最终印刷

研究：

- black / white point；
- 4 / 6 / 8 色阶；
- Bayer cell 尺寸；
- dither 强度；
- ramp 色彩；
- grain；
- bloom 与量化的先后关系。

目标不是“复古”，而是把不同来源资产压进同一种媒介。

输出：`SSNoirStylize` 的正式参数与算法修订。

### Phase 6 — Procedural Grammar / 世界生产

视觉基线稳定后才研究大规模生产。

建立：

- 建筑体块语法；
- 窗口节奏；
- 屋顶件；
- 功能性 clutter cluster；
- 背景建筑 LOD / line hierarchy；
- AI 地标资产如何进入统一画风。

输出：CityBox 生成规则，不直接迁 Three.js 代码。

### Phase 7 — Narrative Image / 叙事视觉语法

最后研究“视觉变化如何承担故事”。

例如：

- 报纸：halftone；
- 回忆：不同 ramp；
- 创伤瞬间：negative / 极端黑白；
- 舞台：追光 + 黑场；
- 上层世界与老街：不是两套材质，而是不同的秩序、光与负空间。

只有在基础语言稳定后才做，避免把风格变成效果合集。

## 9. 判断标准

每次改动按下面顺序评价：

1. 情绪是否更接近 noir？
2. 第一眼是否更清楚该看哪里？
3. 黑暗是否变得更有意义？
4. 简单几何是否因此显得“有意设计”而非“资产不足”？
5. 是否仍适合程序化 / AI 资产生产？
6. 是否能清楚翻译回 Unity？
7. 最后才是性能与技术新奇度。

这七条中前六条没有成立，“效果更酷”不算进步。

当前证据见 `captures/reviews/2026-10-03-local/`。下一项优先研究随视点、遮挡和受光变化的雨可见性，以及空气的远近层次。
Print 参数本轮没有改变。几何仍是研究体块；建筑功能与人物尺度的生产验证尚未完成。
