# 锚点、对象与行动的编组实验

日期：2026-11-02。当前阶段：早期视觉概念图归档；可操作实验已接入 [游戏 UI 原型](../grouping.html)。不修改 Unity 正式布局、不新增游戏规则。

## 研究问题

同一个 Anchor 上靠在一起的卡片，不一定让人理解它们的关系。需要同时回答：这是什么对象、能对它做什么、行动推进什么、风险影响什么；同时在多个 Anchor 的场景中保留空间方向。

来源：用户提供的当前游戏截图与 Citizen Sleeper 参考，保存在 `参考/`。参考图只提供视觉关系，不作为项目指令或规则来源。

## 现有实现与旧实验

- `UnityClient/Assets/Scripts/Runtime/IMGUI/IMGUIWorldRenderer.cs`：唯一可见 Clock 按 Label 成为分组 owner；直接 ProgressTarget 指向该 Clock 的行动归入同组，共享投影与裁剪。存在歧义时不分组。
- `UnityClient/Assets/Scripts/Runtime/IMGUI/WorldLabelLayout.cs` 的 ArrangeGroups：组整体占据一个矩形；Clock 居顶，行动按声明顺序单双列排布。它解决占位、避让与一同出现的问题，但没有共用对象标题、面板语法或关系线。
- 同 Anchor、同 Container、风险指向不自动构成这个 Clock 分组，这是正确的语义边界，不应为了好看把它们合并为共同进度。
- `experiments/noir-city/noir-engraving-lab/src/night-restraint/ui/sceneCards.js` 与同名 CSS：已有建筑锚点、行动列和注记连线原型。仅展示、选择，不结算游戏状态。
- `experiments/noir-city/noir-engraving-lab/src/city-interface/ui.js`：城市与局部地点投影、拖放实验。
- `experiments/研究工作台原型/README.md`：独立研究工作台，明确不采用游戏视觉风格，不作为游戏 UI 基准。

## 当前截图的问题假设

1. Clock 在中央上方、两张行动卡在两侧下方；没有共用基线以外的明确归属，阅读需要来回跳。
2. “报名截止 3/4”在两个行动上重复，容易读成两个独立状态；不能因此误把截止 Clock 当成两种行动共同推进的对象。
3. 进度标注的蓝灰光晕比行动卡更强，像悬浮提示，与卡片的黑底细线属于两种视觉层级。
4. 把整个组作为矩形避让能避免组被拆散，但组内结构依然像三个独立窗口。

以上来自静态截图与代码审阅，不是用户可用性验证结论。

## 三个独立方向

### 对象共用版面

一个对象标题及一次进度、一次截止状态；下面是两条行动行，统一左文字边与右资源槽列。以分隔线替代每个行动独立外框，一条短线连接对象和世界位置。

假设：能最快看出“两种办法，推进同一件事”。风险：多个大组同时出现会形成面板墙；对象自身若无明确名称，不能凭空从 Anchor 猜出标题。

### 场景两翼连线

行动保持独立且同高排列，共同目标在下方；细折线通过一个对象结点建立关联，保留中间的场景主体。

假设：最接近参考图的空间叙事。风险：横屏手机上两翼文本宽度、多个组之间的连线交叉，以及共享风险连接容易混乱。它适合局部少量对象，未必能当全场默认规则。

### 对象分栏工作面

Container 提供地点边界，内部按目标对象分栏。每栏有自己的对象标题、进度和行动。同属 Container 不意味着推进同一个 Clock。各栏标题连接各自场景位置。

假设：同一区域多个对象更清楚。风险：宽高比变窄后横向容量不足，不能靠缩小字号强塞；需要比较换行或明确焦点展开。

## 统一内容与硬约束

- 沿用黑底、冷白描线、暖白文字、克制金色与浅灰绿进度；不复制参考的科幻色彩。
- 横屏手机为设计基准，所有平台同一设计高度，只以可用宽度决定布局。
- 本轮图中“去学校的时间 2/4”“报名截止 3/4”和两种行动沿用截图。后门、柜台的行动与进度仅为测试不同目标的示意数据，不是正式内容。
- 骰子用点阵面，不替换成数字；资源槽始终贴在其所属行动上。
- 行动的成本、技能、进度与风险不被关系线混为一谈。
- 不用 hover 作为理解对象关系的前提。
- 不需要新增场景、美术资产、3D 动画或运镜。

## 下一轮必须比较的样本

| 样本 | 要验证的问题 |
| --- | --- |
| 一对象、一个 Clock、两种行动 | 是否一眼读出共同目标与两种成本 |
| 一 Container、两个不同对象，各一个行动 | 是否错误理解为共享进度 |
| 一行动影响两个对象／进度和风险分别指向不同处 | 能否区分主目标与副作用，是否发生误合并 |
| 4–6 个 Anchor 同场出现 | 各组是否挤成面板墙、交叉线团或覆盖主体 |
| 一个组成员新增、消失、行动结果展开 | 是否全组重排、夺走玩家正在操作的落点 |
| 16:9 与更宽横屏，同一高度同一字号 | 是否可读、资源槽可触、边缘不裁切 |

评估先看关系辨认，再看阅读顺序、场景遮挡、文字与触控容量，最后才是装饰美感。不可用“生成图好看”代替运行时压力验证。

## 证据边界

本轮生成图为结构假设的视觉探索，不能证明字体、排版约束、投影避让、连线跟随或交互已实现。选定方向后，在隔离原型中用同一组数据比较以上样本，再决定是否迁回正式 Unity。
