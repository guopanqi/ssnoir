# 全城镜头巡检（可分批续跑）

目标：打磨已有世界→地点、地点返回、内部演出过渡。默认每次推进1–2个地点，不要求一次完成；此目录是长期交接记录，尚未安排定时自动执行。任何模型都可按本流程继续。遵守项目 AGENTS 和 make-scene Skill。

## 如何接着做

1. 读取 `checklist.json`，选未检查地点或待复核问题；建立下一编号 `batches/NNN/`。同一地点有多个内部机位时，在批次报告列出逐条路由，不用一句“该地点通过”概括。
2. 先确认当前源、构建缓存和已发布资产是否一致。记录相关文件hash/时间、机位、尺度、坐标、可见性以及工具版本；缓存过期就标记，不默认重建全城。
3. 从实际 Unity 场景/运行时代码确定世界机位与转换。完整装配用于跨地点检查；独立Prefab只用于本地机位。世界视角可拖动，固定起点仅是代表样本；Stage的Portal路径单独标记，不把不可达直飞路线判成正式缺陷。
4. 用运行时共享 `FocusTravelMath.cs` 选路与采样。只选本批路由，避免全城相机两两组合。日常不启动Unity、不全城构建。先读 `tools/camera-review/README.md` 的输入与证据边界。
5. 完成下面清单；无法查明的项记“待确认”及原因，不能以推断填“通过”。把命令、输出、耗时、结果与建议留在批次目录。
6. 更新总表状态与证据路径、内部路由清单及下一步；检查后的相关资产/中央策略变化会使旧结果需要复核，历史报告不覆盖。

## 每条路由的检查清单

- [ ] 路由真实可达：起点、终点、返回、Portal/演出触发和可见性与运行时一致。
- [ ] 输入可靠：完整装配、坐标尺度、FOV、焦点优先级与正式配置一致。
- [ ] 终点构图：主体是谁，明确使用主体视觉中心，不拿UI Anchor或地面交点冒充主体。
- [ ] 途中取景：观察0/25/50/75/100%及异常附近采样；主体偏出画面、突然转头、俯仰翻转、FOV变化有记录。位置直线不等于观感直接。
- [ ] 机身/近裁剪面：穿墙、进楼、地形穿插、通行空间越界；标明交叉对象及发生区间。
- [ ] 主体遮挡：检查实际主体到镜头的可见关系；几何射线和有限采样有误报/漏报可能，应保留代表图或明确尚未视觉审阅。
- [ ] 动画实际画面：读取CutscenePlayer黑边策略，按实际可见区检查，采样过程峰值而非只看首尾；按clip from/to稳态分别检查入场与返回。
- [ ] 起终接续：聚焦、返回和播放后回机位是否造成无意义重复绕行；动画的不同阶段需分别注明，静态快照不代表全片段。
- [ ] 分类与建议：真实焦点 → 机位/构图 → 通行空间/既有安全切换；仅有证据说明建筑阻碍合理镜头时才建议改建筑，不自动改动正式内容。
- [ ] 证据等级：静态审阅、共享曲线数值、Blender几何、Blender画面、Unity导入、实际交互分别记录。

## 状态与完成标准

总表状态：未检查 / 检查中 / 已检查有问题 / 待确认 / 代表样本无已检出问题 / 待复核。没有实际视觉证据不得标“视觉通过”；代表样本不承诺所有拖动起点安全。

首轮以诊断与流程检验为主，不自动修建筑、发布、启动昂贵验证。发现缺陷后给出具体最小修复建议；修复授权及范围沿用用户指示。每批报告说明已用时间、瓶颈和下批可独立执行的动作。

## 委派提示词

“读取 experiments/全城镜头巡检/README.md 和 checklist.json，遵守 AGENTS、make-scene Skill。只检查下一批1–2个地点，使用共享运镜数学和完整装配，不启动Unity、不全城构建、不改正式资产。记录真实路由、证据和限制到下一 batches/NNN，更新清单。重点区分位置路径、主体取景、几何遮挡与运行时可见性；无法核对标待确认。汇报问题、最小修复建议和下一步。”

## 检查与修复闭环

用户已授权按小批继续：优先由 Luna high 做检查，主代理复核并负责修复已确认的既有镜头缺陷；便宜模型的诊断不直接当作修复依据。每批把“检查发现 → 主代理确认 → 修复 → 重跑原失败样本与受影响范围”写清再收尾。可独立完成的普通代码/机位修复不反复请求确认；涉及不明确的艺术方向或扩大场景改造时，先做具体证据，避免为假阳性重做建筑。一次推进小批并留下下一步，不代表已设置定时任务。
