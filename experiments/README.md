## 什么不放这里

- 正式资源的构建日志、导入验证、镜头巡检和修复回归：放 [工程验证记录](../artifacts/工程验证/README.md)。它们回答“现有实现是否正确”，不与设计候选混排。
- 可复用的 CLI、检查器与生成器：放 `tools/`；某次验证专用的脚本可随证据保留，不必包装成公共工具。
- 已确定、持续维护的游戏设计与工程说明：放 `docs/`。未定的网页设计草图仍属于这里。
- 可重建缓存、临时构建目录：使用项目既有 `.cache/`、`scratch/` 等约定，不另建“某次 agent 工作”目录。

## 新增之前

先找已有原型：UI 编组试验放进游戏 UI 原型，城市画风对照放进城市视觉，同一问题不要每轮另开顶层目录。只有独立设计问题才新建目录，按问题命名，不按模型名、日期或 agent 名命名。每项说明写清入口、要比较的问题、哪些是假数据／未实现，以及本轮得到的结论；不要把“跑过一次命令”当成设计成果。

历史研究不因本次整理而被判为无效。旧候选先保留在所属实验内部，需要精简时按结论与复用价值逐项判断，不一并删除源码和证据。

本次整理合并了 UI 编组概念图，移出了七组工程验证记录，并将带模型名的工作台目录改为“研究工作台原型”。没有删除原型、图片或验证证据。
