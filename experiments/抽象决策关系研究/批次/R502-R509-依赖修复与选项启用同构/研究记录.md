# R502–R509｜修复关系改变行动集合，就比购买一个选项更新吗？

2026-10-13。接续R486的反证（同一个θ只会损坏一个分支，根本没有两条都值得修的问题）。现在让X、Y两条依赖**独立损坏**，玩家实际可遇见“两条都坏”的状态，修复X/Y又能改变下一手可执行的FINISH-X/Y。本实验仍首先问强简明基线：若把“修复一条连接”改称“花相同成本启用一项操作”，玩家是否在做完全一样的事？

## 去情景机制卡

两条任务X、Y各自以1/2概率故障，故障状态在准备阶段公开；独立出现需求q∈{X,Y}，一半条件在准备时就知道q、另一消融要等下一手才知道。玩家先用一个**准备时段**选择KEEP、REPAIR-X、REPAIR-Y（修理成本为1分效用；若没有修理便不付）；修理只使其所对应的任务成为下一手合法选项。下一手只可执行一个未损坏的FINISH-X/Y，若等于本期需求得4，另一个得1，若都不可用得0。修复**不是无代价的完成目标**：它占用准备阶段，真正FINISH仍需下一手。

对照：将REPAIR-X/Y改名为ENABLE-X/Y，两者的成本、可用性、公开状态和后续FINISH完全一致；不存在隐藏额外奖励或额外容量。该对照不是证明所有真实关系图都能扁平化，而是为这一个最小机制建立严格同构。

| 编号 | 结果 |
|---|---|
| R502 | 两条都坏的状态真正可达，概率**1/4**；不再是R486必有且只有一条坏 |
| R503 | 双坏且q已知：修理当前需求的那条，净收益**3**；q=X时REPAIR-X，q=Y时REPAIR-Y |
| R504 | 双坏但q只有修理后才揭晓：提前修任何一条的期望净收益**3/2** |
| R505 | 提前知道故障与需求，四种故障×两种需求的精确期望最大值**7/2** |
| R506 | 禁止修理：同条件期望**9/4** |
| R507 | 把需求消息推迟到修理决定之后：期望**23/8** |
| R508 | **8个完整公开需求状态、4个延迟需求状态**里，REPAIR-X/Y与同成本ENABLE-X/Y每条合法动作、净收益和最优集合一一对应；两个总体根值相同 |
| R509 | 修理免费时全局期望**4**；修理成本升至4时退回**9/4**，总收益再高也并非每次都修 |

## 研究判断

这里确实克服了R486“只有一支会坏”的伪选择：两支同时失效且只能先修一支是正常可达状态；玩家也能依据新出现的需求反转修复方向，公开需求的价值为7/2−23/8＝5/8。但是**动作关系仍被普通准备/启用菜单完整覆盖**：玩家反复在做“根据需求和代价购买一个可执行任务”，不需要在因果依赖层面重新解释先前做过的事。它更像P13准备提升未来机会、P02选择互斥目标与R157动作解锁的组合，而不是新颖的依赖图操作。

未来有价值的分叉至少需要：修复一条关系会同时改变另一条**尚未选择**的关系或已完成成果的含义，且无法被购买一个新操作选项按同成本模拟；如能模拟仍直接归并，不继续为状态数编写复杂图。没有真人证据、没有精选/Debug晋升。可执行证据 `tools/content-validator/experiments/r502_r509_graph_enable_isomorphism.py`。
