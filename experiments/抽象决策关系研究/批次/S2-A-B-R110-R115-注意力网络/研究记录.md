# S2 阶段第一批｜R110–R115 真实执行与反证

日期：2026-10-12。长阶段总目标和后续验收见 [S2 阶段计划](../../S2-多事件注意力网络阶段计划.md)。**六个研究问题已经执行**：前三个属于 S2-A，后三个属于 S2-B 第一批。两套可重跑的 Python Exact Fraction 脚本与 2 个独立 CI Job 全部通过：[SSNoir S2 Mathematical Research](https://github.com/guopanqi/ssnoir/actions/runs/38194546474)。原始 JSON 产物分别为 `ssnoir-s2-information-time`、`ssnoir-s2-goal-network`。

> 本批全为四到五行动的**纸面独立假设**，不是 Unity C#+Scheme 官方系统的等价模拟，更不是真人理解、犹豫或乐趣证据。效用都是定义好的数学奖励，不是胜率。禁止自动加入 Debug；仍只保留 R09/R37/R54。

## 第一阶段 S2-A：信息／机会何时出现（R110–R112）

### R110 关门条件在什么时刻公布？

从 R109 原来 R108 的四行动、工作自然给线索概率1/4、四地点、主目标完成是否立即关闭副线的对照出发；本轮冻结目标状态后让「是否关闭」在开局以 1/2 先验随机决定，四种条件只改变公开时点，玩家不得提前使用隐藏类型。消息类型与工作结果相互独立。精确 Fraction 结果：

| 是否及时告知 | 完整状态下的最优期望 |
|---|---:|
| 开局知道 | **2113/864** |
| 第一手行动之后知道 | **2113/864** |
| 第二手行动之后才知道 | **1049/432** |
| 始终不主动告知 | **1049/432** |

晚一手造成严格期望损失 **5/288**。对已经通过第一手行动到达「进度1、四处未查、余三手」的同一公开状态，副线始终开放时继续工作价值29/12而先探查7/3；主线会关门时继续工作7/4而探查7/3。玩家需要做的是根据**刚听到的新消息**改变下一步，而不是在开局预先挑一条固定顺序。由于第一手工作在两种信息类型下均合理，开局知道并不优于第一手后及时告诉。

**判决：**保留“行动间的及时消息可以改变已进行的计划”。模型信息价值5/288，不能把它称为强乐趣或复杂策略。与 R109 的关门条件本身不同，R110 检验的是**消息公布的时间**。

### R111 某件新事情由成功还是失败引起？

一回合四动作、工作0/1/2等概率、主进度4完成奖1；每次工作好结果2或坏结果0以相同单步概率1/3**产生一件新的可选事情**，帮一次获得奖励，在主线完成前才可做。关闭新事、出现后永远帮、永远不帮、逐手自由取舍四种对照。

- 可选奖励1：好结果产生的自由最优效用**89/81**，坏结果产生的自由最优**86/81**；出现后立即帮的单一简单流程分别完整达到这两项最优。
- 可选奖励1/2：好结果产生的自由**7/9**，最强「总是帮／不帮」为**62/81**，剩1/81；坏结果自由**61/81**、简单最强**59/81**，剩2/81。
- 可选成果不存在时，模型只剩主线，效用50/81；不同触发源的期待不能当成唯一因果项，因为出现与进度相关。

**判决：**出现的**来源**确实改变机会量及与主线完成的相关性，但常识性策略在多数奖励条件下已经足够。奖励低时留下的一点差距只是在两个极弱开局规则上的上界，下一步必须先用状态公开的条件优先级反证，而不能直接当作复杂规划。与 R103“生成待修问题”不同，这是会打开积极副任务的结果。

### R112 有效期仅一手的新机会

五行动模型：玩家先做一个工作动作（0/1/2），之后以概率1/2收到一个可选帮忙机会；需要一行动兑现，帮助奖励在1/3、1/2、3/5、1、3/2中比较。机会「永不失效」与「只在下一行动内有效」对照，同时关闭帮忙功能、总是立即接受、自由策略。

- 奖励1/3：可永久等待时自由71/81，下一手必须接时47/54，**损失1/162**。
- 奖励1/2：等待优势仅1/324；奖励3/5：仅1/810。
- 奖励1或3/2时，持久与下一手过期的最优效用**完全相同**。
- 五种奖励条件下，「机会出现就立即接受」均已达到过期版本的自由最优。

**判决：**暂不保留「短有效期」作为独立值得试玩的结构；若玩家只要看见就马上做，截止时间只是表面紧张，反而无新计划选择。此研究的真实价值是负例。

## 第二阶段 S2-B：目标之间真正发生什么关系？（R113–R115）

### R113 完成A才开启C，和独立B争行动

主目标A进度2可得1/2奖励，B独立进度2得 `B_reward`，C进度2得2，但**只有完成A之后才能行动C**；总共四动作，每次对一个目标推进0/1/2等概率。比较：没有C、C开局就可做、完成A解锁C的自由策略、六种可执行且会跳过未解锁目标的固定优先级序列。

- B奖励1：正式解锁条件下自由**287/162**，最强固定优先级142/81，余差**1/54**。
- B奖励3/2：自由**161/81**，最佳固定优先级**161/81**。B奖励2、5/2时同样是固定优先级已达自由最优。
- 无C版本和开局无门槛C版本分别给出**是否新增机会**和**前置任务占用行动**的上下界：不等于本规则好玩的直接证明。

**判决：**“完成一条线才能开启另一条”是基础叙事网络关系，数学上存在独立机会价值；但大多数参数根本不需要复杂重排。必须通过具有正常可达质量的新事件来证明比固定优先级多做了什么，才值得提议新原生试玩。

### R114 过剩容量会让责任机制彻底消失（严格负例）

四动作、主目标只要3次必得的稳健+1就完成并获得奖励2，额外帮忙仅耗一动作就拿0.5、1或1.5。另一种风险动作0/2波动，成功会生成“下次做主线要付代价”的热问题；帮忙可冷却问题，亦可花一动作空修。两种工作压力0.5/1。比较关闭帮忙、取消“帮忙可冷却”、取消问题、自由与强简单规则。

**全部六种设置里**自由策略与无问题版本相同，帮忙可冷却相对帮忙不可冷却**独立增量均为0**。最简单“做三个稳健工作 + 做一次帮忙”就获得全部奖励，规避整套风险问题。

**判决：**失败，不保留这个容量条件的机制。它实证了 R37/R103 类“进展制造问题”的前置检查：玩家有余裕稳妥完成所有目标时，系统再多也只会成为可忽视的装饰。

### R115 原封压力规则，只把主目标需求从3调至4

使用相同四行动、同一稳健/风险动作与“风险成功制造热问题”、帮忙可清掉热问题。只将主目标从需3进度调至**需4进度**，使三个稳健工作加帮忙不能全拿。六组可选回报/热问题代价对照，另穷举简单公开阈值族「问题热度、剩余行动、已有进度、是否仍可能稳健完成」。

- 帮忙价值1、下次工作问题代价1：完整自由最优**9/4**；取消帮忙为2，保留帮忙但帮忙不再冷却问题为2；帮忙冷却的**直接独立增量1/4**。
- 同一条件若**完全取消问题**，上限也为9/4。冷却不是让问题产生额外奖励，而是恢复本来会被问题剥夺的选择。
- 强化后的公开阈值族最佳17/8，尚落后自由**1/8**。帮忙价值3/2时，完整自由11/4，禁用冷却5/2，最佳测试口诀41/16，差3/16。
- 帮忙价值1/2时，即使主目标4也仍被四次稳健工作支配，冷却独立收益0。

**判决：**与 R114 正面反证成对保留：可见**净行动容量**使玩家在“承担风险加速主线／帮人顺便解除麻烦／专注安全路线”之间第一次出现严格对照。但现有强策略集还不等于所有可学口诀，**不能把1/8剩余差直接称为复杂玩法价值**；下一阶段先找更强状态口诀，再考虑实际人物情境。

## 第一批合并判断

保留的阶段性语法不是六个新模式，而是三条待验证关系：

1. **及时消息**：在做第一件事过程中得知另一件事将丧失，玩家有机会改变注意力（R110；R109是基础关门关系）。
2. **有前置条件的发现**：解决一件事才可能开启新目标，但必须与一条实际竞争行动的既有线并行（R113；通常被固定优先级覆盖）。
3. **生产性的临时改道**：另一项值得做的事情能顺便化解正在恶化的问题；**必须先有行动容量不足**才有意义（R114负例→R115）。

R111是“行动后生成好机会”的辅助来源；R112的单手过期独立性太弱，不建议单独发展。对三个保留方向均未有人类理解证据，本批不新增 Debug，也不自动把六种纸面模式加入20项正式候选名单。
