# R54 人类反馈触发的容量消融：四骰对照五骰

日期：2026-10-09。**不是第七种模式**，也不是为了提高系统难度的重新设计。本轮依据 [R54 首份真人反馈](../../反馈/inbox/SSNoir-feedback-R54-20261009-062528-43765ce6ee.json) 与 [原研究者回复](../../反馈/reviews/SSNoir-feedback-R54-20261009-062528-43765ce6ee.json) 做一个最小检验。

## 为什么研究

首份反馈来自1人共5局独立网页示意版：甲完成1局、乙完成1局、超时3局。设计者最清楚的判断发生在**开局看骰面后**：低质量骰更倾向容易兑现的甲，较好骰考虑高回报乙。在过程中已投入目标、剩下两颗骰子很难改道完成其他目标，因而少换。**开局选择可能本身很有价值，不因中途切换不多就淘汰 R54。**

研究问题：减少中途的容量困境是否会增加真正有意义的过程改投？还是只是让乙更容易完成，玩家依旧主要在开局择路？

## 冻结的对照

甲：目标3、完成收益1。乙：目标5、完成收益2，完成任一项立即结束。公开对手在**第2/4次行动后**扣除当前进度领先目标最多2（平手甲），尚未完成时生效。每个骰独立d6，成长1，普通 FateStrip 判定坏0／中1／好2。两组唯一差异：**四颗骰子 vs 五颗骰子**。五骰组仍在第2/4手受击，且第5手没有新增攻击。

4骰枚举126种无序手牌（组合权重覆盖所有1296有序手），5骰252种无序手牌（组合权重覆盖7776有序手）。使用 `tools/content-validator/experiments/r54_capacity_ablation.py` 精确 Fraction 动态规划、最强按开局完整手牌选择固定目标序但逐手仍可选用任意剩余骰的基线、沿特定同值规则选出的最优策略前向路径统计。没有蒙特卡洛误差，不是完整引擎回放，也不是玩家样本。

**GitHub Actions 真实成功**：[R54 capacity run 37896433811](https://github.com/guopanqi/ssnoir/actions/runs/37896433811)；[JSON证据](https://github.com/guopanqi/ssnoir/actions/runs/37896433811/artifacts/11600810793)。脚本回归断言四骰结果与原 R54 精确结果完全兼容。

### 决策

五骰增加了完成乙的机会与可被引导的对手反应，但**不支持「仅给玩家更多骰子就会更频繁地产生中途改道」**这个简单假设。注意42.95%和41.26%是选择特定并列最优策略下、所有随机结果的数学路径质量。开局依然可能是体验核心。更多成果并不是更多有趣决策的证据。

这里的「第三手严格换线」特意限定为首次敌方反应之后的那手：在原策略所选的前序路径与剩余骰面之下，最优决策选另一目标，且严格高于下一手继续之前的目标。并非所有临时换路，也不代表人类应当发现这个选择。样本来自**策略展开**而非真人。

## 人类后续验证（小型，不要求刷局）

人类工作台 [Pages](https://guopanqi.github.io/ssnoir/) 的 R54 浏览器简化版新增 **行动容量：4 / 5颗骰**选项。4是原始对照，5是独立网页容量消融；`runs[].handSize` 会跟随玩家反馈保存，旧4骰反馈即使无该字段也继续有效。正式 C# + Scheme R54 仍是4骰的独立权威原型，**5骰尚未原生接入/验证**。

仅需观察：“额外一颗骰是让乙更容易拿到，还是会让你在第二手受击之后主动改变目标？”欢迎明确说“两者都没有”或“开局选择才有趣”。第一次体验不要先从这个表中学习最优打法；上表只出现在可展开的研究结论，不应成为试玩预设。

**下一轮优先次序**：R50「动作回声」没有人类体验评价，优先于要求更多 R54。R54保留可选跟进，不强迫完成4/5成套对照。已有人类反馈及review与本批相互关联，但不覆盖任何玩家原话和现有5条原始轨迹。

## 持续研究边界

不再为了让玩家换线而盲目增加奖励、额外行动技能、第三个目标或攻击强度；先听真实玩家对简洁交互的判断。未来有新的 R54 反馈提交，Agent 须检查 `feedbackSha` 与现有review一致性，必要时重新审阅。这个容量结果不会单凭数学改变人类反馈结论。
