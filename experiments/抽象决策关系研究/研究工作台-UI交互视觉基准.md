# SSNoir · Research Desk · UI / Interaction Baseline v3

日期：2026-10-09。设计权威：本文件定义人类研究入口的视觉和交互意图；研究数据、试玩规则、反馈协议仍以各自的 JSON / C# + Scheme / 校验器为准。

## 产品定位

这不是统计后台，也不是游戏分发站。它是一份不断更新的**研究手册**，连接 Agent 的自主研究和真实玩家的观察。用户回来时先回答：现在探索什么？哪些结论改变了？我有没有必要投入注意力？

## 信息架构

1. **研究简报 / overview**：简明使命、一个有意义的当前邀请、人类真实待办、研究更新。数据来自版本化研究配置。不能伪装成实时运行监控。
2. **实验室 / experiments**：按个人反馈状态与研究优先级导航；左侧目录，右侧连续纵向工作流：研究问题 → 可玩规则或正式入口 → 开放式观察 → 反馈同步 → 研究者按版本回复；支持历史反馈再编辑。
3. **研究地图 / map**：先呈现未解问题，再分组阅读候选机制、证据身份、反例、适用边界、相关实验与停研判断。实验数量不是核心成果。

## 视觉基准

**Editorial Research Desk**，一本正在写作中的研究记录。

- 背景：温暖纸色 `#f5f2eb`；表面：`#fffdfa`。
- 字色：蓝黑墨色 `#202b30`；沉静深色 `#17292b`。
- 强调：烧陶铜色 `#b85a3b` 用于焦点、序号和关键分隔，避免常见 SaaS 的大片蓝绿强调。
- 辅助：杉绿 `#28645c` 用于证据、反馈、链接；绝不把颜色作为好坏评分。
- 排版：文章型标题使用宋体/衬线回退，说明文字使用系统无衬线，编号与证据标签使用等宽字体。
- 布局：桌面较宽的正文与有意不对称的焦点卡；窄屏变成单列。优先内容阅读，而不是装饰组件。
- 组件：方形细边框、少量阴影、纸张分隔线；保留清晰的焦点态和减少动画偏好。

## 人与 Agent 的合作契约

- **玩家观察 ≠ 机制好坏裁定**；Agent 记录观察、解释与不确定性。
- **正在等待 Agent 审阅 ≠ 需要玩家重新试玩**。首页的“需要你的参与”只列真正尚无提交的优先试玩。网络失败时不猜测未完成。
- **反馈是可持续对话**：原反馈可再编辑；GitHub 提交版本保留；Agent 回复绑定反馈 SHA，旧回复必须显示“针对上一版本”。
- **没有后台即时 AI**。静态 Pages 只能展示版本化研究产物与 GitHub 上实际存在的回复。
- **GitHub PAT**：只授予这个公开仓库的 Contents 读写；仅在用户主动提交时需要，localStorage 仅在用户选择后保存，不能放入网页源码或提交文件。
- **正式与示意版明确区分**；网页规则不能冒充 Unity / C# + Scheme 原生规则。

## 交互验收

- 从 `#overview`、`#experiments`、`#map` 与 `#study-Rxx` 可导航；旧 `#research-log` 仍能抵达实验室。
- 搜索 / 筛选 / 排序实验，个人反馈状态不污染研究证据状态。
- 打开实验后可实际试玩、填反馈、备份 JSON、提交到 GitHub。首次点提交时若没连接，应自动展开 Token 设置并聚焦输入。
- Agent 的研究回复严格绑定反馈 SHA；修改后旧回复显示过期提示。
- 支持手机窄屏、键盘 Focus、减少动画，不依赖外部 CSS/JS/CDN。
- Pages 产物由 `build_mechanism_atlas.py` 生成。提交时必须与模板 / 数据 / CSS / JS 字节完全一致。

## 日后演化

研究的问题、结论和实验绑定关系应继续数据驱动，避免把研究内容写死在组件内。若 Agent 需要新增长期领域，如研究简报时间轴或假说状态，先扩展 schema 再构建展示。
