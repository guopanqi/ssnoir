# Prefab 局部构建验证

2026-10-29。入口：`city-box/build.sh --prefab <已有顶层名...>`，默认构建并发布；`--no-publish` 仅构建。

实现复用最近的 city_build.blend，在缓存场景中替换指定顶层 Prefab，调用与完整构建相同的装配、材质、描线和动作清单逻辑。城市填充与其他 Prefab 不重新生成；世界 FBX 因包含全部公共语义节点仍需导出，地点 FBX 只导出指定范围。场景契约仍完整检查。临时目录中的结果全部成功后才替换正式构建文件。

实测：巷战含动画，局部构建 33.144 秒；雕像为普通非 Stage 地点，15.933 秒。此前完整构建发布约 439 秒，非严格性能基准。

证据：

- 巷战单独构建后，其他 37 件地点产物的 SHA256 和时间戳未变。
- 两次局部构建的 Prefab 契约与动作清单保持原值。
- 连续两次 --no-publish 累积巷战、雕像两个待发布地点，真实发布后正确清空。
- 局部发布之外 78 件文件（含 meta 和动作清单）的内容与时间戳未变。
- 全部 30 个地点的 World.visual.json 哈希记录与实际构建文件匹配。
- 临时目录测试覆盖范围外文件保留、只清理目标的过期 clip、GUID 保留、重复发布。
- 不存在的名称直接失败，原 report.json 未改写。

result.json 为结果摘要；构建与发布日志保存在同目录。未重跑完整整城构建，未启动 Unity 或执行游戏交互。首次尝试曾因缓存源 Collection 被 Blender 清理而失败，已改为从作者 city.blend 读取基底身份；失败轮次没有改写构建基线。

限制：显式指定范围，不自动追踪源码/道具/共享规则变更。需要现有完整构建发布基线；嵌套件指定父级顶层，共享道具指定所有受影响地点。布局、footprint、基底、共享构建规则、Stage 身份和新增/删除顶层地点需完整构建；共享 infra 描线依赖尚不支持局部更新，直接拒绝。已知这些边界后，普通地点迭代不需要经过完整城市构建。
