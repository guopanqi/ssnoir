# Research Log

## R0 — 实验基线

问题：能否用 SSNoir 现有城市、剧院和巷子模型，在无表面贴图的条件下建立一套不同于现有实验的“黑色剧场版画”基线？

固定条件：两个场景、四个镜头、同一后处理 profile。

初始假设：先用大黑形和硬光组织观看，再让选择性结构线与暗部排线服务阅读；线不承担造型的主要责任。

状态：等待第一轮自动截图。

## R1 — 修复循环并校正最终颜色输出（2026-10-03）

问题：提交后的 CI 在初始化时栈溢出，无法到达截图和 review 回写。`render → controls.update → change → render` 形成递归；构建成功不能发现这个运行时错误。

固定条件：原场景、四个固定镜头、材质、灯光和印刷参数。先只修复更新职责：change 回调只绘制，交互帧循环更新阻尼，capture 模式关闭阻尼。加入锁文件、源 SHA 检查、逐张进度和全程浏览器错误检查。

首次本地 16 张截图完成后实际查看 contact sheet：城市只剩地标顶端，后巷只剩门和人物，final 黑像素比例为 98.7%、94.7%、98.1%、95.3%。后处理缺少线性颜色到屏幕的转换。

变量：在共享后处理末尾增加 OutputPass，统一 tone mapping 和 sRGB 转换；不改变任何场景或机位。再次构建、截图并实际查看全部四个镜头。

观察：
- 整城斜俯视：地标亮面和地面边界更清楚；城市模型仍集中在地标脚下，尚未形成街区层次。
- 地标纵深：地标分层和投影恢复可读，但城市纵深不足。
- 巷口：门与人物仍是主焦点，消防梯和地面开始可辨，墙体大黑形保留。
- 人物近景：人物轮廓稳定，门光由刺眼黄变为浅暖色，地面投影更清楚；人物形体仍是占位几何。

结果：final 黑像素比例降至 90.8%、89.5%、92.0%、87.6%。保留职责修复与 OutputPass。拖动、阻尼、四机位切换、模式切换、隐藏 HUD、resize 的真实浏览器检查无 pageerror。

边界：这轮验证循环和颜色管线，不代表艺术方向已成熟。shape 与 light 目前仍共享同一灯光输出，不能作为独立光照诊断；下一轮应解决城市导入尺度/结构和诊断层职责，再调艺术参数。Unity 迁移结论：最终颜色空间转换应只在渲染管线末尾统一进行，不靠提高灯光数值弥补输出错误。



## R2–R9 — 恢复空间，转入本地快速循环（2026-10-03）

开始时下载并实际查看 Actions 37126227065 的 16 张截图。后处理吞掉中暗部，城市像地标脚下一团线，后巷像门、矩形人物和悬空栏杆。

先做一轮 Actions 诊断（37126737178）：`shape` 用独立中性法线材质；感知亮度中量化后再还原线性颜色；manifest 加入原始模型包围盒。量化改善了地面可读性，但没有解决导入。

查明三项资产问题：城市外围地面范围 280000，真正建筑高度约 10000，外围几何污染统一缩放；后巷 root 自带 100 倍缩放和 -π/2 X 轴转换，原归一化覆盖二者；剧院独立导出仅含描线和穹顶壳。相继移除城市外围与导出描线、保留 FBX 缩放，再保留其轴转换。每次修正后实际回看，暴露了原机位落进恢复后的墙体，随后按真实巷道重新定位四个固定镜头。

用户建议本地循环。安装锁定依赖与 Playwright 浏览器，普通 Chrome 因环境 Unix socket 限制启动失败，Playwright Headless Shell 能正常运行。Actions 37126956077 导出完整可携带实验包后，本地获得全部模型，不依赖远程桌面。之后进行了多轮成功的本地截图（16 张完整或 4 张最终），另有一轮地面 Shader 因浮点常量类型错误被浏览器健康检查拦截，修正后重新拍摄。

### 观察与保留

- 城市：程序化退台地标、柱廊、檐口；中景少量办公楼体块；暗色远景。降低环境填光，保留高亮地标和屋顶，拉长投影。最初加入的两侧巨大黑块抢占画面，删除。方形底板抢视线，改为场景尺度的解析衰减；低亮度减少量化，避免衰减被切成突兀亮度环。
- 后巷：真实墙面、窗口、消防梯和道具恢复后，巷口形成暗前景与尽头光场。只保留一个风衣、手臂、腿与帽子组成的人物；门光与背光建立身体和长影。中近景首次落入墙内，实际截图发现后移回巷道。使用两张同一空间镜头检查，未写单镜头材质例外。
- 媒介：亮部保持干净；排线只在中暗部，黑场不加颗粒；线阈值从 0.115 降到 0.035，亮度边缘终于能解释檐口。几何墨线只来自明确标记的檐口，禁止对整个导入城市做拓扑描边。
- 工具：快速模式 `CAPTURE_MODES=final` 四张约 13 秒；完整四层 16 张约 24 秒。快速模式不覆盖完整 review。manifest 记录实际代码指纹、模型 SHA-256、实际模式和耗时；最终四镜头单独输出 2×2 总览。源码包让新环境直接启动，不必下载整个游戏仓库。

### 阶段判断

四个镜头已能用形体、光和有限结构线建立同一套阅读规则，值得作为保留版本。人物与后巷的叙事焦点最明确；城市的原始低矮密集建筑与新中景体块仍有尺度节奏差异，下一阶段应围绕街区聚合继续研究，而不继续叠加后处理。本轮不据此宣称 Unity 迁移或最终艺术风格已经完成。

迁移结论：先保护模型导入坐标契约；用体块层级建立城市中尺度；灰阶量化应在感知亮度中进行，并保留低亮度连续衰减；最终输出统一处理颜色空间。轮廓线和颗粒不能替代这些步骤。

验证：最终本地 `npm run build` 和 16 张完整截图通过；真实浏览器检查四机位键盘切换、四模式、HUD、带阻尼的 Orbit 拖动与 844×390 横屏 resize，未发现 pageerror 或 console error。
