## 这次回答什么

**一句话：城市是一排剪影，一条灯河，一个焦点。**

- 前景（河 / 湿街）是黑的镜子，只拉出纵向光带；
- 中景（整城体块）是实体黑，只有朝向对的碎面和冷银边浮出来；
- 焦点（剧院街口一带）是全城唯一的暖 + 红，眼睛落点只此一处。

与黑水 / 剪影夜城的关系：黑水是**城市视角的重装备路线**
（逐像素体积雾 raymarch + 半分辨率镜像反射 RT + 屏幕空间逆光线）；
剪影夜城是**程序化城市的海报路线**（inverted-hull 墨线壳 + 官方 Bloom 直出）。
灯岸是第三条路：**真实城市几何 + 全前向解析光**——无 raymarch、无反射 RT、
无深度/法线预 pass，体块、银边、灯池、雾全部在各自材质里一次算完。
问题意识是：如果城市视角的 noir 可以用"零额外 pass"成立，
迁回 Unity 的就是几个材质参数，而不是一套后处理管线。

## 五条决定

五条互相独立。`captures/lantern-spark/review-4/{shape,lamps,final}` 三列是逐层证据。

### 1 体块 MASS —— 建筑是黑的，亮的是朝向对的碎面

- 九片区反照率 0.012–0.036（`districtTint`），实体黑；
- 月亮是低角度冷键：硬终止线漫反射（`terminator [0.30, 0.70]`）+ 紧镜面瓣
  （`specPower 160`），只有"朝向正好把月亮反进眼睛"的面才亮；
- 每片区 ±8% 明度抖动（`aRand`），破实例重复感；
- 地面 / 郊野的镜面强度单独压到 0.06 / 0（`uSpec`）：月亮的尊严在墙上，不在地上。
  review-1 的教训：地面与屋顶的镜面眩光会淹掉半座城。

### 2 银边 RIM —— 轮廓只做法线 fresnel，只属于竖直面

- `pow(1-dot(N,V), 3)`，面向月亮的边更亮，另有一道极弱冷底线保住"被画出来"的身份；
- `vert = 1-smoothstep(0.45, 0.80, |N.y|)`：地面 / 屋顶不吃银边——
  掠射角下的大平面 fresnel 是整城发白的元凶之一（review-1）；
- 没有屏幕空间描线 pass，没有深度/法线 RT。

### 3 光 LIGHT —— 建模与灯池是两笔账

- **建模分量**按反照率（`× albedo × 14`）：楼体保持近黑，只留朝向；
- **灯池分量**（`uPool`）只给贴地与水面：城市地面 1.0、河面 0.8、楼 0.15–0.2、
  郊野 0。灯不染高楼（高度衰减 `exp(-max(y-灯高,0)×0.062)`）；
- 8 盏暖池各有动机（码头三盏、广场、剧院街口、北桥、东岸、酒馆）；
- 叙事色两点：剧院檐口红、东岸绿。**远距离可见性不靠照亮街区**
  （那会把整片区染红，review-3 的教训），只靠自发光信标点 + Bloom。

### 4 湿 WET —— 纵向解析拉丝，无反射 RT

- 镜面瓣水平收窄（`uStreakNarrow 0.35`）：光带只沿纵向拉长；
- 灯在镜面方向的纵向拖尾是解析近似，不采样任何 RT；
- 只有贴地与水面有；竖直面取反射会自我提亮（黑水已证实，沿用结论）。

### 5 空气与镜头 AIR & LENS

- 前向解析高度雾 + 市中心暖辉（只暖雾，不暖楼；`glowGain 0.3`）；
- 天空：双色渐变 + 一线暖烟 + 硬月亮 + 稀疏星；
- 探照灯是两座加法锥体几何（纵向 × 边缘双衰减，缓扫），不做体积；
- 成片：曝光 → 冷暖分离 → 中调去饱和 → 显示域求黑
  （`max(c×gain-crush, 0)`）→ 只量化亮度（12 档 + IGN 抖动）→ 乘性颗粒 → 暗角 → 径向色散；
- Bloom 用官方 `UnrealBloomPass`（阈值 0.8，只收窗光与信标）。

## 开源实现借鉴（实际采用了哪些概念或代码）

> 先说明：本目录 `HEISHUI-RESEARCH.md` 已把关键开源实现抓取核实过一遍，
> 灯岸站在它的肩膀上，不重复考证链接，只写**本实验实际拿了什么、拒了什么**。

**采用了（按对画面的贡献排序）：**

| # | 概念 / 代码 | 出处 | 灯岸的用法 |
|---|---|---|---|
| 1 | 只量化亮度再按比例缩回 + 显示域求黑 `max(c×gain-crush,0)` + IGN 抖动 | 通用打印级色阶三条硬规则（HEISHUI-RESEARCH §4.5） | `post.js` 成片逐字实现；review 证明暗部无青块/红块 |
| 2 | 镜面瓣只在纵向收窄的"湿地面光带" | drei `MeshReflectorMaterial` 的粗糙度纵向 blur 思想 + §3.5 廉价解析光带 | 水面/地面 shader 里把法线水平分量 ×0.35，不开反射 RT |
| 3 | 炯炯有神的窗：合并面片 + per-quad hash 明灭 + **量化时间**闪烁 | 三个官方 instancing 示例推出的方案（§6），"不量化就是噪点"是关键判断 | `makeWindowMaterial`，`floor(uTime×rate)` |
| 4 | 逐环染色思想（小而亮的源给高阈值 Bloom） | `UnrealBloomPass` 的 `bloomTintColors` 思想（§4.1） | 阈值 0.8，只收窗光与信标，大面积暖雾不进 Bloom |
| 5 | 径向色散（只有边缘有）+ 乘性颗粒（黑位安全） | pmndrs chromatic-aberration / three.js `FilmShader`（§4.4） | 成片 shader；强度分别只取 0.0008 / 0.035，review-2 证明再大就廉价 |
| 6 | 灯光高度衰减是零成本高收益项 | 黑水 `pointWash` 的结构命门（HEISHUI-STUDY §3） | 同一指数形式，前向逐像素；"灯不染高楼" |
| 7 | 面法线 `cross(dFdx, dFdy)` + 平面距离哈希做 per-face 随机 | GLSL ES 3.00 规范（§2.5） | 全部表面材质用法线，合并网格与实例网格行为一致 |
| 8 | IGN 抖动函数 | three-good-godrays（§1.1） | 量化前抖动与颗粒抖动 |

**明确没做，以及为什么：**

| 技术 | 原因 |
|---|---|
| 体积雾 raymarch / froxel | 本实验的问题就是"零额外 pass 能否成立"；解析高度雾在城市尺度已够分层 |
| 平面镜像反射 RT | 同上；纵向解析拉丝给出 8 成效果，0 成额外 pass |
| 屏幕空间描线（depth+normal Sobel） | 前向 fresnel 银边已给出轮廓层级；省掉 G-buffer 与组合 pass |
| inverted-hull 墨线壳 | 那是剪影夜城的路线；且对凹面/折边全描，不符合"选择性" |
| pmndrs `GodRaysEffect` 径向模糊 | 不读 3D 灯、不做遮挡，灯被挡住照样有光柱 |
| `HalftoneShader` 网点 | 印刷网点变漫画，与"打印级色阶"不是一回事 |
| 每扇窗一个 `PointLight` | forward 管线灯数爆炸；8 盏解析暖池 + 自发光窗足够 |

## 走过弯路（都有截图证据）

| 现象 | 真因 | 处理 | 证据 |
|---|---|---|---|
| 整城地面蓝白一片 | 地面/屋顶镜面眩光（视角恰好落在月亮 glint 区，`spec×albedo×40≈1.4`） | `uSpec` 按材质分档：楼 1.0/0.9，地面 0.06，郊野 0 | review-1 → review-2 |
| 整城暖褐、楼像陶土 | 暖池不乘反照率，整栋楼吃满 1.3 钠灯 | 拆成"建模（×albedo）+ 灯池（uPool，只给贴地/水面）" | review-1 → review-2 |
| 整城染红 | 叙事色加了远距离瓣，无遮挡各向同性染全城 | 删远瓣；远距离可见性交给自发光信标点 + Bloom | review-3 → review-4 |
| 窗是白色太阳 + 重彩边 | 窗 lift 2.1 进 Bloom + 色散 ×40 | lift 1.1、分档降功率、Bloom 阈值 0.8、色散 ×12 | review-1 → review-4 |

## 和正式城市的关系

**灯岸不改任何正式产物。** 只读冻结在 `public/heishui/city.{json,bin}` 的快照
（与黑水共用同一份烘焙，不跑 CityBox 流水线）。

可以往回搬的只有**判断**，不是代码：

1. 暖池"建模与灯池分开、灯池只给贴地"是零成本、高收益的一项（高度衰减的姐妹项）。
2. 地面/大平面材质的镜面强度必须单独设档，否则城市视角的月亮 glint 会淹城。
3. 叙事色在城市尺度下靠"自发光点 + Bloom"可读，靠"照亮街区"必然染红一片。
4. 前向 fresnel 竖直面银边可以替代一档屏幕空间描线（省 G-buffer，Unity 侧是常规操作）。

不可以直接搬的：灯强、半径、曝光数字是为 Three.js 线性管线调的，
迁回 Unity 时用原生灯光分层重调，只带走比例关系。

## 实验边界：关于对 CityBox 的依赖

与黑水相同的明确例外（研究问题本身就是"真实城市的城市视角"，
程序化几何替代不了它）：运行时只读冻结快照，零依赖 CityBox 正式输出。
