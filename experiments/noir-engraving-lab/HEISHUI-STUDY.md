# 黑水 · 城市视角视觉实验

启动沿用本实验室的 Vite 服务，访问 `/heishui.html`（也可以从实验室主页 `/` 的
「视觉变量」面板底部进入）。当前本地地址：
http://127.0.0.1:5173/heishui.html

独立构建：`npx vite build --config vite.heishui.config.js`，结果在 `dist-heishui/`。

| 命令 | 作用 |
|---|---|
| `npm run dev` | 起服务，`/heishui.html` 实时观察 |
| `npm run build:heishui` | 独立构建 |
| `npm run capture:heishui` | 七机位 × 四阶段出图 + 联络表 + 亮度统计 |
| `npm run perf:heishui` | 逐帧 `readPixels` 同步实测帧时 |
| `npm run export:heishui` | 从 CityBox 构建产物重新烘焙城市数据（见下） |

操作：**拖动环视 · 滚轮推拉 · 右键平移** · `1`–`7` 切机位 · `R` 复位到当前机位 ·
空格暂停时间 · `H` 隐藏控件 · 触屏双指缩放平移。

## 固定机位与自由观察

七格机位是**被设计过的构图**，联络表的四阶段证据全部出自它们——那是实验的可比性基础。
但研究画面不能只能看七张，所以补了自由观察（`src/heishui/controls.js`）：

| 操作 | 行为 |
|---|---|
| 左键拖动 | 绕当前机位的 target 环视 |
| 滚轮 | 推拉（24 m – 7000 m） |
| 右键 / 中键拖动 | 平移，贴着地面走 |
| 双指 | 缩放 + 平移（触屏） |
| `R` / 「复位」按钮 | 回到当前固定机位 |

相机一旦偏离机位超过 1.5 m，左上角出现「自由观察 · R 复位」；点任一机位按钮或按 `R` 即切回。

用 three 官方 `OrbitControls`，不自己写——阻尼、触屏、平移的边界情况都在里面调好了。
**唯一自制的部分是地面约束**：OrbitControls 没有"相机不许钻到地面以下"，所以每帧按
当前的 target 高度与距离反算极角上限 `cos(phi) ≥ (5 − targetY) / dist`。
这样低机位（相机在 target 之下，比如码头那一格）仍然合法，而拉远之后不会穿到地底。
实测猛往下拖，相机停在 y = 5，没有钻地。

### 为什么原来是固定的

游戏里的世界机位（`Camera_世界`）本身是一台 **Pan 相机**（`drag = "pan"` + `PanBounds`）：
机身能在边界内平移，朝向固定。所以"城市视角"在游戏里就不是自由环视。
加上自由观察是给研究用的**检视**能力，不代表游戏会放开这个机位——游戏那边仍然受 PanBounds 约束。

## 这次回答什么

**一句话：城市不是被照亮的，城市是黑夜里几处光源在湿地面与河面上留下的痕迹。**

现行全城机位把城市画成深蓝底上的白色线框——每栋楼同等对待、每根边同样亮。
那是图纸，不是夜。黑水把这张图纸重新变成一块黑，只让光碰到过的地方浮出来。

与桥头 / 住所两个实验的关系：那两个是**近景**（街角、室内），回答"一个空间怎么被照亮"；
黑水是**城市视角**（上千米外），回答"一整座城怎么被照亮"。
尺度不同，光比、描线层级、空气浓度都要另算一版——所以它是独立实验，不是同一个 profile 的变体。

## 五条决定

五条互相独立：改任意一条都不需要动别的。`captures/heishui-2026-10-04/{shape,haze,line,final}`
四列就是它们逐层叠加的证据。

### 1 体块 MASS —— 建筑是黑的，亮的是它的一小块面

现行画面里，建筑靠 **albedo + 匀光** 被看见。黑水反过来：

- 建筑反照率压到 **0.012–0.034**（`DISTRICT_TINT`）。它们是**实体黑**，不是深灰。
- 月亮不是泛光，是**镜面高光**（`moonSheen`）。只有"朝向正好把月亮反进眼睛"
  的那些面才亮起来，且**不给中间过渡**——终止线是硬的。
- 漫反射只剩一口耳语（×0.28）：够让黑块不至于变成剪纸，不够把城市提亮。
- 再叠一条**逆光银边**（面向月亮 + 掠射角）：把黑块的轮廓从背景里划出来。

结果是一片碎银。朝向对的面亮，朝向错的面彻底黑——这正是黑色电影的"碎镜"。

### 2 描线 LINE —— 线由它背后的光决定

正式城市把描线烘成 Mesh（全城 100 万顶点），代价是**每一根边都同样亮**。
黑水一根烘焙线都不用，全部在屏幕空间现算：

- **轮廓** = 深度断裂（`silhouette`）。归一化到中心深度，所以远处的楼缝一样锐利。
- **折面线** = 法线跳变（`crease`），**且只给主角**（地点外壳、桥、驳岸、广场）。
  填充楼没有折面线——它们只靠体块和窗。
- **线的亮度**（最关键的一行）：

  ```
  glow = 0.13 + 1.70 * smoothstep(0.010, 0.30, bgLuma)
  ```

  背后是黑的，线就只剩一道极弱的冷底线（保住"这是被画出来的城市"这个身份）；
  背后有雾有光，才烧成一道银边。**黑贴黑不画线，黑贴亮才画线。**
- 线的颜色跟着背景的冷暖走：冷背景出钢青，暖背景出钠黄。

### 3 光 LIGHT —— 一冷一暖，各有动机

- **冷键**：城东偏北、仰角 19° 的月亮。它落在城的另一侧，于是照相机位在西边时
  城市是一块**逆光的黑**，只有碎面和雾是亮的。
- **暖池**：全城 **11 盏**，每一盏都有动机——三座桥、中心广场、水塔顶、
  码头岸线的三个点、市中心街口、老城酒馆一带、东岸滨江大道。半径 40–74 m。
- **高度衰减**（`pointWash` 里那一行 `exp(-max(P.y - 灯高, 0) * 0.062)`）
  是黑水的结构命门：**灯只洗到街面往上十几米，再往上就没有了。**
  少了它，一盏钠灯会把六十米的塔整栋染成暖褐——那正是"没有黑色电影"的样子。
- **窗光**：正式画面 3430 扇窗均匀铺开；黑水把每扇窗提亮到 2.3 倍并交给光晕，
  少数窗会自己灭掉（`WINDOW_LIFE`）。城市的神经系统是窗，不是灯。
- **叙事色**：全城只允许三点红/绿（`ACCENTS`）——霓虹、酒馆招牌、东岸一个绿灯。

### 4 湿 WET —— 地面和河是镜子

一次真实的**镜像相机渲染**（半分辨率 + 镜面以上的裁剪面 + 隐藏地面与雨），
按粗糙度沿屏幕纵向拉丝，再加雨滴涟漪把反射的 UV 推开。

- 反射只给**贴地和河面**（`uReflective`）。竖直面也取反射会造成"楼反射楼"
  的自我提亮回路——这个 bug 真的发生过，整座城被抬亮一档。
- 水面单独一档：更宽的镜面瓣 + 更高的增益，于是月亮和钠灯在水上拉出长条。
- 强度是克制的。**noir 不是铬地板。**

### 5 空气与镜头 AIR & LENS

- **体积雾**：从深度反推世界坐标，沿视线 26 步，每步跑真正的灯表
  （11 盏钠灯 · 5 处城区底光 · 2 道探照灯锥 · 月亮前向散射），
  Henyey–Greenstein 相位，半分辨率 + IGN 抖动。**雾是被灯照亮的，不是一层灰。**
- **天空**只有两个色 + 一颗月亮 + 稀疏星点。月晕收得很紧（`pow(m, 260)`）——
  松一点整片天就亮了。
- **成片**：曝光 → 冷暖分离 → 中调去饱和 → 暗角 → **显示域**求黑
  （`max(c*gain - crush, 0)`）→ **只量化亮度**的受限色阶（14 档 + IGN 抖动）
  → 乘性颗粒 → 静止片门暗边 → 色散。
- **光晕分两条独立通道**：冷 bloom（阈值低、半径小）+ 红 halation
  （阈值高、半径大）。合成一条只调 tint 会让普通高光也泛红，立刻廉价。

## 走过弯路（都留在记录里）

这些都是实际画面暴露出来的，不是假想：

| 现象 | 真因 | 处理 |
|---|---|---|
| 整座城白得像纸 | 冷键写成了"硬终止线的宽泛银面"，屋顶 `dot(n,L)=0.33` 全部过线 | 冷键改成镜面高光，终止线抬到 `[0.26, 0.68]` |
| 城区整片暖褐 | `DISTRICT` 材质里分区序号和"表面角色"共用同一个 varying —— village(8) 被判成暖白发光表面，newport(4) 被判成亮金 | 发光判定收进 `#ifndef DISTRICT` |
| 湿地面/河面灰白一片 | 楼的竖直面也在取镜像反射，形成自我提亮回路 | 加 `uReflective`，只给贴地与水面 |
| 暗部成片跳成青块/红块 | 受限色阶逐通道 `floor`，把色相撕碎 | 改成只量化亮度再按比例缩回 |
| 整幅画面被抬高半档、黑不下去 | `floor(x*lv + 0.5 + d)` 的 `+0.5` 是一个半档 lift | 去掉；并把密度控制与量化移到**显示域** |
| 一盏路灯把 60 m 的塔整栋染暖 | `pointWash` 没有高度衰减 | 加 `exp(-(y - 灯高)/16)` |
| 雾把城市糊成一团发光墙 | 月亮前向散射沿整条 ray 是常量，`s × 光学厚度` 直接爆掉 | 系数从 3.2 降到 0.10；灯表系数同步下调 |
| 描线层几乎看不见 | 线的亮度阈值高于全城背景亮度，等于永远不画 | 改成"极弱底线 + 强背景依赖" |

## 和正式城市的关系

**黑水不改任何正式产物。** 它只读 `build/city/city_build.blend`。

可以往回搬的只有**判断**，不是代码：

1. 全城描线的"每边等亮"是当前城市视角最大的问题。线的亮度应该由背后的光决定。
2. 分区反照率（`DISTRICT_TINT` / `Materials`）在城市尺度上偏亮，
   和"建筑是黑体块"的意图相反。
3. 灯光的高度衰减是零成本、高收益的一项。
4. 窗光的稀疏度与提亮倍数值得单独调一轮。

不可以直接搬的：这一套是为**城市视角**调的。地点近景需要另算一版光比。

## 实验边界：关于对 CityBox 的依赖

实验室 `AGENTS.md` 的边界是「不依赖 CityBox 正式输出」。**黑水是这条边界的明确例外**，
理由是研究问题本身就是"真实城市的城市视角"，程序化几何替代不了它。处理方式是：

- **运行时零依赖**：页面只读冻结在 `public/heishui/city.{json,bin}` 的城市快照，
  不跑 CityBox 的流水线、不碰 Unity / Engine / Scheme。
- **烘焙是一次性的**：`tools/heishui-export.py` 从 `city-box/build/city/city_build.blend`
  读一次几何写成快照。它属于"加入外部资产"的许可范围，不是运行时耦合。
- 快照的 `.bin` 不入库（见 `.gitignore`），需要时用 `npm run export:heishui` 重烘。

## 帧时（实测）

Apple M4 · 无头 Chrome · ANGLE/Metal · WebGL 2.0 · 画布 1600×900，**全部 pass 打开**
（镜像反射 0.5× · 主场景 · 体积雾 0.5×/26 步 · 描线 · 光晕 0.125× · halation 0.125× · 成片）。

每格同步连渲 24 帧、每帧后 1×1 `readPixels` 强制 GPU 落地并逐帧记时。结果**不是一个数，是一个区间**：

| 观测条件 | min | 中位 |
|---|---:|---:|
| 机器空闲、连续两次独立复测 | 6.7 – 9.8 | 8.7 – 13.1 |
| 机器上有别的重活时 | 17 – 39 | 20 – 54 |

**结论：这一链路在 1600×900 全开下约 9–13 ms/帧（75–115 fps）是可信的渲染成本；
机器一忙，同一个二进制的读数会上浮 2–4 倍。** 报告里给 min 而不是均值，因为 min 最接近真实成本。

### 测量方法踩过的坑（都记下来）

1. **`gl.finish()` 在 ANGLE 下基本是空操作**，用它同步会量出 0.3 ms/帧、4000 fps 的假数。
   只有 1×1 `readPixels` 会真的等 GPU。
2. **机器上有别的重活时，同一份代码的中位数是 43–51 ms；独占重测两遍是 10–13 ms。**
3. 一度怀疑是刚加的 `OrbitControls` 让帧时翻了倍。做了 A/B（把它从主循环里摘掉再测）：
   有 controls `min 26.5 / 中位 32.9`，无 controls `min 32.3 / 中位 38.4` —— **更慢的是摘掉的那次**。
   也就是它根本不在被测路径上（controls 跑在 rAF 里，而 `bench()` 是同步连渲，
   期间主循环的渲染被 `state.benchmarking` 关掉了）。差异全部来自机器负载。

所以这类"同步点密集"的链路，**必须独占测、必须测两遍、必须看 min**；单次均值没有意义。

要提速，按性价比排：体积雾步数 26 → 14（几乎看不出差别）· 体积雾降到 0.35× ·
镜像反射隔帧 · 描线 8 邻域降 4 邻域。原始数据：[perf.md](captures/heishui-2026-10-04/perf.md)。

## 可复现性

联络表必须能复现，否则"改一个变量前后对比"就不成立。这一轮修掉两个破坏复现的缺陷：

1. **雨的每一滴用 `Math.random()` 生成。** 实验室纪律要求程序生成使用可复现 seed，
   已改成 `config.js` 里的 `makeRng()`（mulberry32，`SEED = 20261004`）。
2. **截图时时钟还在走。** `tools/heishui-capture.mjs` 在设完 `setTime(7.5)` 之后要等 260 ms
   让着色器稳定，而主循环在这段时间里继续推进 `uTime`——同一格每次截出来的雾和雨都不同。
   现在改为：**先 `setPaused(true)` 冻结时钟，再摆机位、设时间、渲染、截图。**

修完实测：同一格连截两次，PNG 的 sha256 完全一致。

- 七机位 × 四阶段（体块 / 空气 / 描线 / 成片）实际渲染并截图；
