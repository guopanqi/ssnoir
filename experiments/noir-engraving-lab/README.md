# Noir Engraving Lab

SSNoir 的独立视觉实验。它不是第二客户端，不读取 Unity、Engine、Scheme 或 CityBox 正式产物；目标是用最少的技术变量回答：**什么能真正增强 SSNoir 的黑色电影表现力？**

## 当前假设

最终画面不追求“更精细”，而追求一套稳定的视觉机器：

`简单几何 → 选择性线条 → 戏剧性光 → 空气层次 → 少量亮度档 → 有序抖动 → 冷色版画`

这套语言必须同时满足：

- 无纹理或极少纹理仍成立。
- 低模、程序生成、AI 生成模型都能进入同一画风。
- 黑暗是主动构图材料，不要求把所有东西说明白。
- 线条承担“信息显现”，而不是把所有几何边都画出来。
- 光和空气优先于表面细节。
- 实验结果可以拆成独立结论，再迁回 Unity；这里不成为生产依赖。

## 第一版包含

- 完全程序化的小城市街段：剧院、仓库、两排街屋、后巷、消防梯、路灯。
- 无贴图材质，主要依赖形体、明暗、emissive 窗光。
- `EdgesGeometry` 几何描线，并区分重要线 / 背景线。
- 冷色主光 + 补光、指数雾、湿路面、雨粒子、简化体积光锥。
- Bloom。
- 自定义全屏 Noir Shader：luminance → black/white normalization → 亮度量化 → 4×4 Bayer dither → 黑/夜蓝/蓝灰/冷白 ramp。
- 四个固定摄影机位，用于后续视觉回归。
- 面板可实时 A/B：涂装、描线、雨/空气、光束、色阶、Dither、雾、Bloom。

## 运行

```bash
cd experiments/noir-engraving-lab
npm install
npm run dev
```

构建：

```bash
npm run build
```

当前固定 Three.js `0.186.1`、Vite `8.3.2`，便于实验阶段保持渲染结果稳定。

## 操作

- 鼠标：OrbitControls，自由观察。
- `1`–`4`：固定摄影机位。
- `Space`：开关雨。
- `H`：隐藏实验面板。

## 实验顺序

### A. 少画是否更 noir

保持镜头不变，只比较：

1. 全描线。
2. 当前选择性描线。
3. 背景线再减少 50%。

观察重点不是“信息更多没有”，而是主体是否更清楚、黑色面积是否更有力量。

### B. 空气是否比模型细节更有效

固定所有几何，只切换：

1. 无雾、无雨、无 Bloom。
2. 只有雾。
3. 雾 + 雨。
4. 雾 + 雨 + 光束 + Bloom。

如果 2–4 的提升明显高于增加模型小件，应优先把开发成本投向摄影和空气。

### C. 色阶数量

测试 `4 / 6 / 8` 级。目标不是复古滤镜，而是找到“还能读清空间，同时把不同资产来源压成同一媒介”的最低档位。

### D. Dither 强度

Dither 必须像纸面/印刷介质，而不能抢过故事。测试 `0 / 0.45 / 0.85 / 1.2`；重点看暗部渐变、雾、窗光边缘。

### E. 光作为叙事选择

后续新增实验不要增加“更多灯”，而要增加**更明确的光源理由**：剧院门光、仓库门缝、汽车灯、百叶窗、舞台追光、码头探照灯。

## 迁回 Unity 的原则

只迁“结论”，不迁这个项目本身。例如：

- 若背景线减少显著更好：修改 CityBox 描线策略。
- 若非均匀雾有效：在 Unity 加一层低频噪声雾，而不是把 Three.js 代码搬过去。
- 若 6 色阶稳定：继续校准现有 `SSNoirStylize` 的 ramp / white point。
- 若光束有效：为少数叙事光源实现 Unity 版本，而不是全城体积雾。

这个目录可以大胆失败；生产工程保持稳定。
