## Baseline 0.1

当前版本建立第一套可运行基线：

- 无纹理程序化街区；
- 选择性 EdgesGeometry 描线；
- 冷色主光 / 补光；
- 雨、指数雾、街灯光锥；
- Bloom；
- luminance → black/white normalization → finite levels → Bayer dither → cold ramp；

这仍是“基线”，不是经过验证的最终画风。下一阶段先研究 Shape，不继续叠加新效果。


## 2026-10-03 — Hero / Context / Silence

**问题**

普通街屋的轮廓线是否真的帮助空间阅读，还是把背景重新拉回前景。

**固定条件**

四个 benchmark 镜头、几何、主光、空气和 Print 均保持不变。

**变量**

普通街屋主体从 Context 改为 Silence；剧院、仓库和后巷连桥继续保留 Hero，少数结构细节保留 Context。重新加入轻量 Line 诊断。

**观察**

- 01 剧院：Hero 线仍明确强调剧院，普通街屋消失的结构线没有破坏街道纵深。
- 02 仓库：仓库屋顶与主体轮廓仍可读，远处街屋更安静。
- 03 后巷：连桥仍是唯一明显结构线之一，前景黑块没有被重新勾亮。
- 04 城市压缩：街屋不再形成连续白边，建筑层级更依赖明暗面和 silhouette。
- Shape → Line 的平均亮度变化在四镜头中约为 +0.001 到 +0.002，说明线层开始从“全局滤镜”退回为稀疏的信息层。

**结论**

- 保留：Hero / Context / Silence 三级语义，其中 Silence 是正式的一等状态。
- 放弃：普通背景建筑默认描边。
- 尚不确定：Context 的 0.11 opacity 是否还可继续降低，暂不调整。

**原因**

线仍能帮助关键物件被识别，但背景不再因为几何边缘本身而获得视觉优先级。这样更符合“显示什么与不显示什么同样重要”的 Noir Engraving 原则。

**迁回 Unity**

CityBox 资产应允许显式的 line importance / outline mask，而不是统一屏幕空间 Outline。Hero、Context、Silence 应由叙事和构图层级决定。


## 2026-10-03 — 低角度侧后主光

**问题**

全局主光是否可以减少道路亮面积，同时保留建筑垂直面的可读性。

**固定条件**

四镜头、几何、线层、仓库/后巷叙事光和 Print 均不变。

**变量**

主光从较高的 [-42, 30, -28] 改为更低的 [-44, 17, -30]，强度不变。

**观察**

- 01 剧院：道路明显退暗，建筑侧面仍保持层级。
- 02 仓库：Final 中 bright>20% 从约 38.3% 降至 25.4%，此前抢眼的道路亮面缩小，仓库工作区仍可读。
- 03 后巷：由于灯光层隔离，几乎不受影响，证明叙事光隔离有效。
- 04 城市压缩：水平面更黑，明暗带更接近街道峡谷，而不是均匀照亮的城市模型。

**结论**

- 保留：更低、更掠射的全局侧后主光。
- 放弃：让全局 Key 以较陡角度同时照亮道路和建筑。
- 尚不确定：是否还需要进一步把 Context 建筑从全局 Key 中分层隔离。

**原因**

在相同强度下，降低入射角自然减少水平面的受光，同时加强垂直面的方向感。这比单独压暗道路材质更接近可迁移的摄影规律。

**迁回 Unity**

优先从 Directional / large-area key 的方向关系控制水平面与垂直面的受光比例，而不是依赖后处理压暗地面。


## 2026-10-03 — 稀疏叙事色墨

**问题**

Noir Print 是否应该把所有叙事色都压成冷白，还是允许极少量暖色 / 红色穿透。

**固定条件**

四镜头、几何、线层、灯光、空气、黑白归一化、有限色阶与 Dither 均不变。

**变量**

Print 在冷色 ramp 之后增加严格的色度门控：只有源画面中确实具有明显红色或暖黄色偏向、且亮度处于可读区间的像素，才混入少量 red / warm ink。

**观察**

- 01 剧院：竖牌重新保留暗红色，入口与极少数灯点保留暖色；建筑和雨仍保持冷色版画。
- 02 仓库：主体几乎不受影响，只留下很少的暖色灯点，没有出现整体彩色化。
- 03 后巷：远端门从冷白恢复为唯一暖色目标，近中景仍保持黑蓝。
- 04 城市压缩：红色剧院牌与少数暖窗可作为远距离定位点，其余城市保持冷色。

**结论**

- 保留：经过色度门控的少量叙事色墨。
- 放弃：Final 阶段把红牌、暖门等叙事信号统一压成冷白。
- 尚不确定：不同剧情状态是否需要动态更换色墨配额，留到 Narrative Image 阶段。

**原因**

色彩不是环境装饰，而是稀缺的信息资源。只允许极少数有理由的物件穿透 Print，可以保留版画统一性，同时让叙事亮点拥有与冷白高光不同的语义。

**迁回 Unity**

SSNoirStylize 可在最终冷色量化之后增加受 mask / chroma gate 控制的 narrative ink 通道；不应恢复通用全彩材质。


## 2026-10-03 — 放弃 Three.js Layers 作为 Light Linking

**问题**

能否像 Unity Light Layers 一样，用 Three.js Object3D Layers 让全局 Key 不照普通 Context 建筑。

**固定条件**

镜头、材质、Print、灯光强度与方向均保持不变。

**变量**

新增 CONTEXT layer；普通街屋 / skyline 只放入该层；相机、fill 和 ambient 启用 CONTEXT，而 key 不启用。

**观察**

- 01–04 的 Shape / Line / Preprint / Final 视觉结果与上一轮相同。
- report 中所有主要亮度统计与上一轮相同到当前精度，说明这个改动没有改变物体的实际受光。
- 因此此前把 WAREHOUSE / ALLEY Object3D Layers 当作“叙事光隔离”的解释也不能继续成立。

**结论**

- 保留：叙事光必须有明确作用域这一视觉原则。
- 放弃：在 Three.js WebGLRenderer 中把 Object3D Layers 当作 Light Linking / Light Layers。
- 下一步：实验室用有限距离、有限锥角和真实遮挡实现局部叙事光；迁回 Unity 时再映射到 Rendering Layers / Light Layers。

**原因**

实验结果没有产生任何图像差异，而且 Three.js 的 Layers 公共契约是相机可见性 / 射线过滤，而不是材质受哪盏灯影响。代码层面的“看起来被分组”不能替代实际截图验证。

**迁回 Unity**

这一结论不否定 Unity 的 Light Layers。它只说明 Three.js 实验不能用 Object3D Layers 模拟同一机制；迁移时应使用 Unity 原生灯光分层。

## 2026-10-03 — 后巷：远置摄影光与真实遮挡

**问题**：交接版本的局部灯虽然使后巷可见，但 Final 两侧墙形成巨大白色弧形，中景不再服务远端门。

**固定条件**：四镜头、材质、主 Key、Print 和背景线策略保持不变。先审阅 artifact 11274632881，再用本地 Chromium headless shell 复现。

**变量**：摄影灯位置、目标、锥角、距离、强度；局部 lift 从 90 降到 12；巷口增加服务顶棚作为真实遮挡。最后把摄影灯沿照射轴移远，保持覆盖范围，减少墙面的圆弧明暗带。

**四镜头观察**：01 剧院主体层级保留；02 仓库没有重新出现成片被提亮的邻近屋顶；03 黑色巷口、冷色中景墙和暖门成立，平台与顶棚阴影读作结构，地面出现有限亮路；04 城市没有回到均匀照亮的状态。早期较宽锥角曾提亮 02/04 两处屋顶，已放弃该配置。

**结论**：保留远置有限锥角 Spot 与真实建筑切光。放弃靠近可见墙面的高强度灯、过宽作用域以及旧全城 DirectionalLight。移远之前的稳定阶段后巷 bright>20% 从基线 26.2% 降到约 3.5%；最终整合版本为 2.7%，black<2% 为 84.2%。

**原因**：单改锥角不能去掉近光源的距离衰减轮廓。把灯沿光轴移远后，墙面受光更均匀，主要亮区边界可以交给顶棚和平台；暖门因此重新获得权重。灯不是 diegetic 物件，仍使用真实三维光照与阴影。

**迁回 Unity**：制作“遮蔽巷口 + 单侧中景摄影光 + 暖门”的场景模板；使用真实遮挡和 Unity 灯光分层。Three.js 的强度数字不直接迁移。只验证了固定镜头，不宣称任何自由机位都成立。

证据：`captures/reviews/2026-10-03-local/baseline/`、`accepted-alley/` 与最终 `final/03-alley-mouth.png`。

## 2026-10-03 — 城市长焦镜头与地标内部线层级

**问题**：04 的飞塔被画面上缘截断，黑色飞塔外缘的 Hero 白线变成过大的空线框。

**固定条件**：后巷的稳定照明、城市几何、材质、主光、空气和 Print。

**变量**：04 机位从 [72,12.5,1.5] 改为 [72,9.5,2.5]，目标从 [2,5,-1] 改为 [2,7,-9]；FOV 保持 30。剧院飞塔由 Hero 改为 Context，入口建筑与雨棚保持 Hero。

**四镜头观察**：01 的亮侧面、红牌与入口仍能辨认，飞塔体量不依赖白框；02 与 03 的空间层级不变；04 飞塔不再被上缘截断，红牌与入口更靠近阅读中心，前景遮挡保留，飞塔白线框消失。

**结论**：保留。地标内部也应分配线的重要性，不必整栋建筑统一 Hero。构图变化意味着新旧 04 的黑面积不能被当作纯渲染参数的提升。

**原因**：线的语义应该指向需要阅读的入口与结构；高大的辅助体量可以依靠 silhouette 和亮侧面成立。

**迁回 Unity**：CityBox / 地标模型应允许部件级 line importance；镜头明确为入口与地标标点留出位置。

证据：`captures/reviews/2026-10-03-local/framing/`。

## 2026-10-03 — 雨退到空气层，以及本地循环

**问题**：全尺寸 04 中雨线在黑底上成为大量亮标记，与结构线争抢阅读。

**固定条件**：已保留的构图与部件线策略、同一 seed、同一雨滴数量、雾和 Print 参数。

**变量**：rainOpacity 0.12 → 0.055；rainLength 0.90 → 0.65。

**四镜头观察**：01 的入口与红牌、02 的工业轮廓和窗光仍优先；03 保留稀薄空气，没有抬灰近景；04 的雨仍可察觉，但大片长白线显著退后。未加入新空气效果。
