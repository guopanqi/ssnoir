# 雾与霓虹（Fog & Neon）— 城市视角 · 黑色电影视觉 + 交互 UI 实验

把官方构建的城市几何放进浏览器，用一套完整的黑色电影渲染管线重新演绎"世界视角"，
并在其上试验**世界视角的交互 UI**：地标标注、两层镜头、四角 HUD 与拖拽玩法。
by ZCode 会话（2026-10）。

## 视觉论点

现有世界视角是"均匀夜色 + 均匀描线"的夜间蓝图：干净，但光不作恶、雾不欺人。
黑色电影的城市恰恰相反——**黑暗占有城市，光是被争夺的稀缺资源**：

1. **光即叙事**。一盏硬月光（长影）、成排的钠灯（地上的琥珀光池）、几块霓虹（竖着的色牌）、
   成片的窗光（生存的痕迹）——画面里只有这四种光，其余交给黑。
2. **雾分层**。远景霾压掉天际线、贴地流雾在街面滚动、高度雾让楼宇"沉"进黑暗。
3. **线是墨，不是粉笔**。地标亮线保留，暗线压到将现未现。
4. **黑水面**。河面做成暗色平面反射镜（three.js `Reflector`），只回答灯与窗的倒影。

## 界面论点（交互 UI）

UI 不是叠在画面上的玻璃，而是**长在画面里的一片光**：

- **地标标注（callout）**：角括号（取景标记）→ 制图引线（发丝）→ 案卷标签（打字机小卡）。
  全部是场景内 sprite/线：自动吃雾、辉光和调色。
- **尺寸契约：屏幕恒定**。标签宽（≈19% 视口高）、引线肘部、角括号臂长按像素定义，
  每帧在锚点距离处反投影回世界——全局视角下标签大得能点，聚焦近景下也不显巨大。
- **两层镜头**：世界（全部地标）↔ 聚焦（推近单栋楼，其余标注隐去，左上角「‹ 返回城市」
  反向飞回离开时的机位）。这是唯一的镜头语法。
- **HUD 四角**：左上案卷头+任务+返回，右上功能菜单（单字方印），左下人物（剪影半身像+
  行动骰子），右下物品（与骰子同尺寸）。统一"案卷"视觉语法。
- **拖拽**：骰子/物品拖到地标标签上投放，目标亮起、资源消耗、案卷区打行动日志。
- **四主题**（右上「式」轮换，HUD 与场景内标注同步换装）：
  - **案卷**（默认）：档案纸——打孔刻痕、方框卡、点数骰面、冷银剪影。最克制、最融入。
  - **铅华**（极乐迪斯科取向）：书页卷宗插图——铜金双线框、墨绿近黑、奶油衬线、
    菱形花饰；场景标注去框改双线注记；骰子为衬线数字。
  - **号外**（报纸剪报）：浅纸面板压夜城、油墨衬线、粗细双规、中文序号任务、
    虚线裁切券骰子、**网纹印刷半身像**；场景标注为微倾斜的纸片剪报。
  - **胶片**：胶片片边——面板顶边一排片孔、等宽帧计数（`FR 01`）、琥珀读数；
    场景标注为带片孔的黑条。

## 运行

```bash
cd experiments/noir-engraving-lab
npm run dev          # 打开 /fog-neon.html
```

拖动旋转 · 滚轮缩放 · 右键平移 · 点标签聚焦 · 左上返回 · 骰子/物品可拖到标签上 · `H` 调参。

## 数据再生成（改了城市构建后）

```bash
cd experiments/noir-engraving-lab
npm run export:fog-neon          # city.glb + lamps.json + anchors.json（读 city_build.blend）
npm run export:fog-neon-roads    # roads.json（读 prefabs/世界.blend 的干道曲线）
```

导出过滤：剔除 `内部_*`（世界层不可见）与东北角舞台区（y>900 且 x>700）。
运行时只读 `public/fog-neon/` 的冻结快照，不接触 CityBox。

## 技术与参考（举一反三的来源）

| 技术 | 实现 | 参考 |
| --- | --- | --- |
| 平面反射（黑水） | `Reflector` 深色镜面替换 `河面` | three.js 官方 `webgl_mirror` |
| 辉光 | `UnrealBloomPass`，**radius=0**（多级模糊链会把画面拖黑，只用最紧一级 = "光源晕圈"） | 官方 `webgl_postprocessing_unreal_bloom` |
| 高度雾 + 远景霾 + 流雾 | 独立 RT（挂 `DepthTexture`）+ 全屏 pass 重建世界坐标，IQ 解析积分 | [IQ: fog](https://iquilezles.org/articles/fog/) |
| 胶片调色 | 线性域低支点对比 + 降饱和 + 阴影偏冷 + 暗角 + 暗部颗粒 + 径向色差 | — |
| 标注尺寸 | 屏幕空间设计 → 锚点距离处反投影回世界 | — |
| 路灯/车流数据 | 干道网格边界边采样 / `干道_*` 曲线 | `tools/fog-neon-*.py` |

**踩坑记录**（复现时注意）：
- 大气 pass 读的深度纹理必须放独立 RT；与 composer 的 ping-pong 目标共享会构成
  读写反馈回路，深度读回垃圾值，整屏被雾吃掉。
- 调色对比曲线的支点必须贴近黑（线性 ~0.02）；经典 0.18 支点把整个夜景压成纯黑。
- 后台标签页的 RAF 被节流到近 0——飞行/打字机要能同步推完（`finishPending`），
  外部直设 `camera.position` 后记得 `lookAt`。
- `import.meta.url` 会被 Vite HMR 加 `?t=` 污染，静态资源路径用挂载常量（`/fog-neon/`）。
