# SSNoir 故事设计总纲

> 定位：**所有章节与短篇故事的写作原则**——长命设计文档，随游戏演进持续回修。
> 它回答"故事该怎么写"，不含任何一条具体剧情。
> demo 短篇的具体设计见 [demo短篇·夜莺故事设计.md](demo短篇·夜莺故事设计.md)；
> 真主线剧本（手写源头）见 [手动编辑的/夜莺剧本-第一章.md](手动编辑的/夜莺剧本-第一章.md)；
> 系统侧的姊妹篇是 [城市生活设计.md](城市生活设计.md)。

## 1. 故事与经济的关系

故事是线性的，小节是固定的，但每个小节的满足条件是自由的：
**故事是线性的，抵达方式是非线性的**（苏丹的游戏的概念）。每次小节推进
（账单的完成）本身是重新规划的时刻，也是局势的变化。

从经济的角度看，故事是目标之一，是存量前往的水槽；但故事的推进同时
拓展行动空间、可用动作集合。从故事的角度看，经济是玩家用不同方式提高
能力、完成故事小节的方式。**不要把交锋当小节本体、把一切当备考——方向是反的。**

## 2. 小节结构四原则（所有章节小节的写作模板）

自 Citizen Sleeper 1/2 提炼：

1. **故事给玩家非常具体的近期目标。** 不是"变强"、不是"准备未来危机"，
   而是：查出一个人的落脚处、在某天前弄到一种保护、备好一种了断方案。
   玩家随时知道自己现在缺什么。
2. **目标有多个抵达方式，横跨不同生活线。** 钱可以买、关系可以换、
   程序可以压、拳头可以抢。玩家不是在选剧情分支，而是在选
   "我用我的活法怎么把这件事办成"。
3. **难度可以不可读，赌注必须可读。** 永远不要求玩家为未知难度的战斗
   做准备；要求他为一张明码标价的账单做准备。交锋要么嵌在某条抵达
   路径里（你主动上门），要么是账单未清时的后果（他们找上门）。
4. **小节完成 = 局势变化 + 行动空间扩容。** 每个账单结清后，世界必须
   打开新的东西——新地点、新人物、新动作、新委托、新账单。主线不是
   单纯消耗资源的水槽，它同时是经济系统的扩张器。

一句话：**故事提出具体账单 → 城市生活提供多种解决方式 → 完成账单打开
新的城市结构。**

## 3. 章节间缩放（第五原则）

数值层有铁律：**技能封顶 0–4、判定分布表在 B≥7 封顶，永不突破**
（见城市生活设计 §4）。因此章节升级只能走**时间轴**，不能走数字轴：

- 账单规模每章升一档，单位是**骰子-天**（完成它需要投入的行动骰总量），
  不是更大的数字面板。
- 账单形态从**单线**走向**多线并发**：第一章一次操心一件事，
  后续章节同时压着两三张互相争夺骰子的账单。
- 维护率、转换链长度、并发义务是可用的加码手段；每次加码必须有
  **叙事理由**（局势升级了，而不是"数值该涨了"）。

## 4. 人物规则

- **人物不是任务标记**：核心人物在小节之间必须有自己的场景；
  他们始终在出力（钱、情报、物件、一首歌），情感由其韧性勾出，不靠眼泪。
- **人物的安危/处境是胜负的一部分**：坏结算推进可见的处境状态，
  改变后续场景；故事可以失败，但不做硬 game over。
- **所有故事状态可见**：状态卡、当前账单、到期倒计时，
  遵循城市生活设计 §1 的 Clock 可见性规则。
- **文本量上限**：每一拍两三屏；对话用 `play-dialogue!`，过场用 `spotlight!`。

## 5. 文案基调（写 .scm 文本时的约束）

- 黑色电影腔：短句、具体名词、不解释情绪。人物不哭；玩家不独白。
- 所有账单、到期日、风险预告写在看得见的地方（状态卡、时钟备注、
  动作副标题）；惊吓只用于剧情揭示，不用于机制惩罚。
- 章节可以有自己的专属文案戒律（如 demo 短篇的"真名只出现一次"），
  写在该章节的设计文档里。
