# 第二幕《手头的事》——目标感与尼尔的打算（作者审核）

> **运行内容已接入，台词仍为 Dialogue 临时版。** 本文不是第二套运行配置，脚本是真相来源。结构承接第六天酒馆告别，第七天进入第二幕，第八天彩排，第九至十二天人物事件，第十三天公共公告。现阶段不增加等级、成长点和强制侦探委托。

## 要回答的问题

重新加载存档时，玩家不必立刻获得一张任务清单，但至少应该知道：
- **眼前会发生什么**：已知日期、约定、会自然结束的机会。
- **现在有什么生活选择**：旧街食堂/零活、剧院临工、原来的日常生计。
- **尼尔希望过怎样的生活**：他曾印过「尼尔，私人调查」名片，想要一份真正需要调查的工作。
- **持续需要维护什么**：旅馆每四天收取 40 美元；首次交租以后仍在「手头的事」里可见，沿用原有倒计时，不另建一根钟。

## 本次事项衔接

- “夜莺：大剧院”收拢首次彩排、已知的赞助人试演、遇见后的伴奏故障及首演宣传回应，替代泛泛的“这里有我的朋友”和单独的试演条目。
- 露西的顶班与代班费是“夜校报名”下的两种处理办法。帮忙后等待消息，亲耳听到报名表已交才了结；没参与也可以从余波获知她自己换班报名的结果。
- 艾迪的期限由对白交代为账房封账前的复核窗口；事项按真实交锋结果、亲耳听到的后续更新，不把缺席写成参与。
- 所有相对日期从 `world-day` 推导；节点期限与开放窗口一致，不增加展示用存档状态。未来只展示已公开或亲耳听到的安排，不预告后台故障。
- 原生定向检查：`dotnet run --project tools/content-validator/SSNoir.ContentValidator.csproj -- --test-second-act-matters`，覆盖知情门槛、相对日期、真实顶班、后台入场、期限、余波与冷读档。

## 面板约定

- **玩家可见名称：手头的事。** 底层仍使用 `dossier` 和既有存档 ID，避免存档迁移。
- 分类提示：`主线→近期`、`人物→人物`、`城市→生活`、`打算→打算`、`委托→委托`。分类表达信息性质，不表示一条条强制任务。
- 只把 **:primary** 事项默认留在地图上；其他事项在面板里，玩家可以手动钉住。已有取消钉住的记录仍然有效。
- 预告来自剧情已公开的信息或尼尔确实得到的消息；不会利用脚本内部的未来事实向玩家剧透。
- 已过期或处理完的事件会按既有的「了结」状态保留回顾，不假装玩家参与过。

## 尼尔个人愿望（不计经验、不强制打勾）

**旧名片**：第二幕起，旅馆中出现一次免费可读的旧名片事件。这是主角自己的经历，进入第二幕后在面板「想做个真正的侦探」中可见；无需认识任何 NPC。

临时 Dialogue：

> 世界：抽屉底下压着几张旧名片，边角已经卷了。
>
> 世界：上面写着：尼尔，私人调查。
>
> 尼尔：来城里都一年了。找到的倒都是搬货、跑腿和替人收拾麻烦的活儿。
>
> 尼尔：总会有人真需要我查点什么吧。

**经理的认可与反思**：第一次在剧院做完临工，经理已经认可尼尔做事可靠；如果尼尔读过旧名片，回家会出现一次免费反思。它不是虚构的调查任务，也不代表尼尔已经成为侦探。

> 世界：尼尔把从剧院领来的工钱和旧名片放到一处。
>
> 尼尔：终于有人觉得我做事可靠。可光会搬景片，算哪门子侦探？
>
> 尼尔：下次要是有人找我查事，可得认真接下来。

**开放的创作问题：** 第三幕是否给尼尔正式的调查委托、谁第一个愿意支付报酬、是否与经理的上层机会形成冲突，仍应在作者审核时设计。当前仅建立主角愿望，不添加无来源的新职业系统。

## 人工审核与试玩重点

1. D7 打开「手头的事」，能否在十秒内选出今天要做的一件事？
2. D8 如果错过彩排，是否只显示已结束的公共事实，而非共享演出现场的私人回忆？
3. 只工作不探索的玩家，是否能在旧地点得到新机会，但不被后台私人信息剧透？
4. 第二幕已经认识艾迪/露西，但尚未听他们亲口说当前的麻烦时，是否仍不会显示具体事件？
5. 手机上顶栏四字入口是否够宽，地图上默认最多只留重要压力，其他事务能手动钉住？
6. 旧档读取、跨日换日以及首次房租已交的情况，需要真机/客户端验收。此处的静态括号检查不等于这些操作已被验证。
