## 1. 这一条线要验证什么

乔不是一组对话，而是一段会持续占用玩家日程的关系：

> 一起做工 → 替他照看孩子 → 公共坍塌与两日救援 → 连续照料 → 人物命运

它验证五件事：

1. 重复生活动作可以自然长出具名人物，而不是刷满抽象好感。
2. 人物请求会与主线、挣钱和休息争夺同一批行动骰。
3. 公共事件能把已经建立的关系变成危机中的具体选择。
4. 危机之后还有数日维护，不以一段结算对话代替人物线。
5. 玩家不介入时，人物仍会被世界带到一个明确结果。

乔的哲学支点很简单：**孩子明天还要吃饭，所以今天这班工不能丢。**
他不讨论城市该走向哪里；弗兰克、林、公司和记者的观点，最后都落在他的腿和饭桌上。

## 2. 最小码头坍塌事件

### 2.1 事实与第一章口径

- 坍塌来自旧码头长期缺乏维护：锈蚀的支撑、反复补过的栈桥和超期使用的起重基座最终失效。
- 新机器、试运行和一次裁员都不是事故原因。公司的新港计划与撤走维护投入早已开始，
  但第一章不提供足以证明“蓄意放任”的证据。
- 第一章当场形成的主导解释是：旧码头危险、落后，更新不可避免。
- 工人会说维修申请一直没有回应；这时听上去仍像事故后的推责。真相留给后续章节重新解释。
- 新机器确实参与救人。技术的价值必须是真的，才有资格在以后与它造成的社会代价发生冲突。

### 2.2 世界状态

坍塌只保存一组公共状态：

| 状态 | 含义 |
|---|---|
| `未浮现` | 旧码头仍在使用，事故尚未成为可进入的内容 |
| `可发生` | 主线已经进入老街；世界可以安排事故，不依赖机器建设或任何人物线 |
| `待响应` | 坍塌已经发生；玩家必须在当天决定是否赶去码头 |
| `救援中` | 玩家已经进入现场，两日救援正在进行 |
| `已结算` | 两日救援结束，公共结果与人物后续已经写回城市 |
| `缺席结算` | 玩家在事故当天没有赶去；现场由其他人自行救援 |

坍塌只能结算一次。人物线改变玩家在现场能做什么，不改变事故是否发生。

公共事件另存一个救援结果，供后续人物线读取：

| 救援结果 | 含义 |
|---|---|
| `兼顾` | 乔及时获救，撤离通道也被稳住 |
| `乔优先` | 乔先被救出，其他工人主要依靠现场人手与机器撤离 |
| `工人优先` | 多数工人先撤出，乔被较晚救出 |
| `失控` | 现场伤亡较重，机器只来得及救出一部分人 |
| `缺席` | 事故在没有玩家参与时自行结算 |

乔的初始伤势由这个结果派生，但属于乔的人物状态；公共事件不持有他的养伤进度。

### 2.3 进入条件

唯一的剧情前提是：**主线进入老街阶段**。从这一刻起，坍塌进入`可发生`，
不读取新机器是否卸完、林的研究是否推进、玩家是否认识乔。

世界在随后一个没有强制主线过场的早晨启动事故，并进入`待响应`。具体隔几天由第一章节奏配置，
但必须为“两日救援 + 四个完整照料日”留下足够时间；如果配置不足，属于内容错误，不在章末压缩结算。

事故当天，码头出现「赶去救援」。玩家仍可处理主线、挣钱或休息，但如果结束当天仍没有进入，
事件立即结算为`缺席`，以后不能补打一场迟到的救援。只要玩家当天进入，便承诺参加完整的两日救援。

### 2.4 两日救援结构

救援是一场持续两个游戏日的专门交锋。进入后，当前日与次日都在坍塌现场；正常日历、房租和主线期限
继续推进，但玩家不能在两日中途返回城市处理别的行动。第一日使用进入时剩余的行动骰，
日终后刷新第二日的骰子；第二日日终强制按实际进度结算。

交锋不是两根并列的“救人进度条”，而是一张会逐层打开的现场：**先判断和挖开，再救人**。

| 现场节点 | 功能 | 后续 |
|---|---|---|
| 清点失踪者 | 用敏锐或交际确认谁还在下面 | 揭示被困位置，避免把行动耗在空处 |
| 撑住断梁 | 用力量、见识或机器减缓二次坍塌 | 打开较安全的深入路线，保护所有未救目标 |
| 挖开货棚 | 持续投入清除外层瓦砾 | 完成后出现货棚下的工人 |
| 被压住的搬运工 | 一个独立救援目标；关系足够时显示为乔 | 完成质量决定乔的初始伤势 |
| 货棚下的工人 | 由“清点 + 挖掘”共同揭示的多人目标 | 决定公共伤亡与劳工评价 |
| 吊机房的值班员 | 被重物封住，普通人力代价很高 | 是林与机器最鲜明的用武之地 |

现场另有一根「二次坍塌」危险钟。日终必然推进，危险行动的坏结果也会推进；
稳定结构可以延缓它，但不能让两日截止停止。部分目标只有完成前置节点才会出现，
因此玩家必须在“继续挖，看看下面还有谁”和“先把眼前的人救走”之间选择。

基本结算为：

| 处理结果 | 公共结果 | 乔的初始伤势 |
|---|---|---|
| 关键目标全部完成 | `兼顾`：多数工人获救，被压住的搬运工及时救出 | 较轻 |
| 优先救出被压住的搬运工 | `乔优先`：乔先出来，深处仍有人没能及时救出 | 较轻或严重 |
| 优先打开通道并救出多人 | `工人优先`：公共伤亡较少，乔被较晚救出 | 严重 |
| 二次坍塌压过救援进度 | `失控`：伤亡较重，机器仍救出一部分人 | 危重 |
| 玩家没有进入事件 | `缺席`：弗兰克、林和码头工人自行救援 | 严重；关系达标时仍可进入照料 |

判定很好或前期人物条件充分时，可以兼顾两个目标；这应当是既有生活投入的兑现，
不是界面上免费出现的最佳选项。

### 2.5 林与机器

林不加入玩家的常规同伴队伍，也不做成每回合自动替玩家推进某一目标的背景节点。
前者会让事件专用能力泄漏到整个城市，后者则把机器最重要的选择权拿走。

救援开始后，场内出现一个专用行动单位：**林与机器**。

这台试验装卸机由林随公司的救援车辆带到现场，是公共事件本身提供的条件；
玩家是否接过卸机器的工作、是否推进过机器建设，都不影响它出现。

- 每个救援日提供一次额外的「机器行动」，不消耗玩家自己的行动骰。
- 只能投入带有“抬升、清障、支撑”性质的节点，不能清点人员、安抚伤者或决定救援优先级。
- 行动非常可靠：没有普通意义上的失败结果，单次推进明显高于人力。
- 玩家决定把机器放到哪里。林能告诉玩家机器做得到什么，但“先抬哪一块”仍由玩家负责。
- 即使玩家此前没有推进林的人物线，基础机器行动也存在；完成精密调试只解锁靠近伤者的操作目标，
  不决定机器能否参加，也不成为坍塌触发条件。具体见[第一章：林与机器](第一章-林与机器设计.md)。

这样技术的优点不是一句“机器救了人”，而是玩家亲手用过一次可靠、强大的行动；
与此同时，机器只解决力量问题，不能替玩家回答谁应该先被救。

以后扩展时，弗兰克提供清点人手、维持通道和控制危险钟的方式；记者不参与抬梁，
负责保存伤亡数字、现场说法和事故后的解释。这些内容都接入同一次坍塌。

### 2.6 乔的关系门槛

公共救援不会自动开放乔的私人照料线：

| 坍塌发生时与乔的关系 | 事故中的呈现 | 事故后的结果 |
|---|---|---|
| 完全陌生 | 一个被压住的搬运工 | 码头原位置留下「最近没看到乔」；不开放住处与照料，乔留下残疾 |
| 已经认识，但接送未完成 | 玩家在现场认出乔 | 码头原位置留下「最近没看到乔」；不开放四天照料，乔留下残疾 |
| 已完成接送孩子 | 乔是明确的具名救援目标 | 码头原位置出现乔的工友；打听去向后开放居民区照料 |

关系的作用不是改变事故会不会砸中乔，而是决定玩家能否认出他，以及是否知道他的住处。
即使玩家缺席公共救援，只要已经完成接送孩子，仍可在码头向乔的工友打听去向；
缺席只令他的初始伤势更重，不关闭已经建立的私人关系。四日伤势期限从事故结算开始流逝，
不会因为玩家晚去打听而暂停。

### 2.7 事故后的最小变化

坍塌后立即发生三件事：

1. 乔离开码头，但他原来的空间位置不留空：关系完成时由「乔的工友」替换，打听后才开放居民区照料；
   关系不足时由「最近没看到乔」替换，并保留到后续章节显式改变乔的状态。
2. 码头出现一条简短的事故余波：机器参与救人，公司把它称为旧港必须更新的证明。
3. 玩家保留公共救援结果，供弗兰克、记者、首演游行和后续章节读取。

当前切片不加入完整工会抗议、记者调查、维修账目或公司阴谋证据；那是后续人物线的内容。

## 3. 乔的第一章完整故事线

### 3.1 第一拍：同一班货

**触发**：玩家第一次在码头搬运。

乔不会站在原地发布任务。他在工作结果里出现：提醒玩家怎么使力、递水，或者在失手时替玩家向工头解释。
继续与他同班，填充「与乔熟悉起来」。工作仍然首先产出工资，关系是生活留下的痕迹。

**完成结果**：两人能彼此叫出名字，乔愿意谈一件家里的难处。

**玩法功能**：把挣钱、劳工关系和人物关系放进同一个动作；第一小节只让乔自然出现，
不在交割款最紧的时候立刻增加人物账单。

### 3.2 第二拍：接孩子放学

**触发**：熟悉进度完成后，与乔吃一顿饭。他说明自己接连排到下午班，孩子放学后没人接。

**目标**：在居民区多次完成「接乔的孩子放学」。每天最多推进一次，需要行动骰；
判定影响当天是否顺利以及推进质量。

这不是一段对白，而是一项会持续数天的生活义务。玩家可以暂停推进，但公共坍塌一旦发生，
尚未完成的接送请求就失去继续深入乔线的机会：乔仍在事故中活下来，却留下残疾，
进入`未介入残疾`，第一章不再开放照料与邀请。

**完成结果**：

- 乔送出一份朴素谢礼；
- 玩家知道他的住处、孩子和真正不能丢掉工作的原因；
- 坍塌发生后，乔会作为具名目标出现；玩家可从码头工友处问到他被送回了哪扇门。

**玩法功能**：第一次让人物关系与主线争夺“每天的一颗骰子”；同时为伤后探望与照料建立可信入口。

### 3.3 第三拍：码头坍塌

**触发**：主线进入老街后，世界启动公共坍塌事件。它不读取乔的人物进度。

乔一定是事故中的受伤工人之一；变化只在玩家当时如何认识他：陌生人看见一个被压住的搬运工，
熟人能认出乔，完成接送孩子的玩家则从一开始就知道那是乔，并能在救援后进入他的私人生活。

**分支**：关系达到门槛时，救援结果把乔的初始伤势写成`较轻 / 严重 / 危重`，
决定接下来四天有多难。关系未达到门槛时，不开放私人照料；第一章结算为半残疾。

**玩法功能**：把前两拍建立的人情变成公共危机里的具名目标，并让“先救认识的人还是先救更多人”成为选择。

### 3.4 第四拍：四天照料

**触发**：玩家已经完成接送孩子，并经历坍塌结算。乔被送回居民区，伤在腿上；
工头没有主动处理工伤和赔偿。码头上乔原来的位置出现一名工友，玩家主动打听后，
工友说明乔被送回居民区。玩家此前接过孩子、认得那扇门，于是居民区才开放限时照料。

如果关系没有推进到这个门槛，公共事件照常结束，但不开放私人照料；乔进入`未介入残疾`。

乔身上同时显示：

- **伤势倒计时**：四个完整日终后结算；事故当天不扣一天。
- **照料进度**：初始值受救援结果影响，填满可提前痊愈。

每天提供两种维护手段：

| 行动 | 消耗 | 规则 |
|---|---|---|
| 照顾乔 | 一颗行动骰 | 每天一次；交际判定决定无进展、普通推进或较多推进 |
| 给乔用药 | 一份药品 | 每天一次；稳定推进，可与当天照顾并用 |

当天至少使用一种手段，伤势不会因无人照看而恶化；整天不管，照料进度倒退。
照顾失败不倒扣进度，因为玩家已经支付了行动骰与冷静，且“尽力照顾反而害了他”不符合情境。

**玩法功能**：形成第一章第一条持续维护线。玩家每天都要重新决定：主线、挣钱、休息和乔，今天先顾哪一头。

### 3.5 第五拍：命运与回报

照料结束有三种结果：

| 结果 | 条件 | 人物状态 | 玩法回报 |
|---|---|---|---|
| 痊愈 | 照料进度填满 | 乔重新站稳 | 可邀请入队，提供正常同伴骰 |
| 残疾 | 到期时未填满，但没有跌入死亡区 | 乔活下来，腿留下永久损伤 | 可邀请入队，同伴骰永久降质 |
| 死亡 | 到期时照料进度处于死亡区 | 乔死亡，码头很快补上他的班 | 无同伴；空位本身成为后续世界状态 |

邀请不是自动发生。乔活下来后，玩家仍要亲自开口；不邀请，他就留在自己的生活里。

**主线兑现**：只有已经建立深层关系且仍能行动的乔，才可在首演之夜守外圈。
他只负责封门和疏散，不进入内场替玩家处理暴力；残疾会改变同伴骰，但不把他从故事里抹掉。

## 4. 状态机

乔的状态必须能区分“人物处境”和“是否有资格成为同伴”，不能只用一个好感数字覆盖全部含义。

| 状态 | 进入方式 | 可用内容 | 离开方式 |
|---|---|---|---|
| `陌生` | 新游戏 | 码头搬运中的初见 | 第一次同班 |
| `熟悉中` | 第一次同班 | 继续搬运，积累熟悉 | 熟悉目标完成 |
| `等待请托` | 熟悉完成 | 与乔吃饭 | 接下请求 |
| `接送中` | 接下请求 | 居民区接孩子 | 接送完成；若坍塌先发生则转入`未介入残疾` |
| `关系已建立` | 接送完成 | 等待公共事件；保留乔的住处与家庭关系 | 坍塌发生后进入养伤 |
| `养伤中` | 坍塌救援结束 | 先在码头打听乔的去向；之后在居民区照顾、用药 | 痊愈、到期残疾或死亡 |
| `痊愈待邀请` | 照料填满 | 邀请乔 | 入队或章节结束 |
| `残疾待邀请` | 照料到期 | 邀请乔 | 入队或章节结束 |
| `已入队` | 玩家邀请 | 每日同伴骰、首演外圈帮助 | 跨章保存 |
| `死亡` | 伤势结算 | 无 | 跨章保存 |
| `未介入残疾` | 坍塌发生时关系未达到照料门槛 | 码头保留「最近没看到乔」；不开放照料与邀请 | 作为第二章起点保存 |

`未介入残疾`与`残疾待邀请`不是同一状态：前者表示玩家没有经历这场危机，不能在章末临时领取同伴；
但此前是否认识、是否完成接送仍应保存，供第二章决定乔是否还愿意见玩家。

## 5. 第一章章节结算

第一章结束时，公共坍塌必须已经是`已结算`或`缺席结算`，再保存乔的命运：

| 章末情况 | 结算 |
|---|---|
| 与乔的关系未达到照料门槛 | 无论玩家是否参加救援，乔都活下来但半残疾，进入`未介入残疾` |
| 关系已经建立，但玩家缺席救援 | 乔以严重伤势进入正常四日照料，不跳过私人后续 |
| 章节结束时乔仍在养伤 | 状态错误；事件排期必须留下完整四日照料，不能提前压缩结算 |
| 乔已痊愈或残疾，但玩家没有邀请 | 保留关系与身体状态；乔不是同伴，第二章从其实际所在地续写 |
| 乔已入队 | 保存同伴与永久伤残修正；第二章继续提供对应同伴骰 |
| 乔死亡 | 保存死亡；不以同名替代人物重开这条线 |

如果章节结束时坍塌仍处于`未浮现 / 可发生 / 待响应 / 救援中`，说明第一章事件排期或结算错误，
不应悄悄补一个章末结果。

半残疾不是惩罚弹窗。码头上乔原来的位置长期留下「最近没看到乔」：事故发生了，乔活着，
但以后不能再像从前那样搬货。这个 observe 与乔共用同一个 Anchor，直到后续章节让乔再次出现。
玩家应当清楚这是自己没有走进去的一条生活，不被告知“选错了”。

## 6. 当前切片的边界

本轮执行只需要形成以下闭环：

1. 从搬运认识乔；
2. 完成接送孩子的持续目标；
3. 主线进入老街后独立启动公共坍塌；
4. 玩家当天可选择缺席，或进入持续两日的多目标救援；
5. 林与机器作为场内专用可靠行动，由玩家分配到重型目标；
6. 救援结果改变公共伤亡，并在关系达标时改变乔的初始伤势；
7. 四天照料得到痊愈、残疾或死亡；
8. 活下来的乔可被邀请，关系不足则以半残疾状态进入第二章；
9. 全过程能够保存、读取，并由首演人手条件读取最终状态。

暂不在这一切片实现：弗兰克的组织手段、林的前置调试人物线、记者的事故报道、维修资金证据、
工会游行升级和公司的完整舆论行动。它们以后都接在本文定义的同一次坍塌及其公共结果上。
