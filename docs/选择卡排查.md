# 选择卡排查

状态：**已排查，暂不处理。**

## 问题定义

游戏目前最稳定的交互认知是：行动卡代表一件可以投入骰子、物品或其他明确资源的行动。玩家通过
分配来做决定，结果由投入和判定产生。

与此冲突的是“选择卡”：它没有资源投入，只把一句对白表态、一个结局按钮或一次放弃包装成普通
行动卡。玩家看到同一种卡面，却不能再用原有的分配规则理解它，因而不知道这是动作、剧情入口、
确认按钮，还是一次不可撤销的选择。

不是所有免骰卡都有这个问题。“见夜莺”“赴晚宴”一类单独出现的必经事件入口，只负责进入一幕
演出，没有同时提供多个立场，暂时不列为选择卡。商店购买、下注等明确投入物品的卡也仍然属于
资源分配。

## 明确的对白选择卡

### 艾迪第四场拳赛：点头／摇头

位置：`UnityClient/Assets/Resources/Content/scenes/world/艾迪.scm`，`signal-nodes`。

拳赛演到艾迪抬头看尼尔之后，演出结束并返回世界树，再并列显示“点头”和“摇头”两张免骰卡。
它们唯一的功能是选择“照约定倒下”或“让他赢”，是纯粹用行动卡模拟对白菜单。

这一处与已经从《三封信》中删除的“追究／摊牌／照帮／沉默”四张回答卡属于同一问题。后者留下的
说明位于 `UnityClient/Assets/Resources/Content/scenes/world/三封信.scm` 的
`node-give-negatives` 上方。

将来处理时，不应继续保留这两张世界行动卡。候选方向只有两个：

1. 对白系统支持当场选择，在人物仍处于演出画面时完成表态。
2. 不提供当场菜单，让结局由玩家此前的投入、下注、关系或行动结果决定。

在对白选择机制尚未确定以前，不为这一处单独制造临时 UI。

## 免骰收场与妥协卡

这类不是纯对白菜单，但仍与投骰行动并排显示。它们表达“停止投入”“接受当前结果”或“选择安全
方案”，玩法意义成立，表现载体有问题。

- `world/第二章/机器进入老街.scm`：**看着这一天过完**。与拦艾迪、停机器、劝人群并列，实际是
  结束第二章现场的按钮。
- `encounters/让他们安静.scm`：**今天到此为止**。直接以当前局面失败收场。
- `encounters/船修好了却不开.scm`：**接受部分付款**、**交回关键部件**。两张都是直接结算交锋的
  免费结局卡，并与继续投入骰子的行动并列。
- `encounters/核赔.scm`：**坐实骗保**。免费确认报告；与需要投入骰子的“替他放过这一笔”构成
  不对称选择。
- `encounters/无人班次.scm`：最后一批货同时出现**让它自己处理**、**叫他先出来**、**紧急停机**，
  只有第一项需要投入骰子。
- `encounters/失控的机械.scm`：**拉总闸**。与拖人、撑住、自己上手等投骰行动并列，但点击后立刻
  安全收场。

将来更合适的方向，是给交锋建立独立的“收手／接受当前结果”控制。它可以明确展示后果并要求确认，
但不应占用行动牌位，也不应伪装成一次无需分配的普通行动。至于“拉总闸”“叫工人来”这类确实是
场内动作、只是目前没有成本的方案，还需逐场判断：要么赋予真实成本，要么承认它属于交锋的安全
退出机制，不能机械地全部改成同一种东西。

## 没有真实选择的表态卡

`world/三封信.scm` 的**什么也不说**是单张必看卡，没有并列选项，却用第一人称表态作为标题。玩家
实际上只能点击沉默，因此它不是选择，只是在视觉上假装玩家选择了沉默。将来应改成中性的剧情推进，
或者直接接在前一段演出之后自动播放。

其他“灯重新亮起来”“散场之后”“见剧院的经理”等单张必经卡目前不列为优先问题。它们更接近
进入演出或确认场景已经推进；是否进一步自动化，应作为“必经演出的呈现方式”单独讨论，不与选择卡
清理混在一起。

## 暂定设计原则

> 行动卡必须承载分配：投入骰子、物品或其他明确资源。纯对白选择不用行动卡；必经演出自动发生；
> 放弃或收场使用交锋级控制。

处理顺序暂定为：

1. 先处理艾迪拳赛“点头／摇头”，因为它是最纯粹的对白选择卡。
2. 再定义统一的交锋收手结构，逐场迁移免费收场和妥协卡。
3. 最后清理“什么也不说”这类没有真实选择、却伪装成玩家表态的必看卡。

## 对白选择机制的既有方向

如果以后确认游戏确实需要当场对白选择，方向是让对白序列自己能收尾于选择，而不是退回世界树。
编码方式倾向于“分支写成数据、默认合流”：选项只携带插入主干的几句对白和状态效果，播放完继续
公共后半段。不要让每个选项用回调各自接管后半段，否则公共内容会复制，Scheme 缩进和状态收束也会
迅速失控。

两条护栏：分支默认合流；不合流的多个结局不强塞进这套接口。选项效果至少写入一个可存档状态，
否则玩家的决定实际上没有进入游戏状态。

可能的实现路径：`DialogueSequence` 增加浅层分支节点，依次打通 native、终端 `OverlayWidget` 和
Unity `ConversationPlayer`，最后用艾迪第四场拳赛验证实际手感。是否值得建设这套机制，要等未来新增
剧情证明它不只是服务单独一处。
