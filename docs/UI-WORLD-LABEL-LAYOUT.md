# 世界标签布局：统一空间契约

Unity 的世界标签布局由 `UnityClient/Assets/Scripts/Runtime/IMGUI/WorldLabelLayout.cs` 拥有。本文记录现行实现，不是第二套规则。

- **测量**：世界卡、地点牌和锚定标注先量出实际矩形；场景标注带提供每条文字真实的占位矩形（不再把整行算成障碍）。
- **占位**：安全区、顶栏、钉住条、手牌、场景标注属于硬障碍；人物肖像和视觉焦点属于软障碍。模态窗口遮挡并禁用世界交互，不会推动后台世界标签重排。
- **统一排布**：`PlacementState.Arrange` 先为当前仍存在的标签登记旧位置，再依照地点 → 动作 → 锚定标注的稳定顺序为新标签解算；非阻塞对白由同一个 `PlacementState.Place` 契约布局，并使用独立台词 ID 缓存。
- **局部性**：候选位置来自锚点附近、期望位置附近以及现有占位的边界，而不是全屏搜索；每种标签都有以锚点至卡片边缘计算的最大连接距离。无有效解时保留主体关联并记录 `Overflow`，不会通过跨屏移动掩盖拥挤。
- **稳定性**：`PlacementState` 保存标签相对于投影锚点的偏移和内容尺寸。镜头拖动、锚点跨越屏幕中线、画面边缘和临时 HUD 遮挡都**不能触发标签换边或重新搜空**；已有标签以固定偏移跟着对象移动，必要时自然移出视野。只有相机布局上下文切换、场景重建或标签尺寸变化才重新求解；新标签首先绕开所有已有标签。镜头移动和布局重新决策是两个独立阶段。进入下级地点不会清除仍在场景根树中的世界地图标签记忆；镜头运动结束也不是布局失效条件。
- **绘制**：求解器只返回矩形；世界卡的引线依然由 `CardLeaderLineDrawer` 绘制，锚定标注保留它自己的细竖线语言，气泡保留三角尾巴。视觉样式不属于求解器。
- **交互**：`Space.IsUiBlocked` 与排布使用同一批硬区域，但整条顶栏仅用于排布，实际命中只锁可交互控件，避免重叠点击。

原有的 Pan 全屏网格搜空、Orbit 左右栏和分列堆叠解算器已撤销。不得再新增与 `Space` 并行的局部避让系统。

**返回世界的呈现时序**：城市根层级的返回操作在同一次导航事务中选定最终焦点机位，使用无二次运镜的 Cinemachine cut；它等待相机 LateUpdate 应用后再显露世界投射标签，避免一帧旧机位 + 一段新机位动画造成地图「出现后又跳一次」。进入地点、剧情过场及 Stage Portal 的编排仍使用原有过渡路径。

**布局交互取舍**：已有标签在镜头移动时宁可部分离屏或临时被固定 HUD 覆盖，也不为维持可见性突然换到对象另一侧；固定 HUD 仍绘制在世界卡之上。需要编辑作者调整布局时，改变场景/锚点或重新建立布局上下文，而不是在拖动中触发自动换边。

## 验证

Unity Editor 菜单 **SSNoir → Validate World Label Layout** 使用生产求解器检查长引线、密集动作卡互不重叠、相机拖动及跨越屏幕中线保持相对方向、屏幕边缘不翻边、从地点返回世界重用地图位置、内容新增保持旧位置、结构性重排及交互遮挡。

在 Play Mode 中还应人工复查：码头第 2 天截图、相机 Pan/Orbit、宽窄横屏和三档 UI 缩放、任务钉住条长短变化、同锚多条标注、人物连续插话，以及设置 / 卷宗等模态窗口打开关闭。**编译通过不代表视觉验证通过。**
