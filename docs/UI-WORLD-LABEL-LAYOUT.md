# 世界标签布局：统一空间契约

Unity 的世界标签布局由 `UnityClient/Assets/Scripts/Runtime/IMGUI/WorldLabelLayout.cs` 拥有。本文记录现行实现，不是第二套规则。

- **测量**：世界卡、地点牌和锚定标注先量出实际矩形；场景标注带提供每条文字真实的占位矩形（不再把整行算成障碍）。
- **占位**：安全区、顶栏、钉住条、手牌、场景标注属于硬障碍；人物肖像和视觉焦点属于软障碍。模态窗口遮挡并禁用世界交互，不会推动后台世界标签重排。
- **统一排布**：地点 → 动作 → 锚定标注，使用相同的 `Space.Place` 过程，排列顺序固定，每张成功排放后立刻登记占位。随后非阻塞对白向同一 `Space` 登记自己的矩形。
- **局部性**：候选位置来自锚点附近、期望位置附近以及现有占位的边界，而不是全屏搜索；每种标签都有以锚点至卡片边缘计算的最大连接距离。无有效解时保留主体关联并记录 `Overflow`，不会通过跨屏移动掩盖拥挤。
- **稳定性**：保存的是**当前投影锚点的偏移**，不是过期的世界坐标或屏幕绝对坐标。相机/模式/安全区变化及转场落镜会重置缓存；其他情况下若既有位置满足当前占位约束，则维持不动。占位变化使位置失效时自动局部重排。
- **绘制**：求解器只返回矩形；世界卡的引线依然由 `CardLeaderLineDrawer` 绘制，锚定标注保留它自己的细竖线语言，气泡保留三角尾巴。视觉样式不属于求解器。
- **交互**：`Space.IsUiBlocked` 与排布使用同一批硬区域，但整条顶栏仅用于排布，实际命中只锁可交互控件，避免重叠点击。

原有的 Pan 全屏网格搜空、Orbit 左右栏和分列堆叠解算器已撤销。不得再新增与 `Space` 并行的局部避让系统。

## 验证

Unity Editor 菜单 **SSNoir → Validate World Label Layout** 使用生产求解器检查长引线、密集动作卡互不重叠、相机相对偏移稳定、HUD 变化触发局部重排和交互遮挡。

在 Play Mode 中还应人工复查：码头第 2 天截图、相机 Pan/Orbit、宽窄横屏和三档 UI 缩放、任务钉住条长短变化、同锚多条标注、人物连续插话，以及设置 / 卷宗等模态窗口打开关闭。**编译通过不代表视觉验证通过。**
