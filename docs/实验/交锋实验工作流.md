# 交锋实验工作流

持续目标：做出10个不同的交锋模式原型，决策直观、规则简短，并保留初评证据。模式通过作者初评不等于玩家认可；人类试玩之后再决定进入结构库、修订或淘汰。

## 一个实验算什么

先写一句人物的矛盾，再写一个能被推翻的假设。例如：想拿更多线索就要靠近，但此前的偷听会改变对方下一次回头的危险。不是“做一个跟踪玩法”，而是“这会不会让玩家根据当前状态主动改变距离”。

一个主关系，两三种主要动作，通常两三根钟。必要时更多，但要能说明删掉哪根会丢掉什么决策。原型无须场景美术、配音、城市接入，直接使用正式引擎与唯一Scheme内容。不要为实验新造引擎、存档或第二个客户端。

“新模式”按玩家决策关系区分：触发时机、对手回应、信息与行动的关系、资源的跨步作用、不可逆承诺等。改名字、改钟长、替换人物，或把多目标多威胁换一套皮，不单独计数。与结构库已有想法比较，说明具体新增了哪种关系。既有想法的有效拓展可以是候选，但需能指出它改变了什么选择。

## 每场怎么做

1. **提出假设。** 写出主矛盾、两个合理选择、什么状态会让选择反转，预计主要风险。允许最后推翻假设。
2. **做最小情景。** 先在开场明确人物为何行动，并在场内常驻目标说明：想得到什么、怎样结束、失败会失去什么。目标换阶段时同步更新说明。赌注、转折条件和下一拍尽量可见。隐藏的信息必须服务玩法，不拿信息缺失制造假难度。动作文案遵循write-scheme，现有原语足够就不扩展。
3. **直接载入验证。** `./run --validate` 必须明确列出本场。载入成功不能证明回合规则、结束或体验。
4. **逐步观察CLI并决策。** 一步一观察，在工具调用之间决定下一步，理由写在行动之前。保留至少一局完整轨迹。不用预先写好的选择循环替代这一阶段。每次理由应说明当前事实、想保护什么、接受什么代价；不是复制“选择最优动作”。
5. **修订。** 记录问题从哪一步观察到、为什么改、改后是否重新走到了相关路径。操作接口错误与设计问题分开。
6. **然后才做脚本对照。** 固定策略用于复跑、分支检查、数值比较。脚本理由标为模板，作者路线知识标明；不能把21局相同结果称作21局玩家评估。同seed也不保证不同策略消耗的随机数相同。
7. **记录初评，提供人类入口。** 写一个值得保留的决策和一个不成立／未确定的地方，列清验证边界。用户先自主试玩，再读作者方案。

作者看过实现，就不能把自己的会话称作盲测。仍然必须逐步玩：它能发现信息表达缺口、规则误解、原计划变更和不必要的操作。独立盲评需要另一位不知道内部实现的评估者；本次未默认使用子Agent。

## 判断标准

- **先懂目的：** 不看作者文档、不猜Clock名称，玩家能回答“我为什么在这里、要得到什么、做到哪一步能结束”。达标后要明确交稿／撤离动作，不能让玩家以为仍需继续填钟。
- **容易读懂：** 能用一句话说清此刻的主要选择；关键代价在观察里，而非作者解释里。
- **选择会变：** 能指向轨迹中的具体时刻，说明同一动作的价值为什么变化。无需每步犹豫，但不能始终重复收益最高的动作。
- **动作有去处：** 差骰、好骰、免费动作的用途可以不同。不要为了动作数量强行保留永远劣于另一张卡的动作。
- **情景成立：** 玩家权衡应当就是人物在权衡的事；比如枪手认路应让玩家思考下一次枪口，而非只优化两根无关进度条。
- **结果有意义：** 次优结局和撤离要说清失去了什么；副目标不能只增加分数，最终还要有情景上的区别。
- **不过度复杂：** 新规则必须产生新选择。失败后先检查信息和关系，别马上叠更多Clock。

记录评级使用“继续候选／需要修订／淘汰”，不写“已证明好玩”。试玩通过的模式再记回结构库并标注证据。

## 工具与证据

逐步控制台：

```sh
python3 tools/content-validator/experiments/manual-session.py encounters/实验·枪口认路 --seed 19 --record /tmp/枪口作者局.json.gz
```

控制台不选择策略，只完整读取公开观察、压缩显示、按明确指定的卡和骰转发命令。相同点数骰默认第一项；复杂多槽组合请使用原生version／operationId精确指定。

```json
{"card":"穿过货棚","die":4,"reason":"当前枪口在栈桥；先推进保底片的路线"}
{"card":"end-turn","reason":"这一回合路线已走过，不为用完骰而行动"}
{"command":"quit"}
```

正常quit自动存原始协议到指定gzip，不覆盖已存在记录。EOF或异常退出不承诺保存，长局可用原生save命令额外保存。完整JSON记录保留所有事件和阶段快照，控制台展示只用于阅读。

重放是版本严格检查：指纹覆盖全体内容，新增其他实验也会让旧记录不能直接`--replay`。历史记录仍可用于审阅，不能修改原指纹伪装成当前结果。最终交付前对当前版本的轨迹复核；发生变化的场必须重新逐步试跑。脚本重演已经记录的决定，需要比较观察和事件，明确标为回归复核，不能当新玩家局。

每场目录保留：假设／修订／具体决策／局限／操作路径、逐步记录、必要的对照。原型不塞进GameTester，也不把一次性脚本发展成第二套内容系统。

## 接收试玩反馈

请记录场景名、seed（若知道）、大致在哪一步，以及以下任意一点：

- 你当时以为会发生什么，实际发生什么。
- 哪次选择让你停下来想，哪段只是在重复操作。
- 哪个动作没用过，为什么。
- 结果是否符合这个情景，以及你还想不想再玩一局。

把反馈先归到具体证据，再决定修情景还是修流程。例如作者知道但玩家看不到的预告，优先修改信息验收标准；一直出现优势动作，修改候选动作判断；空间呈现导致误读，则补Unity验收，而非直接改规则数值。

## 数学上可行，不等于决策有趣

实施前用最乐观结果计算期限内的最大进度。若保留某资源根本不可能成功，放弃它就只是强制步骤，不能算动态取舍。赃款v1就是这个问题：抱三袋三次好结果仍不到出口，必须修改收益后再试玩。

永久投资同时检查前置耗骰、少掉的回合、免掉的维护次数与容错余量。不能因永久效果看起来强就认定它值得做；也不能因两种策略都成功就认定二者都有选择价值。小样本若显示一条路线更稳，保留这个疑问，继续找另一条路线实际有用的公开局面。

## 记录有利的退步

不要把“推进目标钟”直接等同于好动作。记录什么时候玩家主动退进度、弃掉资源或撤销此前成果，以及公开状态为什么使它值得做。证词掺水作者局中，五格含假话不如四格可信；这是具体观察，不代表所有污染机制都好玩。另检查两步组合是否容易退化成一个固定按钮，不能只凭动作数量判断决策丰富。

## 试玩没有触发主假设时

首局顺利完成不一定是正面证据。如果威胁还没发生，解除威胁的承诺就没有得到检验。封死退路v1一回合救走证人，未观察到封门价值；延长目标后再试玩，同时保留不承诺也能成功的最乐观路径。不得为了测试新按钮而无理由主动选它，再把人为选择称为策略价值。

## 眼前与未来机会互斥

写清兑现当前机会会关闭什么，等待后是否还能补救。等买主现身的地址与账本互斥；送货人离开后不能回头抓他，准备每轮会衰减。先计算未来窗口的最大可达进度，再根据当前余量记录收手理由。固定等待没有代价时不算这类取舍；把未知新手牌当成已知好骰也会误评。

## 全局指纹变化后的回归复核

新增任何内容会改变严格重放的全局指纹。不得改旧记录指纹来伪造通过。工具revalidate-authored.py启动当前版本的新会话，按旧作者决策逐步执行，逐项比较每步完整Before、After、Events以及入场事件；任何差异直接失败。匹配后由原生会话保存新的回归记录，再严格重放。它证明既有决策在当前内容下行为未变，不是一次新的作者试玩。规则改变且无法匹配时，必须另做逐步试玩并保留旧记录。

## 首批人类反馈后的优先门槛

当前第二轮目标是两个高质量交锋，不再用数量衡量进展。四颗行动骰子代表时间与行动力：主动作默认允许反复投入；任何次数限制必须解释其情景原因，并证明剩余骰仍有互相竞争的有意义用途，不能靠限制按钮制造所谓选择。检查完整手牌分配，不只找一次策略转折。

至少有影响关键结果的属性判定；若所有有效动作都只是消耗骰子，需说明为何属性成长没有作用，否则修订。用不同成长与手牌复核效果，不能用机械胜率冒充体验。

主动认输不是默认动作。正常成功由目标达到触发；失败由压力、期限或倒下触发。只有目标允许部分收获、玩家已明白所得与所失时，才加入“带已得成果离开”，不能用含混的提交／拔线／放弃按钮替代明确结果。本轮两个原型移除主动失败出口。

威胁被解除后仍需检验资源分配是否成立；无限刷单一目标不算有效第二阶段。信息线索必须说明用途，成功与次优结果必须明确。用户反馈优先于作者所谓初评通过。
