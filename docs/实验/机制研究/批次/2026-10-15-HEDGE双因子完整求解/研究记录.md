# HEDGE-FACTOR01：早期机会窗口 × 并行许可的完整独立求解

2026-10-15。接续 HEDGE-OBSERVE02。依据研究队列和反馈 inbox 检查：仍只有R37/R50/R54历史反馈，没有新的HEDGE真人试玩。本轮优先解决旧四组观察协议缺少**独立完整数学验证**的问题，不再增加未执行的观察卡，也不扩展正式Game。

## 冻结协议

五手 OPEN_A / OPEN_B / WORK_A / WORK_B / DROP_A / DROP_B / SIDE。OPEN耗一手，打开时揭晓A独立H14/L5、B独立H14/L0，各H/L等概率；每项需要两次WORK才可完成。开放后若经过三个全局行动仍未完成，扣4并关闭；最终仍LIVE扣4。SIDE即时得1。两个二值规则独立开关：

- EARLY：A只能在第1手开启，否则A可在任意未开启时打开。
- PARALLEL：是否允许同时持有两份LIVE工作。禁并行时必须完成/放弃原项目才能OPEN另一项。

注意只有是否开启过的许可，**OPEN同一项目不允许无限重抽类型**。没有未宣告的额外资源，也没有因模型知道未来H/L而偷用真值。玩家每次OPEN后只观察对应项目的实际品质，下一步依公开状态重新选择。

## 第一轮：完全独立于原HEDGE的状态值求解

[新求解器](../../../../../tools/content-validator/experiments/pattern_hedge_full_factorial_20261015.py)使用Python标准库Fraction和带缓存的全行动动态规划；状态包含时点、两项目品质（未揭晓哨兵值）、是否开启过、OPEN所在手、当前已投入工作次数以及两个合法性规则。每个OPEN对两种品质按1/2计算条件期望；DROP和超期按照实际动作发生时点结算。不是拿HEDGE原策略作为输入。

| A早期窗口 | 允许并行LIVE | 独立DP根最优 | 最优首手 |
|---|---|---:|---|
| 有 | 是 | 51/4 = 12.75 | OPEN_A |
| 有 | 否 | 47/4 = 11.75 | OPEN_A |
| 无 | 是 | 51/4 = 12.75 | OPEN_A（存在同值方案） |
| 无 | 否 | 51/4 = 12.75 | OPEN_B |

四格全部与历史HEDGE摘要一致，且可与 HEDGE-REPLAY01 中另一种**独立前向状态机**对部分最优路径及各目标完成概率交叉检查。两种实现并非同一个算法：本次全树逆推最优行动，上一批前向执行公开给定策略。

## 第二轮：交互项，而不是“并行更好”的误读

| 并行许可带来的根值提升 | 差额 |
|---|---:|
| A有早期窗口：并行减不并行 | **+1** |
| A无早期窗口：并行减不并行 | **0** |

两种制度的差中差为 **+1**。这说明在冻结的任务容量与品质协议里，并行许可的收益依赖于旧A不能轻易等以后再OPEN。它是一个真实的**相互作用条件**，不是两个各自自足的“加成机制”。

相反，取消早期窗口时，即便完全禁止重叠，最优仍能先OPEN B，B低则DROP B再OPEN A，追平51/4。因此“体验上同时显示两项LIVE工作”既非获得12.75的必要条件，也不是足够让玩家在意两个成果的证据。

## 第三轮：最强反证与证据层级

- 单独有早期窗口却不准并行，根值从12.75降至11.75。不能只展示有早窗的主配置而不让玩家知道可同时保留的反事实。
- 允许无早窗串行时最优同为12.75，但按历史公开策略分别有P(A完成)=1/2、P(B完成)=1/2；有早窗并行公开策略为A3/4、B1/4。**同标量不等同成果身份**，这是HEDGE-REPLAY01的前向执行证据而非本次DP直接产出。
- 原HEDGE协议的A/B品质不对称，任务类型是数值价值，不自动成为玩家自身选定的叙事责任；不能以数学+1推断体验有趣或会产生情感牺牲。
- 这个模型仍属于普通开放许可、任务生命期和后到品质的成熟组合，能够在Python有限状态机逐动作复刻。**不发现新原语**。
- 与HEDGE-OBSERVE02的四组人类观察设计对应，但本批并没有参与者。反馈inbox没有增加HEDGE观察记录。
- 本次Fraction DP为独立完整求解，上一批仅重放12条公开政策，证据身份须区分。脚本的静态代码与本地同结构运行已通过四格断言；仍不属于独立Agent盲测、原生Unity或真人试玩。
