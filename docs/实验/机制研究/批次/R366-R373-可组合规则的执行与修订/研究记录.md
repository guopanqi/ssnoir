# R366–R373｜玩家真的在构造一个可执行规则，而非切换模式

2026-10-12，横向研究**编写→执行→看反馈→修改自身操作函数**的心理循环。与R194选预设策略、R198失配就翻转A/B、R220–R228只排列相同算术工具不同。本批是纸面精确可执行逻辑结构，不是增加正式游戏的脚本编辑器。代码 `tools/content-validator/experiments/r366_r373_program_composition.py`；CI `.github/workflows/ssnoir-r366-r373.yml`。

## 完整去剧情规则

玩家手上只有一个持续存在、可实际执行的布尔函数。输入是公开的两个位(x,y)，共四种等概率，**每一手开头才出现本手输入**。玩家函数最初总输出0。目标函数是秘密固定的XOR或XNOR，先验各半。六手内可进行：

- `RUN`：在**当前输入**上执行现有函数，输出与隐藏目标函数匹配则得1，否则0，并收到真实的正确/错误反馈。因为XOR和XNOR在所有输入上相反，第一次RUN结果可完全识别隐藏目标；**不允许在第一次RUN之前读取此秘密**。
- `EDIT-X`：耗一手，给现有程序的输出追加/撤销一项`x`（异或）。
- `EDIT-Y`：耗一手，追加/撤销一项`y`（异或）。
- `EDIT-I`：耗一手，追加/撤销“全部反转”子句。

最终函数真正由玩家组成：`g(x,y)=a·x XOR b·y XOR c`。为了写出XOR，必须先后编辑X、Y两项；为了从零写出XNOR，要编辑X、Y和反转三项。每次编辑本手损失本可以RUN得分的机会，且会同时改变**之后所有输入**的正确性，不是“看到这手失败、修本手一个数”。

## 研究意义

**玩家操作的对象已从“目标进度”和“规则A/B档位”变为下一次会自动执行的函数本身**，而且编辑两个子句的组合可以创造单独编辑不存在的收益。执行反馈帮助辨别目标函数，当前输入影响是否值得立即运行或牺牲眼前分去维护规则。因此这是本阶段值得留存的**抽象组合原型**，实际改变了连续玩家操作的形态。

不过全部输入只有四种，隐藏规则只在XOR/XNOR之间二选一。玩家是否会把编辑过程当成思考操作语言，还是死记子句组合，仍完全未知。下一步应准备可读的无提示少量纸面演示，迁移到另一函数族，并检查理解/认知负担和反复吸引力。**数学高于固定脚本≠证明游戏好玩，也不自动晋升六精选、历史20或Debug3**。
