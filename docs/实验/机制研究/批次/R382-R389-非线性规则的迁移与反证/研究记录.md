# R382–R389｜从XOR/XNOR换成AND/OR：玩家写规则的循环能迁移吗？

2026-10-12。本批旨在**反证**R366的“两个编辑子句产生独立组合价值”是否只是XOR结构偶然挑出的优势。维持6时段、4种等概率公开输入、RUN与编辑均占一手、持久可执行函数，同一研究问题；但把隐藏目标变为AND或OR，并允许玩家写入非线性AND子句。脚本 `tools/content-validator/experiments/r382_r389_nonlinear_program.py`，CI `.github/workflows/ssnoir-r382-r389.yml`。不是给正式游戏增加编程系统。

## 两个实际变化，不是换名字

1. **反馈只能提供部分信息**：AND和OR在输入00、11时结果相同，执行的正确/错误不能区分它们；只有输入01、10时两者输出不同，RUN的反馈才会揭示隐藏目标。因此玩家并非必然第一次RUN就知晓一切，后续对现有规则的信念也可能保持双态。
2. **可写操作语言扩大了表达力**：除了`EDIT-X`、`EDIT-Y`和`EDIT-INVERT`，增加`EDIT-N`，真实输出规则变为`g(x,y)=a·x XOR b·y XOR c·(x AND y) XOR d`。AND函数只需写N，OR可由X、Y、N三个子句组合完成。编辑时没有任何即时积分。

玩家看当前输入才决定执行还是编辑，当前编辑会影响以后的所有输入。完成时只统计RUN正确次数，不对写出的公式名字付分。

### 研究判断

R366的编辑互补性**不能被不加条件地推广**：在AND/OR任务里，一个非线性子句的单次编辑已经有效，最强提前编程策略也不再是“永远RUN”。因此我们应该把潜在玩法建立在**不同输入上测试与修订同一规则**，而非某个特殊算术函数恰好需要两步的现象上。

两组规则都出现了看输入→执行/编辑→反馈→改变函数、在随后新输入上验证的活动。它比只选择一项固定任务更接近玩家写自己的行动方法，值得作为**未认证的机制组合方向**继续做少量人类可读原型。不过规则面板是否有趣、玩家会不会觉得过于抽象或公式化，仍然没有真人证据；保持精选6、历史候选20和Debug3不变。
