# R398–R405｜“我写规则让工具自动替我干活”：玩法来自规则，还是额外行动容量？

2026-10-12。严肃检验[R366实际规则创作](../R366-R373-可组合规则的执行与修订/研究记录.md)与[R358交出决策权](../R358-R365-独立目标与委托决策权/研究记录.md)是否一组合就产生新心理玩法。这里的自动执行者**明确只是工具**，没有私人目标、不会自主更改规则，不得借“委托”“伙伴”名字冒充另一个社会角色。脚本 `tools/content-validator/experiments/r398_r405_script_capacity.py`，CI `.github/workflows/ssnoir-r398-r405.yml`。

## 最小三回合机制卡：行动机会需要事先算清

每次行动开始，公开一个0/1输入；同一回合有两种合法工作A、B，各自获得固定公开奖励。玩家手工只能执行其中一种，且看得到输入。

玩家可以花掉一整个回合**安装自动工作规则**，从下一回合开始让自动工具读取当前输入并选A或B。可安装四种规则：永远A、永远B、输入0选A/输入1选B、输入0选B/输入1选A。可再次花回合更换程序。

测试两种**结构完全不同**的限制：
1. **单行动槽（SERIAL）**：自动执行占用玩家本来也能自己用的一次行动机会。玩家同回合可以改用MANUAL，但不能再加第二份输出。既然玩家能看当前输入并手工选A/B，自动规则不可能改善能力或产出；安装还占一手。
2. **双行动槽（PARALLEL）**：工具装好后可与玩家**同时**操作。玩家可以手工选择另一项工作；同项被手工和工具重复执行只记一次结果。故工具给了第二份实际工作容量。需要分清“多了一只手”和“写了更聪明的规则”。

数学方法：一条完整公开状态的Bellman策略可选择手工A/B、安装/重写四程序、已装工具自动执行；每手公开输入均只对当时可见状态有效。另一套**不共享Bellman递推**的算法枚举4种固定程序、2³输入路径及两手最强手工补位，得出的容量代数上界等于DP。不是通过故意让手工基线执行错误的目标来制造自动化优势。

## 反证意义和边界

这直接否定“R366的可组合函数 + R358的委托 = 天然出现更丰富玩法”这种相加假设。如果工具与人争夺同一个动作机会，自动化只是旧动作的替身，甚至白白花时间安装。如果工具能并行，多出来的产出源于**获得第二次行动**，而不源于脚本能响应输入，因为玩家知道输入并可执行剩余工作。

若想继续研究真正有趣的程序式委托，应先提出自动工具独有的**观察/反应/时序约束**，使规则的写法影响玩家确实无法亲自完成的任务，而不只是多给一个资源。此批是强阴性原型，不放精选6、历史20或Debug3，没有真人/原生证据。
