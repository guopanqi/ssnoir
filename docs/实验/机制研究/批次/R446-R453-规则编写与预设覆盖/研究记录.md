# R446–R453｜何时需要亲自编写规则，而不是直接选择现成程序？

2026-10-13。沿R422「预编译函数比复杂子句更强」的反证继续**跨输入函数族**，而不是给旧XOR/XNOR调回合数。对照三种具有**相同操作时点/编辑耗一手**的接口：逐步编辑四格表；只能选择四个预设；或能一步选择全部16种四格函数。对照只在四位布尔函数的明确定义下成立，不意味着全部真实编程可被穷尽菜单替代。代码 `tools/content-validator/experiments/r446_r453_rule_authoring_menu.py`；八项检查，无真人。

## 去情景机制卡

公开目标函数分别为XOR/XNOR/AND/OR，每期先见x，晚到y只有机器运行时才可读取。玩家每期只能做一次：提前手工选择0/1、让已有持久程序自动处理(x,y)，或占用全期编辑程序。初始程序四格皆0；RUN正确得1，否则0；编辑期0分。实验枚举四期目标函数所有 **4⁴=256种公开序列**，x/y都是等概率独立输入。该模型没有隐藏目标、人物动机、自动并行额外产能。

- **AUTHOR**：翻转输入X=10/11、Y=01/11、I=全部、N=仅11；反复修改形成四格程序。
- **FOUR**：放弃子句编辑，用一手选择现成 FALSE/TRUE/XOR/XNOR 中任一程序；没有AND/OR。
- **ALL**：用一手直接选择所有16种四格表中的任一种。动作数量更多，但每次切换成本同样是一个完整回合；作为一个理想化的**完全表达式强上界**，不声称真实玩家在UI中无成本理解全部16种。

## 裁决

这比“预编译总是最好”更准确：

1. **有限预设菜单确实可能不够**。在48个目标序列中，玩家亲自编辑有严格数值价值，因为目录中缺少它能构造的函数。
2. **但这是表达能力的差别，不是已经证明新的心理活动**。当全部可构造四格表都以同成本提供，编辑的数学产出严格被覆盖；用户是否愿意发现、组合、反复调试，必须另由人类体验观察，而不能从根值推论。
3. 这一轴不应靠继续增加布尔输入位数“逃离”预设菜单。任何有限语法最终都可被包含其表达能力的同成本完整菜单模拟。新的研究需清楚解释玩家**为什么要创造规则**：例如界面可读性、工具抽象与复用、不知道未来任务时建立可泛化结构等；这类体验命题先需要最小真人卡和跨局迁移，不能单凭有限DP晋升。
