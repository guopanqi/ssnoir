# HAND01—08｜把工作交出去，不等于完成成果已经归我

2026-10-13。接续 main 8c454d55f55c69d4de01ef2d4ee95fddd35c3c05 的 FOCUS/META02，遵守[研究定位与评价](../../研究定位与评价.md)与[研究Skill](../../../../skills/research-mechanisms/SKILL.md)的抽象决策关系口径。已读取最新 main、知识地图、队列、记忆和反馈（仍仅 R37/R50/R54，questions未收到真人答案）。本批研究**异步工作如何改变当前玩家可用的行动容量**，以及成果完成、质量报告与验收之间的区别；不增加正式游戏功能、精选、历史候选或Debug入口。

使用[Python标准库Fraction可复现源码](../../../../../tools/content-validator/experiments/pattern_async_handoff_20261013.py)：动态逐状态求解、质量报告到达时点的五种条件、固定行动脚本（非法命令给合法SIDE回退）、两个不同时限和强对照。**本地对相同脚本的全部断言已执行通过；GitHub上传版尚未单独触发 CI**。没有独立 Agent 盲玩、真实玩家或 Unity 证据。

## 1. 为什么这是另一种玩家活动

前轮FOCUS中，玩家亲自转换工作焦点需要消耗一手。HEDGE中，玩家同时保留A/B两个尚未完成任务，经过信息反馈决定保留谁。HAND的起点不同：

**我可以花一手把 A 的一部分工作交给别人，让它在我亲自推进 B 的同时自动进展；但我何时知道对方实际做了多少、最后可不可以直接使用成果？**

这一心理循环可以描述为 **选择移交 → 我亲自继续做别的事 → 接受进度报告 → 补齐不足或改投别的结果 → 必要时验收**。它不意味着真实社会协作系统已经成立：本批的“别人”只有等概率好坏的自动产能，没有独立效用、保留劳力的权利或自己拒绝参加的选择。**把受托者改名为一个自动工具，全部公开规则、状态转移与结果一字不变**。强真实多主体先例参照 [ACT01](../2026-10-13-行动权利与自主他者/研究记录.md) 和 [GRC01](../2026-10-13-可信合作与信息公开逆转/研究记录.md)，二者在对方自主回应这一点上与本批不同。

## 2. 冻结的最小 HAND 协议

四手版的A需累计三单位才得12；B需两单位才得9；SIDE即时得1。玩家每手可以亲自做A（+1）、B（+1）、SIDE（+1收益），或只使用一次**SEND**。SEND占完整一手，将A交给受托者：

- 受托者有GOOD/BAD两种产能，各1/2；GOOD在**后续两个玩家行动结束时**各自动完成A+1，合计2；BAD只在第一项后续行动结束时自动完成A+1，合计1。
- 不消耗玩家在这两个后续行动里的A/B/SIDE操作；玩家同一时刻仍可以自己补A，达到3后多余进度不加奖。
- 质量信号可以在SEND后即时或经过0/1/2/3/4手才公布；**在报告之前，受托者的真实进度也不可观察**。玩家只看见自己做的A/B、已送出及已经过去的行动数。质量不会预测B的收益。
- 原版后台进度只要生产就自动生效（passive）；另有**ACCEPT版本**：受托者必须至少经过两次后续行动才能交付，玩家花**完整一手 ACCEPT**验收；不验收的代理进度**不参与A结算**。自己的A进度始终仍能结算。该验收不是凭空增加风险数，而是明确加上一项获得使用权的行动门槛。
- 两种版本没有不按规则执行的自主主体、代理持续学习、报价或可再委托权。因此 GOOD/BAD是**外生质量事件**，不是agent意愿或道德可靠性。

**结果不是免费助手**：SEND已经消耗一手，验收版还另花完整一手ACCEPT；“我在另一项工作时后台完成A”并不等于所有委托都严格划算。

## 3. HAND01—04：异步并行的实际行动价值及公开两行全优方案

| 四手规则 | 从真实起点动态最优 | 固定预写行动最优 |
|---|---:|---:|
| 玩家只能亲自做A/B/SIDE，不允许SEND | **13** | 13 |
| 允许SEND，质量可及时得知，后台A自动生效 | **17** | **15** |

最短可读且达到全局最优的协议：首手SEND，第二手亲自A。之后：
- GOOD：第三、四手做 B、B。玩家自身A1+助手A2完成A12，B2完成9，得 **21**；
- BAD：第三手再做A，第四手SIDE。玩家自身A2+助手A1完成A12，SIDE1，得 **13**。
等概率平均 **17**。这是两个实际可达的不同后续目标选择，且确实有时A/B两项同时结算。对比不委托的强方案A,A,A,SIDE得13，异步后台工作提供了新**行动容量**。

固定SEND,A,B,B虽然GOOD可得21，但BAD只得B9，平均**15**；完整预写枚举不会更高，且“非法重复SEND”自动改SIDE，不故意制造低基线。另一个最佳固定可以先A再SEND做两手B，表明首手立即SEND不是唯一最优开局；**首手A后再SEND也能达到动态17**：好时接B,B，差时亲自A再SIDE。没有理由宣称「一旦委托可用，就必须第一手先委托」。

这项机制最值得保留的不是“受托者有GOOD/BAD抽奖”，而是**我做B的手，并非就停止A的进度**；而受托者实际完成不足时，我还有机会重新把亲自行动投回A。

## 4. HAND05：信息与完成进度是两个不同的时钟

仅延后质量报告，原四手、工作进度、奖励、受托者好坏概率不变：

| SEND后经过多少项后续行动才报告 | 动态最优 |
|---|---:|
| 0，当场得到报告 | **17** |
| 1，先做一次别的动作才知道 | **17** |
| 2，再做两次动作才知道 | **33/2=16.5** |
| 3，已做三次后续动作才知道 | **15** |
| 4，行动耗尽前无法获知 | **15** |

第二行与第一行根完全相同：SEND后无论GOOD/BAD，第一项亲自操作A都是可接受的；质量早知道一手不会改变最佳当手判断。信号只晚到第二项后续动作时，一条全优短路线是先 SEND,A,B，GOOD再B得到21，BAD最后改A得到12，期望**33/2**。若到第三项后续动作才报告，已经没有足够转换机会，退回固定方案最优15。

注意没有改变质量分布，也没有假装GOOD必定承诺执行：后台完成进度和玩家获知该进度只是**可区分的两个时点**。这个成熟结构可归入DISC信息时点/P03边做边看，但委托工作进展是信息来源；本批不能把它称为独立的新“信息原语”。

## 5. HAND06—08：验收这一手能把“看似多了人手”变回无用

| 时限与协议 | 全局动态最优 |
|---|---:|
| 四手，后台成果直接有效 | **17** |
| 四手，必须花一手ACCEPT才能使用代理进度 | **13** |
| 四手，根本没有代理可用 | **13** |
| 五手，后台成果直接有效 | **43/2=21.5** |
| 五手，必须花一手ACCEPT | **21** |
| 五手，无代理可用 | **21** |

强结构性反证：SEND成本1手，ACCEPT又成本1手，代理GOOD最多只贡献2单位、BAD只贡献1。若没别的限制，把SEND和ACCEPT这两次玩家行动都拿来亲自做A，就能得到**至少相同的A进度**；没有验收授权的额外稀缺身份、地理距离或专属能力，就算两边名义上都在同时施工，真正可结算的工作量也不会因此增加。代理质量信号只描述其自身进度，不指示另一个独立目标的情况。这个资源支配解释了为何四手/五手动态结果分别与纯亲自工作一样，而不是某次偶然算出同分。

本模型里的ACCEPT刻意是**另一项完整动作**，而非普通在最终分数上扣一小笔赔偿。因此它测量的是交付、检查与行动容量的关系：看见对方工作进度，不意味着结果已经归玩家使用。也应谨慎：这个四/五手根值相等只证明**对应工具收益下可以不靠委托达到同样的最优**，不宣称所有合法委托策略的结果向量或玩家体验与无委托完全同构；这是STAKE/META证据强度要求。

### 强替代与非创新判决

完全相同的计时、好坏报告、自动生产A和接收动作，可以把“助手”改名为 **AUTO_A工具**：玩家花一手启动一个有GOOD/BAD结果的自动生产器，后续工作和报告完全照规则进行；必要时用ACCEPT领取机器产物。本模型所有状态、玩家合法动作、机读后果一一对应。**所以HAND无法认证为独立“同伴意志”基础机制，更不能证明社交互动的趣味性**。将代理改叫“会出错的同事”只改变情景描述，没有改变玩家抽象活动。

如果要真正研究有人自主工作的版本，至少需要其选择何时接受任务、是否转做自身目标、玩家提供承诺/补偿是否改变其自主最优，以及玩家是否仍有可执行替代路线。这些并非建议本作新增多人AI，而是为跨RGT/ACT/GRC历史分类划定边界；该方向已有严谨模型，应优先吸收而非盲目重复。

## 6. 与前轮交锋的可用组合和停止条件

- 对 **HEDGE/FOCUS**：保留A退路、之后自行处理B的决定来自玩家持续保留行动余量。HAND展示另一种材料——**移交后A即使无人亲自关心也在推进**。两者可以同场，但须先看是否有明显的固定顺序、保底等待旁路，以及是否真的多出可交付结果。
- 对 **STAKE**：必须分清已经做出A的物理工作、看见报告、以及有资格把工作结算成自己的完成结果。HAND验收要求与STAKE原件保全同样强调“结果是可被认领的具体状态”，不等于改大A奖励。
- 对 **ACT/GRC**：本批没有自主意志，不能把已有社会反馈研究的结论借到自动代理里；双方都有决策权时还要检查“对方愿不愿意”“他者外部机会是否让今天的帮助消失”。
- 对 **CS2**：可将它视为既有“Preparation / Crew Composition × Parallel Objectives”交锋结构语言的**作者推论**，不是《Citizen Sleeper 2》任务中实际包含SEND/ACCEPT四手规则或任何官方分类。

**同一研究者独立设计批评（非盲评）**：强公开口诀「派出后自己先A，GOOD再做B,B，BAD再补A,SIDE」就已全优，玩家可能只是在读一条条件操作说明，而不是感到真正需要信任另一个主体；ACCEPT甚至可能使最有意义的操作变成“根本不委托”。不应用继续调GOOD概率或增加第三位助手救它。若要验证“移交”确实有独特心理意义，需要玩家自己面对一份已有价值的责任、不能亲自完成的专业工作或受托者明确自有目标；这些是未来另一类实验，数学没有替真人决定。

**本批裁决**：保留两项可重用成熟组合与一个否定边界：**异步代理与亲自行动的容量互补**、**报告时点与最后可用于改选的行动窗口**、**验收成本可能全局吞掉后台工作优势**。没有新独立玩法原语，不改正式Debug/精选，不虚构玩家认可。[未执行观察卡](无答案观察卡.md)只为以后异步校准。
