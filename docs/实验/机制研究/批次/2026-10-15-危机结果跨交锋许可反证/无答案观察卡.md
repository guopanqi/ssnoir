# BRIDGE：两段交锋的行动资格与备用路线——无答案观察协议

**状态：未组织真人或独立 Agent 盲玩。** 研究员不得将自己写下的DP策略、最优行动和各行动命中概率拿给参与者看。规则与隐藏事实应先冻结，且留下真实行动顺序、输入与随机结果；自动化浏览器抽样不属于玩家体验样本。

## 玩家版：你有四手、两段彼此影响的交锋

第一段两手，第二段两手。你不知道第二段需求究竟是E还是S，二者机会相同。第一段结束前你会收到一条**75%可信但可能错**的预测；第二段开始才看到真实需求。

第一段第一手：可以冒险推进（有50%概率触发危机），或安全准备（立即得到1点保底收益）；第二手：若冒险，选择完成原任务取得E资格，或者处理危机保住S资格。**没有发生危机时完成原任务可同时取得E和S**。若安全准备，第二手只能保证获取E或S其中一种资格。

第二段两手：若有E/S资格，每种可花一手完成一次，对当前需求对应的成果得12，非当前需求得2。另有不限资格的备用工作ALT，需要**连续两手**才完成并得8；其他工作SIDE每手得1。每局最后明确标记兑现的E、S、ALT各是哪一种成果。资格不等于成果，没实际使用就不能计入终局。

特别观察：玩家是否认为“处理危机”和“完成原任务”不可兼得；是否能区分预测和真需求；是否主动将已经到手的某资格放着不用、转向ALT；若有两种资格是否能理解可以在两手内都兑现；安全准备是否被直觉地认为是完全没用的选项。**所有不理解、拒绝、或只用固定口诀完成的结果都应原样记录**，不要事后改写为研究预期。

## 必须彼此独立的对照

1. **完整BRIDGE**：第一段危机+预测；第二段公开实际需求W，允许ALT。
2. **不透露第一段预测Y**：公开危机，但玩家需在不知道W的情况下选PRESS/AID；第二段仍公布W。
3. **不公布第二段真实W**：第一段仍给预测，但玩家在做第二段行动时只能按预测判断；结算后再公布真实需求。
4. **强直接资格**：安全准备后可以一次取得两种资格，明确告诉玩家这是另一套更强规则。该组不是等效换名实验，不要用体验差异直接归咎“危机机制没价值”。

相同玩家玩多组时，应记录顺序和学习影响。**不可将四个条件里自动分数更高的版本直接称为“玩家更喜欢”。**

## 停止门槛与设计批评

本批数学发现：第一场实际发生的事情只被第二场`E/S`票据概括。若玩家试玩确实仅是“先拿将来用的钥匙，后面照需求选按钮”，归类为成熟跨交锋资格/保留选项结构；不要再增加时钟、NPC或新代币以制造原创性印象。

若参与者在第二段持续惦记**第一段没能保住的人或结果**，需要记录可观察的具体原话，再决定是否构建真正的返回或补救结构。不能靠研究者直接赋予“后悔”数值为其下结论。尚没有可供认证的真人、盲Agent或Unity正式Game证据。
