# R83｜真实机会窗口与开局优先级：强简单策略反证

2026-10-10。**裁决：保留「可错失机会」为基础时机关系；本配置不晋升新的独立高质量模式，不创建原生试玩场景。** 数学有严格条件性选择，但最强「按线索预先决定优先目标」简单策略族在全部126手达到自由最优。以下是精确纸面模型，不是正式 C# + Scheme，也不是人类乐趣验证。

## 冻结问题和语义

四颗独立 d6，FateStrip 成长1，126种无序起手牌按排列数加权；每手选择剩余骰与行动。A 是有期限的机会，B 是长期可做的替代。两者各需累计3格，完成进度永久兑现；真正需要哪项由隐藏类型决定，初始 P(A)=1/4，完成正确项得3，否则0（两项都完成也仅3）。第一手结束后自然出现一个准确率3/4的公开信号：正信号概率3/8，A 后验1/2；负信号概率5/8，A 后验1/10。玩家只看信号，不看隐藏真值。

首手做 A：获得正常判定进度，锁住 A 的可用性。首手做 B：同样获得正常进度，但有独立1/2概率令 A 在此后永久关闭，关闭状态公开；B 永不关闭。关闭不撤销已完成进度；关闭后不可再选 A。全部行动消耗一颗骰，不能免费等线索，剩余骰可逐手重选。无伤势、住院、跨回合或其他正式场景规则。与旧 R79 的「直接给等待扣分」不同，此处机会是**可达动作集合真正缩小**。

可达性审查：每次最多四手，目标进度上限3；两项均可完成时仅结算正确项一次；没有对已完成目标再扣进度。首手 A 与 B 均为合法普通推进；B 后 A 关闭与不关闭都有正概率。空等一手得到同一线索和同一关闭抽签，但没有 B 的非负进度，因此被首手做 B 逐结果弱支配。**「先等等」并不是第二种有价值的行动；真正的对立是「抢先保住 A」与「先做 B」**。这直接修正 R83 最初假设。

## 反证设计

最强简单族：开局看完整手牌，允许在四种「正/负信号→先做 A 或 B」映射中选择最好的一种；首手动作与用骰最优，之后每手仍可选最优骰，但目标顺序预先由信号映射决定，仅在优先项完成、关闭或按最大剩余容量无法完成时转到另一项。这比僵硬固定脚本强得多，不能当作简单人类口诀已被验证。

直接关闭新增规则：将「首手 B 有1/2概率关 A」改成「A 永不关闭」，其他概率、进度、可见性、动作和奖励完全相同。比较两版本每个初始手牌的 A/B 首手 Q 值，而不只比较总期望。另比较永远先 A、永远先 B 和上述强简单族。

## 运行与结果

本地以 Python 3 执行 `python3 tools/content-validator/experiments/r83_public_window_audit.py` 的 Fraction 精确枚举；126个加权手牌的概率和为1，逐根断言强简单族不超过自由值、禁用关闭不降低最优值，并检验两类严格首手偏好均存在。复核数值（终局效用期望，不是完成率）：

| 条件 | 期望效用 |
|---|---:|
| 有窗口、自由策略 | 2.602721247 |
| 关闭窗口规则、自由策略 | 2.627005369 |
| 窗口的直接因果代价 | −0.024284122 |
| 有窗口、固定首手 A（后续自由） | 2.592861516 |
| 有窗口、固定首手 B（后续自由） | 2.425063899 |
| 有窗口、最强按信号固定优先目标族 | 2.602721247 |
| 自由相对强简单族剩余 | **0（126/126根完全相等）** |

严格首手 A 的无序牌型105/126，严格首手 B 的21/126；B 优先的加权正常开局质量9.9537037%。窗口关闭机制令105种牌型从「无窗口时 A 不严格更优」变成「有窗口时 A 严格更优」。注意105/126不是概率质量，不能混用。

可复核的普通根反例：

- 手牌(1,1,2,6)：有窗口时先 A 比先 B 高 **7/192**；关掉关闭规则后先 A 比先 B **低 1/18**。同一手牌发生严格方向逆转，归因于机会丧失，而非奖励重调。
- 手牌(1,1,1,1)：有窗口时先 B 比先 A 高 **143/384**。尽管 A 可能关门，低容量下优先推进更可能被需要的 B 仍然合理。

## 失败解释、边界与证据缺口

这次**不是**「没有选择」：两个正常开局都存在严格且条件不同的可行行动；关闭规则确实改变选择。但是在这组冻结参数中，开局最佳选择相对「总是先 A」只增加约0.009860效用，且四种事先指定的信号优先顺序就覆盖自由最优；未证实有价值的中途主动重排。窗口是机会约束，禁用后最优分数反而更高；不能把这0.024284损失误报成新增动作的正收益。

退化：关闭概率为0时，没有任何牌型严格要求 A 先手；若 A 的先验概率升至1/2，首手 A 在本配置全部126根严格更优；等待如果仍无收益则被 B 逐结果弱支配；容量或奖励让固定一边总能完成时会进一步流程化。不同先验与关闭概率仅为敏感性提示，不是另一项通过验证的模式。

**原生与人类层级**：当前环境未安装 dotnet，也没有仓库本地检出，未运行正式 C# Session、Scheme 行动、赔率校准或严格回放；未建立任何新 Content，未获得新的真人反馈。因此 R83 不满足「至少一段原生行动路径」准入，更不算20种研究者认证模式之一。此前P17–P20的原生动作证据不自动转给R83。
