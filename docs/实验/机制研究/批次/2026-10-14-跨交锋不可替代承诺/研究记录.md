# OBLIGATION05：跨交锋共同成果的可达性审计

2026-10-14，接续 OBLIGATION04。沿用第一阶段五手 A/B/C/SIDE，A前两手需两份得8，B前四手需两份得9，C在第一手后得知普通需两份或便利需一份（各半）得10，SIDE每手1。第二阶段两手，X每次得3、SIDE每次得1、Q单次得9需第一阶段完成A、R单次得5需第一阶段完成B。Q/R分别定义成可观察成果P/R。强对照ALWAYS允许Q/R不依赖前期A/B，其余成本不变。

玩家可在行动前选择一组结果作为硬约束：两种事件下必须都取得它们。脚本 [复现](../../../../../tools/content-validator/experiments/pattern_cross_stage_commitments_20261014.py) 穷举共同首手、条件后缀与全部第二阶段两动作方案，使用Fraction计算。

| 必须保留成果 | 条件解锁最优 | Q/R无条件合法 |
|---|---:|---:|
| 无 | 73/2 | 37 |
| P+R | 73/2 | 37 |
| P+C | 36 | 37 |
| R+C | 34 | 37 |
| P+R+C | 不可行 | 37 |
| A+B+C | 不可行 | 不可行 |
| A+B+P+R | 73/2 | 73/2 |

普通状态中A、B、C各需两手，总共六手，第一阶段只有五手；当P/R各需A/B的资格时，P+R+C等价于事先完成A+B+C，因此不可能。无条件许可时P、R可在第二阶段完成，第一阶段只保C即可。这是成果组合的**可达性变化**，不只是分数差异。

反证：普通has_A、has_B标记已经能逐状态复现Q/R合法性，因此仍是成熟条件解锁与跨阶段结果组合，不是新原语。安全X/SIDE从未禁用；本批把P/R/C设为必保，是实验者设定的约束，不代表玩家真会如此关心。完整条件策略可事前编译，也不需要策略性第三方。

证据为完整有限动作枚举；未做人类试玩、独立盲Agent、Unity原生复核。正式游戏、精选、Debug均未改变。下一题转向玩家如何预先表达关切及观察后续后果，或者对照GRC既有的第三方自利参与，而不是增加权限位。
