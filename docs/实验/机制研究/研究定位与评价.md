# 抽象玩法结构研究：定位、评价与交付契约

更新：2026-10-09。本文件是抽象机制研究的**目标与质量判断权威**；Skill 管如何执行，队列管下一步，模式库和 HTML 总览向设计者解释结论，原始数学模型／正式 Content／试玩反馈分别保存证据。不要复制几份互相漂移的结论。

## 我们研究什么

研究对象是**抽象的决策关系（decision pattern）**：少量可描述的规则如何改变玩家眼前的可选行动、行动代价、信息、时间、资源与目标之间的关系，并引出可理解的权衡、计划改变、优先级重排或不同取舍。

- 基础关系如**稳做/险做**：承担更大波动以换取更高收益；与角色、场景无关。
- 复合关系如**推进目标产生待处理问题**：现在做正事也创造未来负担，局面会反过来改变下一步的合理选择。
- 不确定关系如**三候选仅一个随后有效**：提前分散准备还是押注，揭示不能提前购买。
- 行动间影响如**动作回声**：上一手对哪一项投入改变下一手判定，玩家会随进度重排顺序。

研究目的不是生成关卡、叙事、人物反应，也不是寻找数学上最难求解的系统。**设计者之后可以把同一个抽象结构赋予情景与情感意义**；映射效果是独立的创作／试玩问题。本研究不以剧情代替抽象选择，不强迫每轮提供「故事应用」。

## 什么才算一种模式

模式最小说明：**初始可见状态 → 可采取的行动 → 触发/反馈 → 决策为什么改变 → 可复用的边界**。通常可用一句「玩家要在 X 和 Y 之间作出什么判断」表达。

“有三根钟”“有五个目标”“计算最优值提高0.1%”不是独立模式；必须指出变化的因果来源及玩家可以观察或预期的条件。相反，不同数值与皮肤可能只是同一结构的实例。基础关系可以有价值，不要求每个模式都足以撑起整场长交锋。

## 评价维度（不合成一个伪科学分数）

1. **决策意义**：明确出现什么可理解的取舍；是否有两个以上合理选择或条件性切换。
2. **动态性**：随机结果、时间、行动后果或新信息是否改变优先级；区分固定开局计划与真正逐手响应。
3. **简洁与可读**：玩家能否凭公开信息预测后果、解释自己的选择；复杂度/认知成本是否合理。
4. **抗固定套路**：与最强可解释简单策略对照（固定目标顺序仍可择骰、优先完成一项、始终高骰、固定交替等）；局部反例不能替代正常路径意义。
5. **适用性与组合力**：在何种容量、成长、时间与效用偏好下成立；能否与另一结构组合时产生不可分解的新判断。
6. **潜力判断**：研究者可对“值得试玩 / 可复用基础 / 数学有趣但低优先 / 停止本变体”作定性判断，必须写理由、弱点及下一证伪。**潜力不是已证明的乐趣**。

不能以成功率、状态数量、代码行数、文件数量、最优与次优的百分数或模拟对局总数替代上述判断。对学习成本、是否犹豫、是否愿意再玩等结论，只有真人反馈才能确证；Agent 逐步会话不是人类样本。

## 证据身份

- **结构推论 / 纸面排除**：支配、交换性、容量与边界。
- **数学模型**：明确冻结的规则、概率、效用；精确求解与近似策略分开。回答结构是否成立，不能称正式玩法或乐趣证明。
- **原生 C# + Scheme**：正式 Content 唯一来源；Session、事件、赔率、终局、严格回放可确认规则与可观察行为。记录 seed/成长/内容指纹、测试覆盖，不用 CI 绿灯掩盖失败（含 pipefail）。
- **真人体验**：理解、犹豫、重复感、策略调整及愿不愿继续；注明玩家条件，不把模型路径质量写成人类选择频率。

任何展示上的单一“推荐”只代表**研究者基于已有证据的创作潜力判断**，不是统计结论；展示数学效果时写清效用与对照、适用范围。

## 实验循环

1. **打开探索空间**：从已有模式边界或新结构提问；主动尝试不同的关系种类，避免只围绕一个数学题越算越深。
2. **冻结最小假设**：写下规则、可见性、真正变化的决策、一个最强反例与停止点。
3. **先低成本淘汰**：支配、对称、交换性、资源容量、强简单策略。如果常识性流程足够，记录边界并转向新题。
4. **按需深化**：精确小模型与敏感性 → 必要时正式 Scheme 原型 → C# Session/回放 → 需要时真人体验；不是每批都必须走完整流水线。
5. **做判断而不是刷数值**：说明最有启发的状态、正常分布质量、与旧模式区别、认知成本、退化条件、组合方向，明确“基础/值得试玩/暂缓/停止”。
6. **更新面向设计者的 Artifact**：维护结构化 [模式库](模式库.json) 与由其生成的 [研究总览](研究总览.html)。总览首先展示**目前保留的5–6种有代表性的模式、研究状态、决策意义、证据与反证、当前优先级、具体下一步**，然后链接原始批次。数量不是指标，只有真正增加可理解关系才晋升。
7. **让研究方法本身进化**：每批记录哪种筛选节省了计算/避免了假阳性，必要时改 Skill、验证脚本、证据契约、模式库字段；不因小问题重写整个引擎。每次改进方法要可复现，并能被新会话接手。

交付顺序：研究记录与可运行证据 → 结论归档/模式库 → HTML 生成与一致性检查 → 当前状态及下一研究队列。旧实验不必为了统一新格式重跑；没有证据的新方向写“待研究”。

## 可持续 Artifacts（责任与更新时点）

- [模式库.json](模式库.json)：面向设计者的人类可读结构化结论，**不是规则权威**；每个精选模式必须包含决策问题、最小规则、触发变化、为何可能有趣、最强简单策略、局限、证据级别、源记录及下一判断。一个新模式不成熟也可只在研究队列，不必塞进精选库。
- [研究总览.html](研究总览.html)：从模式库生成的离线可浏览页面，展示当前状态、结构图例、证据分层、对照、筛选和深入阅读入口；GitHub Actions 校验其与 JSON 同步、上传 HTML artifact；**只有 JSON/HTML 变化走轻量 Atlas workflow**，数学/Content/Session 变化走完整研究 workflow。这样不会为说明文案反复编译 .NET。
- [关系索引](关系索引.md)：更宽的已探索空间，包括止损、弱关系和否定结果，不受精选6模式约束。
- [当前状态](当前状态.md)：最新证据身份、工作状态、恢复路径；[研究队列](研究队列.md)只保留可判别的下一问题。
- [批次记录](批次/)：每轮原始结果/参数/反证/版本；不能用总览里的简写替代。

长期目标是发现**少量能反复用于创作的决策语言**，不是维护一大堆越来越复杂的演示场景。

## 人类协作的正式接口（2026-10-09）

研究工作台 [研究总览.html](研究总览.html) 不再是静态状态牌，而是人类理解实验、安排试玩、给出反馈的入口。它的权威来源分为 [模式库](模式库.json)（研究者结论）和 [试玩任务](试玩任务.json)（当前请人类协助的项目、优先级、研究问题）；生成 HTML 与测试由仓库自动校验。

最重要的入口应是**下一轮最缺哪种人类证据**，而非最近算出来的最大百分数。每个邀请必须包含：玩法最小规则、实际可用的入口、实验与正式引擎的关系、值得观察的一两点、如何匿名导出反馈。拒绝把数学最优提示预先灌给玩家，避免污染第一次体验。

[反馈协议](反馈/README.md)定义 `反馈/inbox/*.json` 上传、允许部分填写和 Agent 接续义务。浏览器 R50/R54 是明示的独立 JS 简化示意版，**不是**正式 C# / Scheme 客户端；不会把网页胜率写回原生数学模型。正式试玩来自 Unity 调试入口或现有 C# 会话。用户给出的理解、转向、困惑和重复感应优先更新研究方向，即使数学最优策略仍有严格收益也不强迫保留。

网页不嵌入 GitHub token、不暗中上传、不依赖第三方运行服务。用户可离线填写、导出文件、上传到仓库。浏览器可能不允许本地存储，所以自动保存只作便利，导出 JSON 才是可靠的交付。GitHub Actions 只验证格式，不改写玩家原话。
