# SSNoir 抽象机制实验室：结构、职责与可持续接续

2026-10-12 定版。**这是一份导航和信息责任表，不是第二套研究目标，也不是剧情规划。**

## 一、这个实验到底研究什么

研究 **abstract decision patterns**：玩家面对有限的行动、资源、时间和信息，在不同选项间如何形成有意义的选择与分配；一次行动后的反馈如何使下一次判断变化；由此能否形成**可学、可复用、实质不同的玩法循环**。

同一结构可以后来映射到侦探、城市、人物和故事中；这些元素不参与抽象机制的价值认证。“调查一封信”和“获得一个资源”可能是同一结构；“又遇见一个人物”“又解锁一条剧情”不自动构成机制创新。

**准确区分：**玩起来有意思的简单基础规则，可以保留；纯数学求解困难不等于好玩；求解器优于固定策略也不足以证明新形态。人类反馈可改变判断，但不是自主研究的同步阻塞点。

### 为什么要有 Skill？

Skill 相当于给不同会话或不同 Agent 用的**短执行手册**：入口次序、如何区分数学与真人证据、如何选择验证工具、如何更新产物、如何避免自动晋升Debug。它**不能**作为新的研究目标来源，不能追加每个批次的复盘，不能在顶部累积“下一步必须研究S3”这类历史命令。研究主题的权威只在《研究定位与评价》；下一步只有《研究队列》；原始结论只能在对应批次。长记录要么归档，要么归并成一句对未来选题有用的反证原则。

如果今后 Agent 已经熟悉项目，也可以从 README + 队列开始，不必逐字读取全部历史批次。Skill 只用于提醒执行契约。

## 三、单向数据流：新想法如何成为保留模式

```text
研究定位 → 横向探索地图 → 当期队列
    ↓
去剧情机制卡（公开状态／行动／反馈／再次判断／退化）
    ↓
廉价排除同构/固定流程；必要时数学或最小可玩原型
    ↓
批次原始证据（数学/原生/真人标清） ──→ 关系索引 / 精简研究记忆
    ↓                                    ↓
由研究者审查新颖性、体验潜力及反例 → 更新当前状态/队列
    ↓ 只在明确通过筛选时
模式库.json（精选） → 研究总览.html（自动生成）
    ↓ 只有必要且版本隔离的真人问题
试玩任务.json → 工作台反馈 inbox → 独立 review → 下一次研究判断
    ↓ 只有经人工批准
DebugResearchPlaytests.json
```

**禁止逆向流动**：不能因为正式故事出现新人物，倒推一个新的抽象研究题；不能因为多写了一份纸面代码，自动填“第21个模式”；不能因为数学CI绿灯就新增人类Debug；不能因为工作台的摘要较新就用它覆盖原始规则。

### 人类观察的证据位置

- **纸面/精确模型**：只能证明在冻结假设下的可达性、因果、支配与策略边界。
- **C#+Scheme 原生记录**：只能证明官方规则对应该场景执行成功，不能证明新玩家喜欢。
- **真人反馈**：可以支持或否定可读性、犹豫、体验价值和重复感；原话不可改写，也不要求意见服从最优策略。
- **Agent判断**：可以形成筛选建议，但必须保留不确定性与对旧模式的同构检查。

## 四、每次自主循环的最小可审计单元

每项研究不按“再跑十次”的形式立项；先写一张抽象**机制卡**（可存在对应批次的研究记录中）：

1. **一句话判断**：玩家究竟在什么不可兼得的选择中分配什么？
2. **完整循环**：首次行动 → 状态/信息反馈 → 下次有何不同判断 → 收束/重开。
3. **去情景规则**：状态、可见范围、可做动作、行动成本、结算规则；用A/B而非角色或道具。
4. **新颖性陈述**：与关系索引/20候选/精选六的哪一种接近，真正不同的*反复活动方式*在哪里。
5. **最便宜反证**：固定流程、支配、无新规则的消融、无可达严格选择或极端参数退化。若证伪应立刻停止单体深挖。
6. **验证身份和裁决**：推论/数学/原生/真人分别有什么；保留、合并、暂缓、停止。
7. **可复现信息**：版本SHA、源脚本、冻结输入、CI/原生执行链接、失败原因和下一次具体假设。

*选择在时间上能改变是好现象，但不规定每手必须改变主意；熟练可学的简明策略同样可能有魅力。不要伪造难度或复杂状态证明设计价值。*

## 五、哪些文件什么时候改

| 文件 | 何时修改 | 不该存什么 |
|---|---|---|
| 定位与评价 | 用户明确改变研究目标/质量标准 | 每轮实验进展与排错 |
| Skill / 研究约定 | 研究方法真的改进、需所有后续 Agent 一致执行 | R编号流水账、第一章任务、重复的目标 |
| 探索地图 | 发现新的抽象方向或同构后重划边界 | 具体剧情支线和任务工单 |
| 队列 | 假设新增、证伪、暂缓或优先级改变 | 已完成的详细统计和剧情修复待办 |
| 当前状态 | 一个有意义批次完成/接续变化 | 一年式追加式日志（历史进批次） |
| 自主研究记忆 | 归并新原则/失败解释/下一种心理循环 | 历史全部JSON结果（单独在归档与批次） |
| 批次和脚本 | 实际执行可复核实验 | 伪装成已认证的研究结论 |
| 关系索引 | 新关系/重要阴性反证/同构判决 | 每个数值敏感性结果 |
| 模式库 | 通过质量筛选的精选模式本体/明确纠错 | 临时假设、自动晋升、故事内容Bug |
| 试玩任务 | 确认人类评价需求与有效独立版本 | 原生BUG清单或数学任务派发 |
| 工作台 HTML | **只由生成器生成** | 人工编辑后的未同步数据 |

## 六、清理与历史兼容原则

本次只清理**默认入口和重复说明**，不重写历史研究、脚本、反馈、已有人类试玩和Unity Debug内容。旧全文保存在[校准前归档](归档/2026-10-12-方向校准前/README.md)；原批次和Actions链接保持原路径。S2/S3 的正典问题进入[独立正式内容索引](../正式内容验证/README.md)，不是被宣称已修复。

**新会话三步恢复：**先读 README/定位/队列，检查简明状态和反馈，再选两个不相邻的抽象方向做去剧情机制卡。需要复核旧结论时，才沿关系索引→源批次→实验代码读取。提交前先看 GitHub main 是否被其他研究者推进；避免覆盖并行工作。所有经过计算的指标只支持所冻结的模型，不等于有趣。

## 七、自动校验范围

- `python3 tools/content-validator/experiments/validate_abstract_research_scope.py`：确保历史完整备份、当前入口短小且机制优先、队列不是人物续集、研究工作台摘要不回到S3。
- `python3 tools/content-validator/experiments/validate_mechanism_portfolio.py`：候选与Debug分开，不自动晋升。
- `python3 tools/content-validator/experiments/validate_debug_playtests.py`：现有人工 Debug 白名单。
- `python3 tools/content-validator/experiments/build_mechanism_atlas.py --check`：模式库/试玩任务/生成HTML严格一致；研究工作台另有浏览器测试。

上述均为**工程一致性**，不是玩法价值判断。验证失败不得改弱约束以掩盖真正不一致；必须分析是否是因研究范围变化而需要正式调整规则。
