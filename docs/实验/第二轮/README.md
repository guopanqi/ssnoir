# 第二轮：两场重做后的验收候选

首批反馈暴露的是玩法结构问题：四骰没有形成资源投入，重复行动被无理由限制，失败被混入主动退出，属性判定和目标表达不足。本轮只重做「实验·枪口认路」「实验·信封换人」，其余八场不列入本轮验收。两场均无投降／放弃按钮；动作可重复投入，达成目标自动结算，威胁、期限或倒下导致失败。

作者设计与实验已完成，等待真人判断是否值得收入结构库。CLI通关不能证明有趣；下面的作者试玩知道规则，不是盲测。

## 在 Unity 中试玩

使用现有交锋调试入口，分别选择「实验·枪口认路」「实验·信封换人」。不需新增2D客户端。入场对白说明情景，场景上方「目标」标注常驻说明达成条件与失败条件，Clock备注说明增长和代价。两场均使用现有四骰、技能判定、冷静与伤势系统。

| 交锋 | 明确目的 | 本轮检验的取舍 |
|---|---|---|
| 枪口认路 | 封锁满2前，脱身推进到14；尽量保住交易底片 | 暴力压制占用跑动所需骰子；敏锐判定跑动。走被瞄准的路线每次消耗当前火力的冷静。栈桥更快但海水会毁掉底片，仍需实际跑完，不是退出按钮。 |
| 信封换人 | 警戒触及4或离开满2前，把交人推进到8 | 弱骰付5金保证进2、降警戒1；交涉好档进2，中档进1但加警戒；强抢好档进3但加警戒，中坏更危险；安抚用交涉判定降警戒。现金能替代判定风险，技能可以节省现金。 |

枪口的火力归零只在当前回合安全，下轮恢复1；封锁始终推进。枪手下轮改盯最后走的路线。信封的警戒先结算：触及4就被带走，不会再推进救人进度。失败后的说明明确告诉玩家没能完成什么。

## 修订依据与实际证据

第一版逐步试玩后，固定策略反例发现两处问题：枪口「先压制再跑」过于稳定；信封「连续谈判」在三个基线种子都免费成功，付款几乎无价值。第二版把枪口的进度从12调到14、封锁期限从4轮收紧到2轮；信封中档谈判也增加警戒，期限由3轮收紧到2轮。

另修复真实暴露的倒下路径错误：消耗冷静导致倒下时停止正常结束与后续跑动进度，交由既有 `on-encounter-collapse` 处理。信封先触及警戒失败时也停止推进交人，避免满进度却失败的画面。

当前版本作者逐步记录：

- 枪口 seed7：九步完成，两轮四骰全部有投入。首轮6点保证压制；末轮还差8格，选择把3点用于压制，保留三颗6点保证跑动。带底片脱身，剩3冷静、无伤。
- 信封 seed19：六步完成。强骰谈判、弱1付5金降压，下一轮高警戒时实际发到6点，直接用保证好档的谈判完成救人；共付5金、剩4冷静、无伤。没有为了让所有按钮都用上而强行安抚。

两份 `当前回归复核.json.gz` 均在最终源码下重新执行并严格重放成功。枪口完整公开观测与事件一致；信封完整观测一致、效果内容一致，但修订使中档条目的警戒显示先于进度，原作者记录的事件顺序因此有变化，未宣称旧事件逐项完全相同。

第二版36局固定策略对照用于查反例，位于 `v2/`；最终边界修订后另有19局定向复核，位于 `最终补充/`、`分配复核/`、`最终失败复核/`。这些是小样本，不是胜率估计，也不是玩家体验评分：

- 枪口 seed41：固定压制策略到13格被封锁；进度不足时把末轮四骰全投入货棚，则带底片脱身、轻伤1。压力管理与推进确实竞争骰子，不是固定每轮维护一次就够。seed53两种策略都失败，未保证任何局势都能无伤挽回。
- 枪口连续硬闯货棚会倒下；直接走栈桥可更快脱身，但底片损毁。结算区分保住证据、失去证据、被封锁、倒下。
- 信封 seed19：基线属性连续谈判失败，混合付款成功；growth2连续谈判成功。无钱的控压打法在growth1下该种子失败，growth2成功。安抚在无钱时参与骰子分配，仍会被时间挤压。
- 两场连续结束回合均自然失败，没有点击「认输」。倒下、警戒失败、期限失败三条最终轨迹严格重放通过。

不同策略会消耗不同数量的命运骰，后续手牌可能随之改变。同种子对照是各策略的完整情景结果，不能解释成逐动作完全相同的随机条件。

执行验证：`./run --validate`通过，包含两场加载与渲染；两份作者当前轨迹与三份失败轨迹严格重放通过；副标题与对白长度审阅通过。未操作Unity，画面、阅读体验与实际手感仍需真人验收。未更改引擎或新建客户端。

## 验收关注点

请只玩这两场，主要看：是否一进场就知道目标；是否会根据骰面与局势改变分配；失败能否解释为风险与投入的后果；是否仍存在明显包办整场的动作。完成本轮实验不等于宣布两场已获真人认可。

`策略对照.py` 是固定策略反例工具，读取公开观测，不读取脚本私有变量。重跑可用 `python3 docs/实验/第二轮/策略对照.py 新记录目录名`，不覆盖旧记录。作者逐步记录仍是主要设计证据。首批及v1记录仅留作修订历史。
