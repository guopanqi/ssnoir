# 赃款会拖脚

## 假设与规则

同一件战利品既是收益也是负担。扔下一袋是免费的不可逆选择，减少重量会增加下一次移动的收益；希望玩家根据当前骰子、剩余路程和追兵位置决定是否割舍，而不是入场就固定丢掉。

初始三袋，脱身需要六格，追兵三回合追上。每回合仅移动一次。好结果走5减钱袋数，中结果走4减钱袋数；坏结果原地停步并花一冷静。最终保留袋数只是原型结算值，没有实际给库存增加金钱。

## 作者逐步试玩与修订

v1的好结果只有4减钱袋数：抱三袋即使连续三个好结果也不能走完。这让开场丢钱成为强制前置动作。旧记录保留在历史/v1，不拿旧策略结果评价新版本。

v2把好结果增加到5减钱袋数，中结果增加到4减钱袋数。seed31作者逐步局，看到每回合都有6骰，连续三个好结果走完六格，五步操作保住三袋、剩三冷静。每一步理由记录在作者逐步-v2-seed31.json.gz；这是知道设计的作者试玩，不是盲测。

此前v1的逐步局曾在最后一轮因中档保证进度不足而临时丢一袋；这个决策关系有潜力，但需要人类确认v2是否仍能自然触发，而不能把旧版本观察直接归给新版。

## 后续脚本对照

第二批对照结果.json中的五个种子：死抱三袋三次脱身、两次被追上；固定保两袋五次脱身；保一袋和全部丢弃也都脱身。末轮才求稳仍有一次失败，丢钱不能补救此前所有停步。记录在对照记录，打法由probe-second-batch.py固定实现，不代表玩家行为。

小样本说明保三袋有实际可能、保两袋更稳；尚不能证明最优策略或难度。不同动作会改变随机消耗，不能把同一种子两条轨迹直接当成仅改变重量的控制实验。

## 待人类验收

读数是否足以心算下一步；免费的不可逆丢弃是否容易误触；每轮一次移动是否导致空耗剩余骰子的乏味感。Unity画面与触控未验收，主线现金结算未接入。
