# Unity IMGUI 世界界面视觉审查

- 日期：2026-07-06
- 范围：世界概览单屏，包括顶部导航与关系、世界节点标签、底部队伍/物品面板与返回操作。
- 证据：[01-world-overview.png](01-world-overview.png)
- 审查模式：UX + 视觉可读性审查。

## 步骤 1：世界概览（健康度：较差）

玩家需要在线框城市中识别可交互节点，理解当前位置和状态，并从底部资源区发起行动。

### 保留点

- 深蓝近黑场景与白色建筑线稿已经有明确记忆点，方角矩形也符合建筑线稿语言。
- 顶部、世界中、底部的功能区基本已经分开。
- 代码已经有明确的 locked/disabled 交互上下文，不需要通过伪造输入来解决交互优先级。

### 主要问题

1. **UI 和场景使用了同一视觉频道。** 白字、灰色细边框、透明深色底与建筑白色描边竞争，玩家无法一眼分辨“世界”和“交互层”。
2. **40% 透明 HUD 在当前场景上失效。** 场景本身就是深色，面板明度差几乎消失；而 IMGUI 并没有实现 `DESIGN.md` 所描述的高模糊，因此实际只剩下一层很薄的灰色蒙版。
3. **没有明确的主操作色。** 代码中虽有 Steel Blue 与 Burnt Amber，但 Steel Blue 与场景白蓝线稿距离太近，而 Amber 只在少数语义中出现，截图中看不出稳定的选中焦点。
4. **状态只靠 1px/2px 边框变化。** 在高密度白色建筑线中，hover、selected、focused 很难区分，且不利于低视力用户。
5. **顶部信息既稀疏又挤压。** 贯穿屏幕的细分隔线增加噪声，左上角状态文字又与世界物体叠在一起。
6. **底部面板缺乏层级。** 队伍、骰子、物品和返回都像同一级的线框；右侧留白大，“返回”却远离顶部面包屑，导航模型不连续。
7. **字体规范与实现不一致。** `DESIGN.md` 定义 Hanken Grotesk + JetBrains Mono，实现只注入 MiSans。当前大量 12–14px 文字在 1574×890 截图中显得过小，中文模糊后尤其明显。

### 可达性风险

- 选中、悬停和可用状态过度依赖颜色与细边框，缺少形状、填充或位置上的第二线索。
- 小字、薄线和半透明文字的实际对比度容易受场景明暗影响。
- 单张截图无法验证键盘焦点、指针命中区、动效和不同分辨率下的缩放。

## 方向选项

### A. 暖铜调查仪（推荐）

保留深蓝黑场景和白线建筑，HUD 改为高不透明深蓝灰材质，用暖铜/琥珀作唯一主交互色。它与白蓝场景的色相距离最大，适合选中节点、主按钮、当前步骤和世界连线。质感是“老式城市档案终端”，不会变成通用科幻 HUD。

### B. 冷青传感器

用冷青作选中色，暖橙只表示警告。系统感强，但与建筑白蓝线稿仍有竞争，必须依赖高不透明面板和明显形状才能成立。

### C. 象牙纸档案

弹窗和重要卡片使用暖象牙白表面、深蓝黑文字，形成“纸面资料压在蓝图上”的反转。质感最强，但面积一大会破坏沉浸，更适合仅用于剧情结算、信件、关键发现，不适合作全局 HUD。

## 推荐规范：方向 A

### 核心色板

| Token | 颜色 | 用途 |
|---|---|---|
| `SceneVoid` | `#0B1019` | 场景底色 |
| `HudBase` | `#101722` / 94% | 常驻 HUD，不再使用 40% 透明 |
| `HudRaised` | `#172131` / 98% | 卡片、下拉、弹窗 |
| `HudInset` | `#0B111B` | 槽位、轨道、数值底 |
| `TextPrimary` | `#EDF0F3` | 标题和主数值 |
| `TextSecondary` | `#9BA8B8` | 辅助说明 |
| `Keyline` | `#3C495C` | 常态边框，避免纯白 |
| `Accent` | `#E2A45F` | 选中、主操作、当前步骤 |
| `Danger` | `#DF6B62` | 错误、严重负面后果 |
| `Success` | `#65B9A6` | 成功、可放置 |

`Accent` 不再同时表示警告；警告使用 `Danger`，进度使用中性米白或所属角色色。

### 材质与细节

- 常驻面板用高不透明色块建立剪影，不做无模糊的伪玻璃。
- 常态边框 1px `Keyline`；内侧可加 1px、4% 亮线；弹窗外侧加 2–4px 近黑压边，不依赖大柔影。
- 只在选中项上出现短角标、3px 左导轨或底线，它们是状态标记，不是全局装饰。
- 允许极轻的 2–3% 颗粒纹理，但禁止大面积扫描线；扫描线只服务于“正在执行/解析”语义。

### 交互状态

| 状态 | 填充 | 边框 | 第二线索 |
|---|---|---|---|
| Default | `HudRaised` | 1px `Keyline` | 无 |
| Hover | Accent 8% | 1px Accent 70% | 标题提亮 |
| Pressed | Accent 18% | 1px Accent | 内侧 1px 暗线 |
| Selected/Focused | Accent 14% | 2px Accent | 3px 导轨 + 世界锚点同色呼应 |
| Disabled | `HudInset` | 1px Keyline 45% | 文字 45%，不响应交互 |
| Danger | Danger 12% | 1px Danger | 明确的文字后果说明 |

选中不应只是 hover 的加强版；它是持续状态，必须在鼠标移开后仍然可见。

### 布局调整

- 顶部改为两个内容宽度的独立模块：左侧“位置/当前节点”，右侧“关系/时钟”；取消贯穿全屏的纯装饰分隔线。
- 返回操作回到左上面包屑的起点，底部右侧留给当前节点的主行动。
- 底部手牌区可保留全宽，但底色提高到 92–96% 不透明，内部用 16/24px 间距和色块层级分组，而不是靠更多边框分组。
- 世界节点标签使用至少 88% 不透明的小背板、一条明确的 leader line 和 44px 最小命中区。选中后，标签、连线、世界锚点和侧边详情使用同一 Accent。

### 弹窗

- 遮罩：`#05070B` 68%，明确压低世界层。
- 容器：`HudRaised` 98%，外黑压边 + 1px `Keyline`；顶部 3px Accent 只表示当前主任务弹窗。
- 主按钮：Accent 实心填充 + 深色文字；次按钮：透明底 + Keyline。这能解决当前所有按钮都像同一级线框的问题。

## 实施顺序

1. 先重写核心 token 和交互状态，但不改布局。这一步就应解决“找不到 UI”。
2. 再改顶部模块、底部手牌分组、返回位置与弹窗层级。
3. 最后再做世界节点、人物特殊表现和纹理动效，避免用装饰掩盖基础层级问题。

## 证据限制

本次只有世界概览的单张静态截图，未观察 hover、selected、拖放、弹窗、对话、不同分辨率和键盘导航的实际运行状态。
