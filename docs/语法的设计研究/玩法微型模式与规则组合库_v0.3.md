# SSNoir · 玩法微型模式与规则组合库

> **核心问题：少量通用规则怎样组合，才能让玩家通过行动亲身感受到一种事物的性质？** 例如精密工程的艰难、有限救济的善意、潜行调查的警觉，或人与人逐渐熟悉的过程。
>
> **本文件是持续扩充的研究底稿，不是游戏当前已实装功能表。** 上半部是可复用的规则语言；下半部按来源保存真实案例与原创假设。新研究可以补充案例、修正实证、提出新的组合，而不必改写既有条目的身份。

- **实例来源代码**：`CS1` = 《Citizen Sleeper》（2022）；`CS2` = 《Citizen Sleeper 2: Starward Vector》（2025）；`SSN` = SSNoir 创作中的候选设计。
- **证据状态**：`已核对` = 有可追查的游戏节点资料或攻略；`待核对` = 来自游玩观察、讨论或有来源冲突，待逐项复现；`原创假设` = 尚非任何游戏的实装事实。
- **观察与解释分开**：每张案例中的「原始规则」只描述行动、结果与状态转换；「体验解释」是我们的设计推断，不冒充开发者意图。
- **扩展方式**：增加一个实例，复制文末案例模板，分配不重复的 ID，写明引用的基础规则编号与证据链接。不要凭主题相似就将两个不同的机制混为一谈。

# 一、基础规则与元素

## 1. 一条微型规则的最小结构

无需把「维修」「赌博」「安慰」「调查」分别实现成全新玩法。可以先表示为：

`行动（消耗 / 条件） → 结果判定 → 状态变化 → 阈值事件 → 新的可选行动`

例：`打听（1 颗骰子） → 失败 → 警觉 +1 → 警觉达到 4 → 店主拒绝接待 → 解锁别的接触路线`

这里涉及的是**行动如何改变局势**，不是光用 Clock 给剧情加一个进度条。规则应产生玩家能观察、预测或从后果中学习的因果关系。

## 2. 基础元素（Elements）

| ID | 元素 | 可变化属性 | 描述与作用 |
|---|---|---|---|
| E-01 | 行动（Action） | 重复 / 一次性 / 限次 / 消耗物品 / 需条件 | 玩家实际选择和付费的最小单位 |
| E-02 | 判定结果（Outcome） | 成功、中立、失败；也可不随机 | 同一行动在不同结果下改变不同状态 |
| E-03 | 进度 Clock（Progress） | 长度、起点、增减量、能否倒退 | 工作、调查、建设、熟练等目标进展 |
| E-04 | 压力 Clock（Pressure） | 来源、增长、下降、阈值 | 警觉、事故、危险、嫌疑、敌意 |
| E-05 | 时间 Clock（Time） | 每 Cycle 变化、截止、窗口、等待 | 事件随日常时间自动变化，而不依赖骰运 |
| E-06 | 容量 / 次数（Capacity） | 总次数、每日次数、补充方式、耗尽后关闭 | 救济额度、库存、最后几次机会 |
| E-07 | 可消费资源（Resource） | 金钱、食物、物资、线索、道具 | 允许一种活动的结果支持另一种活动 |
| E-08 | 行动能力（Capability） | 骰子数量、骰面、技能、疲劳、伤势 | 玩家或队友当下能够做到什么 |
| E-09 | 门槛 / 锁定（Gate） | 前置条件、技能要求、阈值解锁、关闭 | 同一个地点 / 人物在不同局势下允许不同交互 |
| E-10 | 关系状态（Relationship） | 熟悉、信任、惧怕、债务、照料 | 行动长期改变人与人、人与地点的关系 |
| E-11 | 目标连接（Objective Topology） | AND、OR、先后、主次、可选 | 多个 Clock 如何组成一项工作或故事 |
| E-12 | 结算 / 后果（Consequence） | 奖励、损伤、机会损失、分支、世界变化 | 让已发生的事留在世界里，而非恢复原状 |
| E-13 | 人物意图（Intent） | 行动者、目标、准备做的事、触发条件、可放弃性 | 让非玩家人物主动尝试改变世界，而不是只响应玩家 |
| E-14 | 局势事实（Situation Fact） | 真/假、类型、来源、派生条件、持续时间 | 描述当前成立的条件；供 Gate、收益和人物行动引用 |
| E-15 | 后果承担者（Consequence Receiver） | 谁承担、程度、能否转移、责任归属 | E-12 的显式目标参数，不应再等同于“玩家扣数值” |
| E-16 | 跨日约定（Commitment） | 承诺双方、事项、期限、依赖、兑现/违约结果 | 让今天的决定在未来改变他人预期与行动 |
| E-17 | 人物动机（Motivation / Goal） | 想得到/避免什么、优先级、底线、可替代方案 | 解释意图为何形成、为何改变；不同于已经决定的行动 |
| E-18 | 认知与信念（Knowledge / Belief） | 谁知道、谁相信、确定性、是否错误、来源 | 区分客观事实与每个角色眼中的世界 |
| E-19 | 持有与控制权（Custody / Control） | 当前持有人、使用/转交权限、来源、可信度 | 区分“东西存在”与“谁能用、谁有权用、交付是否可信” |
| E-20 | 事件记忆与痕迹（Event Trace） | 行为、时间、地点、参与者、遗留物、可发现性 | 保存“曾经发生过什么”，用于以后调查、追责、回忆 |

**设计提醒：** `进度`、`压力`、`时间`都可以显示成 Clock，但它们的**更新原因**不同；不要只因为视觉相同就视为同一种设计。

## 3. 基础运算符（Operators）

| ID | 运算符 | 规则形式 | 可表达的体验 |
|---|---|---|---|
| O-01 | 增加（ADD） | `P += n` | 累积劳动、收集、建立关系 |
| O-02 | 减少（SUB） | `P -= n` | 倒退、损耗、努力受挫 |
| O-03 | 保底（FLOOR） | `任意结果 P += 至少 1` | 尽力就有意义、善意不以表现论资格 |
| O-04 | 同时变化（COUPLE） | `P += n` 且 `Risk += m` | 进步带来代价，收益与危险捆绑 |
| O-05 | 自然变化（TICK） | `每 Cycle P +=/-= n` | 时间、成长、腐败、流逝 |
| O-06 | 消耗容量（SPEND） | `Uses -= 1`，归零后关闭 | 机会有限、资源匮乏 |
| O-07 | 结果转化（CONVERT） | `金钱 → 物资 → 进度` | 经济和行动系统相互支撑 |
| O-08 | 门槛切换（SWITCH） | `X 达阈值 → 动作 A 关闭、B 打开` | 事故升级、变得熟悉、失去资格 |
| O-09 | 产生新问题（SPAWN） | `Pressure 满 → 新危机 C` | 善后、连锁事件、临场改计划 |
| O-10 | 路径分叉（BRANCH） | `A 或 B → 同一目标 / 不同后果` | 多策略、身份价值选择 |
| O-11 | 周期重置（RESET） | `每 Cycle 次数重置 / 压力部分恢复` | 日常节律、等待明天、季节性机会 |
| O-12 | 结果反转（REVALUE） | `发现信息 → 原目标的意义改变` | 背叛、抉择、主动放弃原定成功 |
| O-13 | 形成/修订意图（PLAN / REPLAN） | `动机 + 认知 + 局势 → 意图`；新情况可改变意图 | 人物自主、被说服、背离原计划 |
| O-14 | 自主执行（ACT） | `到时且条件成立 → 人物尝试动作` | 世界不等玩家点击才变化 |
| O-15 | 观察与知晓（OBSERVE） | `发生事件 + 有观察条件 → 某人获得认知` | 目击、发现、误会、秘密 |
| O-16 | 订约与兑现（COMMIT / RESOLVE） | `今天承诺 → 到期判断履行/违约` | 守信、依赖、爽约、借债 |
| O-17 | 转交与承担（TRANSFER / ASSIGN） | `物品/控制权/损失 → 指定人物` | 托付、代偿、保护、嫁祸 |
| O-18 | 留痕与记忆（RECORD） | `事件 → 可追溯记录或遗留物` | 过去的行为以后重新产生作用 |
| O-19 | 传播与误传（PROPAGATE） | `某人知道/相信 → 传播 → 他人形成信念` | 流言、舆论、隐瞒、错误归因 |

这些不是引擎 API，只是一组人可以阅读和组合的规则词汇。一个案例通常只需要两到四个运算符。

## 4. 判断“组合”而非“内容”的标准

- **不是微型组合**：把酒馆改名为医院、把收集 6 个改成收集 8 个，而玩家思考完全不变。
- **是微型组合**：同样「投入骰子推进 8 格」，失败现在会产生新的故障；故障达到阈值后要花钱买零件，玩家不得不重新考虑风险和资金。
- **判断题**：把人物和场景名称全部去掉后，是否仍能描述这套行动—反馈—变化关系？如果可以，它便有机会成为跨场景复用的模式。

# 一·补充：主体、认知与因果元素

> **0.2 核心判断**：初版 E-01—E-12 已能描述工作、资源、压力和结算。新增 E-13—E-20 不是为了制造八种新数值，而是补足「谁在主动行动」「谁知道什么」「谁持有某物」「过去的事何时再次发生作用」。这一节属于 **SSNoir 规则语言的原创建模假设**，不是 CS1/CS2 的现成系统。

## 1. 四个讨论中提出的元素，不是同一种层级

| 概念 | 应怎样建模 | 与现有元素的边界 |
|---|---|---|
| **Intent 人物意图**（E-13） | 具体行为计划：谁、准备做什么、何时尝试、满足何条件、遇阻怎么办 | 不是单纯 Clock；Clock 可表示准备程度和剩余时间，却不能说明行为目的、行动对象或替代方案 |
| **Situation Fact 局势事实**（E-14） | 可判断的世界条件；既有持久事实，也有由数值与事件派生的事实 | 不是数值变化运算符；`警觉 +1` 是变化，`警觉≥4 → 已暴露` 是事实判断，Gate 再根据该事实关闭行动 |
| **Consequence Receiver 后果承担者**（E-15） | 每条后果作用到谁/什么对象，谁负责，能否代偿 | 是 E-12 后果的目标/归属参数，不必发明独立数值池 |
| **Commitment 跨日约定**（E-16） | 双方、事项、期限、兑现方式、另一方据此采取的行动 | 是 E-05 时间 + E-10 关系 + E-12 后果的复合对象；作为重复使用的设计词汇有独立价值 |

## 2. 另外四个值得新增的元素

**E-17 人物动机（Motivation / Goal）** —— 意图回答“准备做什么”，动机回答“为什么”。夜莺的目标可以是「演出必须继续」，由此产生“拒绝取消排练”的意图；情况变化后，她仍可能保持同一目标，却改为其他行动。不要急着用复杂的效用函数模拟所有居民；第一阶段只需要每个关键人物 1—2 个稳定愿望与 1 个明确底线。

**E-18 认知与信念（Knowledge / Belief）** —— 世界里确实发生的事实，不等于每个人都知道、相信或正确理解的事。必须区分 `WorldFact(照片来自某店)`、`Knows(尼尔, 某痕迹)`、`Believes(店主, 尼尔是警察)`。其中 Belief 可以错误，证据和对话才有了真正的作用。这是侦探游戏最值得优先验证的新增元素。

**E-19 持有与控制权（Custody / Control）** —— 照片存在，不意味着尼尔拿得到；尼尔拿到了，也不意味着拥有原件或可以合法交给警方。它与 E-07 资源有交集，但加入持有人、复制品/原件、借用、授权、交接对象后，玩家能感受到盗取、保管、托付、归还与欺骗的区别。先在关键证据和承诺中的物品上使用，不必给每一个杯子模拟所有权。

**E-20 事件记忆与痕迹（Event Trace）** —— E-14 是“此刻什么成立”，E-20 是“谁在何时何地做过什么、留下什么”。留在现场的痕迹与某个角色回忆的内容也不是同一回事；痕迹可以尚未被发现。需要时可用少量带时间戳的事实/事件记录实现，不要求独立日志系统。

## 3. 哪些概念不必再提升为新元素？

- **目击/注意力**：可先用 `人物在场`、`可见`、`关注中` 等 Situation Fact，配合 O-15 OBSERVE；只有需要复杂视觉/听觉模拟时，再研究专门的注意力系统。
- **传闻、名声、猜疑**：是认知传播加关系/压力状态的组合，不必立即发明新的 Reputation 条。
- **机会窗口、先后顺序**：已有时间 E-05、Gate E-09 和 O-08 SWITCH 足够表达。
- **责任、恩情、债务**：可以先通过 E-15 Receiver、E-16 Commitment、E-20 Trace 和 E-10 Relationship 的组合实现；验证有独特策略需求后再细分。
- **优先级/需求评分**：是 E-17 动机的属性与 O-13 形成意图的选择规则，而非另一套人物成长等级。

## 4. 最小规则语言：把世界状态、人物认知、后果分开

```text
世界：  状态(对象, 属性)         例：剧院.演出取消 = false
事实：  满足条件(世界状态)       例：夜莺仍有演出机会
认知：  相信(人物, 命题, 来源)   例：经理相信尼尔会阻止演出
动机：  人物想得到/避免什么       例：夜莺希望被观众认可
意图：  人物准备何时执行何行动   例：夜莺准备今晚登台
约定：  谁答应谁、何时、做什么     例：尼尔答应艾迪明早见面
行动：  条件成立时进行状态转移     例：尼尔去后台切断可疑电源
后果：  什么变化，最终落在谁身上   例：演出延期，夜莺承受损失
记录：  发生过何事、留有什么痕迹   例：后台工人见到尼尔切电源
```

一个完整的简单例子：`夜莺要继续演出（动机）→ 明晚登台（意图）→ 尼尔发现吊灯损坏（尼尔的认知）→ 选择把证据告诉夜莺（传播认知）→ 她决定坚持还是改演出方案（重议意图）→ 若事故发生，受损对象由干预方式改变（后果承担者）→ 众人记得尼尔在后台做过什么（事件记录）`。不需要把每一步都显示为 Clock。

# 二、常见组合语法

| 组合代号 | 规则公式（抽象） | 玩家感受 | 典型语境 | 案例 |
|---|---|---|---|---|
| C-01 艰难工程 | `长进度 + 不利结果损伤能力` | 漫长、艰苦、身体代价 | 大型船舶、城市工程 | CS1-01 |
| C-02 危险工序 | `进度 + 事故压力 + 阈值后换方法` | 越做越危险、不可硬来 | 维修、手术、侦查 | CS1-02 |
| C-03 有保障的帮助 | `成功多收获 / 失败仍有保底` | 温暖、可靠、劳动不白费 | 照护、食堂、邻居帮助 | CS1-03、CS1-04、CS2-01 |
| C-04 有限机会 | `保底 + 可用次数减少` | 善意受物资限制、珍惜机会 | 救济、临时接济 | SSN-02、CS2-01-OBS |
| C-05 熟人进程 | `重复日常 + 关系进度 + 新行动` | 融入、熟悉、关系变深 | 酒馆、店铺、人物线 | CS1-05、SSN-01 |
| C-06 危险并行 | `目标进度 + 警觉/事故压力` | 克制、见好就收 | 潜行、偷拍、脆弱货物 | CS1-06、CS2-04、SSN-03 |
| C-07 对手赛跑 | `己方 Clock + 对手时间/进度 Clock` | 抢先、竞争、时间紧迫 | 竞争搜寻、新闻 | CS2-02 |
| C-08 危机衍生 | `压力达阈值 → 新 Clock + 持续惩罚` | 原计划被打断、陷入困境 | 事故处理、暴露 | CS2-03、SSN-07 |
| C-09 成本平静 | `无局部倒计时 + 每轮仍耗生活资源` | 安静、可以慢做但不免费 | 帮工、清理、修复 | CS2-05 |
| C-10 发现后改变目标 | `先推进目标 + 新信息 + 可主动放弃` | 道德抉择、关系比报酬重要 | 侦探委托、告密 | CS2-06、SSN-08 |
| C-11 损坏能力的循环 | `行动/推进 → Stress → 可用能力下降` | 透支、恶性循环、极限 | 长时间交锋 | CS2-07 |
| C-12 日常附带调查 | `相同生活行动 + 条件性额外信息` | 城市互相关联、自然发现 | 送货、冲印、打工 | SSN-04 |
| C-13 独立行动者 | `动机 + 意图 + 时机 + 自主执行` | 城市里的人有自己的生活 | 离开、迁居、准备首演 | SSN-09、SSN-10 |
| C-14 不同的人眼中不同的事实 | `事实 + 分角色认知 + 行动` | 秘密、误会、怀疑与侦探推理 | 照片来源、错误指认 | SSN-11 |
| C-15 被依赖的承诺 | `跨日约定 + 他人意图 + 履约/违约` | 期待、歉疚、信任的重量 | 赴约、担保、送东西 | SSN-12、SSN-13 |
| C-16 留下的证据 | `行动留痕 + 延迟发现 + 他人反应` | 事情过去以后仍能找上门 | 跟拍、盗窃、侦查 | SSN-14 |
| C-17 谁控制证据 | `物品 + 持有人 + 来源记录 + 条件性交付` | 托付、真实与可疑的证据链 | 旧照片、信件、档案 | SSN-15 |

# 四、CS1：已存在的组合

## CS1-01｜Sidereal Horizon：沉重的长期建设

- **来源 / 状态**：CS1 · 已核对。
- **原始规则**：殖民船建设共享一条 **24 格**进度；相关工作成功推进 **+2**，中立推进 **+1**，失败不推进，但仍得工资且 **Condition -1**。此前的技术资格/质量控制阶段另有因错误而失去资格、需要重新取得进场资格的机制。
- **规则组合**：`E-01 + E-02 + E-03 + E-08`；`O-01 + 不利结果损伤能力`。
- **体验解释**：日复一日的精密劳动；失败并非让造好的船神奇消失，而是身体在消耗。工资稳定并不能抵消生活中的成本。
- **适用情境**：大型工程、艰难的谋生方式、需要漫长坚持的共同目标。
- **重要区分**：**24 格建设本身失败并不直接扣建设进度**；不能将前置质量控制 Clock 的倒退混写为 24 格本体的规则。
- **证据**：[Sidereal Hull](https://citizensleeper.fandom.com/wiki/Sidereal_Hull) · [Sidereal Bridge](https://citizensleeper.fandom.com/wiki/Sidereal_Bridge) · [Unit Assembly](https://citizensleeper.fandom.com/wiki/Unit_Assembly)。

## CS1-02｜Ambergris：事故迫使改变修法

- **来源 / 状态**：CS1 · 已核对（概括性结构）。
- **原始规则**：修理船体的工作伴随船况恶化；有一次性高风险的无人机重新接线，也有可重复但危险的船体维修。玩家不能把脆弱的旧船当成普通的安全工作台。
- **规则组合**：`E-03 + E-04 + E-09`；`O-04 + O-08`。
- **体验解释**：本来是在帮助，但每次出手都可能让旧东西更加脆弱。「有技能」不等于「可以一直使用相同办法」。
- **适用情境**：老旧设备、医疗救治、事故现场、失控中的调查。
- **证据**：[The Ambergris](https://citizensleeper.telepedia.net/wiki/The_Ambergris)。
- **核验备注**：具体事故 Clock 的名称、阈值和后继行动，后续可用游戏录像单独补齐；此处不填写未经这次核对的数值。

## CS1-03｜Lem 与 Mina：照护一定有意义

- **来源 / 状态**：CS1 · 已核对。
- **原始规则**：`Babysit Mina` 推进 `A Ticket Out`；成功 **+2 进度、+2 Energy**，中立 **+1 进度、+1 Energy**，失败也 **+1 进度**。
- **规则组合**：`E-02 + E-03 + E-10`；`O-01 + O-03`。
- **体验解释**：照料与陪伴不是一场「没掷好就完全无效」的考试。只要来陪 Mina，就确实为 Lem 提供了支持。
- **适用情境**：陪伴家人、照料病人、探望老人、志愿活动、倾听某人的故事。
- **证据**：[Lem (& Mina) 攻略与行动结果](https://www.neoseeker.com/citizen-sleeper/Lem_%26_Mina)。

## CS1-04｜Min-Gi：失败也能吃上饭

- **来源 / 状态**：CS1 · 已核对。
- **原始规则**：面馆制作面食，成功获得 **+3 Energy 与较多 Cryo**，中立获得 **+2 Energy 与较少 Cryo**，失败仍 **+1 Energy**。
- **规则组合**：`E-02 + E-07`；`O-03`。
- **体验解释**：收入有运气成分，但最基本的热量供给有保障。这是生活中不耀眼却可靠的避风港。
- **适用情境**：包饭的工作、员工餐、熟识店主的照顾、低保底线工作。
- **证据**：[Energy 条目：Min-Gi Express](https://citizensleeper.fandom.com/wiki/Energy)。

## CS1-05｜Tala 的酒馆：日常变为共同事业

- **来源 / 状态**：CS1 · 已核对。
- **原始规则**：起初喝酒会增加 `Overlook Regular` 熟悉度；之后打工既得到 Cryo，也推进 `Good Service`；关系与进度进一步解锁帮助建造蒸馏装置；搜集孢子后还出现 **6 Cycle** 的第一批酿造等待 Clock。
- **规则组合**：`E-01 + E-03 + E-05 + E-09 + E-10`；`O-01 + O-05 + O-08`。
- **体验解释**：一处最初只用于消费和挣钱的地方，慢慢成为有人认识你、愿意分享梦想、邀请共同完成事业的地方。
- **适用情境**：酒馆常客、邻里店铺、师徒、朋友间合伙项目。
- **证据**：[Overlook Bar](https://citizensleeper.fandom.com/wiki/Overlook_Bar)。

## CS1-06｜Rotunda：捷径与警卫警觉

- **来源 / 状态**：CS1 · 已核对。
- **原始规则**：探索 Rotunda 可以逐渐了解地区；也可以尝试危险的 `Steal Dock Plans`，一次取得更多 `Dock Watcher` 进度，但中立或失败可能累积 `Havenage Watchlist` 警觉。警觉满后触发守卫相关事件。
- **规则组合**：`E-03 + E-04 + E-09`；`O-04 + O-08`。
- **体验解释**：慢慢熟悉城市和冒险取得捷径，有不同的代价；速度不是唯一价值。
- **适用情境**：搜集地图、偷档案、初入陌生街区、私闯机构。
- **证据**：[Rotunda](https://citizensleeper.fandom.com/wiki/Rotunda)。

## CS1-07｜Unit Assembly：质量审查与失去资格

- **来源 / 状态**：CS1 · 已核对。
- **原始规则**：先通过 `Junior Tech` 或 `Welder's Mate` 的 **8 格**资格 Clock；不良工序可能影响 `Quality Control`（**3 格**）。质量检查达到失败阈值将关闭装配区工作资格，需要重新从船厂基层工作取得进入资格。
- **规则组合**：`E-03 + E-04 + E-09`；`O-08`。
- **体验解释**：工作的难，不只在眼前损失，而在失去组织信任或准入资格。错误使你退回制度中的较低位置。
- **适用情境**：学徒试用期、秘密组织考核、临时工上岗、专业执照、新闻来源信誉。
- **证据**：[Unit Assembly](https://citizensleeper.fandom.com/wiki/Unit_Assembly)。

# 五、CS2：已存在的组合

## CS2-01｜Nemba 的厨房：失败也有食物

- **来源 / 状态**：CS2 · 「失败仍给少量 Energy」已核对；关于使用次数见下一条。

- **适用情境**：社区食堂、互助厨房、志愿工作、经济困顿时的落脚处。
- **证据**：[Exploring Far Spindle / Nemba's Kitchen](https://www.neoseeker.com/citizen-sleeper-2-starward-vector/Exploring_Far_Spindle)。

## CS2-01-OBS｜成功消耗有限机会的厨房（游玩观察）

- **来源 / 状态**：CS2 · **待核对**，保留使用者对游戏节点的具体观察，不将它写成已复核事实。
- **观察陈述**：「成功会减少使用次数，失败反而回报精力。」
- **若成立的规则组合**：`E-02 + E-06 + E-07`；`O-03 + O-06`。
- **体验解释**：成功取得更大帮助，但消耗公共资源；失败仍获得最低照顾。这可以表现慷慨与匮乏共存。
- **设计风险**：如果失败可以无限重复获益，玩家可能故意用低骰刷资源。核对时应记录：扣次数究竟发生在何种判定、每天是否重置、负面结果是否也扣使用次数。
- **复核任务**：补游戏中的**具体动作名称、正中负三档原文、剩余次数 UI 与跨 Cycle 行为**；验证后决定是否并入 CS2-01。

## CS2-02｜Hidden Wreck：对手抢先

- **适用情境**：抢新闻、警方先行封锁现场、抢购稀有物品、救援中的有限时间。
- **证据**：[CS2 成就及 Hidden Wreck 竞争条件](https://steamcommunity.com/sharedfiles/filedetails/?id=3422760770) · [Contract 攻略索引](https://www.neoseeker.com/citizen-sleeper-2-starward-vector/walkthrough)。

# 六、SSNoir：新组合假设

> 以下均为**尚待实现 / 纸面验证的设计提案**。数字仅为实验起点，而非游戏已定参数；优先测试规则是否表达了正确的感觉，而不是把表格全部装进成品。

## SSN-01｜酒馆：熟悉的工作

- **设计规则**：普通工作给工资，重复成功或中立时累计「熟悉度」；达到阈值后，降低某一类工作的风险，随后解锁调酒师的额外委托。失败仍发最低工资，但不推进熟悉度。
- **组合**：`E-01 + E-03 + E-09 + E-10`；`O-01 + O-08`。
- **体验目标**：初来乍到 → 熟悉人和流程 → 逐渐把酒馆当作生活的一部分。
- **情境**：尼尔在酒馆打工，遇见赖账客人，慢慢接触老街的消息。
- **最小实验**：熟悉度 0/4；前后工作回报相同，但达到 4 后额外出现「调酒师托付」行动。先不直接提高工资，以免退化为刷熟练度。
- **待验证问题**：玩家是否感到归属，而不只是做 4 次工作换一个按钮？

## SSN-02｜老街：有限的善意

- **设计规则**：在居民食堂帮工，失败仍获得少量食物；成功获得更多食物，但消耗有限的一次额外接济额度。每日需消耗行动，容量在下一周期是否恢复由世界中的实际库存决定。
- **组合**：`E-02 + E-06 + E-07 + E-10`；`O-03 + O-06`。
- **体验目标**：这个地方愿意接纳人，但不能无限供给。
- **情境**：尼尔贫困时得到老街居民帮助；后续也可以反过来为居民解决问题。
- **最小实验**：每天最多帮助 2 次；每次行动一定给基本饭食，较好结果给予额外补给，同时消耗公共库存。**这里是为测试而提出的机制，不代表 CS2 厨房已这样实装。**
- **待验证问题**：有没有故意用低骰无限刷保底的占优策略？是否需要用「每次行动都扣一次接济额度」替代「仅成功扣额度」？

## SSN-03｜跟拍：证据和警觉

- **设计规则**：暗中观察推进证据 Clock；快速跟进能一次得到更多进度，但失败更容易增加警觉。警觉满后目标识破尾随，原动作关闭，开启「撤离」「更换观察点」或交涉。
- **组合**：`E-03 + E-04 + E-09`；`O-04 + O-08`。
- **体验目标**：玩家思考的是「什么时候已经足够、是不是该收手」，不只是如何最大化每颗骰子的收益。
- **情境**：婚外情跟拍、追查勒索照片、观察剧院后巷。
- **最小实验**：证据 0/6、警觉 0/4；保守观察成功 +2 / 中立 +1 / 失败警觉 +1；冒险跟进成功 +3 / 中立 +1 且警觉 +1 / 失败警觉 +2。
- **待验证问题**：玩家是否总是给保守观察低骰、给冒险跟进高骰，从而形成无需思考的固定策略？如果如此，需要改变时机、距离或信息结构，而不是单纯加数字。

## SSN-04｜照相馆：日常行动变为线索

- **设计规则**：玩家正常去冲印婚外情照片。到达特定故事阶段后，原本普通的冲印行为额外显露相纸边缘或背面工艺信息；回家检查勒索照片后，可以将其与店内工艺比对。证据只形成推论，不自动证明来源。
- **组合**：`E-01 + E-07 + E-09 + E-12`；`O-08 + O-10`。
- **体验目标**：同一个生活地点因为玩家掌握了新问题，而获得新的意义；发现来自生活，不是任务面板凭空刷新。
- **情境**：夜莺勒索照片与跟拍委托发生自然联结。
- **最小实验**：原有冲印流程保持不变；在玩家取得勒索照片后，对一次冲印行为追加观察文本与一个可携带的线索；再次询问店主才能获得下一条信息。
- **待验证问题**：玩家是否能从相纸信息自然想到回家比对？是否需要一个简短但不过度明示的视觉提醒？

## SSN-05｜夜莺：排练的时间窗口

- **设计规则**：排练进度随 Cycle 自然变化，在有限时段开放「观看排练」；不需要判定成功，也不授予强力资源；错过则无法重新触发同一段人物时刻。
- **组合**：`E-05 + E-09 + E-10`；`O-05 + O-08`。
- **体验目标**：生活不停地经过，人与人靠近是因为愿意抽时间，而不是为了拿满奖励。
- **情境**：夜莺首演前的彩排、与尼尔的短暂安静时刻。
- **最小实验**：设置一段 2 Cycle 开放窗口；一次访问成本为正常城市行动中的时间，不给额外金钱或线索，记录玩家是否主动到场。
- **待验证问题**：如果完全没有奖励，玩家为何来？如何通过事前自然铺垫而非攻略式提示形成动机？

## SSN-06｜艾迪：出色表现的身体成本

- **设计规则**：艾迪训练或比赛准备期间，「比赛表现」与「身体负担」同时变化。某些高强度训练可以快速推进表现，但也增加负担；谨慎训练速度慢、损伤小；达到负担阈值后必须恢复或接受影响。
- **组合**：`E-03 + E-04 + E-08`；`O-04 + O-08`。
- **体验目标**：玩家希望他表现得漂亮，但不忍让他为此耗尽身体。
- **情境**：地下拳赛、假拳压力、尼尔是否帮助他继续打下去。
- **最小实验**：同样可成功的两种训练行动分别设定不同进度和负担；**不要**把「掷出更好的骰子」直接变成更大的处罚。
- **待验证问题**：选择克制是否有可感知的价值，还是更激烈的路线总是占优？

## SSN-07｜码头维修：局部事故衍生新工作

- **设计规则**：推进修理工程时，不利结果累积事故 Clock；达到阈值触发一个新问题（漏油、断电或材料污染）。新问题不一定强制暂停修理，但放任不处理会逐步损伤健康或增加后续成本。
- **组合**：`E-03 + E-04 + E-09`；`O-09 + O-04`。
- **体验目标**：一份简单工作慢慢演变为麻烦；玩家要决定先解决故障，还是冒险把原工作做完。
- **情境**：林的机械事故、码头船体修理、剧院后台设备故障。
- **最小实验**：维修 0/8，事故 0/3；事故满生成「临时止漏」0/3，持续不处理每 Cycle 增加一档损失。以规则上限限制连锁危机，避免无限派生。
- **待验证问题**：玩家是否真正需要改计划，而不是发现「先清危机」永远是唯一解？

## SSN-08｜勒索委托：发现真相后的重新选择

- **设计规则**：起始目标是保护夜莺并解决勒索，调查成果达到阶段阈值后出现证据，暗示委托人的叙述不完整；玩家可以继续原任务、隐瞒某些事实、与夜莺对质，且各自承担不同后果。
- **组合**：`E-09 + E-11 + E-12`；`O-08 + O-12`。
- **体验目标**：「我能不能完成委托」变成「我究竟要帮谁、帮到什么程度」。
- **情境**：第一章后半，夜莺的动机与旧码头利益纠葛。
- **最小实验**：在完成某条调查线后替换原定结算选项，而非只加一个解释文本；每个选择至少改变一个可观察的人物关系或后续任务。
- **待验证问题**：玩家是在权衡真实价值，还是对哪个选项是设计师预设的“善良选项”一目了然？

# 六·补充：新规则组合与第二批原创案例

> 以下均是**原创假设**，不应与真实游戏已确认的机制混在一起。每例仅表达一个主要新增关系；数值与剧情细节待纸面实验检验。

## SSN-09｜莱恩：不是静止等待的目标

- **组合**：E-17 动机 + E-13 意图 + E-05 时间 + E-14 事实；O-13、O-14；C-13。
- **设计规则**：莱恩希望摆脱越来越危险的处境；当前计划是后天夜里离开。若他得到可靠的危险情报，提前离开；若夜莺要求会面，他可能先赴约（不是无条件等待玩家）。
- **体验**：人物有自己的事情要做；调查晚了，情境会实际变化。
- **最小实验**：只给莱恩一个公开或可推断的计划、两个改变计划的条件和一个真正执行的时点；对照静态 Clock 版本。
- **风险**：若无任何可观察迹象，玩家只会觉得遭到设计师突袭。需要在酒馆闲话、打包行李等地方提前给出线索。

## SSN-10｜夜莺：她坚持完成演出

- **组合**：E-17 动机 + E-18 认知 + E-13 意图 + E-16 约定；O-13、O-15；C-13、C-19。
- **设计规则**：夜莺的稳定目标是首演成功；她有自己的排练、登台计划。玩家发现危险后可以告知、隐瞒、试图说服或另找办法，但不能凭“保护进度满”直接替她决定。她的新行动取决于她知道了什么、对尼尔有多少信任，以及危险可信程度。
- **体验**：保护别人不等于控制别人；尊重他人的选择也可能很艰难。
- **最小实验**：固定一个危险事实与三种信息透露程度，观察玩家是否理解她的决定，而非觉得她“故意不配合”。
- **风险**：如果她拒绝一切干预，会成为令人挫败的剧情锁；必须让玩家有真正能影响条件的办法。

## SSN-11｜照相馆：事实与误会分开

- **组合**：E-14 事实 + E-18 认知 + E-20 痕迹；O-15、O-19；C-14。
- **设计规则**：尼尔看出勒索照片和店内冲印工艺存在共性（事实只证明“相似”）；尼尔形成待验证推论；店主可能误以为尼尔在敲诈或替警方查案，从而改变交涉态度。发现相似不能自动把「店主参与勒索」变成世界事实。
- **体验**：侦探调查中的推论与证据分离；每个人的信息不完整。
- **最小实验**：把“客观相似”“尼尔的怀疑”“店主对尼尔来意的判断”作为三种独立状态，检测对话分支是否真的不同。
- **风险**：错误信念须可解释和可纠正，不宜靠隐形变量任意惩罚玩家。

## SSN-12｜酒馆：为赖账者作担保

- **组合**：E-16 约定 + E-15 后果承担者 + E-19 控制权 + E-20 记忆；O-16、O-17、O-18；C-15、C-20。
- **设计规则**：赖账客人说“明天还钱”。尼尔可以替他垫付、做担保、要求留下抵押物、拒绝介入。若尼尔担保，调酒师暂不追究，明日该客人的行为（真还 / 逃走）决定尼尔是否代偿。酒馆之后记得这次处理方式。
- **体验**：信任会把自己置于风险中；一个普通善举有跨日重量。
- **最小实验**：一个债务、一个到期日、三种担保方式，严格限制后续连锁情节。
- **风险**：不可把所有人的善意归结成稳赚的声望点；违约后必须提供可理解的行动机会。

## SSN-13｜艾迪：跨日赴约

- **组合**：E-16 约定 + E-13 意图 + E-05 时间 + E-20 记忆；O-16；C-15。
- **设计规则**：尼尔今天同意明天去帮艾迪训练。艾迪据此提前安排了拳馆。如果明天尼尔去了，可能没有显著物质奖励，但关系加深；如未赴约，艾迪完成自己的安排，也记得这次落空。尼尔可提前改约，代价小于失约。
- **体验**：关系存在于时间中，而不是只存在于对话树里。
- **风险**：不应为了制造罪恶感而无限制造密集约会；给玩家明确的时间提示与适度的补救路径。

## SSN-14｜尾随：遗留的痕迹晚些被发现

- **组合**：E-20 痕迹 + E-14 场景事实 + E-18 认知 + E-13 意图；O-18、O-15、O-13；C-16、C-20。
- **设计规则**：跟踪成功也可能在现场留下一个可发现的痕迹（被看见的外套、问路记录等）；当目标或其同伴后来接触此地，才获得“有人跟踪”的信息并决定反查。不是行动瞬间自动增长一个无所不知的警觉 Clock。
- **体验**：世界留下历史；危险可以延迟到来，更符合侦探叙事。
- **最小实验**：只用一个现场痕迹和一个后来路过的观察者；与即时「警觉 +1」版本比较。
- **风险**：玩家应能预估自己可能留下线索；过分隐蔽的随机追责会失去因果感。

## SSN-15｜勒索照片：证据的持有人与来源

- **组合**：E-19 持有/控制权 + E-20 事件记录 + E-18 认知 + E-09 Gate；O-17、O-18；C-17。
- **设计规则**：尼尔拥有的是照片原件还是复制品？是谁交给他的？交给警方时能否说明取得过程？不同持有和交接历史，决定行动是否开放、对方是否信服；仅有“照片线索 = 1”无法表达这些区别。
- **体验**：证据是物，而不是抽象进度；保管、托付、泄露会改变信任。
- **最小实验**：只追踪一张关键照片的原件/复制、持有人、两个交接事件，避免搭建完整司法证据模拟器。
- **风险**：过度手续化会让侦探故事变成背包管理；仅在需要改变决策时追踪来源。

## SSN-16｜首演夜：保护谁，就改变谁承担代价

- **组合**：E-15 后果承担者 + E-17 人物动机 + E-16 约定 + E-12 结算；O-17；C-18。
- **设计规则**：当后台出现危险，尼尔可以优先疏散观众、帮助夜莺撤离或阻断事故源头。三种处理占用不同时间，改变真正承受风险的人与损失类型。**不是让玩家直接选择“谁受伤”，而是通过可信的行动后果来改变风险分布。**
- **体验**：承担责任、保护的局限性；有人得救不等于毫无代价。
- **最小实验**：只设一次事故、一项有限时间资源和两类可避免/不可避免损失。
- **风险**：若结算总会突然伤到随机角色，就不是有意义的权衡，而是任意惩罚。

## 对新机制的研究与验收

| 验证焦点 | 建议对照实验 | 不通过的表现 |
|---|---|---|
| **自主性是否可感知** | 同一剧情：定时事件 vs 有迹象、可干预的 Intent | 玩家无法预测人物，感觉剧情强行推动 |
| **知识差异是否有意义** | 全知警觉 Clock vs 痕迹被发现后才变化 | 只是增加不透明判断步骤，没有新选择 |
| **承诺是否建立人际关系** | 即时奖励任务 vs 延迟兑现、允许改约 | 玩家只是为了声望按时刷任务 |
| **控制权是否影响行为** | 证据数值 +1 vs 原件/复制与交付条件 | 物品细节只增加微管理，不影响决策 |
| **后果归属是否合乎因果** | 固定失败扣健康 vs 不同干预改变受害者和代价 | 结果无法从前面的选择推导 |
| **是否保持简单** | 用 1—2 个关键人物与 1 个场景测试 | 需要对全城做复杂全知模拟才能运行 |

### 最小推进次序

1. **先做 E-14 局势事实 + E-18 角色认知**：调查线的事实和信念真正分开。
2. **再做 E-17 动机 + E-13 意图**：只让少数关键人物具备可理解的自主计划。
3. **加入 E-16 约定 + E-15 承担者**：跨日人际责任与代价能够落到具体对象。
4. **最后按需要加入 E-20 痕迹 + E-19 控制权**：专门服务于侦探证据、流言与托付，不把世界所有物件都纳入模拟。

> **用法约束**：新增基础元素并不要求它必须显示为独立 UI，也不要求每个 NPC 都被全量模拟。只有当某个事实、认知、意图或物品控制状态**改变可执行行动、成本、风险、结算或他人的自主反应**时，才值得持久保存。

# 七、如何评价与扩展

## 1. 案例评价的四条轴线

| 维度 | 要问的问题 | 不佳征兆 |
|---|---|---|
| 表现力 | 去掉文字解释，规则是否仍传达某种事物的性质？ | 换成任何题材都没区别 |
| 决策性 | 玩家是否因为规则关系而调整行动？ | 永远是把最大骰子投向最大收益 |
| 情感性 | 体验是否让人对人物、地点或后果产生在意？ | 只记得数值，不记得发生了什么 |
| 可持续性 | 了解规则后重复游玩，是否仍然有意义？ | 只靠第一次惊讶；之后可机械刷取 |

并非每张卡都需要在四条轴线上同时很强。**照顾 Mina** 的核心可能是情感表现，不是策略难度；**Hidden Wreck** 更偏向时间与策略。记录它的真正优势，而不是统一用「难度」评分。

## 2. 研究的推荐顺序

1. **先描述生活关系**：什么事情随时间变化？什么行为真的会损坏另一件事？什么人会因为熟悉而改变对待方式？
2. **再抽取规则**：用本文件的 `E` 元素和 `O` 运算符写出最小状态变化，不急着添加新的专用系统。
3. **再问玩家感受**：这种规则让人更谨慎、温暖、焦虑、疲惫、珍惜机会，还是根本无感？
4. **最后验证策略**：测试高骰、低骰、连续失败、极度缺钱、已有大量资源时，是否出现违反设想的占优策略。
5. **记录结论和修改**：保留历史版与被否定的假设，避免同一个实验反复出现。

## 3. 版本与增量规则

- 案例 ID 永久保留；撤销案例时用 `已否定` 标识，不回收编号。
- 事实来源、体验推断与原创变体使用不同的段落；查证后只更新事实与状态，不直接覆盖先前的设计观察。
- 一个案例可以连接多个组合（C），一种组合可以有多个来自不同游戏的案例。
- 新的机制组合先作为 `C-XX` 登记，再补案例；出现新的基础元素时才增加 `E-XX` 或 `O-XX`。
- 数值需要来源；没有可靠数值时，只描述方向，不能把模拟参数写成原游戏事实。

# 八、新增案例模板与证据资料

# 九、情境因果模式：从进度工作到可变化的处境（0.3 新增）

> **研究定位**：这不是替代此前的 Encounter Patterns，而是补上一层关于“事物如何实际相互作用”的可复用规则。CS1/CS2 案例仍然属于游戏原生规则记录；本节 `SCP-*` 全部为 SSNoir 原创、**尚待实验**的情境模拟假设。

## 1. 定义与基本对象

**情境因果模式（Situated Causal Pattern）**：一个局部世界中的人物、物件、地点与过程，按照公开或可推断的规则相互影响。玩家不只是填满目标，也可以改变行动主体、目标、条件或事物之间的关系，使已有规则产生新的局势。

一个足够小的情境可以用下述六项描述：

```text
Objects   = 人物 / 物品 / 地点 / 持续中的过程
Relations = 谁持有、在哪里、谁追谁、哪个设施连接哪里、谁能操作什么
Facts     = 当前成立的条件，如“后门堵塞”“仓库有电”
Intent    = 谁想实现什么、当前准备向哪个对象采取什么行动
Rules     = 在什么事实与条件下，行动如何改变对象、关系、事实与意图
Time      = 哪些过程自行演进，哪些行动将在下一时点尝试执行
```

把 `行动者（actor）— 动作（verb）— 对象（target）— 条件（guard）— 后果（effects on receivers）` 作为规则描述的公共结构。意图与事实不要求总是玩家可见，但导致后果的**关键线索必须能够被察觉、发现或合理推断**。

重要区别：**动机相对稳定，意图与目标可以改变。** 警卫依然想抓住尼尔，但后巷被封后，他会改走街面；夜莺依然希望演出，但停电后可能改变演出形式。

Scheme 适合把规则表示成条件、谓词、事件和状态变换；**不能仅因为使用 Scheme 就认为存在涌现性**。同一套规则必须在不同初始化状态下确实导出不同过程，否则只是在脚本里隐藏了固定分支。

## 2. 组合所需的几种新的关系运算

| 暂记运算 | 形式 | 描述 |
|---|---|---|
| `RETARGET` | 改变 `Intent.target` | 原目标不可达、价值变化后，人物转向另一对象 |
| `REROUTE` | 重算可达路径 | 地点和通路改变，行动的路线及相遇事件随之改变 |
| `REASSIGN` | 改变动作的承担者 | 某人缺席、受伤或能力变化后，由别人补位或工作停摆 |
| `CONTEND` | 多意图竞争独占对象 | 对单件证据、机器、出口、职位争夺使用权 |
| `PROPAGATE` | 沿事物关系传递影响 | 负载、火势、拥堵、流言、危险由一个对象转移到下一个 |
| `SUBSTITUTE` | 实现同一目的的替代手段 | 保持动机，改变执行方式、行动成本或风险 |
| `IDLE-DRIFT` | 无人操作时持续变化 | 设备磨损、队列积压、风险扩散、人员自行离开 |
| `BELIEF-UPDATE` | 事件/痕迹改变认知 | 不同人据各自所知产生不同意图与行动 |

这些是概念运算，**不是游戏现有 Scheme API 的函数名**。如果进入实现阶段，应对照当前脚本系统已有的事件和谓词能力定义统一接口。

## 3. 第一批微型模式索引（原创假设）

| ID | 名称 | 最小因果规则 | 首要体验 | 可移植情景 |
|---|---|---|---|---|
| SCP-01 | 阻断与绕行 | 人物有目的地与可行路径；路径失效后选其他路线 | 不能完全控制对手，环境可利用 | 追逐、货运、疏散 |
| SCP-02 | 麻烦的转移 | 一个地方不再允许某活动，执行者前往另一个可达地方 | 局部解决不等于消除问题 | 清场、驱赶、非法生意 |
| SCP-03 | 争夺同一对象 | 两个行动同时需要同一独占对象；持有权/排队改变结果 | 抢先、协商、失去机会 | 证据、机器、关键人物 |
| SCP-04 | 生产接力 | 多工序有实际输入/输出；人员缺席产生瓶颈和积压 | 协作、脆弱的日常秩序 | 卸货、剧院后台、印刷 |
| SCP-05 | 负载转移 | 一处损坏/关闭导致连着的设施负担增加 | 修一处反使另一处危险 | 电路、设备、城市交通 |
| SCP-06 | 自主使用与磨损 | NPC 因需要而使用设备；使用同时降低其状态 | 设施不是静止等待玩家修理 | 旧城区水泵、酒馆器具 |
| SCP-07 | 避险与聚集 | 人物自主逃向安全点；出口容量受限导致积压 | 恐慌、拥堵、众人的自主性 | 剧院事故、骚乱、逃亡 |
| SCP-08 | 保护与反抗 | 受保护者有自己的目标；阻止其路线后尝试其他行动 | 保护不等于控制，理解他人 | 首演、拳赛、危险调查 |
| SCP-09 | 诱饵与改道 | 目标对象或其吸引力变化；追踪者据认知重新选目标 | 计谋、误导、利用对手动机 | 警卫、媒体、调查 |
| SCP-10 | 隐患与迟发 | 行动留下潜在事实；之后的使用、天气或目击才触发后果 | 延迟风险、过去仍在起作用 | 舞台设备、破坏、修理 |
| SCP-11 | 连锁误判 | 角色凭有限信念行动；行动又改变别人的信念 | 误解滚雪球，误会变成现实 | 老街、警察、舆论 |
| SCP-12 | 缺席与补位 | 原承担者离场；他人可接替但效率或危险不同 | 一个人的重要性、被迫承担 | 码头班次、剧院、照料 |

## 4. 重点模式：规则、短过程和玩家可做什么

### SCP-01 阻断与绕行

- **初始情景**：警卫要从仓库追到尼尔，默认从后巷走；街面也可通行，但有居民。
- **因果规则**：当警卫仍有追捕意图而当前路径被阻断，他在自己已知的可达通路中选择替代路线；经过街面时触发居民目击。
- **短过程**：尼尔锁住后巷门 → 警卫改变路线 → 追捕减慢，但街面居民被卷入，且尼尔的藏身地更容易暴露。
- **玩家选择**：阻门争取时间、制造更长的绕路、保留退路、当面周旋。
- **体验与复用**：阻挡不是“敌方倒计时 -2”，而是**重新分配风险的空间动作**；换成码头堵塞、疏散绕道，同一套规则仍成立。
- **失效风险**：若每次封门都固定出现“居民受害”的剧情，则是假动态。居民是否受影响应取决于实际路线及居民是否在场。

### SCP-02 麻烦的转移

- **初始情景**：老街的一群临时摊贩准备做生意；巡警的意图是清空特定街道。
- **因果规则**：摊贩的动机是继续谋生；某街道不可用时，他们评估邻近地点的租金、可达性与盘查压力，并尝试迁移。
- **短过程**：玩家帮助巡警清场 → 摊贩迁移至酒馆门口 → 酒馆生意可能增加，也可能发生争吵 → 调酒师新的工作条件发生变化。
- **玩家选择**：只清场、提供其他落脚点、说服巡警延缓、帮助酒馆处理后续问题。
- **体验与复用**：**压力不会凭空消失，而是沿人物的生存行为转移**；可用于流民、黑市、地下拳赛、仓库货物流转。
- **失效风险**：避免全城无限迁移和昂贵模拟。只需两个地点、一类人员和一条可见的迁移规则。

### SCP-03 争夺同一对象

- **初始情景**：照相馆只有一份尚未销毁的底片；经理要取走它，尼尔也想拿到它。
- **因果规则**：底片同一时刻只能由一个人持有。经理和尼尔的行动都以“底片在店内、可接触”为前提。一旦被带走，行动对象改为**持有人**，追索方法随之改变。
- **短过程**：经理先取到底片 → 尼尔原本“向店主索取底片”的动作不再可用 → 可转向跟踪经理、寻找复制件或让店主回忆细节。
- **玩家选择**：抢先、交换、复制、监视持有人。
- **体验与复用**：争夺是对同一个世界对象的控制，不只是双方 Clock 比快。可用于钥匙、货船装卸权、唯一医生的空档。
- **失效风险**：必须明确物件是否可复制，不能把“唯一性”人为强加给本可随意复制的信息。

### SCP-04 生产接力

- **初始情景**：码头货物必须经 `船舱 → 起重机 → 仓库`。三段工序各自有人员，货物真实存在于某一段。
- **因果规则**：上一段送到才允许下一段处理；队员可因疲劳、报酬、危险决定停工或离开；未处理的货物会在瓶颈前积压。
- **短过程**：起重机故障 → 船舱货物积压 → 船长准备提早离港 → 仓库空闲人员可以去搬运，也可以修起重机。
- **玩家选择**：优先修理瓶颈、花钱请替班、冒险手工搬运、让部分货物暂留船上。
- **体验与复用**：一个长工程因真实协作关系而变得**精密、具体、脆弱**；同样的生产线可替换为舞台筹备、冲印照片、厨房备餐。
- **失效风险**：别让每一个货箱成为单独实体；用分段物料总量与角色占用即可。

### SCP-05 负载转移

- **初始情景**：剧院照明由主线路和备用线路共同承担。主线路已有隐患。
- **因果规则**：切断主线路会把正在使用的照明负载分配到备用线路；备用线路超过容量则提高过热危险，或者自动熄灯。
- **短过程**：尼尔发现主线路危险而切断它 → 吊灯不再通电，但备用线路过载 → 后台照明开始闪烁 → 工人改变工作方式或停止操作。
- **玩家选择**：先减负载、先加固备用线、直接断电、暂停演出。
- **体验与复用**：**问题不是被解决或没解决，而是转移到了另一个地方**。适用于机器、电路、仓库供货和城市供水。
- **失效风险**：需要直观提示“哪里在承载负担”，否则玩家只会感觉任意事故接连发生。

### SCP-06 自主使用与磨损

- **初始情景**：酒馆的冰柜磨损严重；调酒师仍要营业，自动选择使用它。
- **因果规则**：每日营业提高收入并增加冰柜磨损；修理可以降低磨损，但通常要停机；磨损到阈值则失败概率大增。
- **短过程**：尼尔白天修了一部分 → 晚上继续营业使磨损回升 → 调酒师不得不权衡是否临时停业。
- **玩家选择**：深夜修理、劝调酒师停业、买零件、承担风险继续卖酒。
- **体验与复用**：这不是单纯“每晚进度 -1”，因为退化来源于**一个人仍在做他需要做的事**。可迁移到公交、电网、机器部署。
- **失效风险**：若修理收益总是低于日常损耗，则只是无意义惩罚；需要允许玩家改变使用方式。

### SCP-07 避险与聚集

- **初始情景**：演出事故，观众希望离开危险区域；前厅、侧门与后台三条路线容量不同。
- **因果规则**：每个群体基于已感知的危险、已知通路和拥挤程度选择出口；拥挤反过来影响移动效率和危险承担者。
- **短过程**：尼尔打开侧门 → 一部分观众改道 → 前厅压力下降；但后台工人与观众共享通道，可能妨碍抢修。
- **玩家选择**：打开通路、指挥人群、阻断危险源、优先给一群人留通道。
- **体验与复用**：能从同样的事实自然产生不同分布的损失，适用于港口骚乱、暴雨避险、车站事故。
- **失效风险**：不需要逐一模拟数百观众；按 2—3 个群体与通道容量建模即可。

### SCP-08 保护与反抗

- **初始情景**：夜莺仍想登台。尼尔发现舞台不安全，劝她离开或锁住后台入口。
- **因果规则**：夜莺的高层动机保持；若原路径被阻断，她可能寻找另一入口、请求经理帮忙，或在知道可靠事实后重新评估是否继续。
- **短过程**：尼尔封闭侧台 → 夜莺尝试经前台进入 → 新路线经过危险的升降装置；若尼尔提前展示故障证据，她也许愿意更改演出安排。
- **玩家选择**：命令、阻拦、提供证据、修复隐患、尊重她的决定。
- **体验与复用**：人物**不是玩家操纵的棋子**；保护行为会与他人的愿望发生真实冲突。可用于艾迪执意参赛、莱恩试图离开。
- **失效风险**：不可把 NPC 写成总会固执作对；替代行为应由动机、事实、认知和可达条件决定。

### SCP-09 诱饵与改道

- **初始情景**：警卫的意图是寻找一个掌握文件的人；他相信拿着红色公文包的人是目标。
- **因果规则**：当某个对象符合警卫已有的辨认条件，其追踪目标可改变；一旦获得反证，又能重新识别。
- **短过程**：尼尔让空公文包被发现 → 警卫改去跟踪拿包的人 → 目标获得短暂逃脱窗口；警卫检查后发现被骗，可能回头追查尼尔。
- **玩家选择**：移走物件、制造假目标、避免误伤无关者、趁时间窗取证。
- **体验与复用**：戏剧性来自**使用别人的认知规则**而不是固定“诱敌 Clock +2”。可用于黑帮、媒体、侦探误导。
- **失效风险**：诱饵必须有可解释的信号，不应只凭玩家点击就自动吸引所有人。

### SCP-10 隐患与迟发

- **初始情景**：某根吊索已经被磨损，但还没有断；当前舞台没有重物悬吊。
- **因果规则**：危险不是一个自动倒数的剧情节点；当“受损 + 负载过大 + 设备运作”三个事实同时成立时，才出现事故风险。
- **短过程**：尼尔修理吊索但留下一处隐患 → 排练平安 → 首演换了更重的布景 → 吊索在新的条件下可能断裂。
- **玩家选择**：检查原材料、限制载荷、更换绳索、调整演出方式。
- **体验与复用**：**潜在原因等待合适条件才兑现**，很适合侦探故事中的现场重建。可用于仓库火灾、机械故障、药品保存。
- **失效风险**：隐藏条件必须有发现途径；不要把玩家无法预知的暗雷当成复杂模拟。

### SCP-11 连锁误判

- **初始情景**：警察以为老街发生了一次蓄意破坏；事实上只是电网故障。
- **因果规则**：警察根据自己的信念加强巡逻；居民看到巡逻以为将发生强制清场；部分居民主动搬运物资或抗议，反过来强化警察的误判。
- **短过程**：一次错误解释 → 两方都采取看似合理的防御行动 → 局势不断紧张。
- **玩家选择**：提供可信证据、改变消息传播路径、与某一方沟通、坐视其发展。
- **体验与复用**：没有单个角色必须“邪恶”，仍能形成危险冲突；可用于误会、舆论、黑色电影中的权力关系。
- **失效风险**：避免让角色自动相信玩家的一句话；修正信念需要可信来源与信息可达性。

### SCP-12 缺席与补位

- **初始情景**：首演需要一名熟悉吊挂系统的舞台工。他原定值班，但在前一天受伤。
- **因果规则**：岗位仍需有人操作；其他人可以代班，但技能不足时操作更慢、风险更高；没有人代班则设备不启用。
- **短过程**：工人缺席 → 经理让助手代班 → 排练效率下降 → 若尼尔此前掌握机器操作知识，可辅助处理或劝经理取消高危效果。
- **玩家选择**：找替班、培训、简化演出、强行按原方案进行。
- **体验与复用**：**人物具有不可忽略的实际位置与能力**；不仅影响关系文本，也影响事情怎样被完成。
- **失效风险**：不应把“换人后减少一个骰子”包装成人物系统；替班应真实改变哪些操作可执行、失败时谁受伤。

## 5. 把小模式组合成更丰富的动态场景

### A. 码头大船靠岸：一个“会自己运行”的大型工程

组合：`SCP-04 生产接力 + SCP-05 负载转移 + SCP-06 自主使用与磨损 + SCP-12 缺席与补位`。

1. 船舱、起重机、仓库形成三段货物流；装卸完成才有收入。
2. 船长预计黄昏起航，工人根据疲劳和报酬决定是否继续；这是他们的意图，不是玩家 Clock。
3. 起重机停机时，工人可改人工搬运，但效率低且伤势风险集中到搬运工。
4. 玩家可以修机器、安排替班、付工资、减轻载荷、与船长交涉。
5. 因为这些选择作用在真实的关系上，同一场景能出现多种过程：平稳装卸、半途停工、设备过载、有人受伤、部分货物留港。

**表达的事物性质**：一个大型工程不是很多独立的进度条，而是很多互相依赖的人与设备，任何环节都可能成为瓶颈。比“24 格建设 Clock”新增的不是单纯复杂度，而是**协作网络可以重新组织**。

### B. 首演夜：危险沿着人与设施的关系流动

组合：`SCP-05 负载转移 + SCP-07 避险与聚集 + SCP-08 保护与反抗 + SCP-10 隐患与迟发`。

1. 夜莺有登台意图，经理有维持演出意图，观众想观看，工人想安全完成工作。
2. 电路隐患与设备负载是局势事实；是否会出事，取决于设备是否启用、是否超载。
3. 尼尔断电保护舞台，却导致备用照明吃紧；观众可能以为发生火灾开始向出口聚集。
4. 尼尔可以修电路、引导观众、关闭某个机械效果或向夜莺提供足够证据改变她的计划。
5. 谁受伤、演出是否继续，不需要由一个结局选项直接指定，而是由人实际所在位置、已采取的行动及风险传播决定。

**表达的事物性质**：危险的处境不是一个红色 Clock，而是你想保全的多个东西彼此依赖、又可能彼此妨碍。

### C. 老街清场：局部治理引发的自行迁移

组合：`SCP-02 麻烦的转移 + SCP-09 诱饵与改道 + SCP-11 连锁误判`。

1. 警方追求表面秩序，摊贩追求生存，商户希望不被打扰。
2. 一个路口被清空，摊贩前往其他可用地点；此处顾客、噪音和冲突也跟着变化。
3. 如果警察相信“有人组织抵抗”，他们改变巡逻对象；居民观察到警察聚集又进一步防备。
4. 尼尔可通过提供信息、安排替代场所、帮助特定角色或制造误导介入局势。

**表达的事物性质**：城市像有自身反应的社会网络。改变一个地点并不意味着把整个问题的进度条清零。

## 6. 三种必须严格区分的设计结果

1. **固定脚本**：玩家封门 → 不论现场如何，总触发“警察去了街面”。这只是分支剧情。
2. **有条件的情境规则**：玩家封门 → 警察只有在还要追人、知道街面路线且街面可通行时才转道。结果取决于变化的事实。
3. **局部可涌现结构**：警察改走街面 → 正好遇上迁移的摊贩 → 摊贩因警察出现改变方向 → 酒馆门口人群压力改变。这个结果没有被作者写成唯一的场景流程，而是由几个独立规则相接产生。

并不要求所有情境达到第三层。有些关键故事应保留精心编写的场面。真正的目标是让**合适的事物拥有合理的变化余地**。

## 7. 最小实验方法

每个模式最好只投入 `2—4 个主体/对象 + 2—4 条局势事实 + 1—2 个 NPC 意图 + 2—3 种玩家干预 + 2—4 个时间片`。

对每个小实验检查：

- **可理解的因果**：去掉解释文本，玩家能否从提示与世界变化理解为什么发生？
- **反事实成立**：只改变一个初始事实（例如街面已堵、工人未缺席），事态是否合理不同？
- **行动者独立性**：玩家什么都不做，NPC 是否仍会按其意图行动；受阻时是否按规则重选？
- **决策改变**：玩家是否因为对象、关系或条件变化而改变操作，不只是把骰子重复填进度？
- **情景表达**：是否真的感受到“拥堵”“设备磨损”“人不听你的”“危机转移”，而不只记得计数器？
- **可控复杂度**：复制规则到第二个场景时能否复用；若没有独立表达收益，就删掉状态变量。

**建议先测四个最小件**：`SCP-01 阻断与绕行`（可见性与目标切换）、`SCP-04 生产接力`（协作和瓶颈）、`SCP-06 自主使用与磨损`（日常主动行为）、`SCP-08 保护与反抗`（独立人物意志）。通过后再叠加为大场景。

> **方向提醒**：最值得做的，不是“让每个 NPC 都有 AI”，而是让一两个真正重要的人拥有能改变情境的意图，让物件和场所的实际状态决定行动，从而用少数可组合的规则模拟出具体、危险、可理解的处境。
