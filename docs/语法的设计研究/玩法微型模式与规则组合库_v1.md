# SSNoir · 玩法微型模式与规则组合库

> **核心问题：少量通用规则怎样组合，才能让玩家通过行动亲身感受到一种事物的性质？** 例如精密工程的艰难、有限救济的善意、潜行调查的警觉，或人与人逐渐熟悉的过程。
>
> **本文件是持续扩充的研究底稿，不是游戏当前已实装功能表。** 上半部是可复用的规则语言；下半部按来源保存真实案例与原创假设。新研究可以补充案例、修正实证、提出新的组合，而不必改写既有条目的身份。

- **实例来源代码**：`CS1` = 《Citizen Sleeper》（2022）；`CS2` = 《Citizen Sleeper 2: Starward Vector》（2025）；`SSN` = SSNoir 创作中的候选设计。
- **证据状态**：`已核对` = 有可追查的游戏节点资料或攻略；`待核对` = 来自游玩观察、讨论或有来源冲突，待逐项复现；`原创假设` = 尚非任何游戏的实装事实。
- **观察与解释分开**：每张案例中的「原始规则」只描述行动、结果与状态转换；「体验解释」是我们的设计推断，不冒充开发者意图。
- **扩展方式**：增加一个实例，复制文末案例模板，分配不重复的 ID，写明引用的基础规则编号与证据链接。不要凭主题相似就将两个不同的机制混为一谈。

# 一、基础规则与元素

## 1. 一条微型规则的最小结构

无需把「维修」「赌博」「安慰」「调查」分别实现成全新玩法。可以先表示为：

`行动（消耗 / 条件） → 结果判定 → 状态变化 → 阈值事件 → 新的可选行动`

例：`打听（1 颗骰子） → 失败 → 警觉 +1 → 警觉达到 4 → 店主拒绝接待 → 解锁别的接触路线`

这里涉及的是**行动如何改变局势**，不是光用 Clock 给剧情加一个进度条。规则应产生玩家能观察、预测或从后果中学习的因果关系。

## 2. 基础元素（Elements）

| ID | 元素 | 可变化属性 | 描述与作用 |
|---|---|---|---|
| E-01 | 行动（Action） | 重复 / 一次性 / 限次 / 消耗物品 / 需条件 | 玩家实际选择和付费的最小单位 |
| E-02 | 判定结果（Outcome） | 成功、中立、失败；也可不随机 | 同一行动在不同结果下改变不同状态 |
| E-03 | 进度 Clock（Progress） | 长度、起点、增减量、能否倒退 | 工作、调查、建设、熟练等目标进展 |
| E-04 | 压力 Clock（Pressure） | 来源、增长、下降、阈值 | 警觉、事故、危险、嫌疑、敌意 |
| E-05 | 时间 Clock（Time） | 每 Cycle 变化、截止、窗口、等待 | 事件随日常时间自动变化，而不依赖骰运 |
| E-06 | 容量 / 次数（Capacity） | 总次数、每日次数、补充方式、耗尽后关闭 | 救济额度、库存、最后几次机会 |
| E-07 | 可消费资源（Resource） | 金钱、食物、物资、线索、道具 | 允许一种活动的结果支持另一种活动 |
| E-08 | 行动能力（Capability） | 骰子数量、骰面、技能、疲劳、伤势 | 玩家或队友当下能够做到什么 |
| E-09 | 门槛 / 锁定（Gate） | 前置条件、技能要求、阈值解锁、关闭 | 同一个地点 / 人物在不同局势下允许不同交互 |
| E-10 | 关系状态（Relationship） | 熟悉、信任、惧怕、债务、照料 | 行动长期改变人与人、人与地点的关系 |
| E-11 | 目标连接（Objective Topology） | AND、OR、先后、主次、可选 | 多个 Clock 如何组成一项工作或故事 |
| E-12 | 结算 / 后果（Consequence） | 奖励、损伤、机会损失、分支、世界变化 | 让已发生的事留在世界里，而非恢复原状 |

**设计提醒：** `进度`、`压力`、`时间`都可以显示成 Clock，但它们的**更新原因**不同；不要只因为视觉相同就视为同一种设计。

## 3. 基础运算符（Operators）

| ID | 运算符 | 规则形式 | 可表达的体验 |
|---|---|---|---|
| O-01 | 增加（ADD） | `P += n` | 累积劳动、收集、建立关系 |
| O-02 | 减少（SUB） | `P -= n` | 倒退、损耗、努力受挫 |
| O-03 | 保底（FLOOR） | `任意结果 P += 至少 1` | 尽力就有意义、善意不以表现论资格 |
| O-04 | 同时变化（COUPLE） | `P += n` 且 `Risk += m` | 进步带来代价，收益与危险捆绑 |
| O-05 | 自然变化（TICK） | `每 Cycle P +=/-= n` | 时间、成长、腐败、流逝 |
| O-06 | 消耗容量（SPEND） | `Uses -= 1`，归零后关闭 | 机会有限、资源匮乏 |
| O-07 | 结果转化（CONVERT） | `金钱 → 物资 → 进度` | 经济和行动系统相互支撑 |
| O-08 | 门槛切换（SWITCH） | `X 达阈值 → 动作 A 关闭、B 打开` | 事故升级、变得熟悉、失去资格 |
| O-09 | 产生新问题（SPAWN） | `Pressure 满 → 新危机 C` | 善后、连锁事件、临场改计划 |
| O-10 | 路径分叉（BRANCH） | `A 或 B → 同一目标 / 不同后果` | 多策略、身份价值选择 |
| O-11 | 周期重置（RESET） | `每 Cycle 次数重置 / 压力部分恢复` | 日常节律、等待明天、季节性机会 |
| O-12 | 结果反转（REVALUE） | `发现信息 → 原目标的意义改变` | 背叛、抉择、主动放弃原定成功 |

这些不是引擎 API，只是一组人可以阅读和组合的规则词汇。一个案例通常只需要两到四个运算符。

## 4. 判断“组合”而非“内容”的标准

- **不是微型组合**：把酒馆改名为医院、把收集 6 个改成收集 8 个，而玩家思考完全不变。
- **是微型组合**：同样「投入骰子推进 8 格」，失败现在会产生新的故障；故障达到阈值后要花钱买零件，玩家不得不重新考虑风险和资金。
- **判断题**：把人物和场景名称全部去掉后，是否仍能描述这套行动—反馈—变化关系？如果可以，它便有机会成为跨场景复用的模式。

# 二、常见组合语法

| 组合代号 | 规则公式（抽象） | 玩家感受 | 典型语境 | 案例 |
|---|---|---|---|---|
| C-01 艰难工程 | `长进度 + 不利结果损伤能力` | 漫长、艰苦、身体代价 | 大型船舶、城市工程 | CS1-01 |
| C-02 危险工序 | `进度 + 事故压力 + 阈值后换方法` | 越做越危险、不可硬来 | 维修、手术、侦查 | CS1-02 |
| C-03 有保障的帮助 | `成功多收获 / 失败仍有保底` | 温暖、可靠、劳动不白费 | 照护、食堂、邻居帮助 | CS1-03、CS1-04、CS2-01 |
| C-04 有限机会 | `保底 + 可用次数减少` | 善意受物资限制、珍惜机会 | 救济、临时接济 | SSN-02、CS2-01-OBS |
| C-05 熟人进程 | `重复日常 + 关系进度 + 新行动` | 融入、熟悉、关系变深 | 酒馆、店铺、人物线 | CS1-05、SSN-01 |
| C-06 危险并行 | `目标进度 + 警觉/事故压力` | 克制、见好就收 | 潜行、偷拍、脆弱货物 | CS1-06、CS2-04、SSN-03 |
| C-07 对手赛跑 | `己方 Clock + 对手时间/进度 Clock` | 抢先、竞争、时间紧迫 | 竞争搜寻、新闻 | CS2-02 |
| C-08 危机衍生 | `压力达阈值 → 新 Clock + 持续惩罚` | 原计划被打断、陷入困境 | 事故处理、暴露 | CS2-03、SSN-07 |
| C-09 成本平静 | `无局部倒计时 + 每轮仍耗生活资源` | 安静、可以慢做但不免费 | 帮工、清理、修复 | CS2-05 |
| C-10 发现后改变目标 | `先推进目标 + 新信息 + 可主动放弃` | 道德抉择、关系比报酬重要 | 侦探委托、告密 | CS2-06、SSN-08 |
| C-11 损坏能力的循环 | `行动/推进 → Stress → 可用能力下降` | 透支、恶性循环、极限 | 长时间交锋 | CS2-07 |
| C-12 日常附带调查 | `相同生活行动 + 条件性额外信息` | 城市互相关联、自然发现 | 送货、冲印、打工 | SSN-04 |

> **注意**：组合代号可复用，而案例不应合并。例如 C-03 既可以解释「照顾孩子」，也能解释「供餐工作」，但两者的人物情感和行动结果并不完全相同。

# 四、CS1：已存在的组合

## CS1-01｜Sidereal Horizon：沉重的长期建设

- **来源 / 状态**：CS1 · 已核对。
- **原始规则**：殖民船建设共享一条 **24 格**进度；相关工作成功推进 **+2**，中立推进 **+1**，失败不推进，但仍得工资且 **Condition -1**。此前的技术资格/质量控制阶段另有因错误而失去资格、需要重新取得进场资格的机制。
- **规则组合**：`E-01 + E-02 + E-03 + E-08`；`O-01 + 不利结果损伤能力`。
- **体验解释**：日复一日的精密劳动；失败并非让造好的船神奇消失，而是身体在消耗。工资稳定并不能抵消生活中的成本。
- **适用情境**：大型工程、艰难的谋生方式、需要漫长坚持的共同目标。
- **重要区分**：**24 格建设本身失败并不直接扣建设进度**；不能将前置质量控制 Clock 的倒退混写为 24 格本体的规则。
- **证据**：[Sidereal Hull](https://citizensleeper.fandom.com/wiki/Sidereal_Hull) · [Sidereal Bridge](https://citizensleeper.fandom.com/wiki/Sidereal_Bridge) · [Unit Assembly](https://citizensleeper.fandom.com/wiki/Unit_Assembly)。

## CS1-02｜Ambergris：事故迫使改变修法

- **来源 / 状态**：CS1 · 已核对（概括性结构）。
- **原始规则**：修理船体的工作伴随船况恶化；有一次性高风险的无人机重新接线，也有可重复但危险的船体维修。玩家不能把脆弱的旧船当成普通的安全工作台。
- **规则组合**：`E-03 + E-04 + E-09`；`O-04 + O-08`。
- **体验解释**：本来是在帮助，但每次出手都可能让旧东西更加脆弱。「有技能」不等于「可以一直使用相同办法」。
- **适用情境**：老旧设备、医疗救治、事故现场、失控中的调查。
- **证据**：[The Ambergris](https://citizensleeper.telepedia.net/wiki/The_Ambergris)。
- **核验备注**：具体事故 Clock 的名称、阈值和后继行动，后续可用游戏录像单独补齐；此处不填写未经这次核对的数值。

## CS1-03｜Lem 与 Mina：照护一定有意义

- **来源 / 状态**：CS1 · 已核对。
- **原始规则**：`Babysit Mina` 推进 `A Ticket Out`；成功 **+2 进度、+2 Energy**，中立 **+1 进度、+1 Energy**，失败也 **+1 进度**。
- **规则组合**：`E-02 + E-03 + E-10`；`O-01 + O-03`。
- **体验解释**：照料与陪伴不是一场「没掷好就完全无效」的考试。只要来陪 Mina，就确实为 Lem 提供了支持。
- **适用情境**：陪伴家人、照料病人、探望老人、志愿活动、倾听某人的故事。
- **证据**：[Lem (& Mina) 攻略与行动结果](https://www.neoseeker.com/citizen-sleeper/Lem_%26_Mina)。

## CS1-04｜Min-Gi：失败也能吃上饭

- **来源 / 状态**：CS1 · 已核对。
- **原始规则**：面馆制作面食，成功获得 **+3 Energy 与较多 Cryo**，中立获得 **+2 Energy 与较少 Cryo**，失败仍 **+1 Energy**。
- **规则组合**：`E-02 + E-07`；`O-03`。
- **体验解释**：收入有运气成分，但最基本的热量供给有保障。这是生活中不耀眼却可靠的避风港。
- **适用情境**：包饭的工作、员工餐、熟识店主的照顾、低保底线工作。
- **证据**：[Energy 条目：Min-Gi Express](https://citizensleeper.fandom.com/wiki/Energy)。

## CS1-05｜Tala 的酒馆：日常变为共同事业

- **来源 / 状态**：CS1 · 已核对。
- **原始规则**：起初喝酒会增加 `Overlook Regular` 熟悉度；之后打工既得到 Cryo，也推进 `Good Service`；关系与进度进一步解锁帮助建造蒸馏装置；搜集孢子后还出现 **6 Cycle** 的第一批酿造等待 Clock。
- **规则组合**：`E-01 + E-03 + E-05 + E-09 + E-10`；`O-01 + O-05 + O-08`。
- **体验解释**：一处最初只用于消费和挣钱的地方，慢慢成为有人认识你、愿意分享梦想、邀请共同完成事业的地方。
- **适用情境**：酒馆常客、邻里店铺、师徒、朋友间合伙项目。
- **证据**：[Overlook Bar](https://citizensleeper.fandom.com/wiki/Overlook_Bar)。

## CS1-06｜Rotunda：捷径与警卫警觉

- **来源 / 状态**：CS1 · 已核对。
- **原始规则**：探索 Rotunda 可以逐渐了解地区；也可以尝试危险的 `Steal Dock Plans`，一次取得更多 `Dock Watcher` 进度，但中立或失败可能累积 `Havenage Watchlist` 警觉。警觉满后触发守卫相关事件。
- **规则组合**：`E-03 + E-04 + E-09`；`O-04 + O-08`。
- **体验解释**：慢慢熟悉城市和冒险取得捷径，有不同的代价；速度不是唯一价值。
- **适用情境**：搜集地图、偷档案、初入陌生街区、私闯机构。
- **证据**：[Rotunda](https://citizensleeper.fandom.com/wiki/Rotunda)。

## CS1-07｜Unit Assembly：质量审查与失去资格

- **来源 / 状态**：CS1 · 已核对。
- **原始规则**：先通过 `Junior Tech` 或 `Welder's Mate` 的 **8 格**资格 Clock；不良工序可能影响 `Quality Control`（**3 格**）。质量检查达到失败阈值将关闭装配区工作资格，需要重新从船厂基层工作取得进入资格。
- **规则组合**：`E-03 + E-04 + E-09`；`O-08`。
- **体验解释**：工作的难，不只在眼前损失，而在失去组织信任或准入资格。错误使你退回制度中的较低位置。
- **适用情境**：学徒试用期、秘密组织考核、临时工上岗、专业执照、新闻来源信誉。
- **证据**：[Unit Assembly](https://citizensleeper.fandom.com/wiki/Unit_Assembly)。

# 五、CS2：已存在的组合

## CS2-01｜Nemba 的厨房：失败也有食物

- **来源 / 状态**：CS2 · 「失败仍给少量 Energy」已核对；关于使用次数见下一条。
- **原始规则**：在 `Nemba's Kitchen` 工作换取免费食物，使用 `Intuit`；即使行动出现负面结果，也能获得一些 Energy。工作足够次数后还推进 `Impressing Nemba`，触发人物互动与后续委托。
- **规则组合**：`E-02 + E-07 + E-10`；`O-03 + O-01`。
- **体验解释**：一个愿意给人饭吃、而不是将进食资格完全建立在判定成功上的地方；持续参与会发展人物关系。
- **适用情境**：社区食堂、互助厨房、志愿工作、经济困顿时的落脚处。
- **证据**：[Exploring Far Spindle / Nemba's Kitchen](https://www.neoseeker.com/citizen-sleeper-2-starward-vector/Exploring_Far_Spindle)。

## CS2-01-OBS｜成功消耗有限机会的厨房（游玩观察）

- **来源 / 状态**：CS2 · **待核对**，保留使用者对游戏节点的具体观察，不将它写成已复核事实。
- **观察陈述**：「成功会减少使用次数，失败反而回报精力。」
- **若成立的规则组合**：`E-02 + E-06 + E-07`；`O-03 + O-06`。
- **体验解释**：成功取得更大帮助，但消耗公共资源；失败仍获得最低照顾。这可以表现慷慨与匮乏共存。
- **设计风险**：如果失败可以无限重复获益，玩家可能故意用低骰刷资源。核对时应记录：扣次数究竟发生在何种判定、每天是否重置、负面结果是否也扣使用次数。
- **复核任务**：补游戏中的**具体动作名称、正中负三档原文、剩余次数 UI 与跨 Cycle 行为**；验证后决定是否并入 CS2-01。

## CS2-02｜Hidden Wreck：对手抢先

- **来源 / 状态**：CS2 · 已核对（结构）。
- **原始规则**：搜寻残骸时，Vesna 也在竞争相同目标；玩家既有自己的任务进度，又面临对手到达、抢先完成相关行动的周期约束。
- **规则组合**：`E-03 + E-05 + E-11`；`O-01 + O-05`。
- **体验解释**：不是「不小心才会超时」，而是竞争者在独立行动；即使自己没有犯错，也可能失去机会。
- **适用情境**：抢新闻、警方先行封锁现场、抢购稀有物品、救援中的有限时间。
- **证据**：[CS2 成就及 Hidden Wreck 竞争条件](https://steamcommunity.com/sharedfiles/filedetails/?id=3422760770) · [Contract 攻略索引](https://www.neoseeker.com/citizen-sleeper-2-starward-vector/walkthrough)。

## CS2-03｜Contract Crisis：麻烦生出新麻烦

- **来源 / 状态**：CS2 · 已核对（机制结构）。
- **原始规则**：Contract 中的 Stress 能引出新的危机节点。危机可能要求优先处理，否则持续施加压力。玩家必须重新分配有限骰子；部分危机甚至关系到委托能否继续。
- **规则组合**：`E-04 + E-09 + E-11`；`O-09 + O-04`。
- **体验解释**：工作的真正困难不是进度条长，而是工作过程中出现了不在原计划里的工作。
- **适用情境**：机器漏水、潜入暴露、演出事故、意外受伤。
- **证据**：[Solheim HS22 与 Contract Crisis](https://www.neoseeker.com/citizen-sleeper-2-starward-vector/Escape_Hexport) · [开发者访谈：Contract / crew / stress](https://www.gamesradar.com/inside-citizen-sleeper-2-starward-vector-the-indie-rpg-sequel-with-mass-effect-in-its-sights/)。
- **说明**：各个 Contract 对危机的后果不同，不把「所有危机必须处理」视作通用规则。

## CS2-04｜Winds Long Shadow：脆弱物不能蛮干

- **来源 / 状态**：CS2 · 已核对。
- **原始规则**：要取得多个 Stepsilk 样本；没有特别强的局部 Cycle Deadline 或 Stress Meter，但工作失误可能增加脆弱性 / 减压风险，损坏后目标物可能无法收取。
- **规则组合**：`E-03 + E-04 + E-11`；`O-04`。
- **体验解释**：时间相对充足，但每次出手都需要谨慎；速度不如完整性重要。
- **适用情境**：拆除易碎部件、保存证据、抢救艺术品、取回药品。
- **证据**：[Greenbelt / The Wind's Long Shadow](https://www.neoseeker.com/citizen-sleeper-2-starward-vector/Greenbelt)。

## CS2-05｜Stranded Rig：无危机也有成本

- **来源 / 状态**：CS2 · 已核对（结构）。
- **原始规则**：主要是平稳的维修委托，不依赖同等强度的局部危险或竞速 Clock；但多花 Cycle 依然意味着继续消耗船上补给、维持团队状态。
- **规则组合**：`E-03 + E-05 + E-07`；`O-05 + O-07`。
- **体验解释**：不是每份工作都需要灾难。普通劳动也能有节奏与代价；额外时间等于真实生活成本。
- **适用情境**：普通修复、搬运、清扫、长期维护、非戏剧高潮的工作。
- **证据**：[CS2 Contracts 与 Stranded Rig](https://bonus-action.com/guides/citizen-sleeper-2-walkthrough-all-crewmates-contracts-resources/) · [Stress and Energy](https://www.neoseeker.com/citizen-sleeper-2-starward-vector/Stress_and_Energy)。

## CS2-06｜Solheim HS22：拿到东西后改变目标

- **来源 / 状态**：CS2 · 已核对。
- **原始规则**：玩家接受取回 Data Core 以换取资源的合同；搜寻阶段存在不同方法；取得 Data Core 后，Juni 的意愿引出新的选择。允许她保留核心可能导致原合同失败，但改变两人的关系及后续出路。
- **规则组合**：`E-11 + E-12`；`O-10 + O-12`。
- **体验解释**：技术意义上的成功未必是人物意义上的正确结果。任务完成之前，玩家甚至可能改变自己想要的结果。
- **适用情境**：揭露委托人、受托调查第三人、追回私人物品、保护证人。
- **证据**：[Escape Hexport / Solheim HS22](https://www.neoseeker.com/citizen-sleeper-2-starward-vector/Escape_Hexport)。

## CS2-07｜Stress 与损坏骰：把未来能力当成本

- **来源 / 状态**：CS2 · 已核对（系统结构）。
- **原始规则**：高压工作和 Push 会影响 Stress；Stress 及骰子损伤使后续回合的行动能力面临风险。队友增加可用骰子与专业技能，同时也有自己的压力承受限制。
- **规则组合**：`E-07 + E-08 + E-12`；`O-04`。
- **体验解释**：眼前一次额外努力的成本，不只是扣金钱，而可能让未来更难完成任务；团体的强大伴随照顾同伴的责任。
- **适用情境**：长时间调查、高压修理、疲劳驾驶、危机中透支自我。
- **证据**：[游戏官方 Steam 描述（Push、Stress、Crew）](https://store.steampowered.com/app/2442460/2/) · [GamesRadar+ 开发者访谈](https://www.gamesradar.com/inside-citizen-sleeper-2-starward-vector-the-indie-rpg-sequel-with-mass-effect-in-its-sights/)。

# 六、SSNoir：新组合假设

> 以下均为**尚待实现 / 纸面验证的设计提案**。数字仅为实验起点，而非游戏已定参数；优先测试规则是否表达了正确的感觉，而不是把表格全部装进成品。

## SSN-01｜酒馆：熟悉的工作

- **设计规则**：普通工作给工资，重复成功或中立时累计「熟悉度」；达到阈值后，降低某一类工作的风险，随后解锁调酒师的额外委托。失败仍发最低工资，但不推进熟悉度。
- **组合**：`E-01 + E-03 + E-09 + E-10`；`O-01 + O-08`。
- **体验目标**：初来乍到 → 熟悉人和流程 → 逐渐把酒馆当作生活的一部分。
- **情境**：尼尔在酒馆打工，遇见赖账客人，慢慢接触老街的消息。
- **最小实验**：熟悉度 0/4；前后工作回报相同，但达到 4 后额外出现「调酒师托付」行动。先不直接提高工资，以免退化为刷熟练度。
- **待验证问题**：玩家是否感到归属，而不只是做 4 次工作换一个按钮？

## SSN-02｜老街：有限的善意

- **设计规则**：在居民食堂帮工，失败仍获得少量食物；成功获得更多食物，但消耗有限的一次额外接济额度。每日需消耗行动，容量在下一周期是否恢复由世界中的实际库存决定。
- **组合**：`E-02 + E-06 + E-07 + E-10`；`O-03 + O-06`。
- **体验目标**：这个地方愿意接纳人，但不能无限供给。
- **情境**：尼尔贫困时得到老街居民帮助；后续也可以反过来为居民解决问题。
- **最小实验**：每天最多帮助 2 次；每次行动一定给基本饭食，较好结果给予额外补给，同时消耗公共库存。**这里是为测试而提出的机制，不代表 CS2 厨房已这样实装。**
- **待验证问题**：有没有故意用低骰无限刷保底的占优策略？是否需要用「每次行动都扣一次接济额度」替代「仅成功扣额度」？

## SSN-03｜跟拍：证据和警觉

- **设计规则**：暗中观察推进证据 Clock；快速跟进能一次得到更多进度，但失败更容易增加警觉。警觉满后目标识破尾随，原动作关闭，开启「撤离」「更换观察点」或交涉。
- **组合**：`E-03 + E-04 + E-09`；`O-04 + O-08`。
- **体验目标**：玩家思考的是「什么时候已经足够、是不是该收手」，不只是如何最大化每颗骰子的收益。
- **情境**：婚外情跟拍、追查勒索照片、观察剧院后巷。
- **最小实验**：证据 0/6、警觉 0/4；保守观察成功 +2 / 中立 +1 / 失败警觉 +1；冒险跟进成功 +3 / 中立 +1 且警觉 +1 / 失败警觉 +2。
- **待验证问题**：玩家是否总是给保守观察低骰、给冒险跟进高骰，从而形成无需思考的固定策略？如果如此，需要改变时机、距离或信息结构，而不是单纯加数字。

## SSN-04｜照相馆：日常行动变为线索

- **设计规则**：玩家正常去冲印婚外情照片。到达特定故事阶段后，原本普通的冲印行为额外显露相纸边缘或背面工艺信息；回家检查勒索照片后，可以将其与店内工艺比对。证据只形成推论，不自动证明来源。
- **组合**：`E-01 + E-07 + E-09 + E-12`；`O-08 + O-10`。
- **体验目标**：同一个生活地点因为玩家掌握了新问题，而获得新的意义；发现来自生活，不是任务面板凭空刷新。
- **情境**：夜莺勒索照片与跟拍委托发生自然联结。
- **最小实验**：原有冲印流程保持不变；在玩家取得勒索照片后，对一次冲印行为追加观察文本与一个可携带的线索；再次询问店主才能获得下一条信息。
- **待验证问题**：玩家是否能从相纸信息自然想到回家比对？是否需要一个简短但不过度明示的视觉提醒？

## SSN-05｜夜莺：排练的时间窗口

- **设计规则**：排练进度随 Cycle 自然变化，在有限时段开放「观看排练」；不需要判定成功，也不授予强力资源；错过则无法重新触发同一段人物时刻。
- **组合**：`E-05 + E-09 + E-10`；`O-05 + O-08`。
- **体验目标**：生活不停地经过，人与人靠近是因为愿意抽时间，而不是为了拿满奖励。
- **情境**：夜莺首演前的彩排、与尼尔的短暂安静时刻。
- **最小实验**：设置一段 2 Cycle 开放窗口；一次访问成本为正常城市行动中的时间，不给额外金钱或线索，记录玩家是否主动到场。
- **待验证问题**：如果完全没有奖励，玩家为何来？如何通过事前自然铺垫而非攻略式提示形成动机？

## SSN-06｜艾迪：出色表现的身体成本

- **设计规则**：艾迪训练或比赛准备期间，「比赛表现」与「身体负担」同时变化。某些高强度训练可以快速推进表现，但也增加负担；谨慎训练速度慢、损伤小；达到负担阈值后必须恢复或接受影响。
- **组合**：`E-03 + E-04 + E-08`；`O-04 + O-08`。
- **体验目标**：玩家希望他表现得漂亮，但不忍让他为此耗尽身体。
- **情境**：地下拳赛、假拳压力、尼尔是否帮助他继续打下去。
- **最小实验**：同样可成功的两种训练行动分别设定不同进度和负担；**不要**把「掷出更好的骰子」直接变成更大的处罚。
- **待验证问题**：选择克制是否有可感知的价值，还是更激烈的路线总是占优？

## SSN-07｜码头维修：局部事故衍生新工作

- **设计规则**：推进修理工程时，不利结果累积事故 Clock；达到阈值触发一个新问题（漏油、断电或材料污染）。新问题不一定强制暂停修理，但放任不处理会逐步损伤健康或增加后续成本。
- **组合**：`E-03 + E-04 + E-09`；`O-09 + O-04`。
- **体验目标**：一份简单工作慢慢演变为麻烦；玩家要决定先解决故障，还是冒险把原工作做完。
- **情境**：林的机械事故、码头船体修理、剧院后台设备故障。
- **最小实验**：维修 0/8，事故 0/3；事故满生成「临时止漏」0/3，持续不处理每 Cycle 增加一档损失。以规则上限限制连锁危机，避免无限派生。
- **待验证问题**：玩家是否真正需要改计划，而不是发现「先清危机」永远是唯一解？

## SSN-08｜勒索委托：发现真相后的重新选择

- **设计规则**：起始目标是保护夜莺并解决勒索，调查成果达到阶段阈值后出现证据，暗示委托人的叙述不完整；玩家可以继续原任务、隐瞒某些事实、与夜莺对质，且各自承担不同后果。
- **组合**：`E-09 + E-11 + E-12`；`O-08 + O-12`。
- **体验目标**：「我能不能完成委托」变成「我究竟要帮谁、帮到什么程度」。
- **情境**：第一章后半，夜莺的动机与旧码头利益纠葛。
- **最小实验**：在完成某条调查线后替换原定结算选项，而非只加一个解释文本；每个选择至少改变一个可观察的人物关系或后续任务。
- **待验证问题**：玩家是在权衡真实价值，还是对哪个选项是设计师预设的“善良选项”一目了然？

# 七、如何评价与扩展

## 1. 案例评价的四条轴线

| 维度 | 要问的问题 | 不佳征兆 |
|---|---|---|
| 表现力 | 去掉文字解释，规则是否仍传达某种事物的性质？ | 换成任何题材都没区别 |
| 决策性 | 玩家是否因为规则关系而调整行动？ | 永远是把最大骰子投向最大收益 |
| 情感性 | 体验是否让人对人物、地点或后果产生在意？ | 只记得数值，不记得发生了什么 |
| 可持续性 | 了解规则后重复游玩，是否仍然有意义？ | 只靠第一次惊讶；之后可机械刷取 |

并非每张卡都需要在四条轴线上同时很强。**照顾 Mina** 的核心可能是情感表现，不是策略难度；**Hidden Wreck** 更偏向时间与策略。记录它的真正优势，而不是统一用「难度」评分。

## 2. 研究的推荐顺序

1. **先描述生活关系**：什么事情随时间变化？什么行为真的会损坏另一件事？什么人会因为熟悉而改变对待方式？
2. **再抽取规则**：用本文件的 `E` 元素和 `O` 运算符写出最小状态变化，不急着添加新的专用系统。
3. **再问玩家感受**：这种规则让人更谨慎、温暖、焦虑、疲惫、珍惜机会，还是根本无感？
4. **最后验证策略**：测试高骰、低骰、连续失败、极度缺钱、已有大量资源时，是否出现违反设想的占优策略。
5. **记录结论和修改**：保留历史版与被否定的假设，避免同一个实验反复出现。

## 3. 版本与增量规则

- 案例 ID 永久保留；撤销案例时用 `已否定` 标识，不回收编号。
- 事实来源、体验推断与原创变体使用不同的段落；查证后只更新事实与状态，不直接覆盖先前的设计观察。
- 一个案例可以连接多个组合（C），一种组合可以有多个来自不同游戏的案例。
- 新的机制组合先作为 `C-XX` 登记，再补案例；出现新的基础元素时才增加 `E-XX` 或 `O-XX`。
- 数值需要来源；没有可靠数值时，只描述方向，不能把模拟参数写成原游戏事实。

# 八、新增案例模板与证据资料

## 1. 复制此模板新增案例

```markdown
## [来源]-[编号]｜简短名称

- **来源 / 状态**：CS1 / CS2 / SSN · 已核对 / 待核对 / 原创假设。
- **场景与行动**：玩家在什么情况下，选择了什么动作？
- **原始规则**：成功 / 中立 / 失败 / 每 Cycle / 阈值时，分别改变什么？
- **规则组合**：E-xx + E-xx；O-xx + O-xx；关联 C-xx。
- **体验解释**：玩家感受到的事物性质，而非剧情总结。
- **适用情境**：至少两个不同的故事 / 生活情境。
- **可拓展变体**：改动一个规则会产生什么不同体验？
- **失效风险**：是否存在占优策略、刷取漏洞或意义不明的惩罚？
```
