# SSNoir 夜莺最小主线实施计划(第二版:账单结构)

> **已归档（2026-07-11）**：本计划已落地。当前设计的现状描述见
> [../夜莺主线设计.md](../夜莺主线设计.md)。文内相对链接可能已失效。

故事是线性的，节拍是固定的，但每个节拍的满足条件是自由的，故事是线性的，抵达方式是非线性的。这个也是苏丹的游戏里的概念，我觉得这是第一个关键的概念。第二个概念是每次这种故事节拍的推进，这种账单的完成，它本身是重新规划的时刻，也是局势的变化。完成之后，故事奖励会打开新的经济能力和可探索的世界。
从经济的角度来看，故事主线成为了目标之一，成为了存量前往的水槽，是一种需求和必须完成的血槽。但也不是，实际上主线的推进会拓展你的行动空间，可用动作集合。
从故事的角度来看，经济是你用不同的方式提高能力，完成故事节奏的方式。我之前把交锋当节拍本体、把一切当备考,方向反了。

> 本文是"最小叙事骨架"的**可执行改造计划**。目标是给城市生活 demo 一个提供
> 意义与驱动力的短故事:委托与保护。第二版把骨架从"三次到期交锋"重组为
> **三个故事账单 / 三个明确目标 / 三次局势变化**——不是三场战斗,而是三个
> 必须处理的故事问题;交锋是结算方式之一,不是节拍本体。
> 设计源头见 [城市生活设计.md](城市生活设计.md) §8,工程规则见 [../AGENTS.md](../AGENTS.md)。

## 0. 设计总纲

### 0.1 要解决的问题

第一版计划解决了**意义问题**(玩家知道自己是谁、为什么行动),但没有解决
**结构问题**:三次交锋仍是核心骨架,城市生活退化为"为交锋攒条件"——
而玩家无法评估一场未知交锋的难度,"备考"不可读,打听等动作因此没有意义。

### 0.2 结构原则(自 Citizen Sleeper 1/2 提炼)

1. **故事给玩家非常具体的近期目标。** 不是"变强"、不是"准备未来危机",
   而是:查出一个人的落脚处、在某天前弄到一种保护、备好一种了断方案。
   玩家随时知道自己现在缺什么。
2. **目标有多个抵达方式,横跨不同生活线。** 钱可以买、关系可以换、
   程序可以压、拳头可以抢。玩家不是在选剧情分支,而是在选
   "我用我的活法怎么把这件事办成"。
3. **难度可以不可读,赌注必须可读。** 永远不要求玩家为未知难度的战斗
   做准备;要求他为一张明码标价的账单做准备。交锋要么嵌在某条抵达
   路径里(你主动上门),要么是账单未清时的后果(他们找上门)。
4. **节拍完成 = 局势变化 + 行动空间扩容。** 每个账单结清后,世界必须
   打开新的东西——新地点、新人物、新动作、新委托、新账单。主线不是
   单纯消耗资源的水槽,它同时是经济系统的扩张器。

一句话:**故事提出具体账单 → 城市生活提供多种解决方式 → 完成账单打开
新的城市结构。**

### 0.3 故事梗概

雨夜,老街酒馆的歌女(艺名"夜莺",真名全篇只在尾声出现一次)找到玩家
落脚的旅馆,用一小笔预付金委托玩家查清是谁在盯她的梢。她是从邻城一家
歌厅逃出来的:签了十年卖身约,跑在第七年。秘密分三层,随节拍逐次揭开:

1. **开场**:有人盯梢、字条和死鸟。她说不知道是谁。
2. **节拍一结算后**:她知道。来的是歌厅老板派的收账人——要么带她回去,
   要么收赎身钱。而且现在,这是你的账了。
3. **节拍二结算后**:她逃走那晚,老板的心腹追到码头失足落水死了。
   老板咬定是她推的。这不是一笔账,是一条命的交代。

终局按玩家一路攒下的活法分岔;尾声,酒馆里她第一次唱完整的一场,
然后说出真名。

### 0.4 设计规则(沿用第一版)

- **她不是任务标记**:每两个节拍之间必须有她的场景;她始终在出力
  (预付金、情报、戒指),保护欲由她的韧性勾出,不靠眼泪。
- **她的安危是胜负的一部分**:节拍以坏结果结算会推进"夜莺安危",可见、
  会改变后续场景;终局失败 = 她被带走,demo 的故事失败结局
  (不做硬 game over,与现有"交锋不终局"规则一致)。
- **所有故事状态可见**:状态卡、当前账单、到期倒计时、酒馆停业期限,
  全部遵循设计文档 §1 的 Clock 可见性规则。
- **文本量上限**:每一拍两三屏;对话用 `play-dialogue!`,过场用 `spotlight!`。

### 0.4.1 简洁性修订（2026-07-10）

对照"简洁、凝练、必要"设计审查，本计划以下描述已被裁决调整
（与正文其余处冲突时，以本节为准）：

**已裁决不做**（原计划设想过，判定为伪需求/占位）：

- **收账人落脚处的可交互节点**（N4 §4.3 提到的"成为可交互节点"）：
  当前用状态卡 + 交锋入口已完整表达"你知道他在哪、可以主动上门"，
  额外的可交互节点是没有独立读法的占位。
- **警局线通行证冷却减免**（N5 §5.3"警局"分支提到的"办案通行证的签发
  冷却减免一次"）：探长支线的可见回报已收敛为通行证 + 延期两个工具，
  额外的冷却折扣是同一奖励的重复表达，且原实现从未接线（`探长愿意担保`
  是隐形一次性保险，只在失败时自动消耗，玩家从未主动决策），已整体删除。
- **黑市买消息**（N4 §4.1 表格第四行、N9 数值表"黑市买消息 20 金"）：
  老街市集/黑市从未真正挂载，这条路径是纸面设计。已由**"花 1 情报
  +1 查访格"**替代（夜莺状态卡节拍一新节点"花消息买线索"，不占骰，
  消耗 1 情报），语义相通（花资源换查访进度）且情报因此在 17 天主线内
  多一个真实碰得到的消费口，详见[城市互联实施计划.md](城市互联实施计划.md) M3。

**已实现（且已按简洁性修订调整）：**

- **首期 → 尾款折扣**：付过首期（60 金）后，交锋「了断」的赎身钱由
  150 降为 90，账目在状态卡 goal-note 与 situation-text 中持续可见
  （见 [夜莺.scm](../Content/scenes/world/夜莺.scm)、
  [夜莺·了断.scm](../Content/scenes/encounters/夜莺·了断.scm)）。
- **码头线了断门槛折扣**：节拍二选了"码头兄弟看场"方案后，
  交锋「了断」中"码头兄弟到场"的门槛从"自己人"降为"脸熟"
  （文案："他们看过一次场，认这件事"）。
- **探长担保已删除**：官僚线的可见回报就是通行证 + 延期两个工具，
  不再有隐形的失败保险。相应地，N3 §4 中"dock 的 `on-public-event`
  通知保留"一句作废——夜莺交锋结算与码头的暗线耦合（结算自动加钱/
  加情报/加劳工关系，或触发 `smuggle-cooldown`）已整体删除；玩家事先
  看不到、无法决策的隐形奖惩不算真正的系统耦合。

### 0.5 本计划明确不做

- 不接异常货单/老周支线/正式主线;故事自闭环
  (交锋内是否保留货单可选目标,由手写交锋时决定)。
- 不新增引擎机制(唯一 C# 改动是初始金钱一行,见 N9)。
- 不做玩家死亡(引擎无此概念,健康归零的处理维持现状)。
- 不新增交锋引擎能力:交锋内容由设计者手写,只使用现有交锋原语。
- 不做旅途/出城(CS2 的远征节拍留给第二章语法)。
- 旧 酒吧.scm(海伦线孤儿文件):简洁性修订 2026-07-10 已完成清理任务,
  确认零引用后 `git rm`(历史即归档),见 0.4.1。

## 1. 三个节拍总表(验收基准)

| | 节拍一「找到盯梢的人」 | 节拍二「给她弄到保护」 | 节拍三「选择了断方案」 |
|---|---|---|---|
| **故事问题** | 谁在盯她?他在哪?为谁来的? | 他们要来抢人,你能不能让她暂时安全? | 这件事最后由谁定义:钱、街坊、还是法律? |
| **可见目标** | 第 4 天前查出收账人的落脚处 | 第 10 天前落实一种临时保护 | 第 17 天前备好一种最终方案 |
| **到期日(占位)** | 第 4 天 | 第 10 天 | 第 17 天 |
| **抵达路径** | 酒馆打听 / 码头闲话 / 警局查登记簿 / 花消息买线索（简洁性修订 2026-07-10：原"黑市买消息"，见 0.4.1） | 付首期 / 藏进你的公寓 / 警局照看 / 码头兄弟看场 | 付清赎身钱 / 码头兄弟到场 / 程序干预 |
| **完成 → 结算** | 解锁"去找收账人":**你上门**(主动交锋,占先手) | 到期日是**场景**:他们碰了钉子退走,放话了断之日 | 到期交锋「了断」,备好的方案成为场内终局动作 |
| **未完成 → 结算** | 第 4 天**他找上门**(被动交锋,他占先手) | 到期日是**交锋「抢人」**,败则她受伤 | 到期交锋「了断」,只剩硬打,代价最重 |
| **结算后的局势变化** | 账转你头;第二层揭开;赎身钱账单上屏 | 老板知道收账人不够用了;第三层揭开;了断日锁定 | 三个结局(见 N8) |
| **结算后的扩容** | 收账人落脚处成为可交互节点;她引荐酒馆老板→服务员工作解锁 | 按所选方案各自扩容(见 N5 扩容表);她的住所场景线开启 | 结局态内容(她在台上/空酒馆) |

三个节拍无论以哪种方式结算,只要推进即各奖励 1 成长点(沿用现有公共小节规则)。

幕间场景(她的戏份)穿插其间,见 N7。

### N2 夜莺故事模块与开场

**文件:** `Content/scenes/world/夜莺.scm`、[world.scm](../Content/scenes/world/world.scm)

#### 2.1 状态归属

故事闭包 `nightingale` 拥有全部故事状态:

```
story-stage    ; 0=未开场 1=查访中 2=账转你头(二层已揭) 3=知道真相(三层已揭)
               ; 90=了断·成功 91=了断·她被带走 92=中途放她走
beat1-progress ; 查访进度 0..4(见 N4)
beat1-early?   ; 节拍一是否已由玩家主动结算
protection     ; 节拍二方案:无 / 首期 / 公寓 / 警局 / 码头
installment-paid? ; 是否付过首期(影响终局尾款)
safety         ; 夜莺安危 0..3(0=安好 1=受惊 2=受伤 3=被带走)
scene-flags    ; 各幕间场景是否已看(防重复)
tavern-closed  ; 酒馆停业剩余天数
```

世界协调器只保留节拍排程(计数、到期、阻塞);故事状态归夜莺模块,
通过 `set-global!` 镜像必要字段(如 `'夜莺阶段` `'夜莺安危`)供交锋脚本
读取,与 `bout-idx` 的现有模式一致。

#### 2.2 开场·雨夜来客(第 1 天必办)

复用现有"关键事件阻止休息"机制(`rest-block!` / `rest-release!`):

- 新游戏 `story-stage = 0` 时,旅馆内出现必办节点**"回应敲门声"**
  (instant,不占骰),同时挂 rest-blocker"今晚有人敲门,先看看是谁"。
- 节点触发 `play-dialogue!` 开场对话(四至六句:委托、预付金、死鸟字条),
  然后:`add-item! "金钱" 预付金`、`story-stage = 1`、解除阻塞、
  `spotlight!` 一屏定场文案(你是谁、身上还剩多少钱、四天之内查出那个人)。
- 开场对话要点:她付的钱刚够几晚房钱;她不哭,只是把钱按在桌上;
  委托就是节拍一本身——"查清是谁在盯梢",不是"保护我"。
  保护是后来长出来的。

#### 2.3 她的状态卡(账单外化,UI 载体)

`nightingale 'render-data` 在世界根节点渲染容器**"夜莺"**:

- observe 节点:她现在的处境描述(随 story-stage 与 safety 变化)。
- **当前账单行,从第 1 天起常驻**,随节拍更新——玩家每天早上第一眼
  就能回答"我现在缺什么":
  - 节拍一:"第 4 天他会上门。在那之前查出他的落脚处(0/4)。"
  - 节拍二:"第 10 天他们来抢人。在那之前:付首期 60,或给她一个
    藏身处,或让警局、码头罩着这里。"
  - 节拍三:"第 17 天做个了断。付清尾款、让码头站在你这边,
    或让程序咬住他们——总得备一样。"
- **查访/账单进度以 Clock 显示**(节拍一 0/4;节拍二、三显示已落实的方案)。
- safety 三格 Clock,标题"夜莺安危",备注"节拍以坏结果结算会让处境恶化;
  了断失败,她会被带走"。

**验收:** 第 1 天不处理敲门无法睡觉;处理后获得预付金、状态卡与账单行
出现;账单行随节拍正确更新;存读档后全部故事状态不丢。

### N3 世界骨架:节拍排程与结算分发

**改动文件:** [world.scm](../Content/scenes/world/world.scm)

1. **排程表**:三个到期日(占位 `'(3 6 7)`,即第 4/10/17 天)。
   每拍结算后用下一拍间隔重置时钟;时钟标题/备注按节拍输出账单文案
   (与状态卡一致),pending 态输出"事情已经发生"文案。
   探长"延后一天"机制不变。
2. **到期结算委托给夜莺模块**:到期时世界置 pending 并阻塞休息,但
   pending 节点的内容向 `nightingale` 询问——由故事状态决定当天是
   **交锋**(调 `start-encounter`)还是**场景**(播对话/spotlight 后
   直接结算)。世界只管"到期必须处理",不管"处理长什么样"。
3. **提前结算接口**:新增 `resolve-beat-early!`——节拍一玩家主动上门时,
   夜莺模块调用它消费掉当期排程(计数 +1、按下一拍间隔重置时钟、
   不再触发当期到期事件)。
4. **结果回传**:结算后世界通知 `(nightingale 'on-beat-result 节拍号 result)`,
   由夜莺模块推进 safety、解锁当晚对话、执行扩容与留疤。
   （简洁性修订 2026-07-10：dock 的 `on-public-event` 耦合已删除，不再保留。）
5. **中途放她走**:夜莺模块调用 `cancel-public-events!`(计数置满、
   清 pending、释放阻塞、时钟消失),骨架回到静默状态。

**验收:** 三个到期日的时钟文案各不相同;节拍一提前结算后第 4 天无事发生、
时钟直接指向第 10 天;到期日的场景/交锋分发正确;旧存档可读
(新增字段 `assoc-get` 缺省)。

### N4 节拍一「找到盯梢的人」(第 1–4 天)

#### 4.1 查访(多路径,填 2 格进度)

目标是**一个具体结果**:收账人的落脚处。四条来源,任两次成功即满
(全部为占 1 骰的判定,开局第 2–3 天用 3 颗骰可达,但要挤占挣房租的骰子):

| 来源 | 地点 | 判定 | 好结果 | 坏结果 |
|---|---|---|---|---|
| 酒馆里问 | 老街酒馆 | 交际 | +1 格(有人见过他进出) | +1 压力 |
| 码头上问 | 码头 | 交际(劳工关系≥脸熟 +1 修正:"码头工人认得你") | +1 格(他是坐船来的) | +1 压力 |
| 查旅店登记簿 | 警局 | 见识 | +1 格(外地人都得登记) | 无进展 |
| 花消息买线索(原计划为"黑市买消息",简洁性修订 2026-07-10 替代实现) | 夜莺状态卡 | 无(即时,消耗 1 情报) | +1 格 | — |

进度、来源与剩余天数全部可见(状态卡 Clock);
每格附一句情报文案(他用的假名/他为谁办事),信息本身就是报酬。

#### 4.2 两种结算

- **满 4 格(第 4 天前)**:解锁主动行动**"去找收账人"**(占 1 骰,
  挂在夜莺状态卡上)→ 触发交锋一**"你上门"变体**:你选的时间和地点,
  先手优势(具体形式由手写定,如对方压力钟起点更低、多一个交际开局动词)。
  结算后调用 `resolve-beat-early!`。玩家也可以拿着落脚处不去——
  第 4 天他照样上门,但你对他的了解仍在(文案回收)。
- **未满**:第 4 天到期,交锋一**"他找上门"变体**:他占先手。

两种变体可以是同一交锋文件读 flag 分支,也可以是两个文件——手写时定。
无论胜败,结算相同:收账人记住你的脸,撂话"这是你的账了";
当晚第二层揭开(N7),`story-stage = 2`。

#### 4.3 局势变化与扩容

- 账单升级:状态卡出现节拍二账单与赎身钱数目。
- **收账人落脚处**成为可交互节点(挂老街酒馆或居民区):observe +
  后续节拍的交互入口(节拍二"付首期"在此交割;为第二章留谈判位)。
- 她引荐酒馆老板 → **服务员工作解锁**(N1)。
- 交锋失败额外:safety = 1(受惊),玩家掉的健康即是代价。

**验收:** 四条来源各自可推进且只在节拍一期间出现;满格解锁主动行动、
提前结算后排程正确跳转;未满格则到期被动交锋;两种变体的开局差异存在;
结算后三项扩容全部生效。

### N5 节拍二「给她弄到保护」(第 5–10 天)

**改动文件:** `Content/scenes/world/夜莺.scm`、`老街酒馆.scm`、
[警局.scm](../Content/scenes/world/警局.scm)、[码头.scm](../Content/scenes/world/码头.scm)、[home.scm](../Content/scenes/world/home.scm)

#### 5.1 四种方案(完成任一只落实保护,不提前推进节拍)

| 方案 | 门槛 | 成本 | 落实动作 |
|---|---|---|---|
| **付首期** | 无 | 60 金(占位) | 去收账人落脚处交割(占 1 骰) |
| **藏进你的公寓** | 资产≥中(已购公寓) | 无现金成本 | 住所新动作"让她搬进来"(占 1 骰) |
| **警局照看** | 官僚≥脸熟 | 占 1 骰办程序(见识/交际判定,可多次尝试) | 警局新动作"申请巡警照看酒馆" |
| **码头兄弟看场** | 劳工≥脸熟 | 占 1 骰人情(交际判定,可多次尝试) | 码头新动作"请兄弟们看着点酒馆" |

完成任一方案只设置 `protection`,不提前进入节拍三。第 10 天仍然结算:
有保护则播放"他们碰了钉子退走"的场景;无保护则进入抢人交锋。

这是账单节拍的核心体验:每天早上重新规划——攒钱?升关系?还是干脆
把公寓买了(资产线第一次有了故事级回报)?四条路横跨三个势力加资产系统,
"生活方式互联"在此兑现。已落实的方案显示在状态卡上。

#### 5.2 两种结算(第 10 天到期,必办)

- **已有保护 → 场景(不打)**:他们来了,碰了钉子退走。按方案出对应
  一屏文案(巡警在场/码头汉子抱臂站着/人去楼空/收了钱点头)。
  收账人放话:老板要亲自了断。safety 不变。
- **无保护 → 交锋「抢人」**:他们来抢人,你在场。胜:撑住了,safety 不变;
  败:safety = 2(她受伤,躲进你的住处)、酒馆停业 2 天(N8)。

结算当晚第三层揭开(N7),`story-stage = 3`,状态卡账单更新为节拍三。

#### 5.3 局势变化与扩容(按方案分岔)

- **首期**:`installment-paid?`,终局尾款减为 90(账目连续,付过的钱有意义);
  收账人对你的称呼变化(生意人待遇)。
- **公寓**:她住进来 → **住所场景线开启**(家里的对话、她留下的痕迹,
  N7 的幕间场景改在住所播放,依恋感最浓的一条路)。
- **警局**:探长记下这桩事(简洁性修订 2026-07-10：不再有额外的通行证
  冷却减免——官僚线的可见回报是通行证 + 延期两个工具，见 0.4.1)。
- **码头**:码头兄弟认下这件事 → +1 劳工关系,交锋「了断」中
  "码头兄弟到场"的门槛从"自己人"降为"脸熟"(他们已经看过场)。

每条路都为自己那条终局线降一点门槛——**节拍二的选择是对终局路线的
软承诺**,但不锁死:玩家仍可换线,只是没有折扣。

**验收:** 四方案各自门槛正确、完成任一后状态卡更新;到期日场景/交锋
分发正确;四种扩容各自生效;无保护且交锋失败时留疤链条完整。

### N6 节拍三「选择了断方案」(第 11–17 天)

**改动文件:** `Content/scenes/world/夜莺.scm`、交锋文件(手写)

#### 6.1 备战(路线承诺)

状态卡列出三条终局线与各自门槛(含节拍二带来的折扣),玩家在七天里
把盈余投向选定的存量:

1. **付清尾款**:150 金(付过首期则 90)。
2. **码头兄弟到场**:劳工自己人(节拍二走码头线则脸熟即可)。
3. **程序干预**:持办案通行证(节拍二走警局线则签发冷却已减免)。

无准备硬打永远保底,代价最重。幕间场景「旧戒指」在此期间(N7)。

#### 6.2 交锋「了断」(第 17 天,必打)

到期必办、必进交锋(这一场是压力节拍,不可支付跳过——老板要的是当面了断)。
备好的方案成为场内终局动作:

- **付清尾款**:`req-item "金钱" 尾款`,不占骰、即时,直接成功终局。
  文案方向:钱在这个故事里第一次买的不是道具,是一个人的自由。
- **码头兄弟到场**/**程序干预**:效果由手写定,文案分别点明
  "一座不交人的城,成本算不过来"/"落水案在邻城没立过案——他们不敢报官"。
- 安危联动:safety = 2 时本场更凶险(具体形式手写定);
  她的在场文本按 safety 分支(安好时递东西/喊话,受伤时缺席)。

#### 6.3 每场交锋的对外契约(手写时不可违反)

1. 以 `(end-encounter 'success)` / `(end-encounter 'fail)` 结束,
   经世界回传 `on-beat-result`;不做其他出口。
2. 零准备可进入、以失败退出也可(不做硬 game over)。
3. 本场失败对她意味着什么,必须在场内可见(时钟备注/风险预告)。
4. 异常货单可选目标是否保留、放在哪场,手写时定(机制不改)。

**验收:** 三条终局线按门槛(含折扣)正确出现;足额金钱时"付清尾款"
可直接终局;了断到期必进交锋;safety 影响场内文本与难度。

### N7 幕间场景(她的戏份)

**改动文件:** `Content/scenes/world/夜莺.scm`、`老街酒馆.scm`

全部为即时对话节点(不占骰,一次性,看过置 scene-flag),按 story-stage
/天数注入酒馆、旅馆或住所(她搬进公寓后,场景改挂住所):

1. **第二层揭开**(节拍一结算当晚,必看):卖身约、跑在第七年、
   赎身钱数目。若查访拿到过假名/雇主碎片,她的反应有两版(问过/没问过)。
2. **她唱歌**(story-stage ≥ 2,第 5 天后首次进酒馆):一屏氛围文案,
   不给数值奖励——这一拍的报酬是文本本身。
3. **软选择"我走就是了"**(story-stage ≥ 2,第 7 天后):她提出离开以免
   连累你(那 60 块首期,够她走很远)。
   - **"留下"**:一句回应;状态卡多一行"她留下了——因为你开口了"。
   - **"让她走"**:`story-stage = 92`,调用 `cancel-public-events!`,
     状态卡变为怅然结语后次日消失;酒馆恢复普通打听。不奖励成长点。
4. **第三层揭开**(节拍二结算当晚,必看):落水的人。若节拍二以
   交锋失败结算(她受伤),对话在住处播放,文案为受伤版——
   失败玩家拿到的是另一种更浓的相处文本,不是空白。
5. **旧戒指**(story-stage = 3,第 12 天后):她塞给你一枚旧戒指,
   "当了它,能顶一点"。收下(+15 金)或不收(一段对话),均置 flag。

"必看"场景复用 rest-block!(当晚不看完不能睡),备注写明原因
("她在等你回来")。

**验收:** 每个场景只出现一次、条件与挂载地点正确;查访结果影响揭开
对话分支;软选择两条路走通;必看场景阻塞睡觉且原因可见;
存读档后 scene-flags 一致。

### N8 失败留疤与结局

**改动文件:** `Content/scenes/world/夜莺.scm`、`老街酒馆.scm`、[world.scm](../Content/scenes/world/world.scm)

#### 8.1 安危推进(on-beat-result)

| 节拍 | 好结算 | 坏结算 |
|---|---|---|
| 一 | safety 不变(主动或被动交锋胜) | 交锋败:safety = 1(受惊) |
| 二 | 场景结算或交锋胜:safety 不变 | 交锋败:safety = 2(受伤,躲进你住处);酒馆停业 2 天 |
| 三 | → 结局 A | → 结局 B |

酒馆停业:夜莺模块置停业天数,酒馆读取后隐藏工作、显示歇业 Clock;
日终规则递减。

#### 8.2 三个结局

- **A 真名(成功)**:spotlight 两屏——酒馆,她第一次唱完整的一场,
  唱完走到你桌前说出真名(占位名,落地定)。状态卡变为长期状态
  "夜莺(真名)——她留在了这座城";酒馆永久多一个 observe 节点
  (她在台上)。`story-stage = 90`。
- **B 她跟他们走了(失败)**:spotlight 两屏——她自己走出去,换你一条命。
  酒馆再没有人唱歌;住所物品栏多一枚"旧戒指"(若此前未收过)。
  状态卡变为结语后消失。`story-stage = 91`。游戏继续,不做 game over。
- **C 怅然(中途放走)**:见 N7 软选择,`story-stage = 92`。

**验收:** 留疤链条完整且期限可见;三个结局的状态卡、酒馆状态、纪念物
各自正确;结局后无残留阻塞或时钟。

### N10 静态验证(收尾)

用 [GameTester](../TerminalApp/src/Testing/GameTester.cs) 或手动流程验证:

1. **主动线**:第 3 天查访满格 → 主动上门 → 付首期 → 攒到 90 付清尾款。
   验证提前结算、账目连续、三次扩容。
2. **关系线**:查访靠码头 → 保护靠码头兄弟 → 终局码头到场(验证门槛折扣)。
   或对应警局线。
3. **全败线**:三拍全部被动+失败,验证 safety 1→2→结局 B、停业、
   受伤版对话、结局后世界干净。
4. **放走线**:第 7 天后选"让她走",验证排程取消、骨架静默、无残留。

另验证:第 1 天不回应敲门无法睡觉;每天早上状态卡能回答"我现在缺什么、
还剩几天";任意存读档点往返后故事状态一致。

最终判据:**一个没读过设计文档的玩家,在任意一天早上分骰子时,
能说出"我现在缺什么、到期日是哪天、我打算用哪种活法把它办成"。**
