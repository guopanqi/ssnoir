# 命运骰结算实施计划

> 目标：把动作判定从「双随机数字公式」重构为「确定基础档 + 记号命运骰」。
> 设计定稿经 2026-07-11 讨论得出，动机与推导见本文 §0.5。
> 本文是**方案A**，与 [数字命运骰结算实施计划.md](数字命运骰结算实施计划.md)
> （方案B·数字骰 + 命运条）互为二选一，选择要点见方案B文末；两者只实施其一。
> 相关：[城市生活设计.md](城市生活设计.md) §4（落地后需同步修订）。

## 0. 规则定稿

### 0.1 判定公式（两层）

```
第一层（确定，放骰前完全可见）
  基础档 = 放入骰面 + 技能 + 修正        （技能从 0 起）
  基础档 ≤2 → 坏    3–5 → 中    ≥6 → 好

第二层（唯一随机，只对档位做有界扰动）
  按动作风险级掷对应命运骰：
    安稳骰（低/中/高风险，及一切默认 roll）：空 空 空 空 彩头 阴云
    越界骰（越界工作）：                     空 空 空 彩头 阴云 雷霆
  彩头 = 升一档    阴云 = 降一档    雷霆 = 降两档    空 = 不变
  封顶「好」、垫底「坏」（档位不溢出）。
```

### 0.2 修正的用途收窄

- 风险级**不再**产生修正；风险由「换骰」+「outcome 内容狠度」表达。
- 唯一保留的风险修正：**越界工作固定 −1**（由 `工作` DSL 注入，令技能 0 的生手
  放 6 也只能搭出基础中）。
- 其余修正一律是情境的（通行证 +1、风声紧 −1 等），继续走 `roll` 的 mod-fn 回调。

### 0.3 最终概率（校验基准）

| 基础档 | 安稳骰（坏/中/好） | 越界骰（坏/中/好） |
|---|---|---|
| 好 | 0 / 17 / 83 | 17 / 17 / 67 |
| 中 | 17 / 67 / 17 | 33 / 50 / 17 |
| 坏 | 83 / 17 / 0 | 83 / 17 / 0 |

期望档位税：安稳骰 0，越界骰 −1/3 档。越界工作的报酬溢价按此定价。

抽样验证（走私：越界，敏锐，修正 −1）：
- 生手（敏锐 0）放 6：基础 5 → 中，最终 33/50/17。
- 老手（敏锐 2）放 6：基础 7 → 好，最终 17/17/67——高投入失败率低但**永不为零**。

### 0.4 两条内容纪律

1. **词汇表冻结**：全游戏只有 4 个记号（空/彩头/阴云/雷霆）、2 颗命运骰。
   新的风险花样先用 outcome 内容表达，其次情境修正，动刻面是最后手段。
2. **风险差异下放给 outcome**：高风险与低风险共用安稳骰，差别写在坏结果的
   狠度里（−健康 vs +压力）。骰子只标记「合法 / 越界」这一条界线。

### 0.5 设计动机（为什么是这套）

- 旧公式（隐藏运气骰 + 放入骰当 ±修正 + 两次隐藏定心）不可直觉，需要概率条
  预览来补救；且高骰配高风险是唯一最优解，决策扁平。
- 新公式：计算在设计时完成，游玩时只剩「看」。基础档确定 → 手牌可读、
  准备行为（+1 修正）能明确翻转某格档位；命运骰有界（±1，雷霆 −2）→
  投入永不清零；雷霆专打「基础好」→ 越界永无零风险；玩家看着雷霆面自己
  选择掷它 → 无背叛感。

### 0.6 留白（本期一律不做）

- 风声面（越界的跨日热度 Clock）。
- 封顶彩头的小溢出奖励（小费）。
- 雷霆独立 outcome 文案（雷霆与阴云共用坏 outcome，仅结算展示区分掷面）。
- 手牌按选中动作的基础档整体染色（HandPanelWidget / Unity 手牌区，可作后续打磨）。

## 1. 阶段一：引擎判定层

### 1.1 新类型（Engine/Runtime/Core）

新建 `FateDice.cs`：

```csharp
public enum FateDieKind { Steady, Trespass }          // 安稳骰 / 越界骰
public enum FateFace   { Blank, Boon, Cloud, Thunder } // 空 / 彩头 / 阴云 / 雷霆
public enum RollTier   { Fail, Neutral, Success }      // 坏 / 中 / 好（沿用 RollOutcome 亦可）

public static class FateDice
{
    // 骰面表（唯一数据源，UI 预览与判定共用）
    public static IReadOnlyList<FateFace> Faces(FateDieKind kind);
    // 面 → 档位位移：Blank 0, Boon +1, Cloud −1, Thunder −2
    public static int Shift(FateFace face);
    // 基础档：base = die + skill + mod；≤2 坏 / 3–5 中 / ≥6 好
    public static RollOutcome BaseTier(int placedDie, int skill, int modSum);
    // 应用位移并夹紧到 [坏, 好]
    public static RollOutcome ApplyShift(RollOutcome baseTier, FateFace face);
}
```

  若 UI 仍想画三色比例条，用 `FateDice.Faces` 数面即可，不再需要概率类。

## 3. 阶段三：DSL 与内容

### 3.1 engine.scm

- `roll` 构造器增加可选骰类参数，保持向后形状兼容的**显式**变体：

```scheme
;; (roll skill fail neutral success)                    → 安稳骰
;; (roll skill mod-fn fail neutral success)             → 安稳骰
;; (roll-trespass skill mod-fn fail neutral success)    → 越界骰
```

  内部表示为 `(list 'roll skill die-kind mod-fn fail neutral success)`，
  `die-kind` 取 `'安稳 / '越界`。不给裸 `roll` 加位置可选参数的猜测逻辑，
  参数数量不符直接 error。
- `工作` DSL（[engine.scm:198](../Content/scripts/engine.scm)）：
  - risk 为 `低/中/高` → 安稳骰，无风险修正；
  - risk 为 `越界` → 越界骰 + mod-fn 注入 `(modifier -1 "越界")`。
- `roll-action` 保持现签名（默认安稳骰）。

### 3.2 NodeConverter

[NodeConverter.cs:215](../Engine/Runtime/Scripting/NodeConverter.cs)：解析新的
`die-kind` 元素，映射 `'安稳 → Steady`、`'越界 → Trespass`，未知符号抛异常。

### 3.3 内容 .scm

- 世界工作（码头/board/货运公司/公园/警局/夜莺）：**零改动**（走 `工作` 与
  `roll-action`，自动获得正确骰子与修正）。
- 交锋（infiltration / combat / 夜莺三场）：裸 `(roll ...)` 默认安稳骰，本期
  不逐个调整；哪些交锋动词该用越界骰属于内容调参，落地后另行审视。

## 验收清单

1. 技能 0 的生手放 6 做走私：卡面显示基础中；多次执行观察到坏/中/好都出现。
2. 敏锐 2 放 6 做走私：卡面显示基础好；出现过「掷出雷霆 → 坏」。
3. 刷盘子（低风险）放 6：基础好，绝大多数结算为好，偶见阴云 → 中，**从未**坏。
4. 卡面无百分比数字；改放骰不改变刻面行，只改变基础档徽章。
5. 通行证类 +1 修正能把某颗骰的基础档从中顶到好，徽章实时变化。
6. 旧存档载入被拒绝并提示；新开局四项能力显示 0/1/0/0。
7. `TestFateDice` 全绿；全量内容校验通过。
