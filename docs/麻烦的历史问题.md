# 麻烦的历史问题

记录已经解决、但以后很容易再次踩到的问题。重点保留可迁移到其他项目的原因和解法。

## 视频播放发白发亮

### 现象

Unity 中播放的视频比原片略白、略亮。原本加入风格 shader 是为了统一视频和实时世界的画风，调试时
却意外解决了这个长期问题。

### 实际有效的设置

```text
Stylize Intensity = 0
Video Input Gamma = 1
Video Output Gamma = 1
```

此时视频 pass 近似直通：输入、输出的 `pow` 都是恒等，Stylize 的结果也因 `Intensity=0` 被丢弃。
真实效果是让 `VideoPlayer → RenderTexture → 屏幕` 保持原样，不再额外改变中间调。

视频的 full/limited range 和 bt709 标签仍应规范化，但那是另一个资产问题，不是这次发白的最终修复。

### 通用经验

- 判断“中性 shader”不能只看 Gamma 是否为 1，还要确认中间是否有色阶、Ramp、量化或混合。
- 先建立完全直通的基线，再逐项开启风格效果。
- 不要用全局 Gamma 修单个视频；单个文件的问题应在资产预处理阶段解决。

相关代码：`SSNoirStylize.shader`、`CutscenePlayer.cs`。

## Reduce Animation 的 dissolve 冻帧发白

### 现象

dissolve 在 WebGL 中正常，但 Unity Editor Game View 的中段明显发白；两张画面中错位的白描会叠成
大片亮灰。UI 正常，只有参与 dissolve 的世界画面异常。

### 原因

旧实现用 `GUI.DrawTexture` 把冻帧盖到实时世界上，alpha 混合依赖 Editor/WebGL 各自的目标缓冲和
sRGB 状态。Editor 实际在线性空间混合，而这里需要的是显示值空间的感知混合：

```text
错误：LinearToSRGB(lerp(newLinear, oldLinear, alpha))
正确：lerp(newDisplay, oldDisplay, alpha)
```

高反差画面在线性空间混合时，中间阶段会显著变亮。把冻帧 RenderTexture 改成
`RenderTextureReadWrite.Linear` 没有解决问题，因为根因是**混合发生在哪个空间**，不是贴图单独以
什么格式保存。

### 最终解法

不再由 IMGUI 混合冻帧。URP 全屏 shader 同时读取实时世界和冻帧：

1. 两张图都转成显示值。
2. 在显示值空间 `lerp`。
3. 结果转回线性值写入相机目标。
4. UI 在之后照常绘制，不参与 dissolve。

这样 Editor 和 WebGL 执行同一段数学，不再依赖平台的隐式 alpha 混合行为。

### 通用经验

- Editor 正常不代表 Web 正常，反过来也一样；颜色空间问题必须跨目标平台检查。
- dissolve/crossfade 要明确决定在线性空间还是显示值空间混合，不能交给默认 framebuffer 碰运气。
- 只改 RenderTexture 的 Linear/sRGB 标记无法修复混合空间错误。
- 验证 crossfade 要看 alpha 约为 0.5 的中段，两个端点通常看不出问题。

相关代码：`ViewCrossfade.cs`、`SSNoirStylizeFeature.cs`、`SSNoirStylize.shader`。

2026-08-09：用户确认最终方案在 Unity Editor 中恢复正常；WebGL 是必须保留的回归检查目标。

## WebGL 纹理压缩格式不在 ProjectSettings

Unity 把 WebGL `Texture Compression Format` 显示在 Player Settings，但实际保存在
`Library/EditorUserBuildSettings.asset`，不会随 `ProjectSettings` 同步。TapTap staging 有独立的持久
`Library`，所以主工程里手动选择 ETC2 不能保证正式构建也使用 ETC2。

正式构建必须保留这条显式设置：

```csharp
EditorUserBuildSettings.webGLBuildSubtarget = WebGLTextureSubtarget.ETC2;
```

否则 staging 可能继续使用 DXT5/BC3，导致移动设备在 `callMain` 期间用 CPU 解压纹理。

构建脚本还会尝试关闭 Unity Splash Screen，因为 Unity 2022.3 会把内置
`Splash Screen Unity Logo` 以 DXT5/BC3 形式打进 ETC2 包体。Unity Personal 会强制保留该
Logo，它无法通过 Texture Import Settings 修改，是当前包体中唯一允许的 BC3 例外；使用可关闭
Splash Screen 的 Unity 许可证时，构建脚本会自动移除它。看到该 Logo 的 CPU 解压警告时，
不要把它误判为工程纹理的导入配置回归。
