最后回到你那个"地点是底层规则的参数"的观察，我想给它一个更完整的表述。这个结构其实是双向读取的：从机制侧读，厨房、书房、演武场是同一个转换器类的不同实例，区别只在参数表——产出何种资源、消耗多少心相、随机事件表指向哪张。从叙事侧读，参数表的每一项都被角色和情境"认领"了：书房产学问是因为三师兄在那儿，工作减向心是因为这里工作轻松、大家都想抢——连一个负值参数都被给出了社会性解释（同门嫉妒你抢了轻省活）。用你熟悉的 Gibson 的话说，地点就是被叙事皮肤标注了 affordance 的接口：玩家读到的是"去找三师兄"，系统执行的是"调用转换器实例3"。武林群侠传其实也是这套骨架，活侠传的进步在于给几乎每个参数都配了叙事理由，让参数表看起来像一个有人情世故的门派。

这张图摊开之后，有几个只有在这个粒度上才看得见的结构特征，值得逐一指出。
第一，看转换层的副标你会发现，贡献出现在几乎每一个劳作型地点里，而演武场和弟子房是仅有的两个不产贡献的地方。这不是巧合，这是整个日程博弈的骨架：练功（投资自己）和休息（维护自己）都不缴税，只有干活缴税。于是每旬三点的分配问题被结构性地设定为"为门派活"和"为自己活"的拉扯——你所有的自我投资都要靠挤压义务劳动的时间来完成。这正是打杂弟子处境的机制化表达，主题直接长在参数表的分布上。
第二，注意参数表里那些负号。正心堂工作减向心，因为活轻松、大家都想抢；弟子房赌博赢钱加心相但减向心。这些负参数构成了一层暗的社会账本：凡是"占便宜"的行为都在向心（你在同门中的立足）上留下代价。它让每个地点不是单纯的正收益按钮，而是一次小型的取舍——你想清净读书，就要承受同门的白眼。这种"每个转换器至少带一项负产出或一项风险"的设计纪律，是这套系统里避免出现无脑最优解的主要手段。
第三，看资源池那一行的分类标签，六个池恰好六种性质各异的存量，没有重复：义务池（贡献，有强制排水口）、门派层存量（向心，注意它不属于赵活个人，它和门派人数相乘决定群战上场人数，是唯一一个直接写进集体层的个人行为累积）、资本存量（属性，进战斗）、消费存量（钱，经购买锻造回流到属性和装备侧——图上这条回流没画箭头，它从第四列出口斜着流回第三列的池）、关系存量（好感，和时间一起构成事件门的双钥匙：分支剧情的触发条件一个是时间、一个是对应人物好感）、以及保底代币（命运点）。一个养成系统的丰富度大致就取决于它能维持多少种性质上不可互换的存量，活侠传在这一点上做得相当满。
第四，两条虚线回路的不对称很有意思。右上那对是日常的、温和的负反馈：干活耗心相、心相低效率差、于是你去休息——它把系统往均衡推。左边那条红色的是月度的、惩罚性的正反馈：贡献赤字扣心相，心相低更难攒贡献——它把落后者往深渊推。一个稳态回路加一个失控回路，前者管日常节奏，后者管生存压力，这个组合决定了游戏的手感是"平时可以喘息、但月底的刀一直悬着"。顺带说，这也解释了社区为什么怨声载道地SL：当惩罚回路是正反馈时，一次坏骰的代价会被系统放大，玩家自然会选择在骰子这一层直接作弊。设计教训是，正反馈式惩罚必须配足够的场内挽回手段（命运点就是为此存在的，但数量给得太吝啬），否则玩家会去场外找工具。
最后一个观察是关于最右那一列的。失败→命运点→天命盘这条链，加上心相的阈值制（33/66两档解锁额外收益，按行动开始时的值判定），意味着这个游戏对随机性的态度是三层的：用心相调制概率分布的好坏，用天命盘暴露骰子让玩家看见命运，用命运点把最坏结果回收成资源。随机不是被藏起来的实现细节，而是被摆到台面上、配了完整上下游的一等公民——这大概是它最接近 Citizen Sleeper 的地方，只是执行的克制程度差了不少。

Claude：
这是个非常好的自我盘问，因为"机制"确实是那种人人在用、无人能给出一致定义的词。它不是你的问题——游戏研究学界为这个词吵了二十年。
先说词源，因为词源里藏着这个词的默认隐喻。英文是 game mechanic（可数，指某一个机制）和 game mechanics（统称）。mechanic 来自希腊语 mēchanē，机械装置。所以当我们说"机制"时,我们在做一个隐喻：把游戏看成一台机器，机制就是里面的齿轮和连杆——那些咬合在一起、推动状态变化的运动部件。这个隐喻解释了为什么这个词感觉贴切又说不清：它继承了"机器零件"的直觉（可拆分、可组合、有功能），但没有继承机器零件的清晰边界。一个齿轮的边界在物理上是明确的，而"跳跃是一个机制"和"马里奥的平台跳跃机制"和"这个游戏的核心机制是资源管理"里,"机制"的粒度从一个按键动作横跨到整个系统层,同一个词在指完全不同尺度的东西。
学界确实尝试过收紧它。最被引用的是 Miguel Sicart 2008 年那篇《Defining Game Mechanics》,他的定义是:机制是"代理为与游戏状态交互而调用的方法"(methods invoked by agents to interact with the game world)。注意他刻意借用了面向对象编程的"方法"一词——机制是动词,是玩家(或AI)能对游戏状态执行的操作:跳、买、掷骰、指认凶手。这个定义的好处是把机制和规则区分开了:规则是约束(你不能穿墙),机制是能力(你可以跳)。Adams 和 Dormans 在 Machinations 那本书里给的定义更宽:机制是规则加上这些规则运转起来的过程,偏系统侧。MDA 框架里 mechanics 又是另一个意思:游戏在数据和算法层面的全部构成,和 dynamics(运行时行为)、aesthetics(情感反应)相对。所以你朋友听不懂是正常的——这个词至少有三个学术定义在流通,而日常用法比这三个还要散。
那么存在更准确的语言吗?我的答案是:不存在一个更好的词,但存在一组更好的词。"机制"的问题不是它模糊,而是它把好几个应该区分的东西打包了。真正的精确化路径是拆包。按我自己的用法,当有人说"机制"时,他实际在指的通常是以下四层中的某一层:最底层是规则(rule),静态的约束和定义,"贡献每月结算、低于50触发事件"——这是法律条文。第二层是操作(operation/verb/action),玩家可执行的状态变换,Sicart 意义上的机制,"花一点行动力去厨房掌厨"——这是玩家的动词表。第三层是回路(loop/system),多个规则和操作耦合成的反馈结构,"心相调节产出、产出维持贡献、贡献赤字反噬心相"——这已经不是任何单一零件,而是零件之间的布线,我们前几轮画的图全在这一层。第四层是模式(pattern/dynamic),回路运转时涌现的行为倾向,"月底赶工"、"滚雪球"、"SL成瘾"——严格说这已经是 dynamics 不是 mechanics 了,但日常语言里人们照样叫它机制。
你会发现这四层恰好对应你已经有的词汇:规则是 Machinations 图里节点的参数,操作是 affordance 的机制侧,回路是存量流量图本身,模式接近你说的势——系统结构中蕴含的、尚未展开但必然展开的行为趋向。所以某种意义上你早就拥有比"机制"更精确的语言了,只是没有意识到"机制"是这些东西的模糊总称。

回路（loop）、反馈（feedback）、循环这一族词，直接来源确实是系统动力学，但系统动力学自己也是从控制论（cybernetics）和控制工程继承的。feedback 这个词的技术含义诞生于二十世纪初的电子放大器工程——贝尔实验室的工程师发现把输出信号的一部分"喂回"（feed back）输入端，可以稳定放大器（负反馈）或让它自激振荡（正反馈）。维纳在四十年代把这个概念一般化，指出恒温器、生物体的稳态、瞄准系统里是同一个数学结构，这就是控制论。Forrester 作为伺服机构工程师又把它带进管理和社会建模，改叫 feedback loop、causal loop。所以这条词源链是：电路工程 → 控制论 → 系统动力学 → 游戏设计。你之前猜编程里的"流"来自信号处理，这里是完全平行的另一条迁移路径,连起点都在同一批实验室。
"系统"这个词值得多说几句,因为它比"机制"还要被滥用,但它有一个相当扎实的核心定义。你说的"各个东西之间的相互作用"已经接近了,标准表述大概是:一组相互关联的部件,其整体行为不能从任何单个部件推出。定义的重心在后半句。一堆沙子不是系统——拿走一半,剩下的还是沙堆,行为不变;一台钟是系统——拿走一个齿轮,它不是变成"半台钟"而是变成不走的废铁。判据是:部件之间的关系是否承载了部件本身不具有的性质。所以严格说,"系统"指的不是那堆东西,而是那张关系网。这也是为什么系统动力学的图画的全是箭头——节点谁都看得见,值得建模的是布线。放回游戏语境:心相、贡献、行动点各自都只是一个整数,谁也不"是"系统;"每月结算的赤字会扣心相"这条布线接通的那一刻,系统才出现,因为此刻产生了一个任何单一数值里都不存在的性质——那个惩罚性螺旋。
