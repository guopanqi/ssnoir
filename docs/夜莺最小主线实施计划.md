# SSNoir 夜莺最小主线实施计划

> 本文是"最小叙事骨架"的**可执行改造计划**。目标是给城市生活 demo 一个提供
> 意义与驱动力的短故事:委托与保护。它把现有的三次占位公共交锋换皮成一条
> 有起承转合的小故事线,不新增机制、不接主线(异常货单等钩子不碰)。
> 设计源头见 [城市生活设计.md](城市生活设计.md) §8,工程规则见 [../AGENTS.md](../AGENTS.md)。

## 0. 故事总纲

### 0.1 要解决的问题

当前 demo 有推力(六天一次的公共事件)而无拉力:玩家不知道自己是谁、
为什么在这座城市行动、三次交锋意味着什么。机制上已经存在的目标
(非对称准备、工作阶梯、住所升级)没有被宣告,不存在于玩家屏幕上。

### 0.2 故事梗概

雨夜,老街酒馆的歌女(艺名"夜莺",真名全篇只在尾声出现一次)找到玩家
落脚的旅馆,用一小笔预付金委托玩家查清是谁在盯她的梢。她是从邻城一家
歌厅逃出来的:签了十年卖身约,跑在第七年。第一次交锋玩家出手护她,
麻烦从此转到玩家头上——收账人撂话"这是你的账了"。秘密分三层逐次揭开:

1. **开场**:有人盯梢、字条和死鸟。她说不知道是谁。
2. **交锋一后**:她知道。来的是歌厅老板派的收账人,要么带她回去,要么收赎身钱。
3. **交锋二后**:她逃走那晚,老板的心腹追到码头失足落水死了。老板咬定是她推的。
   这不是一笔账,是一条命的交代。

终局(交锋三)按玩家六天里攒下的活法分岔:付清赎身钱(富商/金钱)、
码头兄弟撑场(劳工)、程序干预点破对方不敢报官(官僚)、或无准备硬打。
尾声:酒馆里她第一次唱完整的一场,然后说出真名。

### 0.3 设计规则

- **她不是任务标记**:每两次交锋之间必须有她的场景;她始终在出力
  (预付金、情报、戒指),保护欲由她的韧性勾出,不靠眼泪。
- **她的安危是胜负的一部分**:交锋失败推进"夜莺安危"状态,可见、
  会改变后续场景;交锋三失败 = 她被带走,demo 的故事失败结局
  (不做硬 game over,与现有"交锋不终局"规则一致)。
- **所有故事状态可见**:安危状态卡、终局倒计时、酒馆停业期限,
  全部遵循设计文档 §1 的 Clock 可见性规则。
- **文本量上限**:每一拍两三屏;对话用 `play-dialogue!`,过场用 `spotlight!`。

### 0.4 本计划明确不做

- 不接异常货单/老周支线/正式主线;故事自闭环。
- 不新增引擎机制(唯一 C# 改动是初始金钱一行,见 N6)。
- 不做玩家死亡(引擎无此概念,健康归零的处理维持现状)。
- 不改交锋的机制结构(时钟/打手/援助),只换文案与增减终局动作。
- 旧 [酒吧.scm](../Content/scenes/world/酒吧.scm)(海伦线孤儿文件)不复用、不删除,留待清理任务。

### N2 夜莺故事模块与开场

**新文件:** `Content/scenes/world/夜莺.scm`
**改动文件:** [world.scm](../Content/scenes/world/world.scm)

#### 2.1 状态归属

新建故事闭包 `nightingale`,拥有全部故事状态:

```
story-stage   ; 0=未开场 1=受托查探 2=账转你头(二层已揭) 3=知道真相(三层已揭)
              ; 90=了断·成功 91=了断·她被带走 92=中途放她走
safety        ; 夜莺安危 0..3(0=安好 1=受惊 2=受伤 3=被带走)
scene-flags   ; 各幕间场景是否已看(唱歌/软选择/戒指,防重复)
```

世界协调器只保留它已有的公共事件排程(计数、间隔、阻塞);
故事阶段与安危归夜莺模块,通过 `set-global!` 镜像必要字段
(如 `'夜莺阶段`)供交锋脚本读取,与 `bout-idx` 的现有模式一致。

#### 2.2 开场·雨夜来客(第 1 天必办)

复用现有"关键事件阻止休息"机制(`rest-block!` / `rest-release!`):

- 新游戏 `story-stage = 0` 时,旅馆内出现必办节点**"回应敲门声"**
  (instant,不占骰),同时挂 rest-blocker"今晚有人敲门,先看看是谁"。
- 节点触发 `play-dialogue!` 开场对话(四至六句:委托、预付金、死鸟字条),
  然后:`add-item! "金钱" 预付金`、`story-stage = 1`、解除阻塞、
  `spotlight!` 一屏定场文案(你是谁、身上还剩多少钱、明天先去酒馆看看)。
- 开场对话文案要点:她付的钱刚够几晚房钱;她不哭,只是把钱按在桌上;
  委托内容是"查清是谁在盯梢",不是"保护我"——保护是后来长出来的。

#### 2.3 她的状态卡(目标外化,UI 载体)

`nightingale 'render-data` 在世界根节点渲染一个容器**"夜莺"**:

- observe 节点:她现在的处境描述(随 story-stage 与 safety 变化)。
- `story-stage ≥ 2` 后追加一条 Clock 风格的目标注记:
  "在了断之日前:凑够赎身钱,或让这座城站在你这边,或找到官面上的办法。"
  (三条路一句话,每天早上可见。)
- safety 以三格 Clock 显示,标题"夜莺安危",备注写明"交锋失利会让处境恶化;
  第三次交锋失败,她会被带走"。

**验收:** 新游戏第 1 天不处理敲门无法睡觉;处理后获得预付金、看到定场文案;
世界根出现"夜莺"状态卡;存读档后 story-stage / safety / scene-flags 不丢。

### N3 世界骨架接入故事

**改动文件:** [world.scm](../Content/scenes/world/world.scm)

1. **公共事件时钟换皮**。`public-event-clocks` 的标题与备注按
   `public-event-count` 输出故事化文案(文案暂拟,落地可调):
   - 第 1 次:"盯梢的人:N 天"——"酒馆附近的生面孔越来越多。"
   - 第 2 次:"收账人再来:N 天"——"他说过,这是你的账了。"
   - 第 3 次:"了断之日:N 天"——"这次他会带齐人手。"
   pending 态备注同步换成对应场次的"事情已经发生"文案。
2. **阻塞原因换皮**。`public-event-blocker-reason` 随场次输出
   ("酒馆出事了,必须过去"/"收账人堵在门口"/"了断之日,躲不掉")。
3. **交锋入口换皮**。`node-public-event` 的动作名随场次
   ("赶去酒馆"/"迎上去"/"做个了断")。
4. **结果回传扩容**。`on-public-event-result` 在现有 dock 通知之外,
   增加 `(nightingale 'on-bout-result public-event-count result)`:
   由夜莺模块负责推进 safety、解锁当晚对话、触发停业留疤(见 N6)。
5. **中途放她走的骨架处理**(见 N5 软选择):夜莺模块调用世界提供的
   `cancel-public-events!`(新增小函数:`public-event-count = max`、
   清 pending、释放阻塞、时钟消失)。骨架回到无剧情静默状态。

**验收:** 三次事件的时钟标题/备注/阻塞原因/入口动作各不相同且符合场次;
交锋结束后夜莺模块收到通知;调用取消后世界不再排公共事件、旧存档可读
(新增字段用 `assoc-get` 缺省)。

### N4 交锋换皮与终局三线

**改动文件:** [找上门的人.scm](../Content/scenes/encounters/找上门的人.scm)
(文件名与 `start-encounter "找上门的人"` 保持不变,只改内容)

#### 4.1 三场的叙事换皮(按 bout-idx 分支文案)

| bout | 场景 | 开场 spotlight | 胜利文案 | 失败文案 |
|---|---|---|---|---|
| 0 | 打烊后的酒馆后巷 | 收账人带两个打手堵住她,你迎了上去 | 他们退了,但收账人记住了你的脸:"六天后我来收钱。这是你的账了。" | 你被放倒在雨水里;撂话相同——账一样转到你头上 |
| 1 | 酒馆正门,来真的 | 目标是抢人、砸场子 | 又撑住了一次;他们的耐心在耗尽 | 他们伤了她、砸了场子(→ safety+1、酒馆停业,见 N6) |
| 2 | 了断之日 | 收账人带齐了人手 | → 尾声·真名 | → 尾声·她跟他们走了 |

时钟名同步换皮:"压住场子"→按场次("护住她"/"守住酒馆"/"做个了断"),
"对方逼近"备注写明本场失败对她意味着什么(可见的风险预告)。

#### 4.2 可选目标「异常货单」维持现状

它属于城市互联线,与本故事无叙事关联;仅调整其在场内的引入文案,
使其在酒馆场景中出现不突兀(收账人一伙随身的货单,来路不明)。

#### 4.3 终局动作(仅 bout-idx = 2 出现)

在现有非对称援助(叫兄弟/老周/通行证/塞钱)基础上增改:

1. **付清赎身钱**(新,富商/金钱线):`req-item "金钱" 赎身钱数目`,
   不占骰、即时,直接终结交锋为成功。文案:钱在这个故事里第一次
   买的不是道具,是一个人的自由。
2. **码头兄弟到场**(现有"叫兄弟"换皮,劳工自己人):效果不变,
   终局文案点明"一座不交人的城,成本算不过来"。
3. **程序干预**(现有通行证动作换皮,官僚线):终局文案点明
   "落水案在邻城没立过案——他们不敢报官"。
4. **塞钱**维持现状(30 金 = 2 格),它是小推进,不是终局解。

前两场(bout 0/1)不出现"付清赎身钱"——二层揭开前玩家不知道数目,
揭开后数目写进她的状态卡,倒计时同屏,构成"为什么攒钱"的答案。

#### 4.4 难度与安危联动

交锋三开场时读取 safety:`press-clk` 上限在现有递增基础上再
`- (min safety 1)`(前两场全败则更凶险),她的协助性旁白文本
(纯文案,不给数值)按 safety 分支:安好时她在场内递东西/喊话,
受伤时缺席。

**验收:** 三场开场/胜负文案各不相同;bout 2 且持有足额金钱时出现
"付清赎身钱"并可直接终局;bout 0/1 不出现该动作;时钟名随场次变化;
异常货单机制行为与改造前一致。

### N5 幕间场景(她的戏份)

**改动文件:** `Content/scenes/world/夜莺.scm`、`Content/scenes/world/老街酒馆.scm`

全部为即时对话节点(不占骰,一次性,看过置 scene-flag),由夜莺模块
按 story-stage / 天数条件注入酒馆(或旅馆)容器:

1. **打听换皮**(story-stage = 1):酒馆"打听消息"追加专属分支
   "打听盯梢的人"(占 1 骰,交际判定):好 → 得知盯梢者是外地收账人、
   打听她时用的是**另一个名字**(+1 情报);中 → 只确认是外地人;
   坏 → +1 压力,对方也注意到你在打听。任一结果均置"已打听"flag,
   交锋一后的对话会回收此细节(问过/没问过,她的反应两版)。
2. **第二层揭开**(交锋一结算当晚,必看):`play-dialogue!` 六至八句。
   卖身约、跑在第七年、赎身钱的具体数目(占位,见 N7 数值表)。
   置 `story-stage = 2`,她的状态卡更新目标注记。
3. **她唱歌**(story-stage ≥ 2,第 7 天后首次进酒馆):一屏氛围文案
   (spotlight),不给数值奖励。回压力的效果不加——这一拍的报酬是文本本身。
4. **软选择"我走就是了"**(story-stage ≥ 2,第 9 天后):她提出离开以免
   连累你。两个选项:
   - **"留下"**:一句回应文案;此后她的状态卡多一行"她留下了——因为你开口了"。
     动机从"接了委托"变成"我选的"。
   - **"让她走"**:`story-stage = 92`,调用 `cancel-public-events!`,
     她的状态卡变为一段怅然的结语后于次日消失;酒馆恢复普通打听。
     此结局不奖励成长点(成长点仍按现有规则来自公共小节推进)。
5. **第三层揭开**(交锋二结算当晚,必看):落水的人。`story-stage = 3`。
   若交锋二失败(她受伤躲在你住处),本场对话改在旅馆/住所节点播放,
   文案为受伤版——失败玩家拿到的是另一种更浓的相处文本,不是空白。
6. **旧戒指**(story-stage = 3,第 14 天后):她塞给你一枚旧戒指,
   "当了它,能顶一点"。两选项:收下(+15 金,占位)或不收(一段对话)。
   任选其一均置 flag。

"必看"场景的实现:复用 rest-block!(当晚不看完不能睡),与开场一致;
备注写明原因("她在等你回来")。

**验收:** 每个场景只出现一次、条件正确;打听结果影响交锋一后对话的两版分支;
软选择两条路都可走通,"让她走"后世界不再排公共事件;必看场景阻塞睡觉且
原因可见;存读档后 scene-flags 与阶段一致。

### N6 失败留疤与结局

**改动文件:** `Content/scenes/world/夜莺.scm`、`Content/scenes/world/老街酒馆.scm`、
[world.scm](../Content/scenes/world/world.scm)

#### 6.1 安危推进(on-bout-result)

| 场次 | 成功 | 失败 |
|---|---|---|
| 交锋一 | safety 不变 | 玩家掉的健康即是代价;safety +1(受惊) |
| 交锋二 | safety 不变 | safety = 2(受伤,她躲进你住处);酒馆停业 2 天 |
| 交锋三 | → 结局 A | → 结局 B |

酒馆停业:夜莺模块置停业天数,酒馆读取后隐藏工作、显示歇业 Clock
(遵循可见性规则);日终规则递减。

#### 6.2 三个结局

- **A 真名(成功)**:spotlight 两屏——酒馆,她第一次唱完整的一场,
  唱完走到你桌前说出真名(占位名,落地定)。她的状态卡变为长期状态
  "夜莺(真名)——她留在了这座城"。酒馆永久多一个 observe 节点
  (她在台上)。`story-stage = 90`。
- **B 她跟他们走了(失败)**:spotlight 两屏——她自己走出去,换你一条命。
  酒馆再没有人唱歌;你的住所物品栏多一枚"旧戒指"(纪念物,若此前未收过)。
  状态卡变为结语后消失。`story-stage = 91`。demo 的故事失败结局,
  游戏本身继续(不做 game over)。
- **C 怅然(中途放走)**:见 N5 软选择,`story-stage = 92`。

三个结局都不影响成长点既有规则(每次公共小节推进 +1,与成败无关)。

**验收:** 交锋二失败后酒馆停业两天且期限可见、她的场景改在住所;
三个结局的状态卡、酒馆状态、纪念物各自正确;结局后无残留阻塞或时钟。

### N7 数值与开局(唯一 C# 改动)

**改动文件:** [GameState.cs](../Engine/Runtime/Core/GameState.cs)(一行)、
`Content/scenes/world/夜莺.scm`(常量)

占位数值表(落地时按经济基准调,基准:普通工作约 10/骰、房租 40/3 天):

| 常量 | 建议值 | 依据 |
|---|---|---|
| 初始金钱 | 50 → **15** | 开局必须有生存压力;她的预付金是第一笔救命钱 |
| 预付金 | **30** | 15+30=45,首期房租 40 交得起但立刻见底 → 第一天就得找工作 |
| 赎身钱(终局) | **150** | ≈ 高强度打工 12–15 骰的净积累,可达但必须取舍;与"叫兄弟/通行证"两条免费路线形成真实对比 |
| 戒指典当 | **15** | 象征意义大于数值 |

全部常量集中定义在 夜莺.scm 顶部,便于试玩后统一调。

**验收:** 新游戏初始金钱 15;上表数值生效;旧存档不受影响(存档里已有金钱数)。

### N8 静态验证(收尾)

用 [GameTester](../TerminalApp/src/Testing/GameTester.cs) 或手动流程验证三条完整路线:

1. **金钱线**:正常打工+卖私货,第 18 天前攒到 150,交锋三用"付清赎身钱"终局。
2. **全败线**:三场交锋全部认怂/失败,验证 safety 1→2→结局 B 的推进、
   酒馆停业、受伤版对话、结局后世界干净。
3. **放走线**:第 9 天后选"让她走",验证公共事件取消、骨架静默、无残留。

另验证:第 1 天不回应敲门无法睡觉;每天早上世界根可见"为什么行动"
(状态卡 + 倒计时);任意存读档点往返后故事状态一致。

最终判据:**一个没读过设计文档的玩家,第一天结束时能说出
"我在保护谁、下一个坎是哪天、我打算走哪条路凑筹码"。**

## 5. 文案基调备忘(写 .scm 文本时的约束)

- 黑色电影腔:短句、具体名词、不解释情绪。她不哭;玩家不独白。
- 她的每次出场都要"给出"点什么(钱、情报、一首歌、一枚戒指),
  保护欲来自她的韧性,不来自可怜。
- 所有风险预告写在看得见的地方(时钟备注、动作副标题),
  惊吓只用于剧情揭示,不用于机制惩罚。
- 真名只出现一次(结局 A),全篇其他位置一律"夜莺"或"她"。
