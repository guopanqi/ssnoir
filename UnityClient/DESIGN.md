# SSNoir — UI 设计记忆「墨与纸」（Ink & Paper Noir）

这不是一份自上而下的规范，而是我们在真实对话与调整中逐步确定、再压缩下来的
设计语言记忆。它有三个作用：

- **回顾**：记录上一次我们共同确定的样子。
- **参考**：以后说「直接做一个 X」时，从这里的语言出发，保持一致。
- **起点**：它是可改写的。若某个元素不再让我们满意，就不必遵从——我们会重新
  互动式设计，在真实表现里确定新的样子，再把它压缩回这里，成为新的记忆。

用法约定：设计与执行在这里是一体的。这份文档是过程的长期记忆，不是不可更改的
边界。**若它与当前代码 / 真实表现冲突，以真实表现为准，并顺手更新这份记忆。**

适用范围：`UnityClient` 全部 IMGUI 界面。绘制与缩放的工程规则见 [AGENTS.md](AGENTS.md)。

## 总则（一句话）

**存在靠阴影，操作靠描边，金只做三件事。**

- **存在 = 硬投影悬浮（无边框）。** 世界里的节点、角落的手牌，都是「漂在深蓝图纸上的
  物件」，靠硬投影从背景里浮出来，不靠白线勾边。
- **操作 = 描边方块。** 你要点、要拖、要放的东西（骰子、物品、卡槽 Slot、按钮）才描一圈
  安静的白线 + 硬投影，成为「可操作的方块」。
- **金三岗位**：实心金 = 执行 / 主行动；金描边 = 选中 / 当前；金光呼吸 = 正在发生。
  除此之外金不出现。
- **印章红两件事**：高危标记、失败结果。不做按钮，不做装饰。

> 演进说明：旧版给世界节点描白线表示「存在」；这一轮改为「无边悬浮」——白线只留给
> 可操作的方块与卡槽。人物相册页是唯一保留外框的节点（因为内嵌照片块需要结构）。

## 色彩令牌

### 基底

| 令牌 | 值 | 用途 |
|---|---|---|
| SceneBg（参考） | `#1A1E27` | 场景背景，不由 UI 绘制 |
| Ink 墨 | `#0D1220` @ ≥95% | 节点填充。相对规则：与场景同色相、明度降两档 |
| BlockBg 方块黑 | `#06090C`（≈`rgba(6,8,12,1)`） | 手牌方块 / 已填卡槽的实心底，比 Ink 更暗一档，让方块从卡/场景浮出 |
| PhotoBlack 相纸黑 | `#0C0C0E` | 仅照片块（相册页 / 海报内图像底） |
| Paper 纸白 | `#EFEAE0` | 纸物件底、描边、暗版文字 |
| PaperInk 纸上墨字 | `#1C1A15` | 纸物件上的主文字 |
| HudBg | `rgba(10,12,18,0.92)` | 顶栏 / 纸窗等面板底 |

### 文字

| 层级 | 暗版 / HUD 上 | 纸上 |
|---|---|---|
| 主文字 | `#EFEAE0` | `#1C1A15` |
| 次级 | Paper @ 60% | `#4A453C` |
| 弱化 / 禁用 | Paper @ 35% | `#8A8375` |

### 强调色 — 做旧金 `#E8C35A`

全局唯一主强调色，三个岗位（见总则）。金底上的深字用 `#2A2107`。

### 印章红 `#B3402A` · 概率三色

失败 陶红 `#D16A4E` · 中间 赭黄 `#D4B158` · 成功 苔绿 `#93B06A`。健康 / 冷静等数值
按阈值取这三色（正常白、中段赭黄、危险印章红）。

### 书签色板（卡顶的类别 / 风险签）

签就是一张 Paper：`#EFEAE0` 纸底 + `#1C1A15` 墨字 + 1px 硬影，和弹出纸层、白底数值格同一张纸。
语义**不靠换纸色说**，只靠签左侧一道 4px 色条，色条取结果三色 / 金——和进度格、生命条的阈值上色
是同一套语言。同一语义永远同一道色条：

| 语义 | 色条 |
|---|---|
| 工作 / 低风险 / 修正为正 | 苔绿 `#93B06A` |
| 中风险 | 赭黄 `#D4B158` |
| 高风险 / 交锋 / 非法 / 不可休息 / 修正为负 | 陶红 `#D16A4E` |
| 机遇 | 金 `#E8C35A` |
| 交涉等中性类别 | 无色条 |
| 禁用 | 灰纸 `#CBCFD6` + `#4A453C` 字，无色条 |

（曾用一组马卡龙彩纸——鼠尾草绿 / 粉橘 / 粉蓝 / 淡紫——按语义换纸色；这五个颜色在「墨与纸」里
谁也不认识，压在暗卡上像别的游戏贴过来的，故废。）

## 三个图层

1. **世界层（墨 · 无边悬浮）** — Ink 填充 + 硬投影、无描边的节点，长期存在于场景。
2. **弹出纸层（纸）** — spotlight / 事件 / 结算：米白纸底 + 深墨字 + 硬投影，居中打断，
   图底反转承担焦点。深场景里最亮的永远是这张纸。
3. **黑底手牌层（方块）** — 屏幕左下 / 右下两个角落簇，近黑方块 + 白描边 + 硬投影。

## 节点（世界层，无边悬浮）

**分类是数据驱动的、单一入口** `CardDrawer.CardKind` / `Classify(node, anchored)`：
有 `Resolve` → 动作；锚定 3D 建筑（projected）→ 地点；带 `人物` 标签 → 人物；否则 → 普通。
（内容里目前没有「地点 / 人物」标签，真正的「这是个地方」信号是锚定建筑；标签留作显式覆盖。）

**通用**：Ink 填充 + 硬投影（偏移约 (7,9)、黑 50–58%），**无默认边框**。选中 = 金描边 2px；
正在发生 = 金光呼吸。直角无圆角。

- **牌子族更紧**：字号 21（卡标题 23）、横向内边距 12、行高 26。牌子是标记不是读物，
  一屏要同时看见十来块，才有「场景里有东西」的感觉。地点牌与普通 Container 共用这套。
  （试过把未聚焦的动作也画成牌子、碰到即展开——操作上不顺手、状态不清晰，已退回。
  动作与场景的比例问题准备走「多一层导航」：Container 是牌子，进去才见动作。）
- **动作 / 判定卡**（无边悬浮）：
  - 标题居中；副标题次级。
  - **所有卡的高度都由内容决定**（世界投影与网格瀑布流同一套规则）：时钟行、角色能力栏、标题、
    完整副标题、需求槽和底部操作区依次参与测量。任何位置都不得用固定卡高（旧的网格 190 / 地点 168）
    迫使内容互相挤压。人物卡的照片同样先由卡宽推出首选尺寸，卡再照此长高。
  - 测量与绘制必须共用同一组间距常量和同一个「副标题占多高」函数。两边各写一份 Clamp，
    就会同时长出「盒子长高了、文字没跟上」和「文字要 72、盒子只给 36」两类 bug。
  - **类别 / 风险书签从卡顶边探出**（像档案夹的分类页脚：贴着卡顶、从左上角往右排，文字正常横排、
    绝不竖排；一排放不下就往上再起一排，不裁、不折成「+N」）。不占卡内、不往左伸、不遮内容。
    **归属靠形状说，不靠留白说**：签的底边沉进卡内 3px、盖住卡的顶描边、底边不描——签是**长在**卡上的，
    不是搁在卡上的另一张纸。（旧版横贴在卡左缘外、靠撕口＋胶带说归属；卡贴屏幕左缘时只能挤回卡里
    压住标题，隐喻当场失效，故废。试过给外挂在网格里留出专用档位，代价是同宽的屏幕少一列，不值。）
    网格排版给每张带签的卡在上方预留一排签高；休息阻塞的「必须处理」签因此挪到卡顶**右**角。
    右缘能力片仍往卡内收，只留一小截探出卡边。
    书签是卡面最小的字，字号按 `UIScale.Scale` 反推、保证落到物理屏不低于 12px，签高跟着字走；
    整块 `PixelSnap` 对齐，否则非整数缩放下纸边和字一起发虚。
  - **时钟徽章里，标签和格数谁也不许被静默吃掉**：宽度不够时压缩的是进度格的格子与格距
    （有下限），不是裁标签、也不是少画末尾几格——少画一格就是把玩家的进度读错了。
  - **「只此一回合」这类话不是便签**：便签说这件事**是什么**（类别 / 风险 / 修正），
    钟说它**还剩多久**。只剩一回合，就挂一根一格的倒计时钟。
  - **需求骰位 = 居中横排的方块 Slot**（见下）。判定的核心骰**左侧**贴**技能药丸**
    （`交际` / `见识`…），一根细线连过去，「属性 → 骰子」横着读、不占纵向空间。
  - **空卡只有标题、副标题、骰位**；不套最小卡高，单骰判定卡约 126、无需求卡约 96。
    **操作台是装填后才长出来的附件**：任一槽位放了东西（或正在执行），卡片下方挂出一块——短金线 +
    近黑底 + 描边（可执行 = 金 / 未齐 = 淡白）——里面是执行按钮和命运预览。待命按钮是个什么都不能做
    的按钮，不值得每张卡常驻。无需求的卡（查看 / 即时）按钮直接在正文底。
    **操作台不在卡的矩形之内，卡片高度只由内容决定**：放进一颗骰子，卡片一像素都不长，
    排布里的位置也就不会跟着挪——玩家刚把骰子放进去，那张卡不能从手指底下溜走。
  - **执行按钮**实心金（`执 行`）；未满足 = `待 命`（描边态）；不可用 = 灰。
  - 底部**六格命运条 = 赔率条**：按准备值 B 查分布表**实心染色**（低面坏、高面好，
    档位之间留更大的缝，让坏/中/好的占比一眼读成连续区段而非六颗独立骰子），
    格内写命运骰面 1–6，骰面数字用该档的深色；命运骰落格时该格抬起 + 金描边。
    上方用连续区段文字摘要（如「1 坏 · 2–3 中 · 4–6 好」）。
  - **掷骰是卡片下挂附件**：主体卡不为动画让出内部空间；Ink 附件以短金线连接在卡片下方。
    命运高亮沿命运条**减速扫掠**（easeOutCubic）落在最终骰面 → **落格弹跳** → **定格**
    （命中格金描边、其余格压暗）；掷骰态附件用金描边 + 金光呼吸。
  - **结算继续留在同一附件位置**：结算态头部与掷骰落定态同位置同内容（无缝冻结，命运条不跳动），
    其下方**叙事 + 全部影响行**继续向下揭开。成功 / 中性 / 失败依靠结果文字、命运条和附件描边表达，
    不再把盖章压回主体卡。
  - **附件与层级**：操作台 → 判定条 → 结果条是同一个位置上的接力，一张卡同一时刻只挂一件；
    附件不参与卡片排布（不算进 footprint），只把自己夹回安全区。
    **活动卡压在深度之上**：装了骰子 / 执行中 / 判定中 / 结果还挂着的那张卡在同层最后画，
    不会被一张更近的卡遮住；四个状态首尾相接，所以从放进骰子到收起结果它一直在最上面——
    这不是存下来的层级，是每帧按状态算的，没有「掉回去」。所有附件再统一画在卡片层与物品栏之后。
  - **世界投影附件使用宽松版式**：附件宽于 340px 主体卡（通常 460–540px），命运条、叙事和影响行
    增加内边距与行距；世界投影 footprint 按附件真实宽高避让。只有网格卡受列宽约束，使用紧凑附件。
  - 右上角可选角色能力小栏（Ink 底 + Paper 描边 + 白字，无主题色）。
- **需求骰位 Slot（与手牌方块同族——让玩家看出是同一种东西）**：
  - 骰子 Slot：方块内大字 `D`（空）/ 骰值（已放）。
  - 物品 Slot：方块内 **符号 + 数量**（都放大强调，如 `$`+`×25`），**名称在方块下方展签**。
  - 空 = Ink 槽 + 占位符；放入 = 实心黑方块（BlockBg）+ 亮值。描边按状态给色
    （可放 = 金 / 手里有能匹配的 = 印章红 / 悬停 = 白）。
  - 尺寸 ≥ 手牌方块：骰子 56、物品 62（略大以容纳符号 + 数量 + 名称）。
  - （旧「负片白纸片 = 白底黑字」已弃用，改为与手牌一致的实心黑方块。）
- **地点节点（一行读完的牌子）**：左 = 可选的节点图标（约 24px），右 = 白字地名，左对齐。
  图标不是节点类型推断出来的通用符号：客户端初始化时一次性读取
  `Resources/UI/NodeIcons`，按图片文件名建立索引；存在与节点名同名的图片时才显示。图标尺寸
  恒定、不跟卡宽走。资源使用透明底的白色单色 mask，实际颜色由绘制层按卡片前景色着色；当前
  Ink 黑卡显示为白色。**宽度按图标与地名实际需要收敛**
  （约 136–260），高度就是一行——地点牌不套动作卡的 `MinCardHeight`，按最小触控尺寸兜底。
  一栋楼上挂三四个动作时，地名牌先吃掉半屏正是卡片叠成一摞的起因之一。
- **普通 Container**（无边悬浮）：同样只在存在同名节点图时把图标画在标题前；没有图片就只画
  标题（+ 副标题）。动作节点不读取节点图标。
- **人物节点（黑相册页，唯一保留外框）**：Ink 底 + PhotoBlack 照片块 + 下方白字注记，
  ±2° 微旋转。头像美术待定，占位 PhotoBlack + 白色人形。
- **时钟分两级**：节点自己的时钟画在**卡角徽章**；当前所在层（世界 / 当前地点）的时钟画在
  **顶栏**。两级不重复。

### 世界投射卡摆在哪

- **按身份分两种摆法，不看机位**：Container 牌子（地点 / 人物 / 普通）浮在自己锚点正上方——
  它是「这儿有个地方」，贴着指的东西才读得对；动作面板与结算残留退到**左右两条栏**，
  中间留给场景，引线说明它指哪儿。（旧规则按机位：只有 orbit 机位进栏，Pan 机位的室内
  交锋里几张面板就叠在房间正中。）
- **卡片可以飘满整个安全区**，只避开真的要用手指点的控件（返回键、右上那组按钮、宿主胶囊、
  骰子与物品方块）。避让**按横向跨度**算：飘在屏幕中段的卡一直探到安全区上下边缘，
  只有正压在某个按钮上下的卡才被推开。面包屑、天数、冷静条、半身像都是**读的不是点的**，
  卡片压上去无妨。绝不再用一条横贯全屏的上下边界——那两条墙挡住的东西并不横贯全屏。
- **一列放不下就并排分成几摞**，不是硬挤成一叠。顺序仍是「先上后下、再左到右」；
  引线会说明每张卡指的是哪儿，所以横向散开不会让人跟丢，叠在一起才会。
- 边界按整列的横向跨度算一次、全列共用。每张卡各按自己的跨度算的话，同一列会得到不同的
  上下限，解算好的间距又会在逐张夹取时被压平——「解算完再一张张夹回来」正是重叠的根因。
- **排布不是每帧重算的。镜头在动的时候它冻结**：上次解算的结果作为「相对锚点的偏移」跟着
  锚点平移，卡片像钉在世界上一样随镜头走；镜头停稳（锚点连续静止约 0.15s）再重算一次，
  卡片顺着弹簧摊开。排布的输入是锚点的屏幕投影，镜头一动就一直在变——绕着一栋楼转半圈，
  两个锚点的上下关系会来回交换，卡片跟着换位、分摞方式跟着变，每一帧都对，看着却糟透了。
  只有**离散的一次性变化**（多一张卡、少一张卡、卡片长高变宽）才在冻结期间照样重排。
- 卡片每帧**先按锚点位移刚性搬一次，再走弹簧**。少了这一步，弹簧就得去追一个正在快速移动
  的目标，卡片会拖在景物后面晃；搬过之后弹簧只需要消化排布本身的变化。

## 手牌 HUD（两个角落，无外框）

不再是底部一整条栏。拆成**左下、右下两个独立簇**，靠间距聚拢，不用外框统一——
只有方块（骰子 / 物品 / 按钮）描边 + 投影，其余（名字、冷静、生命体征、标题）直接落在场景上。

- **手牌方块（统一族）**：BlockBg 近黑方块 + 白描边 + 硬投影；上 = 大字（骰值 / 物品符号），
  下 = 可选小标签（物品的数量 / 金额）。选中 = 金描边 + 上浮几像素 + 金字；禁用 = 降到 35%。
  尺寸 56。骰子、物品、卡槽 Slot 共用这一套形态。
- **左下 · 人物簇**：每个行动者自底向上 `行动骰 → 名字/职业 → 冷静`。
  所有行动者共享同一条**冷静 / 名字 / 骰池基线**；只有**主角（最左第一个）**从冷静线往上多挂
  **队伍生命体征**（健康，快照级属性，阈值上色）。每个行动者各自拥有冷静与行动池；主角有四个固定位置、同伴有一个，低冷静或宿醉必须以对应骰池位置的状态标签直接标出，骰子仍可自由投入行动。每加一个同伴向右复制一段下半截。
- **右下 · 物品 / 功能**：物品方块（符号 + 数量 + 名称）+ 功能键（`回家` / 遭遇中为 `休息`）。
  功能键是**实心方块**（与骰子 / 物品同语言），不是空心描边。
- 血量 / 金钱等数值低调；收益变动金字，损失印章红。

## 顶栏（黑底常驻，干净三簇）

从左到右是一句「我在哪 → 世界怎样 → 抽身看队伍」：

- **左**：`返回` + 面包屑（当前位置）。
- **中**：当前所在层的**时钟徽章**（Ink 底 + 40% 描边 + 标签 + 段 / 倒计时 / 饼，居中横排，
  进行中 = 金）。
- **右**：`卷宗 / 成长` 等入口。

所有元素压在分割线（y≈88）以内，别越界。

## 弹出纸层（白版）

**成长面板**（横屏左右两半）：左半是这个人——相纸黑上的霓虹半身像、展签一行（名字 / 成长 N /
「可用 M」墨牌）、四项能力画成四个墨方块骰面（大字数值在上、名字在下、加点钮在底）；右半是
他认识的人——每个给过支援的人一张名片（人名 / 《办法》/ 一句说明），带着的那张金描边 + 金签，
点别的名片换人，交锋里只读。没有圈子声誉：你和谁的关系就是你和那一片的关系。


Paper 底、PaperInk 文字、硬投影偏移 (5,6) 黑 @ 50%。叙事物件（海报、信、告示）允许
±1–2.5° 旋转；功能窗口保持水平。纸上按钮：主 = 黑底白字实心块；次 = 1px 黑描边透明底。
图像区 PhotoBlack 底 + 白色图形，图下配展签式小字（居中、拉字距）。

- **Spotlight / 海报**：大幅纸面 + 照片块 + 居中大标题（拉字距）+ 说明小字。
- **旁白 / 氛围字幕**：电影字幕的做法——画面底部居中的 Paper 白字，底下垫一条上下淡出的
  暗带（Ink @ 62%，两端各三成是斜坡），再加一层贴字的黑投影立起笔画。暗带没有边，也不是
  纸：城市是白描线，旁白一旦做成纸卡就读成「界面里多了一张卡」，而不是一句画外音。

## 阻塞对白舞台

`play-dialogue!` / `play-remote-dialogue!` 不使用世界锚点气泡，而是临时接管全屏：暗化世界、
收起世界的全部界面（标签、动作卡、卷宗、顶栏，台上只留城市和人），
把这段对话里出现过的人物都立在台上，并在底部展开 Paper 对白框。立绘只保留人物剪影与随形阴影，
禁止矩形底板、矩形边框和矩形投影。主角立绘固定在左，NPC 固定在右（右边只站一个，新来的把上一个
顶下台）；说话人「世界」作为旁白，人物留在台上但都压暗，只显示居中的对白框，不伪造人物立绘。

舞台是人偶戏。默认规则不写在脚本里：说话的那个亮，听着的那个压暗到三成多（不是灭掉——他还在场，
只是这句不是他的）；人上台时通电点亮。情绪不从脸上出（霓虹的脸只有两三笔），从姿势、位置和灯出。
台词上的舞台指示只有四个词，身体两个、灯一个、震一个：`:pose` 换哪组灯管（姿势图按
`Portraits/Neon/<人物>_<姿势>` 命名，全角色共用一套小词汇，`基础` 回招牌姿势）、`:move` 逼近中间或退回
边上、`:light` 灯、`:shake` 一震。每一项都是终态，渲染只负责从上一个终态过渡过去，跳过动画也是同一幅
画面；没写的保持上一句。换姿势是招牌切换——旧灯管灭、新灯管通电点亮，两组短暂重影。

灯是一套通用的视觉语言，不分人物；每个人的灯就是他画里的颜色（白管人物是冷白，夜莺是蓝）。
状态三种，保持到下次改变：`surge` 灼——光晕撑开、光池炸开、这个人的颜色洗半个台，是内在翻涌
（怒、骄傲、下决心）；`faint` 弱——光晕全收只剩细管，人还在灯没了（羞、退、认输）；`normal` 收回。
`ember` 残烛——欠压的钨丝，管子发暗橙、没有光晕（消沉、快熄灭）。电流是另一个轴：`pulse` 一两道亮光
沿管子慢慢绕整个人一圈（亮的是管子那一段，不是小球），`racing` 又多又快又长（心跳加速）。
骨架折线离线时按空间连续串成一条巡回，电流才像一根管子从头绕到尾，不在断管之间乱跳。说话人 `surge` 时听者被压得更暗——
谁的光占屏幕谁占上风。
事件三种，几拍就过去：`flicker` 颤——接触不良闪几拍（被戳中、动摇）；`relight` 燃——全灭后从脚到头
一格一格重新点亮（回过神、站起来）；`blackout` 黑——整台黑半秒再一起亮（这句之前的沉默）。
一格一格点亮和局部熄灭都是同一张贴图切横向条带分别画，不拆图。

代码要知道管子在哪，靠离线加工（`tools/portrait-neon/process.py`）：把每张立绘细化成骨架折线
（`<名>.neon.json`），并拆成去点缀色的线稿和点缀色蒙版两层。有了骨架，电流才有路可走；有了两层，
人物的标志色才能由剧情改（`set-portrait-accent!`，全局 `立绘色/<人>`）——林从原教旨的冷蓝慢慢变暖，
是观念的改变落在灯上，不是一瞬间的相变。

声音是灯的一部分，不是新的词：镇流器嗡鸣在人声底下、没人说话时抬起来、`surge` 时升高；`flicker`
自带滋滋和打火，`relight` 自带闸刀，`blackout` 自带断电，换姿势自带继电器一响。全是电的声音，
所以全部程序合成，没有音频资产。闪烁不是均匀地抖，是一段写死的
节奏：亮、死一小段、打火过亮一下、再死、半亮、回来——间隔要长、死得要黑，隔着距离也看得出灯坏了。

画面还有一个词 `:screen`，对象是整个屏幕而不是某个人，旁白也能下：`negative` 负片——环境翻成纸白、
城市消失、灯管变成墨线、对白框墨底纸字，是白热化的局面（贴图 alpha 来自灰度，同一张图染墨画在纸上
就是黑管子，不发光、没有光晕）；`normal` 翻回来；`flash` 白闪一帧（负片里闪黑）——枪声、闪光灯、
耳光，和灯的 `blackout` 是一对。负片是一段而不是一句：在一段白热化的对话开头翻进去，在某个节点翻回来。

灯的语法在负片里不失效，换一套纸上的物理：`surge` 不是发光而是墨渗开——线更重、周围一圈灰晕、
一团灰从这个人脚下渗到对面；`faint` 是墨淡了；`flicker` 是线断掉露出纸；`relight` 是线从脚往上重新
画出来；`blackout` 是整页空白再回来。纸不反光，所以没有光池和倒影。

立绘动画属于“人物登场”，只在一段对白开始或人物首次开口时点亮；同一人物连续说第二句时保持原位，
不得逐句重复点亮。对白框属于“句子更新”，每句新台词都做一次短促上弹并回落，文字随后以打字机效果
逐字显现。打字过程中全屏点击先立即显示本句全文，全文显示后再次点击才推进下一句。

对白期间任意位置左键都推进下一句，世界卡片、顶栏、底栏、相机拖拽和已展开面板必须通过
`IsInputLocked` / `IMGUIInteractionContext` 显式禁用；对白舞台绘制在这些 UI 之上。非阻塞
`play-banter!` 仍使用依附世界锚点的小气泡，不能与阻塞对白共用版式。

### Banter 气泡

气泡尾巴指向**世界里的人**，不指向卡：节点有锚点时落点是锚点上方一个人头的高度，卡片只是
挂在那个人身上的把手。等距视角下人形很小，认不出谁在说，所以有霓虹立绘的说话人在气泡左侧带一张
44px 头像——PhotoBlack 底 + 霓虹头部裁切，和纸层上的照片块同一套语言；没有立绘的只写名字，
不做占位头像。队员仍从底栏人物块引出（队伍在场景里没有人形）。

角色立绘按 `Resources/Portraits/<说话人>` 命名，正式资产使用带 Alpha 的 PNG。缺图时显示同尺寸的人物名占位牌并报警，
不得悄悄退回世界气泡；普通 `play-dialogue!` 的说话人不在场时仍展示同一舞台，但另行报警，
明确的场外对白使用 `play-remote-dialogue!`。

### 霓虹立绘（例：夜莺）

同名资源若存在于 `Resources/Portraits/Neon/<说话人>`，它优先于普通立绘。这不是把普通半身像
简单染蓝，而是“人物以一盏招牌进入画面”：背景进一步压黑，保留灯管图形的完整轮廓，以通电、低频呼吸
和极弱的湿地倒影表达存在。为避免与城市白线模型混淆，霓虹只给与场景有明确关系的角色，默认色只允许深蓝
与白；底部 Paper 对白框继续承担阅读，不改成发光文字。

### 必须处理的动作与路径

休息阻塞表中的目标是“正在等待玩家处理”，不是失败或高危，不使用印章红。

- 屏幕内的目标动作：金光呼吸，并挂实心金色「必须处理」签。
- 通向目标的容器：稳定的金色侧边索引与空心「目标在内」签，不呼吸。
- 路径地点的 Anchor 在镜头外：导航签贴住视口边缘，写地点与阻塞原因；点击只移动当前镜头，
  不设置节点 Focus、不自动进入容器或执行动作。Pan 相机保持高度与朝向平移到目标，Orbit 相机围绕
  既有 orbit pivot 转到目标所在方位。Anchor 进入镜头后导航签消失，由正常地点卡接管。
- 有世界 Anchor 的重要节点始终属于世界空间；移出镜头时折叠成导航签，不得作为网格卡兜底。

## 镜头

- **落点永远是场里摆好的那个机位**。建筑的取景（方位、距离、俯角）是设计过的，运行时不重算、
  不按玩家来的方向就近取一个角度——那样会从背面收场。玩家手动转过的机位只在本次聚焦内有效，
  焦点离开再回来，回到设计机位。Pan 机位是例外：它是玩家在城市上空的位置，不是设计好的一张镜头，
  回去时回到玩家自己平移到的地方。
- **改的是路，不是终点**。不走 Cinemachine 的直线混合（会先把目标甩出画面、到了再转回来），
  而是围绕一个**注视点**走圆弧：方位取最短一侧，俯角与半径同步过渡，过程中目标一直留在画面里。
  节奏沿用 Brain 的默认混合时长。
- **Orbit 与 Pan 是同一条曲线**。两端都用「注视点 + 相机在它周围的极坐标」描述：Orbit 端的注视点是
  orbit pivot，Pan 端是它中心射线落在地面的那个点；过场期间注视点自己也在两端之间滑移。
  于是进和出是同一条曲线的正反读，Pan→Pan 自然退化成原来的直线平移——不需要为每种组合单写一套。
- **过场不可打断**。推进途中输入不接管镜头——点击、拖拽都不行，这一趟送的就是那张镜头，必须到位。
  按住不放跨过落点的，落地后继续拖即可接手，不用重新按。被别的系统（舞台过场）打断时直接落到终点，
  不留在半空。
- 拖拽本身的判定：按下只是候选，指针走出一小段距离才算接手，接手当帧重新取一次起点，
  所以从移动中的镜头接手不会跳。这条同样保护边缘导航签的镜头插值——一次点击不该把它掐掉。

### 减少动画

对齐 macOS / iOS 的同名系统设置：华丽的空间位移换成不移动的透明度过渡。开关是玩家设置不是调试
拨杆，入口在顶栏「设置」，不挂在 Debug 面板下。

- **靶子是旋转和推近，不是所有运动**。让人晕的是"绕着一栋楼转过去"和"往里推"；纯位移反而
  维持方位感。所以打开后弧线和推拉整段取消，灯标平移只是缩短，保留。
- **一个 3D 场景里没有两个画面可以互相溶解，旧画面得自己留下来**：切镜之前另开一台相机
  照着旧机位渲进 RenderTexture，新机位在这张贴图底下就位，贴图退掉的过程就是整个过渡。
  用相机渲而不是抓屏：抓来的后台缓冲是已编码的显示值，再走一遍 GUI 采样就多编码一次，
  线性工程里整张冻帧会发白；相机渲 RT 是引擎常规路径，颜色空间和朝向都不用操心，
  冻的也只有世界，UI 不参与。
- **溶解与黑场分工，因为它们是两种叙事事件**。焦点切换高频、只是换个看的对象，用溶解；
  穿门换场低频、真的换了地方，保留黑场对切——黑场在这游戏里已经是"穿门"的语汇，
  两者混用玩家就分不清"我看了另一栋楼"和"我进了另一个场景"。

## 排版

- 标题拉字距（中文 2–6px，字数越少拉越开，如「执 行」）。
- 「图形在上、小字在下」的展签结构；不用「图标 + 文字并排」的软件式排法。
- 动作名大字：两字用大号，四字自动降档。禁 emoji。
- **字号只有一个入口** `IMGUIStyles.FontSize(baseSize)`：把虚拟字号吸附到「×Scale 后是整数
  物理像素」的值，消掉 0.75 / 1.25 缩放下的次像素模糊。组件里不要写裸的 `fontSize = 12`，
  更不要自备一份「× Scale」的换算——`GUI.matrix` 已经缩过一次，再乘等于平方缩放。

## IMGUI 绘制技法（低成本配方）

全部基于 `DrawTexture` / `DrawOutline` / `DrawLine`：

- **无边悬浮**：先在偏移处画纯黑矩形（硬投影，无模糊）再画 Ink 本体，不描边。
- **方块 Slot**：空 = Ink 槽 + 描边 + 占位符；填 = BlockBg 实心块 + 亮值。
- **手牌方块 / 卡槽同族**：BlockBg + 描边 + 硬投影 + 大字（+ 下方小标签）。
- **时钟徽章**：Ink 底 + 40% 描边 + 标签 + 段（金 / 25% 空段）/ 倒计时框 / 饼。
- **书签**：1px 硬影 + Paper 矩形 + 左侧 4px 语义色条 + 上左右三边墨描边（底边沉入卡内不描）+ 墨字，从卡顶边探出。
- **金光呼吸**：向外扩 2px/4px 各画一圈金描边，alpha = 基值 ×(0.6 + 0.4·sin(t))。
- **盖印**：旋转 −10°~−15° 的圆框 + 大字，alpha 80%。
- **生命体征细条**：标签 + 底槽 + 按阈值上色的填充 + 数值。
