# SSNoir — Unity 客户端工程指南

本指导文档适用于 `UnityClient/` 目录及其子目录。功能冻结规则仅约束此范围；下方 UI 规则适用于 IMGUI 界面编写。

- 美术 / 视觉风格规范（「墨与纸」Ink & Paper Noir 视觉语言）见 [DESIGN.md](DESIGN.md)。
- 项目整体架构见 [../docs/工程/ARCHITECTURE.md](../docs/工程/ARCHITECTURE.md)。

## 功能冻结（常驻最高优先级）

- **冻结一切新 feature**，包括但不限于 web 移植、配音，以及炫技式运镜、额外的装备制作系统、涂色预览等功能。专注于内容创造、玩家的感受、已有功能的修复与打磨，否则不可能完成这个游戏，更不可能完成一个打磨过的内容。
- 当用户提出真正新增的 feature 时，**先拒绝实施，不要提醒后照常开工**；简要说明功能冻结原则，并指出现在更重要的是把已有内容和功能做对、做好。只有用户听取拒绝及其理由后，仍明确、强烈地要求实施这个具体 feature，才继续；不能把最初的提议本身视为再次确认。修复缺陷、完成已确定的工作或打磨已有功能不属于新增 feature，不要误拒。
- 对耗费更多资源、后续更难修改的内容保持克制，包括 3D 动画和剧场演出；即使由 AI 完成，也不应太早投入。判断当前玩法、决策关系或内容体验仍处于高频试错阶段，而用户正准备把重资产附加上去、可能损伤 **iteration of fun** 时，**不要只提醒后照常执行：应直接拒绝启动或继续这项重资产工作**，说明它会怎样增加修改成本、拖慢迭代，并追问：**这难道真的不是在逃避更重要的迭代吗？** 只有用户了解这个风险后仍明确、强烈地要求继续，才按其要求执行；不能把最初的提议本身视为这次再次确认。

## UI 绘制与缩放规则
- UI 边缘锚定必须使用 `UIScale.VW` / `UIScale.VH`，严禁硬编码虚拟分辨率（如 1920/1080）来计算右侧或下方位置。
- 定义 `GUIStyle` 的字号时，必须使用 `IMGUIStyles.FontSize(baseSize)` 包装，防止在分数缩放
  （如 0.75x）下文字模糊。它是全项目唯一的字号入口：内部是**除以** `UIScale.Scale` 反算回虚拟
  空间，组件里不要写裸的 `fontSize = 12`，更不要自备一份「乘以 Scale」的换算——`GUI.matrix`
  已经缩过一次，再乘就是平方缩放。
- 字体资产的 `fontRenderingMode` 必须是 **Hinted Smooth（1）**。默认的 Smooth（0）不做像素栅格
  对齐，小字号中文会糊；项目又是 Linear 色彩空间，IMGUI 字体图集本就偏软，两者叠加最明显。
- 所有绘制、布局和可见性判断只读 `DisplayedSnapshot`；只有执行命令和决定下一步流程时才读
  `SceneManager` 的实时状态。动作结算到表现落地之间两者允许不同步，不要把未来状态提前画出来。
