# 写 SSNoir 的 Scheme 内容

把 [engine.scm](../../Content/scripts/engine.scm) 当作 DSL 的唯一事实来源。使用陌生构造、签名不确定、
遇到接口报错或准备扩展 DSL 时，用搜索定位并读取相关定义与调用点；**不要为每次内容修改通读整个文件**。
参数个数、哪些构造必须传 `outcome`、风险等级、势力名、能力范围和节点形状，应由
`engine.scm` / `NodeConverter.cs` / `NativeFunctions.cs` 的 `error` / `throw` 强制，而不是靠本文复述。
**你已经会 Scheme，本文不教语法。**

写节点优先用包装函数（`container` / `action` / `instant-action` / `observe-action` /
`roll-action` / `工作`），让构造器表达节点的用途。现有包装函数无法表达所需的 `subtitle`、`tags`、
`clocks` 或 `disabled` 组合时，可以使用裸 `node`；若同一种裸结构反复出现，优先补齐 DSL 接口，
不要继续增加一次性包装函数。

本文只讲三件从代码里看不出来的事，以及一个真陷阱。按需展开：
- 写对白 / 演出 → [references/表现.md](references/表现.md)
- 写交锋 → [references/交锋.md](references/交锋.md)

## 一、玩家可见文字的口径

世界是**上世纪美国、黑色电影（Chandler / 马洛）风格的港口城市**。语言是中文，但**世界不是中国**。

> 唯一判断标准：**把这句直译回英文，是不是三四十年代美国人会说的？** 不是，就改。

典型穿帮词：印子钱、驴打滚、衙门、老爷、大洋 / 银两 / 铜板、钱庄、镖局、江湖、拜码头、跑堂。
对应改写：高利贷、当铺、警察局、酒保、码头工头……货币一律写抽象的「金钱」，不写币种年代。
拿不准时选**朴素、去地域化**的写法，别用有强烈本土色彩的俗语。

节点名、副标题、标签、outcome 文本、台词、时钟名、物品名——都算玩家可见。

## 二、引擎背着你做的事

### 效果条是自动生成的

动作 lambda 里对库存、健康、冷静、关系、成长的**实际**修改，会按执行顺序写进 `ActionReport`，
前端在卡片上渲染成效果条。所以别再手写「金钱 +8」这类展示文本：

```scheme
(outcome "勉强完成" "货送到了,但你累得够呛。"
  (lambda ()
    (add-item! "金钱" 8)                    ; 自动生成：金钱 +8
    (spend-composure! 1)                    ; 自动生成：冷静 -1
    (change-faction-relation! "劳工" 2)))   ; 自动生成：劳工关系 +2
```

从状态变化推导不出来的结果，用 `(result-note! "解锁：码头账房")` 补一条中性条目。
资源槽投入算成本、不进效果条；所有条目记的是 clamp 之后的**实际**变化量。

结果描述只有 `outcome` 这一处来源——不要在 effect 里再 `notify!` 一遍。

### 判定不是掷骰求和

准备值 **B = 放入骰 + 技能 + 修正**，B 直接查一张按值定制的六格分布表（坏 / 中 / 好各占几面），
命运骰 d6 只决定落在哪一格，不参与求和。**分布表本身和每一档的设计性格写在
[FateStrip.cs](../../Engine/Runtime/Core/FateStrip.cs) 的类注释里**，那是唯一来源。

你写内容只需要知道：技能 0–4；`modifier` 是玩家可见的数值修正，负数更难、正数更容易，
它通过抬高 / 压低 B 让你在表上**整行移动**。冷静不给判定施加隐藏修正——低冷静的骰子降点
在每天 / 每个交锋回合重掷时就已结算，并直接显示在手牌里。

### 状态有明确的 owner

| 状态 | 家 |
|---|---|
| 地点、人物或故事模块拥有的状态 | owner 闭包里的本地 `define`；需要持久化时显式实现 `save` / `load!`，并接入 `world-save` / `world-load!` |
| 没有更自然 owner、确实属于整个游戏的状态（章节、声誉、全局 flag） | `set-global!` / `get-global` |
| 队伍 / 库存 / 成长 / 骰子 | 类型化对象，走 engine.scm 的包装函数 |

判断标准不是“有几个地点会读”，而是：**谁负责创建、解释、保存和终结这个状态？**
把状态放在生命周期最小且明确的 owner 中。人物或故事可以横跨多个地点，仍应由自己的闭包拥有状态；
跨模块读取走 owner 暴露的消息，不因此把状态搬进 global。

### encounter 是一次性子场景

encounter 读取本场所需的最小输入，只返回结果；外部 owner 负责解释和结算结果。
修改 encounter 或它的调用方时，读取 [references/交锋.md](references/交锋.md)。

## 三、必须由你决定的事

引擎不会替你选，选错也**不会报错**。这些才是写内容时真正在做的判断。

**失败要不要额外花冷静。** `(spend-composure! 1)` 写在对应的 bad outcome 里，不是 `roll` 的
隐式默认。有些失败只推进场面时钟，有些失败才让主角破防。冷静已为 0 时这个调用会改成扣健康，
并自动附上生理击穿说明。

**工作用哪一种。** 带薪劳动用 `(工作 ...)`，不产关系；只有内容语义确实偏向帮忙、经营人情或
承担额外风险时才用 `(关系工作 ...)`（好结果自动 +1 势力关系）。非法行动用 `(非法工作 ...)`——
「非法」是独立维度、不是第三档风险，而且**若可能损害其他势力，必须在 subtitle 里提前点名**
（例如"事败将得罪官僚"）。风险只有低 / 高：低风险的坏结果保持轻度，高风险的中立结果也可以
有损耗、坏结果要明显更重。

**这个状态玩家看不看得见。** 凡是持续若干回合、延迟发生、或下一回合消失的东西，都必须用
可见 Clock 告诉玩家，不能只藏在脚本计数器里。`make-clock` 的 `note` 就是用来解释
"归零 / 填满会发生什么"的。

**玩家能不能认出这个人物。** 具名人物节点标题只写玩家日常称呼的名字。当人物卡或行动卡可能
脱离父容器独立出现，或当前画面不足以让玩家可靠判断其身份时，在 subtitle 中重申身份
（`乔 / 码头搬运工，独自抚养孩子`）；父级语境已经明确时，不为满足格式机械重复。
全名只用于档案、名片、正式介绍，或剧情中特意叫全名的时刻。

**说明卡会不会挡路。** `observe-action` 提供额外背景是好的，但删掉它之后，玩家仍须能从标题、
动作和 Clock 看懂"现在要做什么、失败会怎样"。需要"既有说明、又有子动作"时，把说明做成一张
`observe-action` 子卡放进 `container`，而不是给容器加 `:resolve`。

**休息阻塞要提前告知。** `rest-block!` 之后引擎会拒绝推进回合，但那是兜底——住所的休息节点
必须用 `:disabled` 和原因标签提前展示，别让玩家点下去才吃到报错。读档时先 `clear-rest-blockers!`，
再由各地点按自己的持久状态重新注册；不要把注册写进渲染函数。

## 四、Schemy 的边界

节点列表常写成 `(append (if 条件 (list …) '()) …)`。**`if` 缺 alternate、或 `cond` 全部落空时，
结果是 unspecified 而不是 `'()`**，喂给 `append` 会报错（错误信息会直接告诉你这件事和修法）。
标准 Scheme 里 unspecified 常常悄悄溜过去，这里不会。

`case`、`call/cc`、方括号 `[...]` 不支持。能力总览见
[schemy-master/AGENTS.md](../../schemy-master/AGENTS.md)。
