# 写交锋

## 零、交锋回应规则

世界日终继续使用 `define-turn-rule`；交锋里玩家点「结束回合」后的场面回应使用
`define-opponent-rule`。两者不是同一套生命周期，不要混用。

`define-opponent-rule` 按文件中的书写顺序执行，一条规则就是一个因果批：后一条可以读取前一条已经
提交的状态，移动、拆分或合并规则因此可能改变结果。一条规则内部登记的多个 `beat!` 在规则上视为
同时，不得读取彼此修改后的状态；确有前后因果时拆成两条 opponent rule。

```scheme
(define-opponent-rule "他们会还手"
  (lambda () (not finished?))
  (lambda ()
    (beat! "对付皮夹克" "他攥紧拳头，迎面压了上来。"
      (lambda ()
        (coat-attack 'advance! -1)
        (if (coat-attack 'empty?)
            (spend-actor-composure! 'player 3)
            #f)))))
```

`beat!` 的 thunk 是状态变化的唯一真相。钟、冷静、伤势与 banter 的实际变化由引擎捕获；不要再写一份
展示用 delta。没有玩家可感知内容的记账可以直接写在 rule 中，不必为了每次 `set!` 造 Beat。条件不成立、
或没有登记可见步骤的规则不会在客户端留下空拍，但其中的状态变化与交锋终止仍然生效。

规则运行期间调用 `auto-action!` 只登记下一轮的强制行动。所有回应和回合末维护完成后，引擎先摇出
完整的新骰池，再按登记顺序用真实骰子逐个兑现 AutoAction；全部完成后，剩余骰子才交给玩家。
交锋结束、主角倒下或切回世界会丢弃尚未兑现的登记。

## 一、入场与场内转场

- **场内转折用阻塞式重对话。** 走完一段路线、敌人正式出面、局面换幕——这些真正改变题面的事件，
  用 `play-dialogue!` 交代过程，然后更新阶段状态、让下一份 render tree 接管场面。
  转场对话同样受锚定约束（见 [表现.md](表现.md)）：动作内只能让旧画面已有的角色说话；
  刚进入下一幕的角色若还没有锚点，先用"世界"叙述它的出现，或拆成下一幕里的独立对话。
- **`spotlight!` 只宣告结果。** 它适合交锋成功 / 失败 / 阶段结算这类告示卡，不承担人物对白，
  也不拿来替代换幕过程。
- **入场摆盘面用 `'load!`，不用 `'set!`。** `on-encounter-enter` 里把钟拨到初始格是摆盘子，
  不是玩家造成的变化；`'set!` 会写进发起交锋那个世界动作的报告，点进去先弹一张空的
  行动结果（曾经实测漏出过"踪迹 +3"）。`'load!` 静默设值，越界直接报错，正好拿来做初始化。
