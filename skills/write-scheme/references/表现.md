# 表现接口：谁在说话、阻不阻塞、锚在哪一帧

写对白和演出时读这里。八个接口容易记混，但它们的差别主要是三点：**阻不阻塞、有没有说话人、
锚定的是动作前还是动作后的画面。**

## 八个接口

| API | 阻塞? | 结构 | 谁推进 | 用途 |
|---|---|---|---|---|
| `(notify! text)` | 否，定时消失 | 一行文字 | 自动淡出 | 系统提示、背景事件播报；**不代表"这次行动的结果"** |
| `(spotlight! title subtitle)` | 是 | 标题 + 一段说明，**无说话人、无台词** | 玩家点击 | 告示 / 公告卡：宣布一个转折或阶段性结果，是叙述不是对话 |
| `(play-narration! id)` | 否，定时消失 | 一行文字（Terminal 端显示为 `[旁白] id`） | 自动淡出 | 环境旁白字幕；目前内容脚本里还没有实际用例 |
| `(play-banter! (line …) …)` | 否 | 多行台词 | 自动逐条计时的气泡 | 失败后斗嘴、行动后随口一句；不打断游戏 |
| `(play-remote-banter! (line …) …)` | 否 | 多行台词 | 自动计时 | 电话、门外插话、场外事件；未在场者显示为侧边临时卡 |
| `(play-dialogue! (line …) …)` | 是 | 当前说话人立绘 + 多行线性台词 | 全屏点击推进 | 主角 ↔ NPC 的正式对话；期间其余输入全部锁定 |
| `(play-remote-dialogue! (line …) …)` | 是 | 同一立绘舞台，线性无分支 | 全屏点击推进 | 电话、门外对话、明确不在场者的正式对话 |
| `(play-animation! tag)` | 是 | 命名动画占位（v1 只显示 tag） | 占位 | **只能在动作内调用** |

**最容易记混的一个**：`spotlight!` 是"公告卡"——只有标题和一段说明文字，没有说话人。
只要场面里有人正在开口，就必须用 `banter` 或 `dialogue`，不能拿 `spotlight!` 顶替。

台词统一用 `(line 说话人 文本 [语音] [停留秒])` 构造。停留秒只有 banter 用，`<=0` 表示按文本长度自动估算。

```scheme
(play-banter!
  (line "夜莺" "你管这叫计划?")
  (line "主角" "至少我有计划。"))

(play-dialogue!
  (line "主角" "海伦,我们得谈谈。")
  (line "海伦" "我没什么好说的。"))
```

## 说话人怎么解析

固定顺序：**队员 Id → 队员 Name → 当前场景节点 Name → 你正身处其中的容器名**（导航栈里的
那几层：进入「夜莺」这张卡之后，她本人依然能在她自己的动作里开口）。

节点有世界锚点时，banter 气泡从锚点上方（人形头部高度）冒出，而不是从节点卡冒出；没有锚点的
网格卡才用卡片本身当落点。说话人有 `Portraits/Neon/<名>` 立绘时气泡左侧带一张小头像，没有就只写名字。

说话人 **`"世界"` 是旁白**，不是角色：它不署名、不指向任何人。阻塞 dialogue 中使用同一底部对白框
但不显示立绘；banter 中画成一张贴在底部的叙述纸条。
旁白句不需要锚点，任何一种对白接口里都能用。**只有真正"没有人在说这句话"时才用它**——
有人开口就写那个人的名字。

普通 `play-banter!` / `play-dialogue!` 锚定不到说话人时不会中断：banter 自动显示场外人物卡，
dialogue 继续使用立绘舞台；两者都会给出一次可见警告，Console 保留具体调用与定位信息。Banter 的警告
跟随当前台词状态，每句最多出现一次，不会逐帧刷屏。确实要让不在场的人开口时，仍应**显式**用
`play-remote-banter!` / `play-remote-dialogue!`：显式 remote 不报警，也更准确地表达电话、回忆或
场外事件。这些接口不会自动导航到某地点。**不要拿 remote 去掩盖拼写错误。**

阻塞 dialogue 的立绘按 `UnityClient/Assets/Resources/Portraits/<说话人>` 查找。缺图不会退回世界气泡，
而是在同一舞台显示具名人物牌并在 Console 警告一次；补入同名图片即可接管，无需修改脚本。

remote 是**序列自己的属性**：内容写 `play-remote-dialogue!`，这段对白无论走哪条播放路径
（动作内的阻塞剧情步骤、动作外的即时对白）都保持 remote。

## 什么时候播放（决定了你能让谁说话）

**动作内**：`play-dialogue!` / `spotlight!` / `play-animation!` 按调用顺序排成有序阻塞步骤，
在动作结算后、**采用新快照之前**逐个播放；`play-banter!` / `play-remote-banter!` 延后到
**采用新快照之后**才释放（避免提前剧透）。

**动作外**（进场脚本、规则）：三种对白立即触发；普通 `play-dialogue!` 同样会在锚定失败时降级并报警，
`play-animation!` 不支持动作外调用。

Banter 以完整序列排队：当前序列不会被新序列打断，后触发的序列按 FIFO 顺序播放。客户端最多保留
四个等待序列，超限时丢弃最旧的等待项，避免玩家连续操作后仍在播放已经失去场景关系的旧插话。
阻塞 Dialogue 出现时暂停 Banter，结束后从原处继续；暂停期间新收到的 Banter 仍进入同一队列。

由此推出锚定约束：

- 动作内 `play-dialogue!` 锚的是**动作前**的旧画面。删掉海伦节点之后再让海伦说话 ✓；
  新建"陌生人"节点后立刻让它说话仍会在立绘舞台播放，但会按场外对白报警（新快照还没采用，没有锚点）。
- 动作内 `play-banter!` 锚的是**动作后**的新画面。给刚出现的角色插一句 ✓；给刚删掉的角色 banter ✗。
- 想让"刚出现的角色"做一段阻塞对话：先用一次节点 / 场景推进让它出现，再单独 `play-dialogue!`；
  或者改成锚在已经在场的角色身上。
