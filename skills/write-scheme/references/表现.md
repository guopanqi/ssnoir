# 表现接口：谁在说话、阻不阻塞、锚在哪一帧

写对白和演出时读这里。八个接口容易记混，但它们的差别主要是三点：**阻不阻塞、有没有说话人、
锚定的是动作前还是动作后的画面。**

## 表现接口

| API | 阻塞? | 结构 | 谁推进 | 用途 |
|---|---|---|---|---|
| `(notify! text)` | 否，定时消失 | 一行文字 | 自动淡出 | 系统提示、背景事件播报；**不代表"这次行动的结果"** |
| `(spotlight! title subtitle)` | 是 | 标题 + 一段说明，**无说话人、无台词** | 玩家点击 | 告示 / 公告卡：宣布一个转折或阶段性结果，是叙述不是对话 |
| `(play-narration! id)` | 否，定时消失 | 一行文字（Terminal 端显示为 `[旁白] id`） | 自动淡出 | 环境旁白字幕；正常底部 narration，不锁玩家操作 |
| `(play-bubble! (line …) …)` | 否 | 少量短台词 | 自动逐条计时的气泡 | 可错过的氛围、态度与短促来回；不承载必要说明 |
| `(play-remote-bubble! (line …) …)` | 否 | 少量短台词 | 自动计时 | 场外的短促插话，同样不承载必要说明；未在场者显示为侧边临时卡 |
| `(play-dialogue! (line …) …)` | 是 | 立绘舞台（两人同台的人偶戏）+ 多行线性台词 | 全屏点击推进 | 主角 ↔ NPC 的正式对话；期间其余输入全部锁定、世界界面收起。可带舞台指示，见下文 |
| `(play-stage! (stage-… ) …)` | 是 | 立绘、无字动作、环境音和对白的连续分镜 | 动作自动推进，对白点击推进 | 多人调度或对白之间的无字演出；见 [舞台.md](舞台.md) |
| `(play-remote-dialogue! (line …) …)` | 是 | 同一立绘舞台，线性无分支 | 全屏点击推进 | 电话、门外对话、明确不在场者的正式对话 |
| `(play-video! tag)` | 是 | 视频过场：tag 认 Unity 里的 CutsceneSequence（机位 + 视频）；昂贵，少用 | 阻塞 | **只能在动作内调用**；场景里东西自己动（唱片机、吊灯）走实时动画通道，不用这个 |
| `(play-intertitle! 保持黑幕? (list 文本 Narration音频ID) …)` | 是，自动推进 | 纯黑背景、居中大字，逐页淡入淡出 | 有音频时等语音结束，无音频时按文字计时 | 电影式黑幕独白；不是场景 node。`#t` 用于紧接睡眠换日或下一场剧场，避免黑幕结束后闪回城市 |
| `(play-camera! 锚点 停留秒 地点)` | 是，自动推进 | 运镜到已有锚点的机位 | 自动计时 | 地点为空字符串只运镜；非空时导航落到该地点。显式锚点缺失或没有机位会中断 |
| `(cut-camera! 锚点 地点)` | 是，立即切镜 | 切到已有锚点机位；地点非空时同时导航 | 自动，不运镜 | 剧情明确的剪辑切镜；不把 `play-camera!` 的停留0秒当作瞬切 |
| `(play-motion! 地点/道具 状态 [机位])` | 是 | 场景演出：运镜到 `Camera_<机位>`，播指定地点内道具的实时动画到目标状态，回原机位 | 自动，不点击 | 只能在动作内调用；显式引用缺失会中断。`(play-motion! "首演之夜/大吊灯" "Fallen" "首演之夜-吊灯")` |

**最容易记混的一个**：`spotlight!` 是"公告卡"——只有标题和一段说明文字，没有说话人。
只要场面里有人正在开口，就必须用 `banter` 或 `dialogue`，不能拿 `spotlight!` 顶替。

台词统一用 `(line 说话人 文本 [语音] [停留秒])` 构造。停留秒只有 banter 用，`<=0` 表示按文本长度自动估算。

```scheme
(play-bubble!
  (line "夜莺" "你管这叫计划?" :at "夜莺@酒馆")
  (line "主角" "至少我有计划。"))

(play-dialogue!
  (line "主角" "海伦,我们得谈谈。")
  (line "海伦" "我没什么好说的。"))
```

## Bubble 的内容边界

Bubble 是可以错过的短促人声，只表现背景氛围、随口反应和眼前的情况；优先一两句，少轮次。不要用它交代玩法、任务职责、惩罚规则、必要线索或不可省略的剧情，也不要借延长停留时间把它变成长对话。

比如酒馆首次闹事：醉客与客人各吵一句，已经足以表现冲突。Bubble 到此为止，不再追加酒保叫尼尔处理、解释职责或扣钱。

普通搜找、搬运、核对等行动的物品和数值结果由结算展示；如需短促反应，用一两句 Bubble，
不把每个判定结果都扩成阻塞 Dialogue。必要线索、承诺与真正的人物交流仍用 Dialogue。
同一次动作若已有完整 Dialogue 收尾，不再附加重复结论的 Bubble；尤其要检查之前动作排队的
Bubble 是否会在完成对话后继续播放。不能依赖脚本调用先后让 Bubble 插在 Dialogue 中间。

人物对阶段转折、公共事件的正式回应，以及用于建立人物感情的重要交流，用 Dialogue；
不能仅因为只有一句、是在入场时触发，或只是“表达看法”，就降为 Bubble。
区分标准是这句话是否属于玩家应当经历的人物片段，而非台词长度。

### 气泡说到某句才恢复冷静

当恢复必须发生在人物实际说到这句时，用
`(bubble-restore-composure (line "艾迪" "歇一会儿。" :at "码头-货堆") 'player 1 "冷静恢复1点。")`
包装 `play-bubble!` 中对应的一条台词。包装时不恢复、不写入原动作效果条；客户端实际展示该句时恢复并通知。
同一条最多兑现一次，暂停期间不兑现，队列清除或未播到不会补发，跨游戏日也不兑现。
它仅限普通/场外 Bubble，不用于 Dialogue 或交锋回合的同时气泡。
当天是否已经安排帮助等剧情条件仍由内容模块及现有存档负责；没有排入气泡的分支不得提前恢复或占用帮助次数。

## 说话人怎么解析

固定顺序：**队员 Id → 队员 Name → 当前场景节点 Name → 你正身处其中的容器名**（导航栈里的
那几层：进入「夜莺」这张卡之后，她本人依然能在她自己的动作里开口）。

节点有世界锚点时，banter 气泡从锚点上方（人形头部高度）冒出，而不是从节点卡冒出；没有锚点的
网格卡才用卡片本身当落点。说话人有 `Portraits/Neon/<名>` 立绘时气泡左侧带一张小头像，没有就只写名字。

说话人 **`"世界"` 是旁白**，不是角色：它不署名、不指向任何人。阻塞 dialogue 中使用同一舞台字幕
但不显示立绘与姓名；banter 与 `play-narration!` 共用贴底、避让两侧 UI 的无姓名字幕。外观与推进区别见 [叙事字幕](../../../docs/叙事字幕.md)。
旁白句不需要锚点，任何一种对白接口里都能用。**只有真正"没有人在说这句话"时才用它**——
有人开口就写那个人的名字。

**场内配角的气泡必须显式写 `(line 说话人 文本 :at "已有Anchor")`。**
说话人的身份、显示名和空间落点是三件事；不要假设叫“老板”的人能自动找到食堂的位置。
使用人物所在地点的真实 Anchor，可以共用有意义的空间落点；不能编造不存在的 Anchor。
尼尔及队伍成员可使用队员自身的自动定位，旁白“世界”无需锚点。
`:at` 决定 Bubble 的世界落点，不负责安排阻塞 Dialogue 的立绘舞台。
立绘 Dialogue 按说话人身份安排人物，不检查城市当前屏幕锚点，也不要求预先存在同名人物节点。
这是表现层的边界，不是在场条件的豁免。作者必须在事件触发条件里核对人物当前所在地、
上工／停班／离开状态，并让台词中的经历与该状态一致。不能只因人物相熟就在任意地点播放其对白；
同一事件若跟随人物换地点，必须审阅每个地点下的场面与台词，不能把“正在卸货”的对白原样搬到食堂。


Bubble 运行时保留未解析说话人的警告与场外卡片兜底，这是错误诊断，不是内容写法。
不能因为仍能显示就省略场内人物的锚点。确实在场外的人用
`play-remote-bubble!` / `play-remote-dialogue!`，例如电话或门外插话；
不要用 remote 掩盖缺失的锚点或拼写错误。这些接口不会自动导航到某地点。

阻塞 dialogue 的立绘先按 `UnityClient/Assets/Resources/Portraits/Neon/<说话人身份>` 查找。
有专属肖像就使用专属肖像；否则按人物声明的外貌类型稳定选择通用肖像，没有声明时使用通用剪影，
不会猜测性别和年龄。明确写出的姿势或 `stage-spawn` 图片资源缺失仍报错，不以剪影掩盖资产错误。

### 普通配角在内容附近声明，不维护中央人名册

```scheme
(define 咖啡馆老板
  (speaker "咖啡馆老板" :name (tr "老板" "Owner") :appearance '成年男性))

(play-dialogue!
  (line 咖啡馆老板 "露西去学校了。")
  (line "尼尔" "她什么时候回来？"))
```

`speaker` 返回人物数据，`line` 接受声明或原有字符串。身份用于肖像、锚点与同一人物识别，必须稳定；
`:name` 是显示署名，默认沿用身份。不同地点的老板使用不同身份，可以都显示“老板”。同一人物所有台词
复用同一声明，不用一会儿传声明、一会儿传另一个字符串身份。

`:appearance` 可省略；当前只有与已有资源对应的 `'成年男性`、`'成年女性`。未指定时不猜性别年龄，
使用通用剪影。不要为儿童、老人硬选不匹配的成人类型；需要此类外貌时先准备合适资源再扩展类型。
专属肖像始终优先，同类型变体由身份稳定选取，不随每次对话、存读档改变。同一身份的声明不得互相冲突。

通用类型与资源池由 `UnityClient/Assets/Resources/Portraits/GenericCharacters.json` 维护，只登记类型，
不登记逐个人物名称。字符串写法保持可用，有专属肖像的人物无需改写；没有专属肖像也未声明外貌的
旧字符串说话人现在使用剪影。


remote 是**序列自己的属性**：内容写 `play-remote-dialogue!`，这段对白无论走哪条播放路径
（动作内的阻塞剧情步骤、动作外的即时对白）都保持 remote。

## 什么时候播放（决定了你能让谁说话）

`play-intertitle!` 与 `play-camera!` 只允许动作内调用。电影黑幕的 `#t` 必须接换日或下一场 `play-theatre!`，不能作为普通不换日动作的最后一步，否则黑幕没有退出点。首夜黑幕在换日时由现有睡眠渐亮接管；清晨独白用 turn-start 的 `play-narration!`，不再放阻塞对白。

有后续阻塞剧情或换场的动作，客户端统一按「判定结束 → 结果条完整展开 → 停留 1 秒 → 阻塞剧情 → 采用新快照」播放，同场景与换场景一致。
没有后续阻塞剧情、换日或换场的普通动作，在判定完成后立即采用快照并恢复交互，结果条作为只读附件自行计时消失；不锁悬停、拖骰或重复执行，也不接受点击／ESC 提前隐藏。不要在脚本里为了展示结果增加阻塞步骤。没有结果条的纯剧情不额外等待；睡眠已开始黑幕时不在黑幕后等待结果。不要在内容里添加 `wait` 来补结果阅读时间；只有剧情本身需要的停顿才由内容编排。

回合回应也使用同一个边界：前置阻塞剧情 → 采用该批快照 → 新状态上的气泡与变化提示，不再提前播放人物气泡或在 Dialogue 前显示新节点。

需要让玩家看见新事件时，内容可明确写 `(focus-node! "醉客互相叫骂")`：执行到此步骤才采用新快照，进入指定节点（可为交锋根），等待镜头到位，然后继续后续剧情。它不执行地点 arrival；目标是稳定节点 Id，不是显示名。只在动作或回合报告内使用，目标必须存在于动作后的树中。节点没有明确落点声明时保持当前导航。不要每出现一个节点就指定落点：常规持续效果让玩家保留注意力，
只有新麻烦或关键转折确实需要看另一处时才主动导航。

```scheme
(play-dialogue! (line "世界" "东边这桌有人踢开椅子，站了起来。"))
(focus-node! "醉客互相叫骂")
(play-bubble!
  (line "东桌醉客" "你刚才骂谁呢？" :at "老街酒馆-工作")
  (line "西桌醉客" "说的就是你，怎么着？" :at "老街酒馆"))
```

这里 Dialogue 与 focus 按顺序阻塞播放；bubble 始终是采用新快照后的插话，不是可插入阻塞步骤之间的步骤。不要靠 `wait` 修补先后顺序。

**有报告时**（玩家动作、交锋回合回应、地点入场等）：`play-dialogue!` / `spotlight!` / `play-video!`
按调用顺序排成阻塞步骤。默认在最终采用快照前逐个播放；显式 `focus-node!` / EnterPlace 是串内的提交边界，
其后的阻塞步骤使用已提交的画面。`play-bubble!` / `play-remote-bubble!` 收在报告的 Banter 中，等前置步骤完成、
快照采用后再释放。**先写 bubble 再写 Dialogue，不会让 bubble 先播。**

**无报告时**：不具有上述动作播放事务。不要因代码写在「规则」里就认为它没有报告：交锋回应会持有报告。
`play-video!` 不支持无报告调用；需要和状态变化严格排序的叙事，应放进已有的动作或回合报告内。

普通 Banter 以完整序列排队：当前序列不会被新序列打断，后触发的序列按 FIFO 顺序播放。交锋回应里的本地人物短句
作为同一批的同时气泡呈现；不要依赖多个 bubble 调用制造先后，必须分先后时拆规则或使用阻塞 Dialogue。客户端最多保留
四个等待序列，超限时丢弃最旧的等待项，避免玩家连续操作后仍在播放已经失去场景关系的旧插话。
阻塞 Dialogue 出现时暂停 Banter，结束后从原处继续；暂停期间新收到的 Banter 仍进入同一队列。

由此推出锚定约束：

- 阻塞 Dialogue 的背景使用对应提交边界的画面，但说话人由立绘舞台自身建立。刚登场的配角无需先创建城市节点，也不因缺少屏幕锚点被判为场外。
- 动作内 `play-bubble!` 锚的是**动作后**的新画面。给刚出现的角色插一句 ✓；给刚删掉的角色 bubble ✗。
- `focus-node!` 用于剧情确实需要提交并展示新盘面，不是让 Dialogue 说话人通过锚点检查的手续。

## 阶段转折由触发事件统一拥有

章节公告只是表现，不会推进剧情。演出宣告进入新阶段时，由同一个事件修改阶段事实并排入演出与公告；
地图和「手头的事」从该事实推导，不再各自用次日日期重复判断是否进入阶段。日期只负责真实日程，
例如「后天彩排」可以立即进入事项，但彩排行动仍到当天才出现。不要把转幕状态留在另一条换日规则里。

阻塞步骤默认结束后才采用新快照。如果公告出现时就必须展示转折后的地图与事项，
在前置演出和公告之间使用现有 `focus-node!`，选择新快照中仍存在的剧情落点；
不手工刷新或另存一份事项状态。审阅这类改动时一起核对：演出顺序、阶段事实、地图、事项、实际日程与当晚读档。

## 舞台指示

`play-dialogue!` 的台词可以带舞台指示（姿势、距离、灯、画面），把一段对白排成人偶戏。
词汇、含义和排法见 [舞台.md](舞台.md)。
