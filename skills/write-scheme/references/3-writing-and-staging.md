# SSNoir 文案与演出编排指南 (Writing & Staging for SSNoir)

本指南结合《Fallen London》的文本锤炼法则与 SSNoir 的移动端界面、舞台演出特性，说明人物文字、移动端阅读与叙事载体的分工。

---

## 一、 世界观语调：黑色电影是调味料，不是主食

世界是**上世纪美国、黑色电影（Raymond Chandler / 马洛）风格的港口城市**。语言是中文，但**世界不是中国**（注意货币、称谓、警局体制、街道风貌的西式年代感，同时避免中式成语堆砌与现代网络流行语）。

### 1. 克制使用“硬汉腔”与拒绝陈词滥调
- **少量的风格化足矣**：把黑色电影的冷硬比喻当成胡椒粉，而不是主料。如果每张卡都在感叹“这座城市烂透了”、“夜色黑得像沥青”、“很静，太静了”，读者会立刻产生审美疲劳并直接略过你的句子。
- 避免现代网络梗和穿帮引用；人物说话符合时代、身份与当时的处境。不直接继承其他作品的题材限制。
- **用社会细节充实时间与环境**：晨昏和天气可以直接描写，也可以借人的活动让它更具体，例如“罐头厂的下工铃响过两遍”、“醉客踩着码头积水跌跌撞撞往家走”、“早班送奶工的铁皮箱撞响了台阶”。

### 2. 展示，不要讲述（Show, Don't Tell）
聚焦于尼尔的**感官（看到的、闻到的、听到的具体物证与动作）**，不要把空洞的总结塞进玩家脑子里。尼尔是有明确人格的主角，可以有自己的反应；但不要把他的反应写成玩家必须拥有的感受。
- **警惕“全城都在……”式的宏大偷懒**：当你写出“码头上人人都在议论那桩命案”或“整个街区都陷入了恐慌”时，立刻停笔，换成具体的人、具体的地点和具体的动作——*是谁在议论？是修船工把扳手扔进油桶里低声咒骂，还是酒保把写满欠条的黑板擦了一半？*
- **不要替玩家规定情绪**：不要写“你感到一阵毛骨悚然”，去写那个让玩家自己觉得毛骨悚然的细节；不要把矫情的独句成段当成控制阅读节奏的手段；少用泄气的被动语态，让动作直接落地。

## 二、 手机画布法则：写短，再写短

界面在手机上会自动放大，**手机屏幕是最紧的那块画布，按它写就到处都成立**。

### 1. 当前界面的文案预算（含标点符号）

| 界面字段 | 字数上限 | 写作要求 |
|---|---|---|
| 地点名（带 `:anchor` 容器） | **8 字以内** | 清晰指代空间位置，不加文学修饰 |
| 动作 / 一般节点标题 | **8 字以内** | 明确表达「是什么 / 做什么」 |
| 副标题（`:subtitle`） | **30 字以内** | 说明**眼前是什么、做这件事意味着什么**；禁用时说明原因 |
| 边缘便签（风险/修正标签） | **5 字以内** | 每张卡最多一枚 |
| 边缘信标理由 | **8 字以内** | 如休息阻塞的简短提示 |
| 结算补充（`result-supplement!`） | **20 字以内** | 仅补充数值无法表达的事实（如 `"解锁：码头账房"`） |

### 2. 「一卡三元素」与数字克制原则
手机上一张动作卡只有约 $280 \times 210$ 像素，却可能塞下十种 UI 元素。全用上就是一张没人看的密度图：
- **一张卡上最多让玩家读三样东西**：骰位与执行按钮必须在（交互），标题必须在（身份），剩下的每加一样（副标题、便签、Clock Tag 等），都要问自己：**“少了它，玩家会做错决定吗？”**
- **同一张可交互卡上不要出现第三处数字**：难度修正便签、能力栏等级、骰位面值已经是三处数字，不要再往副标题或标签里塞多余的数字计算。
- **绝不把关键信息只藏在第三行副标题里**：手机上没有鼠标悬停（Hover），玩家是滚动着跳读的。真正重要的转折和线索必须走 `spotlight!` 或 `play-dialogue!`。

## 三、 叙事载体分工：什么话放在哪里说？

按信息需要被看见的程度和所处时机选择叙事载体：

| 载体类型 | 核心职责与玩家体验 | 容易误用的情况 |
|---|---|---|
| **常驻标注 (`note-node`)** | **「站在这儿就看得见的」**：当前场面的局势、地点的环境近况、NPC 肉眼可见的在场/伤势/忙碌状态。漂浮在场景锚点旁，不可点击。 | 禁止写成隐藏规则说明书（如“每日救场 1 次”）；禁止用 `observe-action` 冒充常驻环境说明。 |
| **观察动作 (`observe-action`)** | **「你专门去查了才知道的」**：需要玩家花一次点击（甚至代价）去揭开、且对后续决策有实质帮助的信息。 | 禁止放纯氛围废话（只写景、不改状态、不给决策信息）；纯氛围卡只会挤占版面。 |
| **气泡台词 (`play-bubble!`)** | **「擦肩而过的短促反应」**：可错过的环境交谈、行动结算后的简短嘟囔或生理反应。 | 禁止承载主线关键说明或必读线索（玩家极易错过）。 |
| **聚光灯 / 对白 (`spotlight!` / `play-dialogue!`)** | **「必须停下来看的正戏」**：重要情报揭露、承诺达成、剧情阶段转换、人物正式交锋。 | 禁止在玩家会反复刷的日常行动结算里塞长篇阻塞对白。 |
| **结算补充 (`result-supplement!`)** | **「状态变化之外的干货补充」**：当引擎自动生成的数值条无法说明结果时（如解锁新地点、获得某人口头允诺），补一行 20 字以内的说明。 | **禁止替引擎报账！**（严禁写“推进了 2 格”、“拿到了 15 块”、“冷静减少了 1 点”等噪音）。 |

## 四、 对白与舞台调度

### 1. 检查台词是否能说出口
对白是传达信息的好办法，但极易写成生硬的设定说明文（Exposition）。
- 写完每一句 `line`，自己出声读一遍：一个活生生的码头工人、私家侦探或帮派账房，在当时的场合下真的会这么说话吗？
- **如何消灭说明式台词？** 如果你发现 NPC 正在像百科全书一样给尼尔介绍背景，先明确这个人此刻想做什么、愿意告诉尼尔什么、又有什么顾虑。赶时间或处于困境可以让话更直接，但不必为每次谈话制造危机。一个正忙着往火炉里塞假账本、或者捂着流血肋骨的人，说话自然会直奔主题，并且充满鲜明的性格。

### 2. 拒绝制作记号污染玩家文本
- `D11`、`C1`、`N4` 等开发期日期/节点编号，以及颜色代码、资源 ID、存档键，只供代码与设计文档使用，**严禁出现在任何对白、手头的事、Clock 备注、节点标题或副标题中**。
- 玩家需要知道期限时，必须根据当前日期推导为自然语言（“今天 / 明天 / 后天 / 三天后”），或写成故事里已经明确约定的日子（如“周五发薪日前”）。

*(关于如何将写好的对白编排为镜头、灯位、站位距离与时序，请继续参阅专项文档 [表现接口](表现.md) 与 [舞台调度](舞台.md)。)*
