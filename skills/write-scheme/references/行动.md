# 行动通用知识

用于城市行动、工作和 Scenario / encounter 内的行动。DSL 签名与合法参数以
[engine.scm](../../../UnityClient/Assets/Resources/Content/scripts/engine.scm) 和引擎实现为准。
具体类型的写法见 [工作行动](工作.md) 与 [Scenario](Scenario.md)。

## 能力匹配

先明确角色用什么方法做事，再选判定能力；同一个目标不必只有一种能力，但方法必须说得通。
通常可按主要依靠的手段直接匹配：力量 `violence` 用于出力或身体对抗，见识 `knowledge`
用于知识与理解，敏锐 `sharpness` 用于观察与察觉，交际 `social` 用于沟通与应对他人。
例如搬运靠出力，不因它是“工作”就统一判交际；同样是找线索，询问证人与检查现场可以使用不同能力。

在 Scenario / encounter 中，还要看行动与整场目标、其他行动的关系。不同方法可以影响不同的
进展、代价、前提或后续机会；不要只换能力图标和名字，却让所有选项产生完全相同的后果。
也不必为了覆盖四种能力硬凑四个入口。场内进度尺度和回应时序见 [Scenario](Scenario.md)。

## 风险等级、后果性质与作用对象

这三个问题分开判断：风险等级表示后果有多严厉；后果性质是实际损失或改变了什么；作用对象
是具体哪个人、Clock 或物品。它们也不同于“工作”“非法”等行动类别。
目前没有需要另外填写的独立“风险类型”字段，不新增一套与真实效果重复的分类。

- 判定概率由骰子、技能、修正和 `FateStrip` 决定，`风险等级` 不修改概率。
- 对 Roll 节点声明 `:risk '稳妥 / '冒险 / '危险`。稳妥：坏结果通常无进展或只有已告知的轻微代价；冒险：坏结果触发明显额外代价；危险：中结果也可能造成代价、坏结果更加严重。
- `:risk-target (list 'clock "夜莺的恐惧")` 表示主要负面影响；`:progress-target (list 'clock "回到住处")` 表示正向进展。个人状态用 `(list 'composure "player")` / `(list 'injury "player")`；物品用 `(list 'item "金钱")`。
- `:risk-target` / `:progress-target` 可用于判定或确定性行动，不依赖 `:risk`；花钱推进Clock也应声明进展目标。`:risk`仍只用于Roll。
- 目标是**预告与高亮**，不会自动结算；作者仍须在三个 outcome 中唯一落实实际效果。不能出现 UI 和结算互相矛盾的声明。
- 地点/Scenario的自动回合效果需在可见注释或场景规则明示；不得隐藏成某张动作卡失败时的额外代价。
- 有 `:risk` 的卡不得再写“低风险”“高风险”风险标签；“工作”“Scenario”“非法”等类别标签与风险分离。
- `clock` 目标按 `GameClock.Label` 验证，必须存在、无歧义；用错目标视为内容错误，不静默忽略。

## 投入、结算与可见信息

资源槽表达投入，outcome 实现后果，目标声明用于预告；三者应保持一致，不重复扣费。
实际状态变化自动生成结果条，见 [效果条目是自动生成的](../SKILL.md#效果条目是自动生成的)。
心情消耗与健康损伤的运行时关系见 [身体代价](../SKILL.md#坏结果扣冷静不直接扣伤势)。

影响选择的规则必须行动前可知，见 [规则信息要在行动前可见](../SKILL.md#规则信息要在行动前可见)；
标题、描述、Tag 与 Clock 的分工见 [节点信息](../SKILL.md#节点信息标题描述tagclock)。
不要在每种行动的写法中复制这些规则。
