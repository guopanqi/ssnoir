# Blender 加工

## 导入与几何检查

1. 保留生成器下载的原文件，另存工作 `.blend`。
2. 删除明显无用的生成器灯光、相机和隐藏残片；不要删除尚未判断用途的 Empty。
3. 设置 Metric，约定 1 Blender Unit = 1 米。
4. 让地面位于 Z=0，资产主轴符合 Unity 预期，中心接近可解释的场景原点。
5. 调整最终尺寸后应用 Rotation/Scale，使主体 Scale 为 `(1,1,1)`。
6. 检查 NaN/Inf 顶点、破面、孤立碎片、反法线、穿插和过薄结构。
7. 记录顶点、面数以及三角/四边/ngon 分布。低模要求“四边面”时不能只看总面数。

## 运行描边脚本

当前首选：

`UnityClient/Assets/Resources/Tools/model-outline-handpaint.py`

脚本行为：

- 若选中了 Mesh，只处理选中 Mesh；否则处理场景中全部 Mesh。
- 清空目标 Mesh 材质并赋予 `M_Dark_Blue_Model`。
- 保留边界边和夹角至少 50° 的硬边。
- 忽略短于 0.02m 的边。
- 生成带轻微手绘扰动的 `OutlineLines_*` Curve，材质为 `M_White_Emission_Lines`。
- 使用固定 seed，重复运行结果稳定。

先完成并应用全部几何变换，再运行描边。Curve 点写在世界坐标中；描边生成后若只移动主体，线条会错位。需要整体移动时，把主体、描边和语义 Empty 置于共同 Root 下，或重新生成描边。

如果重跑描边，先确认脚本计算出的目标名字能替换旧 Curve；手工改名的旧描边不会自动删除，可能形成双线。

## 语义节点

按 [asset-contract.md](asset-contract.md) 建立：

- 至少一个有意义的 Camera；场景资产通常使用正交或克制透视的 3/4 俯视角。
- 需要旋转观察时加入 `orbit pivot`，放在视觉重心而非地面原点。
- 需要投射游戏节点卡片时加入 `Anchor_<精确节点名>`。
- 角色站位可用 `Actor_<稳定角色ID>` 记录，但当前只是制作约定。

语义 Empty 应与资产 Root 一起移动，Scale 保持 1。不要把 Anchor 与 orbit pivot 合并为同一对象；两者服务不同系统。

## 预览角度

预览的目标是审查，不是宣传渲染：

- 让资产占画面约 75%–85%，保留四周安全边距。
- 采用能同时展示平面布局与垂直体块的 3/4 俯视角。
- 公园或城市块优先正交相机，避免近端夸张和远端圆形压缩。
- 调整角度使亭子、入口、中心体块和树列互不完全遮挡。
- 使用中性工作台光照；不要用强景深、雾或炫光掩盖拓扑。

可运行 `scripts/frame_and_render_preview.py` 自动计算正交取景，再根据资产重点做人工微调。

## 保存前

- 名称稳定且有意义；中文资源名允许使用。
- 主体、描边、Camera、Anchor、pivot 和专用标记都在预期层级。
- 没有预览专用 Light、Ground 或临时对象混入正式资产。
- 相机视图能完整容纳资产。
- 保存后用后台 Blender 重新打开并运行验证脚本，证明二进制文件可读。
