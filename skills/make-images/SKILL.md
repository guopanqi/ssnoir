# 制作 SSNoir 图片

## 何时使用与如何衔接

只要当前交付物是 SSNoir 的生成图片或图片修改，就使用本 Skill；图片将来用于 3D 场景，并不改变当前图片工作的归属。

- **场景布局／效果探索图**：与 [make-scene](../make-scene/SKILL.md) 配合。make-scene 确定故事动作、空间关系、机位和组合表现，本 Skill 将这些要求转为提示词、选择参考图、生成并审图。布局图还需读取其 [布局预览](../make-scene/references/layout-preview.md)。只要求先看图时，交付到图片审查即可，不自动进入建模或发布。
- **单件资产建模参考图**：与 [make-3d-asset](../make-3d-asset/SKILL.md) 配合，由资产需求确定必须看清的结构，本 Skill 负责图片表达和验收。
- **人物、背景人群、2D 道具**：按下文对应用途处理；不因使用同一生图工具而套用相同验收标准。

本 Skill 决定项目里该画什么、如何判断合格；内置 imagegen 等工具／通用 Skill 决定如何生成，两者配合使用。直接调用生图工具不能代替读取项目视觉要求。仅调整 3D 布局、材质或机位且不生成图片时，无需加载本 Skill。

## 共通基准

世界是上世纪美国黑色电影语境，内容虽用中文，画面不能出现中国物件。画面以轮廓、体块和高对比明暗传递信息；细节投入服从玩家在目标尺寸下真正需要读到的东西。

## 按用途判断

**舞台人物及姿势**：先读 [人物形象设定总表](../../角色库/人物形象设定总表.md)，再看该人物已有基础图和姿势图。保持身份剪影、体型和服装；新姿势只改表演所需的身体动作。用户于 2026-10-11 明确要求正式游戏人物使用描线构成：以明亮、克制的轮廓及少量必要内部线表现人物，身体内部为黑色负空间，不得出现大面积灰色、蓝灰色或其他颜色填充。已有正式游戏描线人物是风格基准；实心灰色人物实验不用于正式资源。不能通过降低 brightness 把填充人物冒充描线人物。

夜莺保持已有形象的年轻、优雅与灵动。用户于 2026-10-08 明确否定显老的形象；画风探索不得擅自加入年龄数字、成熟疲惫神情、眼袋、皱纹、脸颊刻痕或松弛感。正常人物比例不代表老化面貌，黑白排线与网点优先放在衣料，不在脸部制造年龄痕迹。

一场戏先用现有姿势、走位、短促特效和音效编排。只有新姿势在目标画面尺寸下能传达这些手段无法传达的关系或状态变化，才生成新图；不要按动作的每一步拆图。主要人物可以有少量关键姿势，但新图的头身比例、画幅占比、脚底基线和朝向须与基础图及同场人物合拍。

基础立绘遵守人物形象设定总表中的「基础立绘的取景与尺度标准」：统一完整全身并包含双脚／鞋，统一画布、鞋底基线和绘制比例，保留角色相对高矮。禁止混用截腿图与全身图，禁止逐人裁紧后撑满画布来统一大小。缺失腿脚必须重绘；展示半身由镜头裁切处理。验收须在同一地面、同一显示尺度下并排比较。

旧姿势取景不合标准时，按标准基础图重新制作；不要在运行时按角色或姿势补偿缩放。使用 Gemini Image Web 编辑时只上传当前标准基础图作为身份与尺度参考，用文字描述旧姿势的动作；双参考容易让旧姿势的大取景覆盖尺度标准。生成后与基础图以同一画布并排审阅，坐姿、弯腰和奔跑须保持头部及肢体尺度，不能以轮廓总高度重新撑满。

**路人、黑影和其他背景人物**：他们承担人数、移动或环境气氛，而不是独立角色辨识。只保留可读的外轮廓，内部纯黑；不要面部、衣褶、口袋、衣领等内部线条，也不要点缀色。若剧情需要观众认出某人，就按重要人物设计，并明确这次身份升级；不要把背景人形悄悄画成主角级立绘。

次要人物的对峙、打斗和受击优先复用少量剪影，用相对距离、方向、节奏与特效表达；不要给每名酒客分别生成出拳、防守、后仰等动作图。

**2D 道具与场景图片**：先确定玩家需要辨认的功能、年代特征、轮廓和使用尺寸。重要道具突出一个可识别的形态或动作线索；背景小件压低细节和对比，不与主要人物争夺注意力。用途涉及 3D 建模参考图时，同时读取 [make-3d-asset 的视觉定义](../make-3d-asset/references/visual-definition.md)：主体完整、可建模、无遮蔽，结构信息优先于装饰。为 CityBox 场景制作布局／效果参考时读取 [make-scene 的视觉组合方法](../make-scene/references/visual-language.md)，不在本 Skill 维护 3D 色盘或配光参数；2D 人物仍按上文的独立描线标准审核。

## 生成与验收

场景概念／布局图先检查故事动作、通路、分区和取景是否成立，再检查视觉层级与年代物件。区分布局参考、效果探索与正式资源；生成图不能证明网格可行、运行时材质正确或实际交互通过。场景图不执行下方人物描线入库流程。

### 正式描线人物资源的入库硬约束

源图中的线条本身应当遵守共同的白线亮度、黑色负空间和画布标准。**不能把一张忽明忽暗的线稿交给舞台运行时，让演出作者通过 brightness 补救**；舞台的 brightness 只用来表达那一幕的光照、表演与情绪，而不是矫正某个资产。

正式人物新图生成后，先在源图上执行：

```bash
python3 tools/portrait-neon/audit.py UnityClient/Assets/Resources/Portraits/Neon/<人物或姿势名>.png
```

审查器检查大块灰色填充与白描线核心亮度跨度，不合格立即重制源图，不得以修改运行时亮度或缩小预览掩盖。它只能否决明显的像素问题，**无法证明**人物比例、姿势、服装与身份一致；仍必须完成原图、透明化资源及与正式人物同尺度舞台预览三层人工审核。

完成源图审核后，才运行 `tools/portrait-neon/process.py` 派生骨架与线条蒙版。派生资源一律用同一亮白描线核心标准；场景中的调暗、淡入淡出属于运行时表演效果，不写回角色源资产。

默认先试 `tools/gemini-image-web`（Gemini Images / Nano Banana 2 网页适配器），也可使用 Tripo 的 `tools/tripo/image.py` 或当前可用的内置生图模型。服务顺序只是起点，不是硬性优先级：身份、尺度、动作或连续帧画风不合格，且调整提示词仍无明显改善时，及时换服务或模型；不必等额度耗尽，也不要为坚持某个服务降低验收标准。按任务选择能完成要求的模型，Tripo 未指定时可先试较便宜的 `banana2`。

用法与鉴权看各工具 README / `--help`。Gemini 文生图用 `--prompt` / `--prompt-file`，调整已有形象用 `--reference` 加编辑指令；同一浏览器 profile 不能并发。需要保持人物身份时输入基础图，并限制只改什么、保留什么。视觉画风比较先用同一个姿势，不为每个动作生成新图。服务生成成功不代表符合项目风格。

把关节动画转为立绘动画时，跑步等循环动作可以用少量互补姿势交替。两张图须有可读的步态差异，并保持头部、躯干尺度、朝向、画风与接地位置一致；不能用两张同姿势或放大的站姿冒充跑动。需要连续性时可以在同一张图里生成多帧，再在制作阶段拆分、去除图外标签与背景；以实际舞台尺寸和播放速度审阅交替效果。

审图时按目标画面尺寸检查外轮廓、主体完整性、主次层级、时代物件和角色一致性。正式描线人物出现灰色实心衣裤、皮肤或帽子，直接不合格，不接入。重要人物若姿势可读但身份特征丢失，不合格。

正式人物必须分别检查生成原图、透明化后的实际资源，以及与已有正式人物并排的舞台预览。三层检查都满足风格、比例、姿势和接地要求才可接入；生成成功、内容加载通过或演出能播放，不能称为美术验收通过。
