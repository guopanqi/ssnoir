# 抽象玩法机制研究 · 唯一当前执行入口

**最重要的研究对象：抽象决策关系。** 不是 SSNoir 第一章的剧情、人物、香烟、地图、原版物品时序和叙事结局；这些属于单独的正式内容工作。无论旧批次 S2/S3/R149–R173 的结尾写了什么“下一步”，都不构成机制研究的新任务指令。详见[权威研究定位](../../docs/实验/机制研究/研究定位与评价.md)。

## 什么值得研究

先不用故事，直接用 A/B、行动资源、公开状态和结果描述**玩家连续重复在做什么**：看见何种条件、选择哪些动作、得到什么反馈、怎样改变接下来可做之事。至少说清楚：

- **核心判断**：玩家必须分配什么有限资源或选择什么机会，哪些结果不能兼得？
- **反馈关系**：为什么下一次选择与这一次不一样？风险/信息/目标/时间/动作转化中哪个变量真正起作用？
- **独立性**：去掉人物、道具和场景后，是否比历史模式改变了行动、反馈或判断的*形态*？只是新增进度条、新故事或算分权重不算。
- **可学习性**：玩家能否在少量体验后理解，进而在新的情形下运用？简单规则达到最优不是自动失败；数学复杂也不是自动成功。

用“积累→保护/冒险→兑现”“从多目标中选择→行动生成待处理负担→重新分配”“试探→发现条件→保留或改道”等心理循环语言组织假设。保留新颖但可解释的组合；允许基础关系本身有趣，无须堆复杂度。

## 每批工作方式：自主发散与快速反证

1. **横向探索**：从至少两个不相邻的机制族提出候选，如动作互为条件、跨周期兑现、有限容量分配、可改变的操作方式、敌对反馈和不完整信息。不要顺着“下一个人物/剧情事件”做增量。
2. **去情景机制卡**：每个候选先写：公开状态→玩家动作→触发与反馈→真正变化的判断→有意义的取舍→与已有关系区别→预计退化→人类可能觉得有趣的原因。缺失时先不编写代码。
3. **廉价证伪**：测试动作支配、等价换名、固定开局流程、最强可解释公开口诀、空耗成本和正常可达状态。只要已证明它不过是另一个皮肤或固定流程，就收束此变体转下一个机制族。
4. **按需深入**：只有尚有新颖判断的原型才引入精确有限模型、机制消融、可达性/双向真实选择、最小独立试玩。形式模型回答“关系成立吗”，**不能**回答“玩家觉得好玩吗”。历史 C#+Scheme 内容原生验证只用于实际声称与正式游戏一致的候选，**不是抽象探索强制步骤**。
5. **自主总结**：区分“原创候选 / 已知模式新组合 / 情景层应用 / 被反证或停止”，写最强负例与可复用结论。失败要归档，不要用下一轮改数字救它。候选和精选无须为凑20而自动增加。
6. **更新研究入口**：只在研究队列放真正尚未解决的*抽象研究问题*，当前状态控制在一屏可阅读范围；长期记忆保留新认知、失败解释、未探索方向，历史详细数据进归档。必要时更新精选模式库和[研究工作台](../../docs/实验/机制研究/研究总览.html)，但未经筛选不入Debug。

## 证据和试玩的硬边界

结构推理/数学模型/正式C#+Scheme/真人反馈各自有不同证明力；CI通过不是“好玩”。精确模型优先验证语义、正常路径与最强简单策略和禁用新机制的反事实，**但不以DP最优差为研究目的**。人类试玩着重：为什么这样做、会不会重新考虑、是否重复且可预料、是否愿意再玩。反馈不直接变成好玩分数。

正式 Unity Debug只由人工批准清单 [DebugResearchPlaytests.json](../../UnityClient/Assets/Resources/DebugResearchPlaytests.json) 决定。任何历史 R/S 场景或模型都不能自动添加；验证：`python3 tools/content-validator/experiments/validate_mechanism_portfolio.py` 和 `validate_debug_playtests.py`。

## 单独轨道与历史

- **A 本 Skill 唯一默认工作**：新的抽象动作/决策/反馈关系。
- **B 玩法体验验证**：当一个抽象模式有明确值得观察的判断，才组织最小可玩实验与异步人类评价。
- **C 正式游戏内容**：S3-X香烟、S3-Z离队、第一章人物剧情与内容回放等，作为独立内容排错历史保留。**只有用户明确要求修这些内容时，才进入该轨道**；这不是本 Skill 的优先事项。

历史批次不删除，保留在[批次](../../docs/实验/机制研究/批次/)。已发生的S3-Z缺陷仍客观存在，但需要由内容工作流单独处理。

**默认接续准则：先问“还可能有什么不同的玩家选择活动”，绝不能先问“下一个角色/物品/剧情要发生什么”。**
