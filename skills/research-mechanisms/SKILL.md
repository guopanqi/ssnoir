# 交锋机制研究

**S2-C阶段关口（2026-10-12）**： [R116–R118跨日期限与保存报告](../../docs/实验/机制研究/批次/S2-C-R116-R118-跨日期限与保存/研究记录.md) 与 [三个独立Job成功CI](https://github.com/guopanqi/ssnoir/actions/runs/38194919633)。R117已经用可学的五条件规则完整覆盖R115主情境的自由最优；任何再次把R115的1/8差说成额外策略复杂度，都是过期结论。S2-A/B/C共九项数学审查完毕，**下一步只能以S2-D场景整合与正式验证为中心，不再扫同样数学参数**。这不是九个已证明好玩的模式，Debug继续三项。


**S2 长阶段研究（2026-10-12）**：先看 [S2多事件注意力网络阶段计划](../../docs/实验/机制研究/S2-多事件注意力网络阶段计划.md) 与 [R110–R115首批六轮证据](../../docs/实验/机制研究/批次/S2-A-B-R110-R115-注意力网络/研究记录.md)。默认一个 ChatGPT 会话持续推进四个模块：信息机会→目标网络→跨日期限→3目标情境／正式原生；**每次以整个有意义的子阶段与验收门槛收束，不再惯性只做1–2轮**。子实验强反证仍包括最优vs强公开策略、直接关闭新增规则、正常路径转折与容量边界；阴性例子同样保存。API付费多Agent已按用户要求删除，不依赖其启动或调度。S2-A/B目前完成六项纸面研究，无C#+Scheme或真人晋升证据，Debug三精选不变。

**ChatGPT 单会话续研恢复约定（2026-10-12）**：没有 OpenAI API 密钥或无法创建多个真正并行 LLM Chat/subagent 时，**直接由当前单 Agent 自主继续**，不等待也不触发付费 GPT-6 API 工作流；已有GitHub Actions可以验证确定性脚本，但不当LLM子代理。任何旧R83等落后分支不可作为继续研究或归档的强制入口：优先以已授权GitHub connector读取最新main HEAD，直接创建独立研究目录和代码，构造基于最新tree的新commit，以期望HEAD租约更新main，遇到竞争则重读并协调。实在无法写入时保留可复现脚本和精确失败原因，不能因一次工具失败永久暂停其它独立研究。R108此前在另一会话因旧分支创建失败而停止，已由本会话直接从附件完整恢复到main并CI通过。R109另证实主目标提前关闭副目标，可产生严格的注意力重排，但最佳公开阈值仍达最优，未晋升Debug。


**R103–R105并行研究方法（2026-10-12）**：实际可并行的本地/CI计算工作者和真正独立的LLM Subagent不是一回事。研究协调者分配互斥的任务目录，各工作者冻结因果关系与强反证，只输出独立证据；共享记忆、模式库、试玩任务和Debug名单由协调者单点更新。先读 [并行研究协议](../../docs/实验/机制研究/并行研究协议.md) 与 [R103–R105三Job批次记录](../../docs/实验/机制研究/批次/R103-R105-并行因果研究/研究记录.md)。R103匹配单行动的事件概率不等于匹配触发与进度的相关性；R104要扣掉封路后修梯债务；R105必须拿免费自然线索与可自证的探索行为对照，绝不可仅因有「付费探查」新按钮便晋升。三线仅数学，未新增真人或C#证据，Debug仍三项。


**R99–R102-native反证方法（2026-10-11）**：把状态反应规则的复杂性区分为「全局一条规则」「开局可选K条全局规则」「真正途中动态最优」，R99显示四骰压缩条件只需两条储备阈值就完整最优。必须回到原生真实3回合／12骰／冷静消耗的容量检验，不能把两回合4骰的纸面模型当正式性能；R101/R102-native的合计42条脚本显示高阈值3/4在固定seed里取得全部12/12，但不同动作会消费不同随机序列，不能把同seed当共享结果或当作胜率估计。并行R102-paper是一回合数学，与R102-native严格区分；永远不因数学候选自动进入Debug。[证据与边界](../../docs/实验/机制研究/批次/R99-R102-native-策略压缩与正式兑现/研究记录.md)。


**R97 与 R102-paper（2026-10-11）**：研究正式故事机制前先做“完全禁用新增动作”和“强制开局使用新动作”的双消融。R97纸面有限封门期限中，自愿晚封门0.740505，永不封门0.711698，开局强制封门0.636338；正常策略仅第二回合出现严格封门（路径质量0.096879），说明延后承诺才是关系核心。R102-paper采用P10真正的*一回合四骰*（不是R98/R99的两回合总四骰），只对当回合进度计效用：非线性自由12.54235，最佳单阈值12.54097，近乎流程化。这两项均仅数学，**不能覆盖P20/P10原生，不增加Debug**。另有其他Agent已提交R99/R100/R101/另一R102-native，必须按文件证据区分并避免编号混淆。[原始记录](../../docs/实验/机制研究/批次/R97-R102-延后封门与单回合边界/研究记录.md)。


**R88–R92 方法增量（2026-10-11）**：[五轮独立研究](../../docs/实验/机制研究/批次/R88-R92-阶段事件与场景机制/研究记录.md)已完成；正式C#验证某动作能改变追兵/钟表只是*技术因果*，不代表玩家有条件性选择。R89提示公开中途检查的**位置**比简单增加检查概率更重要：第二手查验最优路径0次提前清污，第三手查验约28.6%的严格有利路径，但这是独立纸面新变奏，不得修改P17旧原生身份。R92不同储备阈值的报酬交叉来自两套对照规则，不等于玩家在单一规则中有应当等待的选择。每种研究先问「在正常可达状态下相反选择是否都值得做」，再考虑晋升或故事实现。**Debug名单仍仅三项**。


**最高目标与评价权威**：[抽象玩法结构研究定位](../../docs/实验/机制研究/研究定位与评价.md)。研究的是可复用的抽象决策关系，情景和人物的创作应用不属于本研究，不把模拟数字称为好玩。每批最终需要反证和人类可读的判断，并更新结构化模式库与 HTML Artifact。

目标是在现有规则下找到少量、简洁、值得玩家尝试的设计模式。多个目标争夺行动力只是一个分支，不能限定整个搜索空间。

## R83–R87：独立因果比收益更重要（2026-10-11）

继续研究时阅读 [R83–R87记录](../../docs/实验/机制研究/批次/R83-R87-机会信息与情景价值/研究记录.md) 和 [累计32轮的机读记忆](../../docs/实验/机制研究/自主研究记忆.json)。机会真正关闭也不意味着撤销承诺一定有收益；正常工作提供的线索准确度可能弱支配专用查证；地图换路线本身有价值不证明敌人追踪规则有用；动作提升成功率也不等于出现中途改变计划（P17提前清污为0）；两个不同的叙事成果若未说明后续效用，不能凭数学指定一种玩家偏好。R88–R90自动推进，不需要等待人类反馈；不把数学候选自动送进Debug。

## R79–R82的方法增量

等待是否有现实代价、信息能否通过普通行动自然获得、对手追踪是否有真正会影响后果的效果，都必须做**合理外部选项对照**。R79确认免费等待使撤销承诺收益为零，收费等待下才有撤销收益；R80确认免费自然信息降低但未消灭主动探查价值；R81曾有移动收益但追击开关无影响，R82把追击连到真实伤害后才得非零差。绝不可只因某动作有收益就声称新反馈规则有用。[批次记录](../../docs/实验/机制研究/批次/R79-R82-等待信息与追击/研究记录.md)，机读前沿R83–R85见自主研究记忆。

## 新的研究与试玩准入层级

Unity两个菜单共用DebugEncounterCatalog。剧情清单DemoEncounters.json，研究手动试玩单独DebugResearchPlaytests.json。禁止再次通过Resources.LoadAll扫描全研究目录作为菜单。

20项结构候选见 docs/实验/机制研究/结构候选20.json 与同名Markdown，只是可以解释并反证的独立决策关系。不得把20项候选当20项人类认可的可玩场景，候选新增/改动不得自动改变Debug白名单。

新增Debug研究项必须有独立的人工试玩审阅、实际原生Scheme入口和可追溯依据。验证：python3 tools/content-validator/experiments/validate_debug_playtests.py 及 validate_mechanism_portfolio.py。

自主循环仍需语义不变量、简单策略反证、新增规则关闭消融、正常路径严格决策、原生逐手证据；人类意见异步输入。价值低的候选可以从20项中替换，不许掩盖失败。


## 接手

从本 Skill 源目录解析以下路径。每次续研先读：

0. [研究定位与评价](../../docs/实验/机制研究/研究定位与评价.md)：抽象模式、评价与持续产出契约。
1. [当前状态](../../docs/实验/机制研究/当前状态.md)：结论、边界、证据入口与接续位置。
2. [研究队列](../../docs/实验/机制研究/研究队列.md)：待研究假设、反证条件与状态。
3. [研究约定](../../docs/实验/机制研究/研究约定.md)：质量判断、证据身份、协作和收尾规则。

**研究对话必须在工作台闭环**：新机制或非兼容性改版要新建独立 Rxx 试玩任务，不让用户为新版覆盖旧原始反馈。网页中研究者回复下的「提交独立回帖」创建 `feedbackKind=reply` 和 `inReplyTo`（被回复文件/研究者绑定的版本SHA），不是覆盖旧文件。Agent 续研时将回帖与原反馈、review完整串联阅读；下一轮为回帖写绑定SHA的独立review。对话中的设计者纠正也写进研究记录，并在对应原版review指向新版。用户不必回聊天搬运已在工作台提交的记录。**除非明确被要求，不要为了更改设计而直接修改原试玩规则，把它伪装成同一实验。**

**新增候选的三重归因检查（R66–R75归纳）**：每种机制先声明：完成进度是否永久兑现、能否继续作用已完成目标、强制改目标是否仍算玩家决策；用可达状态不变量检验。除了开局脚本与响应式口诀的强策略差，还必须尽可能**直接关闭新增动作/状态反馈规则**做同条件精确消融，报告新增机制的独立价值；沿完整策略常态路径统计仅包含仍有可选替代的严格有利改路，并列出实际触发路径比例。R66前版R61目标已完成仍被损毁造成语义错位；R71强策略差0.04834但关闭搬移动作仅损失0.00048——两者均不应因复杂DP或表面动态收益晋升。对R67等同构关系先并入旧模式；与旧批次因果相同的数字变体无需重复做正式引擎。[新批次记录](../../docs/实验/机制研究/批次/R66-R75-下一批自主研究/研究记录.md)。

**Agent自主推进是默认路径（2026-10-09）**：不要为了等待真人反馈停顿。每轮按 [结构化自主研究记忆](../../docs/实验/机制研究/自主研究记忆.json) 的 frontier / previous failed explanations 生成新假设，再自主完成最便宜的支配/等价反证和必要的精确数学或原生测试，明确是否晋升/暂缓/排除、保存更新记忆和下一轮假设。可连续执行十轮等批次；负例同样有价值。人的反馈是异步输入，能推翻数学方向或审视体验，但不是研究开展的唯一权威。区别人类体验、模型与C#三层证据，**不追求数量、面积或胜率**。最新R56–R65已执行十轮并归档，[批次研究](../../docs/实验/机制研究/批次/R56-R65-自主十轮/研究记录.md)。优先探索不同抽象关系，避免无意义地围绕一类参数反复扫数。

**真人反馈优先级**：每次续研先检查 [反馈/inbox](../../docs/实验/机制研究/反馈/inbox/) 有无新提交；按 [反馈协议](../../docs/实验/机制研究/反馈/README.md) 区分网页示意版与正式引擎反馈，摘录具体犹豫时刻和重复感。对于已收到但未裁决的反馈，先明确区分开局决策和过程中决策的不同价值，既不因没有中途变化就判差，也不因存在数学动态收益就判好；再解释它是否改变模式的研究优先级，再决定是否继续跑数值；不要无视用户的实际试玩而无限续算。

只按当前问题打开相关历史证据。接手记录标为进行中的任务时，先核对负责人、已有输出和版本，避免重复执行。

## 推进

- 以一个可区分的假设为工作单元。写清最小规则关系、可能退化的原因、最便宜的判别方法和本批停止点；不要直接启动一轮全空间扫参。
- 用用户举的船体压力与多敌人例子理解体验诉求；旧实验不作为优雅结构的质量范本。具体候选和偏好以当前状态及用户最新指示为准。
- 优先找能推翻候选的简单策略、支配关系与退化边界。区分**固定对象顺序（但仍可逐手择骰）**、固定动作规律与完全僵硬的脚本，三者不是一回事。强目标序能否近似自由策略通常比新增状态数更有解释力。
- **证明响应式对手引出特殊决策**时，不能只看自由与固定目标顺序的数值差：必须另测固定攻击者等消融，且用正常最优策略的前向展开（预先声明同值选择规则）计算目标是否真的被诱导、此举是否在反事实中提高后续成果。数学模型路径不等于人类行为。存在最优策略反例不等于好玩；高胜率也不等于有策略。
- 用可交换性、对称换名、容量和强参照做快速筛选，复用校准输入与等价状态缓存。方法见研究约定；未覆盖伤势等机制时明确目标范围，不把保守模型失败等同游戏失败。
- 纸面排除足够时就记录并结束。需要执行内容时使用项目的 [write-scheme](../write-scheme/SKILL.md)；修改可执行内容或工具时按[项目验证指南](../../tools/VERIFYING.md)的相关章节决定最小充分验证。
- 使用现有正式会话适配器与研究工具，工具入口见 [机制研究工具](../../tools/content-validator/experiments/机制研究.md)。正式规则仍以 Content 为唯一来源。
- 并行授权与分工按研究约定落实；各探索者只写分配的任务目录，协调者汇总全局记忆。并行不能混用不同规则版本的数据。

## 收尾与恢复

把本批假设、反证、实际证据、取舍理由和下一步写入任务记录，说明新结果为什么引向这个下一问题；允许据证据重排队列或提出新方向。协调者随后更新队列、当前状态，并从 [试玩任务 JSON](../../docs/实验/机制研究/试玩任务.json) 维护下一轮人类的**最小试玩队列、优先级、无提示问题和正式入口**；发现新反馈时，不强行让用户试玩每个原型。随后维护[模式库 JSON](../../docs/实验/机制研究/模式库.json)及由它生成的[HTML 研究总览](../../docs/实验/机制研究/研究总览.html)；保留原始证据和历史结论的版本身份。成熟度不足的批次可不晋升精选模式。

**交流工作台**：[人类研究工作台](../../docs/实验/机制研究/研究总览.html) 是研究者对设计者的正式进展／试玩请求入口。它必须能离线打开；R50/R54网页示意版与C#正式玩法分别标注；人类输入通过独立 JSON 文件上传，而不是直接编辑生成的 HTML。生成器和 UI 浏览器测试通过后才能声称可用。HTML 不应该成为另一个行为规则权威。

未完成时写具体恢复步骤、待处理输出和版本条件。已经完成的复核不因换 Agent 而重跑；规则或工具变了则先判断证据是否仍适用。研究由项目文件接续，不依赖原 Agent 的会话记忆。


### 反馈—研究者回复—再反馈（简短异步讨论）

- 人类原始反馈不可被研究者改写：`反馈/inbox/*.json`。研究者的解释使用同名 sidecar 文件 `反馈/reviews/<反馈文件名>.json`，含 `schema=ssnoir.mechanism-review/v1`、`sourcePath`、`feedbackSha`、时间、观察、解释、开放问题与下一研究动作。
- 研究者回复是**有条件的解释，不是好坏评级**。同一结构可以有良好的开局选择，但较少中途调整；把两种证据分别讨论。绝不逼人类认可 Agent 先前的数学期待。
- 人类重新编辑反馈后，SHA 变化应使工作台显示“需要重新审阅”；下一次研究任务检查后重新阅读整份反馈、试玩轨迹、补充文本和上一次回复，必要时更正并更新 sidecar SHA。旧版本仍在 Git 历史中。
- 不承诺网页即时 AI 自动答复：当前通过 GitHub 提交一轮研究者回复，人类可在原文件补充或回答问题，研究者后续再审。复杂多轮讨论交给 ChatGPT 对话，不在简单工作台内堆聊天系统。
