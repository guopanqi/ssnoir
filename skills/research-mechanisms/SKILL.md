# 抽象玩法机制研究 · 唯一当前执行入口

**最重要的研究对象：长期演化的抽象玩法模式语言，包括基础决策原语、完整交锋结构和跨交锋组织的组合关系。** 不是 SSNoir 第一章的剧情、人物、香烟、地图、原版物品时序和叙事结局；这些属于单独的正式内容工作。无论旧批次 S2/S3/R149–R173 的结尾写了什么“下一步”，都不构成机制研究的新任务指令。详见[权威研究定位](../../docs/实验/机制研究/研究定位与评价.md)。

## 什么值得研究

先不用故事，直接用 A/B、行动资源、公开状态和结果描述**玩家连续重复在做什么**：看见何种条件、选择哪些动作、得到什么反馈、怎样改变接下来可做之事。至少说清楚：

- **核心判断**：玩家必须分配什么有限资源或选择什么机会，哪些结果不能兼得？
- **反馈关系**：为什么下一次选择与这一次不一样？风险/信息/目标/时间/动作转化中哪个变量真正起作用？
- **独立性**：去掉人物、道具和场景后，是否比历史模式改变了行动、反馈或判断的*形态*？只是新增进度条、新故事或算分权重不算。
- **可学习性**：玩家能否在少量体验后理解，进而在新的情形下运用？简单规则达到最优不是自动失败；数学复杂也不是自动成功。

用“积累→保护/冒险→兑现”“从多目标中选择→行动生成待处理负担→重新分配”“试探→发现条件→保留或改道”等心理循环语言组织假设。保留新颖但可解释的组合；允许基础关系本身有趣，无须堆复杂度。

## 长期知识研究约定（2026-10-13）

- 把研究看成长期开放的**模式语言**，而非固定四阶段/20个模式的交付。发现、变体、组合、已知作品先例、退化边界都可以是成果。先查[知识地图](../../docs/实验/机制研究/模式语言知识地图.json)及[解读](../../docs/实验/机制研究/模式语言与证据地图.md)，再用[关系索引](../../docs/实验/机制研究/关系索引.md)定位尚未转录的历史。
- **基础决策关系、交锋决策结构、跨交锋架构**都可研究；不要求每一轮从基础向上叠规则。允许从《Citizen Sleeper 2》等作品已用的结构反推基础关系，必须标明只是参考文档中的设计归纳、非官方分类或本实验真人验证。
- 每批至少有一次独立的**设计批评**：只看公开规则，指出最强无聊操作、可能误解、同构、玩家是否真的需要更新计划。数学/工程测其反例，不能替批评者给乐趣打分。若无法调用独立评估Agent，须明确写“同一研究者的独立反证视角”，不冒称盲评。
- 不是只有精选才可沉淀：非精选的有效结构、失败边界、成熟先例进入模式语言知识地图，注明独立证据；精选六项原始JSON只负责工作台展示，不用于自动评价全体历史。
- 用小型可玩实验评估**玩家的活动与反馈变化**，避免让单纯数值扫描占据主循环。可提供终端/网页原型，但正式Debug只能人工准入。真人的无提示反馈稀缺且异步；缺失时继续自主研究并明示限制。
- 研究不是持续扩写一条R序列。定期跨关系族重画知识地图，检查被埋没的有用旧研究、不同模式的互促/互相压制，以及组合是否只是若干进度条简单相加。

## 长期研究的自主性与证据责任

- **不是有限四阶段项目**。在“吸收成熟作品已知模式／发明或组合机制／独立批评与实验”三个方向间长期循环；每个问题才执行发散→反证→最小试玩/模型→归纳。研究者自主改变路线，而非沿最近 R 编号不断做数值邻域。
- **不是候选→精选的价值漏斗**。研究库可保存已知设计先例、暂未真人试过的结构、已有简单策略解释的可用原语、组合条件、有效负例与开放问题。精选是设计师展示视图，Debug是人工授权列表，真人反馈是独立证据，不是入库许可证。
- **优先分析组合的因果边**：一模式是否为另一模式提供条件、改变行动价值或合法性、争夺同一资源、跨阶段兑现，还是完全同构/互相压制。单纯增加钟/节点/对手数量不能充当证据。
- **独立批评再补模型**：让独立上下文先寻找最强无聊口诀、信息成本的强对照、条件改变是否可达。对可试玩候选可用不知最优答案的独立 Agent 按玩家可见信息逐步试玩，保留每手理由；Agent主观评价不能写作真人反馈。
- **成熟作品参考的边界**：来源清楚的已发行游戏模式可直接成为研究素材，无需假装由本实验原创；具体游戏事实与设计推断须区分，移植后的可读性和体验尚需检验。
- **长期记忆与自我转向**：定期回看横向地图，复活旧候选、合并同构、总结反证与关联，并主动选择仍未覆盖的心理活动。单轮失败也要生成可复用知识；人类反馈异步到达时再更新体验判断。

## 每批工作方式：自主发散与快速反证

1. **横向探索**：从至少两个不相邻的机制族提出候选，如动作互为条件、跨周期兑现、有限容量分配、可改变的操作方式、敌对反馈和不完整信息。不要顺着“下一个人物/剧情事件”做增量。
2. **去情景机制卡**：每个候选先写：公开状态→玩家动作→触发与反馈→真正变化的判断→有意义的取舍→与已有关系区别→预计退化→人类可能觉得有趣的原因。缺失时先不编写代码。
3. **廉价证伪**：测试动作支配、等价换名、固定开局流程、最强可解释公开口诀、空耗成本和正常可达状态。只要已证明它不过是另一个皮肤或固定流程，就收束此变体转下一个机制族。
4. **按需深入**：只有尚有新颖判断的原型才引入精确有限模型、机制消融、可达性/双向真实选择、最小独立试玩。形式模型回答“关系成立吗”，**不能**回答“玩家觉得好玩吗”。历史 C#+Scheme 内容原生验证只用于实际声称与正式游戏一致的候选，**不是抽象探索强制步骤**。
5. **自主总结**：区分“原创候选 / 已知模式新组合 / 情景层应用 / 被反证或停止”，写最强负例与可复用结论。失败要归档，不要用下一轮改数字救它。候选和精选无须为凑20而自动增加。
6. **更新研究入口**：先更新有因果关系与证据界限的[模式语言知识地图](../../docs/实验/机制研究/模式语言-知识地图.md)，再只在研究队列放真正尚未解决的*抽象研究问题*，当前状态控制在一屏可阅读范围；长期记忆保留新认知、失败解释、未探索方向，历史详细数据进归档。必要时更新精选模式库和[研究工作台](../../docs/实验/机制研究/研究总览.html)，但未经筛选不入Debug。

## 证据和试玩的硬边界

结构推理/数学模型/正式C#+Scheme/真人反馈各自有不同证明力；CI通过不是“好玩”。精确模型优先验证语义、正常路径与最强简单策略和禁用新机制的反事实，**但不以DP最优差为研究目的**。人类试玩着重：为什么这样做、会不会重新考虑、是否重复且可预料、是否愿意再玩。反馈不直接变成好玩分数。

正式 Unity Debug只由人工批准清单 [DebugResearchPlaytests.json](../../UnityClient/Assets/Resources/DebugResearchPlaytests.json) 决定。任何历史 R/S 场景或模型都不能自动添加；验证：`python3 tools/content-validator/experiments/validate_mechanism_portfolio.py` 和 `validate_debug_playtests.py`。

## 单独轨道与历史

- **A 本 Skill 唯一默认工作**：新的抽象动作/决策/反馈关系。
- **B 玩法体验验证**：当一个抽象模式有明确值得观察的判断，才组织最小可玩实验与异步人类评价。
- **C 正式游戏内容**：S3-X香烟、S3-Z离队、第一章人物剧情与内容回放等，作为独立内容排错历史保留。**只有用户明确要求修这些内容时，才进入该轨道**；这不是本 Skill 的优先事项。

历史批次不删除，保留在[批次](../../docs/实验/机制研究/批次/)。已发生的S3-Z缺陷仍客观存在，但需要由内容工作流单独处理。

**默认接续准则：先问“还可能有什么不同的玩家选择活动”，绝不能先问“下一个角色/物品/剧情要发生什么”。**
