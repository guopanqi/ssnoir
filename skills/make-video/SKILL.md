# SSNoir 的视频导演

**这是导演知识，不是调用手册。** 怎么把请求发出去、参数长什么样，全在
**libtv-video-generate skill**（工具在 `tools/libtv-video-generate/`）。
本文只写那个服务不该知道的事：素材和剧情从哪来、一张场景图合不合格、
提示词怎么写、成片怎么判。

一句话流程：**审场景图 → 找剧情 → 写提示词 → 6 秒试 → 看片判断 → 拉时长定稿。**

---

## 1 资产来源

**用户指定的路径永远优先于下面这些默认位置。**

### 场景图由用户提供

Agent 操作不了 Unity，定机位这件事只能由用户在游戏里截图交进来。不要自己找图代替，
也不要拿建模预览图（`.cache/*/​*_preview.png`）冒充场景——那不是游戏里的机位。

收到图之后你的职责是**按第 2 节审一遍并给出意见**：合格就往下走，不合格就说清哪一条不过、
该往哪个方向重截，然后等新图。不要用提示词去补一张不合格的图，第 3 节说明了为什么补不动。

### 其余素材的默认位置

| 要什么 | 去哪找 |
| --- | --- |
| 人物形象 | `UnityClient/Assets/Resources/Portraits/Neon/<角色名>.png` |
| 参考样音 | `角色库/<角色名>/声音/参考样音/<角色名>voice.mp3` |
| 已录配音 | `角色库/配音/候选/<小节>/<场次>/<第几句>/<角色名>.wav` |
| 剧情 | `UnityClient/Assets/Resources/Content/scenes/**/*.scm`、`docs/手稿/` |

**人物必须用 `Portraits/Neon/` 那套霓虹描线版**。`Portraits/` 根目录下是平涂立绘，
那是游戏 UI 用的，风格和场景截图对不上，拿来做视频参考会把整条片子拉向另一种画风。

**剧情从 `.scm` 里取，不要自己编。** 每一场的注释里写着这一场要立哪几件事、节点副标题是什么，
那就是现成的分镜要求。这是整套流程里质量差距最大的一环——自己编的版本和照着注释拍的版本，
差的不是细节，是这场戏还成不成立。

### 会话

一场戏一个 `session`（例如 `过场｜酒馆后巷｜艾迪初登场`）。同一场戏的所有方案、
所有轮次都用同一个 `session`，这样候选留在一处可以对比。素材去重和画布复用由服务负责，
不用管。

## 2 场景图要求

Seedance 2.0 Mini 读不懂复杂构图。它对**多层级 isometric 透视**和**非典型建筑结构**的理解
很不稳定，而 SSNoir 的城市恰好两样都占。

要求一句话：**像舞台布景一样，一张图上就能说清哪是哪。** 可以是 3D、可以有透视，
但结构要稳定、易识别。

五条判定，任何一条不过就退回重截：

1. **一眼能说出这是哪吗？** 地点特征（招牌、吧台、门脸）必须在画面里。
2. **有没有锚点？** 门、窗、灯。人物需要一个"从哪来、站在哪"的落点，带光源的门口最好用。
3. **动作区有没有可站的地面和边界？** 纯开阔的地面会把人物吸过去乱走。
4. **主体有没有被画面边缘切掉一半？**
5. **有没有大片没有任何描线特征的暗区？** 那是模型最容易自由发挥的地方。

好例与坏例（配真实截图）见 [references/场景图规范.md](references/场景图规范.md)。

## 3 提示词模板

极简。**多写一个词，模型就可能往画面里多放一样东西。**

实际提交给模型的是这样一段，但**上半截由服务自动生成，你不用写**：

```
艾迪是 {{Node "角色｜艾迪｜061732c7"}}          ← 服务生成
场景是 {{Node "场景｜酒馆-后巷｜8f0a21c4"}}      ← 服务生成
以 {{Node "场景｜酒馆-后巷｜8f0a21c4"}} 的机位开始，全程镜头完全固定   ← 服务生成
禁止生成背景音乐（BGM），保留人声和环境音效。                        ← 服务生成

画面以后巷开始，路上没有人。                    ← 你写的 prompt 从这里开始
三个男人从门口的阴影里走出来，围住艾迪……
```

**你只需要写空行以下的剧情部分。** 头部那四行——角色绑定、场景绑定、镜头固定、禁 BGM——
由 `libtv-video-generate` 自动加，请求里的 `characters[].name` 就是角色在剧情里被称呼的名字。
证据是镜头04：正文里"围住艾迪"是大白话，没有任何占位符，靠工具加的头部绑定就够了。

### 禁忌

都是踩过的：

- **不写风格。** 参考图已经带着风格了。一提"风格"等于告诉模型这个维度可以动，
  它会重新打光、重新渲染建筑。
- **不写负面约束**（"不要暖光"、"保持描线"之类），同上，提醒即许可。
  唯一的例外是 BGM 那句，因为那是音轨不是画面。
- **不复述参考图里已经有的东西。** 写"窗里亮着，能看见吧台和高脚凳"，模型就会去点灯。
- **不写模型做不到的调度。** 图里没有可用的墙，就别写"背抵着墙"——写了只会被忽略。
- **配角写"剪影"，不给参考图。** 黑剪影在描线场景里读得最准，也省掉三个人造型不稳定的风险。
- **抽象优于具体。** 约束越少越连贯；越是把动作抠死，动作越笨拙。

## 4 迭代流程

生成一律走 **libtv-video-generate**，除了提示词、场景图、角色图和时长，
其余每次完全一样——所以出片变了，就一定是这四样变了，不会是别处飘了。
下面这条"提示词一字不改"的规矩，只有在其余部分被服务钉死的前提下才成立。

**6 秒 `takes=2` 定调 → 用户认可 → 提示词一个字不改，只改 `duration`。**

第一版不要上 15 秒：费积分，也慢。

**时长本身会改变模型的排布方式。** 同一句"三个男人轮番殴打"，6 秒里是一拥而上，
12 秒里模型自己排成了依次从门里走出来。所以节奏不对时**先试时长，不要改提示词**——
改提示词等于同时动两个变量，出了问题分不清是谁的功劳。

台词多了会像读稿。最终时长按台词和沉默的实际节奏定，不是越长越好。
一条镜头装不下的，切成两段，用「以这一帧结尾 / 以这一帧开头」把接缝钉住，
再用 `video-clip` 拼。

关于音频：**15 秒是视频时长上限，不是参考音频的长度限制**。模型 schema 只约束音频**条数**
（`mixed2video` 最多 3 条），没有任何一条声明参考音频的长度限制。
选样音要看的是能不能代表音色，不是秒数。

## 5 验证

不要凭印象说"看起来对"。服务已经替每条片子产出了 `frameStrip`（抽帧条）和
`plateComparison`（输入场景图 / 输出首帧的上下叠图），路径在返回 JSON 里。看四件事：

1. **风格漂没漂。** 看对比图：描线还在吗？建筑有没有被重新打光、被换成实体着色？
   这是最常见的失败，而且只有叠起来看才发现得了。
2. **人数对不对**，全程稳不稳。
3. **节拍到没到。** 收尾画面是不是 `.scm` 里那句话描述的样子。
4. **选优**，并说清为什么选那条。注意两个轴：不同 `variants` 是不同的创作方案，
   同一方案的多个 `takes` 是同一句提示词的多条候选——两个都要看。

失败的成因和修法记在 [references/踩过的坑.md](references/踩过的坑.md)，每踩一个新的就往里加。
