# 制作地点与场景

交付单位是 `city-box/prefabs/<名>.blend`：地标建筑、室内空间、街区和Scenario地点都从这里进入。程序化源通常位于 `prefabs/src/<名>.py`；已有手工模型也可以直接加工。正式净几何、语义节点与作者声明保存在 Prefab，代码和生成服务是制作手段，不决定这个任务属于哪个 Skill。

先确定地点在故事中的身份和主要动作：玩家第一眼看到什么、为什么愿意靠近、随后读到哪些空间关系。建筑轮廓本身可以是焦点，室内通路、人物或家具也可以是焦点。不要把“地点制作”限制成摆道具，也不要因为主体是一栋建筑就改走单件资产发布流程。

## 确定表达并选择制作路线

开始设计先读 [视觉语言](references/visual-language.md)，按入口了解共同基准和作者选项。主导轮廓、空间比例、材质、描线与光共同决定地点的阅读；在早期试配，不把它们当作网格完成后的装饰步骤。

- **从零设计或改变布局**：先确定体量、入口、分区与机位。需要参考图时读 [布局预览](references/layout-preview.md)，空间迭代读 [灰盒](references/greybox.md)。代码灰盒可以直接打磨为最终建筑，不强制替换成服务生成模型。
- **优化已有地点**：保存原机位基线，按目标调整需要改变的层次；不为了套流程重做已成立的布局、模型或道具。
- **需要单件资产**：先复用 `city-box/props/INDEX.md` 和场景私有道具。现有模型加工、代码建模和生成模型都可采用；独立资产的造型、网格与加工由 [make-3d-asset](../make-3d-asset/SKILL.md) 处理，摆放与归属见 [道具](references/props.md)。

同一地点可以混合多种制作方式，最终以游戏机位里的整体表达判断。把本次注意力顺序、关键取舍和审核图留在 `prefabs/review/<名>/`，不把每次候选都提升为共同规则。

## 组合表现与语义

表面、描线和灯光使用项目已有角色；作者声明与限制见 [CityBox 视觉参数](../../city-box/docs/视觉参数.md)，组合与共享资源边界见 [视觉语言](references/visual-language.md)。源模型声明角色，Unity 按 WorldPalette 绑定共享材质；Blender 材质只供制作预览，不自行生成地点专用的 Unity 材质或 Shader 来绕过角色。需要演化共同语言时，先做隔离候选并评估影响，遵守功能冻结约定。

锚点和机位设计见 [机位](references/anchors-camera.md)，消费者与导入约束见 [运行时契约](references/runtime-contract.md)。正式地点身份使用 Scheme `GameNode.Id`，文件、集合、主 Anchor 与 Camera 按该身份命名；显示名称不代替主键。Pan 留下可感知的浏览余量，Orbit 检查实际可达视角，不能只为一张静帧成立。 悬空主体或接近平视的镜头按机位参考主动声明真实焦点；生成器已有 target 时保留它，不让运行时重新猜测。

已有会动道具的部件、clip 与审片流程见 [motion](references/motion.md)。只在当前任务确实涉及它时读取，不由场景制作扩展新运行时能力。

## 审核、接入与发布

先自审主体、通路、细节疏密、受光、遮挡和机位，再交付足以比较的候选。完整标准见 [视觉审核](references/visual-language.md#审核与交付)。需要用户判断方向、最终表现、新布局或正式发布时展示具体结果；已明确授权连续制作或发布时继续完成授权范围，不逐步重复确认。

按 [CityBox 交付](references/citybox-delivery.md) 完成布局装配、构建与 Unity 发布；`city-box/README.md` 维护命令，`tools/VERIFYING.md` 维护验证选择。正式源不保存构建描线，Main 的 City 只保留根变换，不覆盖 FBX 子对象。

日常设计循环在 Blender 完成：审空间、构图、动作节奏、接触、穿插和循环，不把启动 Unity 预览放进每轮修改。内容成立后再构建发布；普通交付以 Blender、共享 C#、构建契约和发布物检查结束，不自动启动 Unity。仅在导出/导入契约、Unity 专有渲染改变、两端出现差异或用户明确要求时，按 [验证边界](../../tools/VERIFYING.md#unity-验证边界) 做最小 Unity 核对。沿用现有契约的独立 Stage、Portal 和相机空间配置，不逐次重复引擎验收。

Blender 已确认正确而 Unity 出现异常时，按导出、导入、播放或运镜的功能缺陷单独定位；预览进程卡住、后台退出挂起也属于工具功能问题，不继续混在内容制作里反复重跑，更不靠修改正确资产来绕过。修复应落在共同管线，使后续内容能复用。构建、最终接入和实际交互是不同证据，只报告实际完成的检查。
