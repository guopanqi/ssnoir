# 场景视觉语言

目标是让玩家在游戏机位下读出地点身份、关键对象和空间关系。几何、表面、线、光与雾共同承担表达；不要求每个场景用齐所有手段，也不以晚宴的金色与抛光质感作为通用模板。

## 开始前读取什么

本参考维护**如何组合已有语言设计和审核场景**，不维护参数目录或全局数值。开始设计先读 [共同视觉基准](../../../docs/制作/城市视觉基准.md) 和 [CityBox 作者参数](../../../city-box/docs/视觉参数.md)，明确当前角色、能力与作用范围；修改语言或参数时回到对应源，不在本文件另写一套。

制作职责分工：

- 本 Skill：注意力顺序、空间与表面的关系、描线／配光／雾的组合方法、场景审图。
- `docs/制作/城市视觉基准.md`：全城与地点共同遵守的阅读层级、风格取舍和共享资源边界。
- `city-box/docs/视觉参数.md`：源 Prefab 可以声明什么、声明在哪里、组合限制；具体支持情况以它指向的代码为准。
- [运行时契约](../../make-scene/references/runtime-contract.md#世界视觉基准)：Unity 资源映射、坐标缩放、显隐、光照数据与导入约束。
- [正式预览工具](../../../tools/citybox-unity-preview/README.md)：如何取得正式画面证据。

按需看正式晚宴、码头、码头居民区与《别给他们想要的》的源 Prefab 和审核图：分别参考材质与配光组合、前后层次、密集环境退后和冲突空间。不要把某一场的选择套到所有地点；生成脚本与 `.blend` 声明可能不同，重跑脚本前确认它能保留当前视觉声明。

`docs/工程/TODO.md` 与 `docs/归档/场景视觉并行探索.md` 说明尚未补齐的场景质感；它们不是已完成效果的证据。暂缓的自由探索候选没有被正式采纳，不作为风格范本，也不将其盲式探索流程用于默认的新场景制作。

## 城市地点首先是叙事角色

城市一级地点的写实可信度服从于辨识度与故事表达。不要只从“这种功能的建筑通常长什么样”出发；先决定这个地点在故事中的立场、动作和情绪，再把它落实为远景可读的大体块。

- 每个一级地点必须有不可与其他地点互换的主导轮廓。优先拉开高宽比、对称/偏心、实心/空心、单体/聚落、屋顶线、主要缺口、悬挑和附属构筑物，不靠材质、颜色、招牌、窗型或表面装饰冒充差异。
- 把建筑当作角色，先为它确定一个能驱动形体的动词，例如压迫、拒绝、招揽、吞吐、藏匿；模型的大轮廓应表达这个动词，而不只是表达警局、酒店、诊所等功能类别。
- 同一批城市资产要做阵容审查，避免各自合理、合在一起却全部变成中等尺度、基本对称的盒状建筑。单体通过不等于城市阵容通过。
- 参考图和低模都要做纯黑剪影缩略测试：去掉标签、压到约 96px 高仍能依靠外轮廓认出，才算一级地点的辨识度通过。
- 描线服务于主形读取。不要让窗框、墙缝和内部结构获得与外轮廓相同的视觉权重，否则统一描线会抹掉建筑个体差异。

上流社会室内（酒店宴会厅、俱乐部）用 Gilded Age / Beaux-Arts 建筑语言（约 1900–1925 建成，故事年代里它已是老钱的场所）：高拱窗、成对壁柱、台口式乐池、半圆卡座、石栏杆露台。厅的长宽比至少 2:1 并明显拉高；接近方形、四周均匀摆桌的大厅会被读成中式宴会厅或会议室，直接淘汰。

## 设计方法：先分职责，再组合

读剧情、动作与锚点，写清玩家的注意力顺序：第一眼的主体、需要辨认的通路或分区、帮助定位的结构、退后的背景。把方案简记在场景 `review/<名>/prompts.md`，指出哪些构件承担这些职责、使用哪些现有角色、希望形成怎样的明暗／冷暖／反光关系。不规定每场固定几层或必须加雾。

- **地点气质**：先判断这是奢华场所、私密会面还是朴实工作空间，材质与照明要像这里实际会使用的东西。饭店可用集中暖光形成桌边私密感；普通照相馆用哑光工作面、克制的中性工作光，暗房安全灯只承担设备区的照明职责。金色和抛光不是通用的“精致”标记，不能只因为色盘里有就套用。
- **表面**：按构件职责选择已有角色，再看受光后的明度和反光。不把所有对象保留同一种默认表面，也不全铺亮饰面；发光灯饰的表面与真正的照明光源各有职责。
- **描线**：先决定物件需要结构线、外轮廓还是由光影呈现，再安排线的主次。减少无意义碎边后再调宽度；亮暗、线宽和显隐是不同控制，不把“暗线”当成“细线”。装饰线的颜色应有构件职责。
- **配光**：用已有光色组织主光、补光和轮廓分离，让主体与环境有关系。不靠整体曝光修补一个暗角，不用均匀补光照平所有体块。
- **环境与雾**：暗部保持可读，远处需要退后时才考虑局部雾；不能吞掉交互落点或把前后洗成同一片灰。查明参数属于地点还是共享作用域，再调整。

例如：关键家具可以用清楚的轮廓和局部受光被看见，围合墙面用较暗表面与结构线保持空间，少量灯饰给冷暖方向，远处是否用雾取决于距离和情景。精致感来自这些关系，不来自线、金色、反光、灯或雾的数量。

灰盒先确认空间，再在占位体上做层次试配；精细道具替换后重新看轮廓、反光与遮挡。灯的位置应与场景可理解的照明方向相符；材质承担形体，描线补足阅读，不让每条墙缝、窗框、椅腿都与关键轮廓争抢。

## 视觉语言的演化与共享边界

已有语言是当前共同基准，不是封闭目录。制作中发现表达不足时，应提出新材质、描线、光影或组合方法；不能为了守住旧色盘而让所有地点长得一样。先区分是现有角色选错、局部参数不合适，还是确实缺少一种可复用的表达，再决定改动层级。

- **场景尝试**：在本场景探索、对照和记录，回答这次情景是否更清楚。已有角色的组合可直接在授权范围内迭代；新角色或新手法可做隔离候选，注明试验身份，不悄悄替换正式共享资源。一次好看的画面还不能证明通用性。
- **语言候选**：说明它解决什么反复出现的问题、现有手段为什么不足、哪些地点适用、哪些不适用，以及需要的参数和实现成本。候选与同机位基线放在发现场景的 `review/<名>/`，不另建一份正式色盘或重复参数目录。
- **正式共同基准**：仔细审核候选的情景表达、跨场景复用、注意力层级与实现影响。Agent 先检查技术和反例，再把可比较的结果交给用户判断审美与方向；只有经过明确评估采纳，才提升为通用语言。

审核要看它在不同用途、光照和构件上是否仍成立，能否通过少量清楚的参数复用；同时看它会不会吞掉轮廓、让证据或人物难读、破坏已成立场景，或只是在为某张图增加装饰。共享资源有现有使用者时，检查代表使用者；影响世界与地点共用资源时也检查世界视角。设计与候选比较在 Blender 完成，Unity 只在最终采纳共享渲染变化时核对代表使用者，不逐轮运行。审核可以得出“只适合这一个场景”，不必把每次改善都升级为语言。

采纳后按职责更新：设计理由与适用范围进 `docs/制作/城市视觉基准.md`，作者选项和组合限制进 `city-box/docs/视觉参数.md` 与实际角色目录，实现映射回共享 Unity 资产和运行时契约；本参考只维护设计与审核方法。记录被采纳的依据，并回查有代表性的现有场景，避免留下相互矛盾的规则。

共享 `.mat`、WorldPalette、URP、Shader 和世界配光的作用范围按实际引用判断；未采纳的候选保留在实验范围，不以复制正式材质或新增随意 HEX 绕开共享边界。视觉设计语言可以演化，但若候选需要新增渲染或演出能力，须单独说明，并遵守项目功能冻结约定，不能把新功能藏进场景精修。

## 审核与交付

Agent 先从游戏相机自审，不能只交一张漂亮概念图：

- **注意力与空间**：不读说明也能找到主体和主要分区；布局仍支持脚本里的行动，画面没有靠招牌、光效补救错误空间。
- **线与表面**：关键轮廓清楚，背景退后，密集碎线不糊成白团；暗部和反光处仍读得出形体，没有所有线一样抢眼或主体无意间失去轮廓。
- **光与雾**：主次和冷暖有理由，保留暗面；雾不吞掉人物、动作落点和通路，高光与 Bloom 不把装饰推成主角。需要烘焙的场景检查光照资源是否随几何更新，尤其晚宴的哈希契约。
- **机位与 UI**：根机位及相关补充机位成立；Pan 中心交代主体与空间关系，四角仍有可辨认、值得浏览的场景内容；允许露黑和局部对象出画，不要求各极限位置同时保留全部关键对象，范围按[宽松平移原则](anchors-camera.md#机位)判断。Orbit 的实际可达视角仍能读到场景内容。卡片、连线与对白覆盖下的阅读须在正式游戏检查，单体预览没有这些 UI。
- **共同语言**：与代表地点比较主次和材质职责，不强求同样亮度或装饰；外壳或世界轮廓有变化时也检查世界视角，嵌套场景检查所属顶层地点的显隐与配光。

用 Blender clay 图审空间，单体 `--game` 图辅助审描线；当前单体预览会统一替换表面材质，不能用来验收表面角色与地点配光组合。组合初审可在整合时批量使用整城聚焦图。需要判断 Unity 专有材质、后处理或烘焙光照的变化时，才用正式共享资源的 Unity 画面核对代表使用者；沿用已验证共享表现、只调整几何或布局时，不要求每个地点再跑一次。Blender 不保证两种渲染器表现相同，报告应说明采用的证据。这是按风险选择的核对，不是交付必经工序。需要自动截图时，可按预览 README 运行 `python3 tools/citybox-unity-preview/preview.py --scene <名>`；它读取已发布资产，不消费未发布的候选 `.blend`。未授权发布时交候选图并说明尚未取得正式 Unity 证据，不用临时材质映射冒充正式效果。

交付保留同机位对照（新场景可用灰盒对照最终版本）、所用表面／描线／光源角色、局部参数和取舍理由；标明每张图的渲染来源。报告实际检查范围，区分构建、固定机位 Editor/Play 一致性与真实交互；未检查的 UI、拖动、动画或手机表现明确写未检查。
