# 锚点与机位

契约原文在 `create-3d-assets/references/runtime-contract.md`；这里只讲做场景时怎么用。

## 锚点按空间位置组织（允许多卡共用）

锚点挂的是**空间里一块说得清的位置**（吧台、卡座、报摊、巷口…），不是每张动作卡各钉一个。命名 `Anchor_<交锋名>-<位置>`（`晚宴-吧台`、`勒索信-报摊`、`勒索信-巷口`…）。一场交锋通常 5–6 个就够；十个动作十个锚点是错的（契约也写明不能为每个动作各建一个）。

**允许多张动作卡挂在同一个 Anchor 上。** 脚本用 `:anchor` 把若干节点指到同一位置名；玩家看到的是同一块地方上换谈话/换手法，卡片不会满厅乱跳。前半在「吧台」听人谈钱、后半同一位置变成「陪他喝一杯」，就是这种用法。

**做场景时必须把脚本里的动作合理映射到空间。** 灰盒 / 道具摆位之前先读交锋 Scheme：哪些节点挂在哪个 `:anchor`、蹲守与追逐各段各自落在哪一块。场景里要有对应的 Empty，位置要对得上剧情读法（报摊对邮箱、巷口推车、货栈边门…）；缺映射或锚点漂在无剧情处，等于场景没做完。嵌进外层地点时，这些 Anchor 仍须能被运行时按交锋名解析到。

脚本侧：`(node name :anchor "晚宴-吧台" …)`；根 `container` 的名字必须就是场景名。分区根节点（或 spotlight / 列表容器）挂分区锚点，子动作卡可继承该挂点，不必每张自建。

主锚点 `Anchor_<名>` 放在画面重心偏上（卡片挂的位置），不是几何中心。

锚点高度落在视觉重心上，不要飘在天上：人物锚点放在头部/上半身高度（约 1.5m，
不高于头顶）；家具锚点放在那件东西的顶部高度（唱片机约 1.2m，不是 2.3m）——
UI 卡片是从锚点做延伸线放出去的，锚点高半米，线头就浮在空中。
主锚点也一样，不高于人物头顶多少（巷子场景曾因 2.35/3.2 全浮空，改到 1.5/2.0；
租屋曾因 2.0–2.4 全浮空，改到 1.1–1.6）。
此前 skill 只讲"按分区"不讲高度，各场景沿用 2.4 魔法数字，低机位下一律穿帮；
新场景按本条给高度，老场景顺手改。第二轮又收了一批：上午十一点零七分（1.8–2.6→1.0–1.8）、
巷子（2.6/3.5→1.5/2.0）、尾随取件人（3.0–4.5→1.7–4.1，按电车顶/雨棚顶）、晚宴卡座沙龙（→1.1/1.2）、
首演之夜（中央台/夜莺/侧台/灯桥/边门/池座落到物件顶部）、剧院中央台（h+2→h，之前飘在 28m 穹顶上 2m）、
三号货栈（控制台/旧轨道/围栏落到件顶）、码头居民区关键楼（屋顶+1.5→屋顶）、格兰德大厅/礼宾台（→3.5/1.0）、
老街酒馆（夜莺@酒馆 21.85→1.55，工作/购买→1.6）。剩下的高锚点都是有主的：室内体量总览、立面与楼层房间、
开放码头与街面总览、纪念碑视点。

## 机位

- `Camera_<名>`：50mm 透视，`cam["drag"] = "pan" | "orbit" | "static"`。室内场景一般 Pan：高俯视，方向固定。
- **"一个空间"的室内 Stage 用同一种视角**（经典室内等距感，勇者斗恶龙 7 重制那种）：从一个前角斜约 35°、俯约 40°
  看进来，距离按整屋一屏收下；靠镜头的两面墙一面不建、一面剖到护墙板高，远处两面全高（门开在远墙上才读得出是门）。
  范例 `prefabs/src/租屋.py`（机位由 yaw/pitch/dist 三个数算出来）。已有的晚宴/剧院等交锋场景没按这条改，
  新做的空间按它来。
- Pan 配贴地框 `PanBounds_<名>`（`pan_bounds_for`、`preview_only`）：约束机身平移的位置，框的宽高是可移动范围，不能直接拿场景地板边界代替。**所有场景默认给宽松、可感知的平移余量**，让玩家能主动查看不同分区、人物和道具，避免只够轻微晃动、像锁住的构图。尺寸按场景、机位距离与浏览用途判断，不统一套一个米数；框中心可偏向更值得看的区域。
- `./build.sh --no-publish --pan <名>` 出中心与四角极限画面。**边角露出黑色背景或空地、部分对象离开画面都可以接受**，不要求每个极限位置收下整个场景或全部关键对象，不按黑色面积比例机械收框。独立 Stage 的黑色外部本来就是空间呈现的一部分，可以更宽容。
- 中心构图交代主体与空间关系，极限位置仍有可辨认的场景内容，玩家能理解自己正在查看哪一侧，并自然拖回其他区域。仅在出现缺乏浏览价值的大片空画面、容易迷失，或露出邻近 Stage、未完成几何等无关内容时，调整框中心或收紧对应方向；不要为了消除边角黑色整体压缩平移范围。
- 固定画面审阅判断构图，正式游戏拖动检查浏览手感与边界是否突然卡住；两者分开报告。历史范围只是例子（晚宴 14×18m、双目标跟拍总览 8×6m），不是上限，也不是其他场景必须照搬的默认值。

## 世界视角下这个场景长什么样

场景只在聚焦时显示标准描线和内部；世界视角下它是一块暗体块。两个对象级属性决定分界：

- `layer = "interior"`：家具、道具、人形、墙内一切（`props.py` 摆的件默认就是）。构建收进 `内部_<名>`，Unity 没聚焦时整体隐藏。外壳（地、外墙、屋顶）不标。
- `outline = "proxy"`：只给要在世界视角认得出的地标用——几个方块勾出主体量，构建生成 `描线_world_<名>` 下的轮廓。交锋场景一般不需要。

`tone`、材质角色与装饰线决定视觉层级，不改变上述显隐作用域；配光与雾也须按所属顶层地点检查。设计与审核见 [视觉语言](visual-language.md)。

嵌套在别的地点里的场景（酒馆后巷、码头的邮箱一角）跟外层一起聚焦、一起隐藏，不单独成文件。

## 一片区域，不是一栋楼

街区类地点（老街/码头居民区）和单体场景做法不同，`prefabs/src/码头居民区.py` 是范例：

- **先定缝，再定房**：巷网（主巷 + 横巷 + 盲巷）、院子是规则的第一层，房子是往缝之间填的；巷宽要让机位看得见地（3–6m 对 6–15m 高的楼），否则一片全是屋顶。
- **松散度是一个场**：以核心点为中心的 `chaos`，层数、劈格、探出、歪斜、抖动、坡顶、屋顶杂物全由它缩放；外圈也有底（0.35），只是缝更宽、不挤——外圈规矩成立方体就又像积木了。
- **边界不是矩形**：起伏半径 + 外圈随机缺格，`pad = False` 不要街区基座；房子直接落在城市地面上才像散在城里。
- **线的层级**：房子全部 `tone = "dim"`，只有剧情路线（楼梯、回廊、门廊、尽头那间）和地标亮。密度问题靠这一档解决，不靠减房子。
- **锚点按路排**：每条通路的锚点在空间上连成一条线（门廊→回廊→尽头那间；楼梯→桥廊→孤门），玩家转 Orbit 时从两个面各看到一条。路线附近的格子不参与随机缺格。
- 屋顶用整块棱柱（檐口 + 脊），别用"斜板 + 填块"——两套边叠在一起就是"复合线"。

## 独立 Stage 与 Portal

不属于城市地表、只能从一个地点进入的交锋空间，在顶层集合设置 `stage = True`。作者只负责两件事：

- 城市地点 Prefab 放一台 50mm 透视相机 `PortalIn_<交锋名>`，站在入口外、视线穿过门洞。**站远一点**：
  离一栋大楼的正立面 4–5m 看它满屏是墙，推进去就是"怼墙"；单体建筑退到 12–16m、高 4–5m，让门框只占画面
  一部分、上面还看得见楼体（剧院 / 格兰德酒店 / 报社 都是这个距离）。巷口那类本来就是洞的入口 6m 即可。
  但有上限：进门是从 `Camera_<地点>` 俯冲到 PortalIn，所以 PortalIn 必须比地点机位更靠近 `Anchor_<地点>`，
  否则镜头先飞离建筑再折回来。构建会核这一条。
- Stage 有普通的 `Anchor_<交锋名>` 与最终游戏机位 `Camera_<交锋名>`。Stage 里**不放** Portal 相机。

门有两端：A 是 PortalIn，B 是 `Camera_<交锋名>` 此刻的位置。进门：从当前机位沿视轴出发，最后 6m 顺着 A 的
视线俯冲、越过 A 1.5m 才黑；亮起时在 B 身后（视轴反向，距离 = B 到 Anchor 距离的 35%），落进 B。出门倒放：
从 B 向后拉到同一点、黑、在 A 门外倒退升回城市机位。

**两处净空由构建核**：`export.py` 沿视轴 `ray_cast`，A 前方 1.5m+0.5m、B 身后 35%+0.5m 内撞到东西就失败，
报出撞到的对象和距离——挪机位或挪那件东西，别改常量。地下室那种矮顶的场地，B 别贴着天花板。Portal
相机不是焦点相机，不配 `drag`、OrbitPivot 或 PanBounds；PortalIn 重复或 Anchor / 同名 Stage 不存在也失败。
Stage 在 `city.blend` 里的位置只服务作者排布：它不占城市地块，全部画面几何只进地点细节文件，世界层只保留
根节点、Anchor、Camera、PanBounds 和 Portal 语义。
