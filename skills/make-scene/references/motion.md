# 会动的道具与环境循环

场景里会动的东西：唱片机、风扇、门、招牌，也包括一次性的剧情演出（吊灯坠落）。**画面是终态，动画只是终态之间的过渡**
（和对白舞台指示同一条房规）。这叫“稳定状态，动画过渡”：人物常态像雕塑一样定格，局势改变时演一次衔接，随后落回新的固定姿态；坐着争执、站着叫喊本身不意味着应持续播放动作。定格也要表达局势和强度：不满时指责、前倾，升级后姿态更具逼迫感，不能把“稳定”误作所有人中性站坐。只有持续运动就是场景当前状态时（追车、风扇等），才保留相对稳定的环境循环；关键事件另播短动作后回到该循环。

模型、clip、审片、发布这几步两类完全一样，只在第 6 步「谁来切状态」分开。

## 一条龙

1. **模型**：整件程序化，一个脚本生成 `props/<家族>/<key>-parts.fbx`（每个刚体部件一个对象，原点 = 它的 pivot）
   和 `<key>-low.fbx`（合并版）。范例 `props/家居/实验/唱片机/build_procedural.py`。
   什么走生成、什么走程序化，看**关节**：部件之间要相对运动、pivot 要精确落位的机关（唱臂/转盘/柜身）
   程序化——生成模型拆件两次都失败（部件糊在一起、pivot 不在该在的地方）；本身是一整块、只做整体位移/缩放的
   件（音符、吊灯的灯体、招牌）按 `make-3d-asset` 选择已有模型、代码或生成服务；需要生成参考图时再用 `make-images`。
   生成件用 `PropLibrary()` 摆好后并进 `parts` 字典一起打关键帧，不需要 -parts.fbx。
2. **clip**：写在 `props.json` 该 key 的 `clips` 里（规格见 `pipeline/motion.py` 头注释）：
   状态 clip（`Stopped` / `Playing`，可带 `loop`）+ 过渡 clip（`from`/`to`/`keys`）；浇水这类不改变终态、
   但每次都要重播的短动作写 `once: true` + `from` + `keys`，播完自动回到 `from` 状态。通道 x y z rx ry rz，
   值是相对摆放姿态的偏移，秒为单位。
3. **摆进场景**：Prefab 脚本里
   ```python
   parts = HOME.parts("唱片机", coll, "gramophone", (x, y), face_deg)
   for o in parts.values(): o["presence"] = "租屋-唱片机"; o["outline"] = ...
   motion.build(coll, "唱片机", parts, HOME.meta["gramophone"]["clips"])
   ```
   `motion.build` 先校验（状态存在 / 循环首尾接 / 过渡首末帧 = 两端状态），再打关键帧、把帧范围记进集合 `clips`。
4. **审**：`blender -b --python pipeline/preview.py -- <名> --game --motion <道具> [--gif]`
   Agent 先读 `build/prefabs/<名>_motion_<道具>.png` 帧带，逐段核对起点、中间、终点的形体、位置、描线与状态；再读每段 `<clip>.png` 的全分辨率代表帧检查细节。帧带是抽样图，不等于每一帧都通过；有突变、穿插或构图疑点时用 `--frames 秒,秒` 补查相邻时刻，剧情演出还要从指定 `--cam` 的整帧看主体在画面里的位置。
   `--gif` 产出 10fps、低分辨率的节奏预览，适合给用户看动作和停顿，也可辅助 Agent 判断时间感；不要只凭 GIF 判断描线、几何和构图。日常以 Blender 的静态帧与动画节奏完成审片；游戏内播放留到最终接入。
5. **发布**：`./build.sh` 照常；`places/<名>.clips.json` 随 FBX 一起进 Unity，导入器切成 Legacy clip `道具__状态`。
6. **谁负责播放**，按动画的职责选择：
   - **场景环境循环**（追车街景等，不由游戏状态切换）：在唯一循环状态上声明 `ambient: true`，例如
     `"行驶": {"pose": {...}, "loop": {...}, "ambient": true}`。地点内部显示时自动开始，隐藏时停止并复位，重新进入从头播放；
     不进存档，不登记阻塞步骤，不调用 `play-motion!`。一件道具只允许一个环境循环，部件必须属于地点内部。
     动画播放状态不等于游戏状态；只有需要玩家改变并读档恢复的情况才使用下面的状态机关。
   - **状态机关**（读档要恢复、可反复切换）：不新增 DSL，状态从**现有游戏状态**推出（唱片机 = 全局键 `音乐`），
     `PropMotion.SyncAll` 每次快照落地时对一遍：首次直接摆、没变不动、变了播过渡。
   - **一次性演出**（吊灯坠落，只活在一场Scenario里）：剧本用稳定 ID `地点/道具`，例如
     `(play-motion! "首演之夜/大吊灯" "Fallen" "首演之夜-吊灯")`。地点用于选中唯一的地点实例，道具部分仍对应
     `道具__状态` clip；显式道具、状态、过渡或机位缺失都会中断，不会跳过关键演出。
     一个阻塞步骤：影幕 + 运镜到 `Camera_<机位>`（Prefab 里加一台 `drag=static` 的机位）→ 播过渡 → 回原机位，
     不需要点击；接 `play-dialogue!` 就是「动画 → 对白 → 回牌面」。道具之后停在目标状态上，不记任何游戏状态。
     范例 `prefabs/src/首演之夜.py` 的 `chandelier()`：灯体一整件 + 吊索各一件，clip 直接写在脚本里。
   - **两者兼有**（码头的巨轮「货船」）：进港那一下用 `play-motion!` 演（世界层入场里也能调，
     演出先播、快照后采纳，SyncAll 不会抢在前面把它摆好），之后由 `SyncAll` 按全局键 `货船在泊` 维持
     （抢修期间 Berthed，修好即 `Offshore` 静默离港；扣船暂隐，恢复后了结那一下改在Scenario收尾播离港）。为什么不做成纯演出：不记状态的话 debug 重置后
     道具还停在 Berthed，再进码头 `play-motion!` 同态无事可播，演出就"消失"了；有状态的话重置把键
     清回 #f，船退回画外，入场才有得演。默认状态得是"不在场"（画外 300 m，雾里），部件之间没有父子，
     船体、锚、吊杆各自复制同一条位移曲线。范例 `prefabs/src/码头.py` 的 `liner()`。

   - **纯一次性、不留任何残留**（格兰德酒店门前的车队）：`once: true`，from = 默认状态且默认状态就是
     "不在场"（s=0）——播完自动回 from，世界上什么都不剩，读档、重置都不用管。代价是首帧和末帧都得是
     不在场：东西只能在**画外**现身和消失（机位边缘之外，不是远处地平线上——远处也看得见 pop），
     所以先定机位再画路线。范例 `prefabs/src/格兰德酒店.py` 的 `motorcade()`：三辆车沿
     直线+圆弧+直线的路径，关键帧按里程写、弧线自动补采样；`--frames 秒,秒` 出整帧看构图。

## 最终接入与管线故障定位

Unity 不参与逐轮动作设计。先在 Blender 审查动作、机位和循环；普通动作内容成立并发布后，不自动启动 Unity；仅在导出/导入/播放管线改变、出现两端差异或用户明确要求时，选代表片段核对一次。需要自动固定帧时才用 `python3 tools/citybox-unity-preview/preview.py --scene <机位> --clip <完整片段名> --times <秒,秒,...>`，参数见 [工具说明](../../../tools/citybox-unity-preview/README.md#动画固定帧)。这是最终接入和故障定位工具，不是每个片段、每次修改都要运行的步骤。

Blender 正确而 Unity 不一致，先保留源文件和对应时刻，作为导出/导入/播放管线缺陷排查；修复后只复核相关路径。后台启动或退出卡住是预览工具故障，不是资产没做完。源机位正确但运行时运镜穿墙、侧漂，同样归运镜功能排查。不要为这些问题不断改姿势、缩放、机位或重复导出正确内容。

## 让动作读得出来

### 骨骼人物

骨骼人物仍走 clips.json + Legacy Animation + Play Motion，不另建 Animator 控制器。刚体 `motion.build` 的偏移通道不生成骨骼曲线；人物作者脚本先重定向并烘焙到同一时间线，再声明相同的帧区间。实际范例见 `city-box/prefabs/src/alley_combat_motion.py` 与“巷子里在打人”。

简单局势变化可先用程序化姿势试配；需要可信的重心和身体节奏时，优先使用现成动作原速重定向，而非继续堆姿势插值。`prefabs/src/drunk_motion.py` 示范椅高、脚点和不同动作的接续，`street_standoff_motion.py` 示范叫喊与保留根位移的后退；通用导入、采样和重定向在 `rigged_actor.py`。不同源动作的座位高度、朝向和根位移未必一致，要按场景校准接触，并从游戏机位审查；不把所有动作统一加速。

- 次要人物的手部不追求分指刻画，优先用合拢的简化手形，保留手腕/手臂表现；避免通用动作里的五指张开在小人偶上变成夸张的扇形。制作期范例是 `rigged_actor.simplify_hands`。
- 次要人物可以共用源网格和动作，每个实例有自己的骨架与姿势。实际 Unity 中，本体和描线的 bones 都必须引用本人骨架。重要角色可使用独立网格，复用同一动作来源。
- 蒙皮人物用动态 `hull` 描线：保留顶点次序、权重与 Armature modifier，不能把静态壳焊点后的索引直接当成权重索引。正式导出保留 ARMATURE，不把动画后的一帧应用成静态模型。
- `motion_parts` 的组可声明 `names`、`anchor`、`present`、`absent`。后三项表示以当前渲染树中的目标锚点是否存在，静默摆到两个显示状态之一，不新增存档。只适合“目标消失确实代表倒下”的内容，不能把所有缺席都解释成死亡。
- 状态片段默认只控制该组 `names` 子树；演出片段的 `participants` 可额外列出尼尔等参演者的根。导入器裁掉其他对象的绑定，防止一人的 Clip 覆盖其他人的状态。推镜前先采样演出首姿；自然结束或跳过都先摆到目标状态，再回机位；回程后恢复临时参演者。
- 目标状态可写 `travelSeconds`，以秒指定本次 Play Motion 的进入和返回运镜时长；0 沿用既有节奏。通常沿用系统标准运镜，不为单个场景随意指定特殊时长；确实需要不同节奏时再做作者声明，不修改全局导航速度。
- FBX 导入可能把 SkinnedMeshRenderer 放成骨架根的同级，不能靠遍历骨架根的子 Renderer 判断人物是否存在。用渲染器的实际 bones 检查归属；姿势由骨架控制。
- 骨骼层级不要在默认帧把祖先缩成0后再 `duplicates_make_real`：零矩阵会使展开后的子骨架/网格丢失局部变换。临时人物用画外默认位置，演出准备时摆到首姿，回程后恢复。

场内站姿先按人物关系确定朝向：围攻者应看向受害人，保留侧身护架，但不能背对目标。逐个目标审阅起手、命中和收拳，不能只看一个接触帧；拳面与面部表面的数值距离仅作辅助，选点要排除发顶和帽檐，仍须从实际演出机位看清命中位置。

每次制作由 Agent 在 Blender 审查片段朝向、两人接触、穿插、首尾姿态、骨骼与描线跟随；导入后的片段范围和作用对象放在最终接入核对。正常完成、开播前跳过、回机位、恢复操作及重入复位属于一次性功能验收，默认给用户简短人工路径，不为它们额外搭建复杂自动化或反复录屏；具体边界见 `tools/VERIFYING.md`。

只有用户明确要求完整自动交互检查时才展开：批处理不绘制 Game View，依赖 IMGUI 绘制的结果卡停留可能不会完成，不能据此判定动画死锁。

### 动作可读性

- 先想机位：动作要**横过画面**才看得见。绕竖直轴摆的东西正对机位只是抖一下（喇叭那次）；侧对机位（`face_deg`）才有幅度。
- 圆的东西转起来看不见：唱片标签上加一道横贯的印记。
- 硬边线按全城标定会砍掉 4cm 以下的边，屋里的小件（唱片圆、臂）就没了：集合上 `min_edge_px = 3`。
  圆滑面（喇叭口）用 `hull`。会动部件的线各自一份挂在部件下，构建自动处理。
- 过渡分段写：抬 → 摆 → 落，每段一对关键帧，比一段直线像机械。
- 静止状态 clip 至少 1 秒保持帧：Unity 会把太短的 clip 拉长，卷进后一段的关键帧。

## 坑

- `preview.py` 成功拼成帧带/GIF 后会删除 `_motion_frame*`、`_gif_frame*` 临时 PNG；帧带、全分辨率代表帧、可选 GIF 和 `--frames` 整帧保留在被 Git 忽略的 `build/prefabs/`，供人回看。重新渲染同一场景、同一道具成功后，脚本只清理该道具上一版遗留、这次没有再生成的预览（例如改名的 clip、旧时间点整帧或取消生成的 GIF）；其他道具和场景的预览不动。最终审阅材料放在 `prefabs/review/<名>/` 并保留，发布或批准不触发预览清理。

- 不是 `presence` 的会动件也各自出线挂在自己下面（outline.py 认 animation_data）；线不跟着动多半是件没打上关键帧。
- 审片 `--motion` 默认沿游戏机位推近；给了 `--cam` 就照那台机位拍，审演出机位用这个。
- 会动部件各自的线叫 `描线_<道具>_<部件>`，`render.set_focus` 把它们和 focus 线同进退；预览里没线先查这个。
- 巨物横过画面：机位要斜着看航道（不是正侧），它才能"从远处压过来、越来越大、最后横在眼前"。
- 演出机位的中心射线要打得到地面（略俯视）：焦点运镜靠它解兴趣点，纯仰拍的机位在来源也解不出时
  （从世界机位直接进来）会退化成 Cinemachine 直线混合。
- 城市文件默认 24 fps，关键帧按 30 打的——`build.py` 已强制 30，别改。
- `duplicates_make_real` 不带动画，`prefab.make_real` 从库里按名字接回 action；部件对象名要唯一（`<道具>_<部件>`）。
- Unity Editor 固定帧审片时，采样骨骼后至少跨一次 Editor 更新再截图，让蒙皮刷新；不要在一个同步循环内连续采样并截图，把上一姿态的蒙皮当成本帧。核对真实导入的 clip 时长，FBX 导出强制保留首尾关键帧，避免末尾静止段被精简裁掉。
- FBX 导出只烘"选中集合里有关键帧的对象"，否则整城每个对象都烘成常量曲线，文件翻倍。
- Unity 导入时会丢掉在 clip 范围内恒定的曲线（Stopped 这种静止 clip 一条曲线都不剩）。运行时 `PropMotion`
  在播任何 clip 前把该道具的部件复位到静止姿态（clips.json 的 `parts`，姿态 = 第 1 帧 = 第一个状态 clip），
  所以 **props.json 里第一个 clip 必须是默认状态**。不要靠状态 clip 本身把东西摆回去。
- 现身/消失这种"这一帧没有、下一帧就有"的两个关键帧，时刻要对齐到整帧（1/30 s）再错开一帧：
  写 `t` 和 `t+0.02` 会四舍五入到同一帧，后一个把前一个盖掉，车从头到尾慢慢缩没（车队那次）。
- 过渡 clip 的 wrapMode 必须是 Once：ClampForever 永远不"完成"，排在后面的目标状态永远轮不到。

- 循环复位不能只检查整帧：即便两端都在画外，60fps以上的渲染仍会显示一帧复位过程的中间插值，造成车辆或窗灯扫过镜头。复位前先在画外缩至0，位置换位的两个关键帧都保持0，抵达远端后再恢复；Blender 制作时补看1/4、1/2、3/4帧，低帧率帧带不足以覆盖接缝；若源曲线正确而Unity仍闪烁，转入管线故障定位，检查实际导入曲线。

- Unity会对FBX缩放样本自动补平滑切线，使1→0→0→1的隐藏平台下冲为负数；正式模型导入器对烘焙缩放样本使用线性切线。出现源曲线正确、Unity仍闪烁的差异时，检查实际导入的Scale曲线并修导入器，不为每次制作重复启动Unity。

- 有零缩放复位的部件，必须连同生成描线的子节点检查。FBX 对零缩放父矩阵求逆会烘出子节点的局部 TRS 补偿，Unity 精简/插值后，即使父部件换位时完全隐藏，描线仍可能在恢复后从原点向外扩散。生成的刚性描线没有独立动作，导入时删除其 Transform 曲线，保留模型固定局部姿态，只继承 motion.parts 父部件。这是导出/导入器的管线责任，修复时检查实际导入曲线及恢复后的画面；制作端仍需看源动画的隐藏前后与循环接缝，不能只看低帧率GIF。骨骼蒙皮与真实动作部件不能据此删除曲线。

## 演出镜头的有效画面

Play Motion 演出由 CutscenePlayer 绘制上下黑边（当前目标宽高比2.39:1），审片要按黑边之间的实际可见区检查主体，不能只证明顶点在完整16:9画面内。对起吊/横移/降落等主体高度变化大的动画，至少看全过程峰值；首尾正常不能替代中段检查。可用共享曲线审入场/返回，按clip from/to稳态评估几何；播放段还要按真实动画帧检查，不用同一个Hold姿态冒充Suspended或Landed返回。裁切可优先调整机位取景方向或焦距，不为迁就错误构图改动画或主体模型。具体黑边数值以CutscenePlayer代码为准。
