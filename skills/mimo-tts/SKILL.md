# SSNoir MiMo 配音

使用项目工具 [`tools/mimo-tts/generate.py`](../../tools/mimo-tts/generate.py) 生成候选音频；完整命令、角色库和命名约定见其同目录 [`README.md`](../../tools/mimo-tts/README.md)。

密钥由工具从当前 macOS 用户的 Keychain 读取，service 为 `com.ssnoir.mimo-tts.api-key`、account 为 `SSNoir MiMo TTS`。不得查找、输出、写入或要求保存 API key 到仓库、`.env`、shell 配置或任何内容清单；只有 Keychain 缺项时，才请用户在其终端完成 README 中的一次性设置。

待生成台词可单条生成，或写入剧情对应的 `角色库/配音/清单/*.json`。语音 ID 是稳定剧情坐标，而不是台词文本：`模块/地点/路径或事件/节拍/说话人`；文字与演出方向改变时保留同一 ID。

### 三种配音模式（--mode）与分流规则

生成器统一采用显式模式分流：`--mode preset | clone | design`。日常调用省略 `--mode` 时，自动从 `角色.json` 的配置继承。

1. **预置精品音色（`--mode preset`，模型 `mimo-v2.5-tts`）**：
   - **适用场景**：主角（尼尔）、世界念白等需要最高声线稳定度的核心角色，以及不需要制作样音的角色。
   - **核心参数**：`--voice <音色名>`（或继承角色配置中的 `voice`）。严禁传 `--sample` 或 `--style`。
   - **支持音色（白名单共 8 种，严格校验，不接受旧版 `mimo_default`）**：
     - 中文：`白桦`（成熟男声）、`苏打`（阳光少年）、`茉莉`（知性女声）、`冰糖`（活泼少女）
     - 英文：`Dean`（稳重儒雅男声）、`Milo`（清亮少年男声）、`Chloe`（甜美微凉女声）、`Mia`（明快少女女声）
   - **约束**：强制使用 `mimo-v2.5-tts` 模型；`voice` 必须是非空字符串。
2. **克隆音色（`--mode clone`，模型 `mimo-v2.5-tts-voiceclone`）**：
   - **适用场景**：常驻配角（弗兰克、经理、记者、贝恩斯等）或需要测试本地录音复刻效果。
   - **核心参数**：`--sample <音频文件路径>`（支持 WAV/MP3，或继承角色配置中的 `sample`）。严禁传 `--voice` 或 `--style`。
   - **规则**：样音定声线；仍按默认工作流为每句提供短 `direction`，短句再附对话历史（见下文）。不要空 direction 硬靠样音猜情绪。
3. **声音设计（`--mode design`，模型 `mimo-v2.5-tts-voicedesign`）**：
   - **适用场景**：临时 NPC、路人、无参考样音且未指定预置音色的角色。
   - **核心参数**：`--style <声音形象白描描述>`。严禁传 `--voice` 或 `--sample`。

### 默认工作流：按句资产 + 对话历史上下文 + 演出方向

游戏可播放配音必须是**逐句独立资产**（每条 cue / 每个 VoiceId 一个 wav），以便字幕、打字机、停顿与混音对齐。不要把整场连读成一条多句 wav 当发布资产；连读只适合试听声线/情绪弧，不能进 `Resources/Voices/`。

官方 API 把未念出的信息放在 `messages` 的 `user` 里，当前句放在 `assistant`。`generate.py` 目前只把一条 `--direction` / cue `direction` 串成**单个** `user` 消息，因此默认把下列内容打包进该字段（或等值的清单 `direction`）：

1. **对话历史（context）**：本场此前已说出口的台词，写成 `说话人：台词` 行（不要用旁白式剧情摘要顶替）。官方说明：user 内容不会进入合成语音。
2. **本句演出方向（direction）**：短中文舞台指示（情绪/意图/力度），例如「冷、短促，像下令」「盘问，句中留一拍」。

推荐 `user` 形态（可按工具能力微调标签名）：

```text
【对话历史】
赌徒甲：把钱放下！
瘦子：你先撒手！
【指导】冷、短促，像下令
```

`assistant` / `--text` / cue `text` 只放玩家可见台词，保持干净。

**空 direction 对短句很糟。** 像「接着打。」「上车。」这种信息量极低的命令句，零提示几乎必然平、僵；clone/preset 也不能只靠样音猜情绪。默认每句都写短 `direction`；历史上下文对短句帮助最大，应与 direction 一起给。长句、且 `style`（design）已写满情绪时，direction 可更短，但仍避免完全空白。

**标签（tags）可选，不是默认。** `(愤怒)`、`[沉默片刻]` 等可写进 `assistant` 文本作调味，但必须另嘱「不要念出标签」，且偶发垫静音/起读晚。优先用自然语言 `direction`；喊叫类可试 tags，审听后再定。

默认不要用“停顿、留白、拖尾、放慢、句尾收住”等**空泛时间性**指令；它们常造成通篇机械拖慢。只有剧情明确需要停顿时才写，且限定在这一句（可用更具体的「句中留一拍」一类锚点，仍要短）。

清单中的 `text` 必须逐字等于游戏 `line` / `stage-say` 的玩家可见台词。先删除「（字幕）」等编辑标记，再生成；不要把“不要念出括号”之类的要求交给模型处理。

生成的文件只是一份候选。试听或获得用户验收后，复制到 `UnityClient/Assets/Resources/Voices/<语音ID>.wav`，带上 Unity `.meta`，并在对应 `(line ...)` / `(stage-say ...)` 的第三个参数绑定同一 ID。不要把未验收的候选直接当发布资产。若本场质量不够、用户选择静音优于劣质 VO：去掉第三个 VoiceId 参数即可（不要留坏绑定）；清单可保留 ID 供日后重做，勿暗示 Voices 已必填。Banter 有绑定语音时会等待播放结束；显式 dwell 只用于额外停顿。旁白机制另走 `Resources/Narrations/` 与 `(play-narration! ...)`，不要混用。

生成后检查音频时长是否明显不符合文本长度；短句若异常拉长，先试听确认是否发生复诵。复诵是生成失败：在该句 `direction` 明确要求“只说一次，不重复文字，不添加内容”后重生成，不在游戏端重复播放或截断音频。

改动 `.scm` 时遵守 `$write-scheme`；改动运行时代码或可执行工具时遵守 `$verify`。每次完成接入后，至少检查路径/ID 一致性、`git diff --check`，并按改动范围做内容或编译验证。

## 经验参考：对 MiMo 模型的机制理解

- **极强的字面遵从性**：模型对提示词字面遵从极强（说“松弛”会通篇过松，说“缓慢”会通篇机械变慢）。direction 要短、具体、非空泛；用 4～12 字的情绪/意图锚点（如「低沉从容，平淡反问」），不要堆时间性形容词。
- **短句需要 context + direction**：信息量低的短命令在空 prompt 下几乎必然发僵；把前置对白塞进 `user`、本句 direction 写清，比「连读整场再切片」更适合逐句游戏资产。连读（同一 `assistant` 多句）只作试听。
- **标签可选**：tags 对喊叫/停顿有时有效，但有念出标签与异常静音风险；默认仍走 direction，不把 tags 当主路径。
- **工具缺口**：客户端尚未暴露多段 `messages` history 字段；在支持之前，把历史与指导打包进单条 `direction`/`user` 字符串。日后若增加 `history: []`，改为多条 `user` + 当前 `assistant`。
- **预置音色稳定性优势**：Preset 在多句连贯、底噪与发音稳定性上通常优于零样本 VoiceClone，适合系统念白与主角主线；配角 clone 仍应用上述 context + direction 默认工作流。
