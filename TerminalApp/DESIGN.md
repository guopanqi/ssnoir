# Terminal 客户端视觉设计规范

本文只适用于 `TerminalApp` 的 Raylib 界面。Unity 客户端有自己的 UI 规则与视觉语言，不能直接把 Unity 的颜色、尺寸或组件样式移植到 Terminal。

## 1. 视觉定位

Terminal 是一套克制、清晰、带轻微电子终端感的深色界面：

- 深紫黑背景与低对比表面构成基础层级。
- 明亮紫色是主要交互色，用于选中、悬停、可操作、焦点和进度。
- 文字普遍偏亮，重要信息不能依赖低对比灰字表达。
- 红、黄、绿只承担明确的结果或警告语义，不作为普通按钮和面板的装饰色。
- 信息密度可以较高，但必须依靠稳定的间距、对齐和层级维持可读性。

## 2. 颜色语言

通用颜色应优先取自 `src/Rendering/TerminalPalette.cs`，不要在各 Widget 中重复发明近似颜色。

| 用途 | 视觉 | 说明 |
|---|---|---|
| 页面背景 | 深紫黑 | 最底层背景 |
| 卡片、面板 | 紫灰黑 | 与背景形成温和层级，不使用纯黑大块切割 |
| 普通边框 | 暗紫灰 | 只负责划分边界，不抢夺注意力 |
| 主要交互 | 亮紫 | 选中、悬停、可执行按钮、当前进度 |
| 强调文字 | 浅亮紫 | 面板标题、已解锁状态、重要可交互信息 |
| 正文 | 明亮冷白 | 名称、数值、状态等需要直接读取的信息 |
| 次要文字 | 紫灰 | 说明文字；不能暗到难以辨认 |
| 坏结果 / 损失 | 红 | 失败、负面影响、冷静击穿与健康损失 |
| 中性结果 / 警示 | 黄或暖杏 | 中性结算、资源警示 |
| 好结果 / 收益 | 绿 | 成功、正面影响 |

普通执行按钮、技能标签、成长按钮、关系里程碑等交互元素使用紫色，不使用金色。金色只承担明确警示语义，例如冷静进入失态区。

## 3. 卡片信息结构

卡片内部采用纵向流式布局，固定顺序为：

1. 标题
2. 说明文字
3. 类型、风险和状态标签
4. 技能与资源槽
5. 执行按钮

后一个区域必须根据前一个区域的实际底边定位，不能分别使用互不相关的绝对坐标。内容增多时允许整体下移或卡片增高，不允许文字、标签、槽位和按钮互相覆盖。

相邻控件之间必须保留可见间距：

- 紧密相关的文字行可以使用约 4px 间距。
- 标签与后续控件至少保留约 8px。
- 骰子或物品槽与执行按钮至少保留 8px。
- 卡片与外部附件之间保留小间隙，并使用连接线表达归属。

“行动”这类不能提供新信息的类别文字不应占用可执行卡片的垂直空间。

## 4. 卡片附件

命运预览和行动结算属于卡片附件，而不是主卡片内容。

- 玩家尚未投入行动骰时，不显示命运附件。
- 投入骰子后，在卡片下方显示准备值公式与**命运条（赔率条）**：六格按准备值 B 实心染色，
  低面坏、高面好，档间留缝让坏/中/好占比一眼可读；格内写命运骰面 1–6。
- 结算后，同一位置高亮命运骰落格（抬起 + 金描边），并显示最终结果、叙事和全部实际影响。
- 附件高度根据内容自动增长，不能用“还有 N 项”折叠实际影响。
- 所在卡片行必须为附件增加的高度留出空间，不能覆盖下一行卡片。
- 附件表面比主卡更深，边框和连接线使用紫色体系，表示从属而不喧宾夺主。

## 5. 文字与可读性

- 人物名称、技能等级、冷静状态、资源数值和禁用原因都属于必须直接读取的信息。
- 上述信息不能使用过小字号或过暗颜色作为“装饰性注释”。
- 常规状态如“冷静”使用明亮正文色；低冷静与宿醉必须作为骰池位置中的状态标签直接显示，例如“失态”“失控”“宿醉”，并使用警示色。
- 标题、正文、标签、状态必须形成清楚的字号层级，但字号差异不应大到破坏紧凑感。
- 长说明最多按组件规格换行；不能依靠缩到难以阅读来塞进固定区域。

## 6. 交互状态

同一控件至少需要区分：默认、悬停、选中或激活、禁用。

- 默认：暗表面、暗紫灰边框。
- 悬停：边框或表面提高紫色亮度。
- 选中 / 激活：亮紫边框与浅紫文字，状态应一眼可见。
- 禁用：降低整体对比，但禁用原因仍应清晰可读。

禁用必须由明确的交互状态控制，不能通过伪造鼠标位置、吞掉无关输入等方式实现。

## 7. 面板与底栏

- 顶部工具栏保持窄而稳定，展开面板不应导致主内容突然跳动。
- 关系、成长 / 队伍等同级面板采用一致的展开、收起结构和紫色交互语言。
- 底栏把人物状态、人物行动骰、物品和功能组织在同一横向区域中。
- 行动骰和物品 token 保持紧凑；选中态使用紫色，不依靠放大造成布局跳动。
- 健康归属队伍；冷静和骰池状态归属各自行动者。角色簇按“骰子 → 骰池状态 → 冷静”排列；骰子位置保持抽象，不写时间名称。冷静按 `TeamState.MaxComposure` 绘制为两格，归零后的额外消耗直接转为伤势。

## 8. 实现原则

- 优先使用约束驱动和流式布局，根据文本尺寸及前序控件位置计算后续位置。
- 公共颜色集中在 `TerminalPalette`；结果语义色可以在结算组件中集中定义。
- Widget 自己管理内部布局，Renderer 负责面板、卡片行和可滚动区域等外部组织。
- 新增组件前先对照现有 Terminal 卡片、槽位和按钮，不以 Unity 界面作为直接样式来源。
- 视觉修改完成后至少检查窄内容、长说明、多标签、禁用原因、多项结算影响和附件展开这几类状态。
