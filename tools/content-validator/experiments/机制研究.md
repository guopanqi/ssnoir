# 机制研究工具

研究结果和试玩入口在 `docs/实验/机制研究/README.md`。本组工具不替代游戏运行器；正式 Scheme 仍是规则的唯一来源。

第二轮另用 `mechanism-round2.py`，可复现命令和数据边界见 `docs/实验/机制研究/第二轮/README.md`。它复用同一个有限模型，增加准备后的公开概率采样、两种新原型、初始状态起算的占用传播，以及目标扫参。`verify`检查新原型的转移和终止信息，再选代表轨迹调用原生严格回放。旧实验结果保持各自的版本身份。

## 复现当前研究

先构建官方内容校验器：

```bash
dotnet build tools/content-validator/SSNoir.ContentValidator.csproj -nologo -v q
```

下列输出目录必须不存在，避免覆盖已有证据。建议使用新的临时目录：

```bash
# 13个配置；每组12局；基础配置另加两类求解策略，共852局。
python3 tools/content-validator/experiments/mechanism-study.py study /tmp/机制-对照 \
  --families 余热转用 分段兑现 情报承诺 --with-dp \
  --seeds 501 502 503 504 505 506 507 508 509 510 511 512

# 同规则的有限模型：技能1和2，优先完成概率。
python3 tools/content-validator/experiments/mechanism-solver.py /tmp/机制-数学 \
  --growth 1 2 --objective 保守

# 偏好尽早完成：研究分数12/9/6、失败0，不改游戏奖励。
python3 tools/content-validator/experiments/mechanism-solver.py /tmp/机制-效率 \
  --growth 1 --objective 效率

# 在同一有限模型里比较固定策略，减少种子样本噪声。
python3 tools/content-validator/experiments/compare-mechanism-policies.py /tmp/机制-固定策略.json

# 检查原生轨迹中的实际转移与有限模型是否一致。
python3 tools/content-validator/experiments/check-mechanism-model.py /tmp/机制-对照

# 用原生回放比较每一步完整观察及事件；内容或工具构建指纹变化会拒绝。
python3 tools/content-validator/experiments/mechanism-study.py replay /tmp/机制-对照
```

`screen` 模式运行六种基础原型的固定策略；`study` 加消融与相邻参数。主样本关闭烟、酒、药品，只读公开观察，通过合法操作目录执行。每局独立进程。

`mechanism-solver.py` 只建模分段兑现、余热转用、情报承诺。目标数值来自正式配置，六档骰面的判定概率来自官方会话 `Odds`；下一轮手牌按无伤四颗独立均匀d6的126个无序组合及其权重枚举。模型条件与限制在研究报告中列明。

`compare-mechanism-policies.py` 不精确评估“一次探查”：该策略需要尝试次数历史，当前模型没有这个状态；正式会话对照仍能评估它。不要从自动输出的普通 witnesses 推断严格策略差异，部分差异来自平手选择。报告使用的 `最终严格反例.json` 单独比较所有其他动作及其最佳骰子，要求完成率有严格差距；这是条件状态证据，不是可达频率证据。

`recheck-mechanism-authors.py` 是一次性的版本迁移记录：重做既有作者决定，检查关键状态与结果，写入 `作者回归/`；目标已存在时拒绝覆盖。它不是新一次作者试玩，不纳入新玩家样本。
