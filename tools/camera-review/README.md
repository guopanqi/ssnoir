# 镜头过渡检查

日常在 Blender 检查场景几何；`FocusTravelMath.cs` 是运行时与命令行共用的焦点解析、默认路径选择和轨迹采样实现，不在 Python 中重写运镜公式。不启动 Unity、不逐帧录屏。

仓库根目录：

```sh
blender -b city-box/prefabs/巷子里在打人.blend \
  --python-exit-code 1 --python tools/camera-review/review.py -- \
  --out experiments/巷战镜头穿墙检查/本轮
```

需要 Blender 和 .NET 9。`--dotnet` 可指定 dotnet 路径。输出目录必须为空，避免失败时误用旧报告。`--unity-import <result.json>` 可逐台核对 Blender 与最终导入机位的位置、朝向和 FOV；`--without-travel-space` 只用于重放无空间约束的诊断基线。

输入是当前打开的 Blender 场景中 `Camera_` 机位与 evaluated mesh（包括集合实例）。输出：

- `cameras.json`：作者机位、交互模式、FOV、近裁剪面、可选 OrbitPivot 和通行空间。
- `routes.json`：同一份 C# 默认策略选出的路径、兴趣点、均匀时间采样机位与朝向，以及是否因通行空间越界而改用溶解。
- `report.json`：每条候选运动的中心线及近裁剪面穿插；`crossfade=true` 的曲线被拒绝，不是实际执行的运动。保留风险记录供定位。
- `overview.svg`：巷战总览到三个还击机位的示意，不是游戏渲染或视觉验收。

脚本自动断言采样首尾与计划机位吻合、所有样本有限。几何检查使用 evaluated mesh；相机中心及近裁剪面边角的相邻采样之间也检查穿越，避免只查离散点漏掉薄墙。近裁剪面检查是有限采样，不是完整连续碰撞证明。

## 地点通行空间

仅在确有空间风险的地点添加，不强制每个地点配置。以相机所属 Prefab 根为作用域，创建一个 `CameraTravelBounds_<地点>` Empty，两个直接子 Empty `_min`、`_max` 的局部位置定义三维凸盒。它们不是 `preview_only`，必须随语义节点导出。盒子应处于可通行空间内并给墙、道具留出余量；不贴着可见墙面画盒子。盒子名称不是相机名，不逐对相机建例外。

CityBox 校验声明；ModelImporter 将其绑定到同根相机。中央过渡策略按实际起点和目标生成计划，检查 120 段中的机身及近裁剪面四角。所选运动越界时，复用已有溶解切换；包括剧情镜头，避免“减少动画关闭”导致不安全路径仍执行。没有声明的地点保持原策略。PanBounds 仍只控制玩家平移，不兼任通行空间。

当前盒子只保证声明区域内的安全，作者需确保内部没有未避开的墙/道具。几何检查报告会帮助发现这种错误。不会运行时寻路或自动绕楼，不承诺人物无遮挡。

## 按需导入核对

日常机位或通行盒数值调整默认只做上面的 Blender 检查。仅在修改轴向、FOV、导入绑定实现、首次建立尚未验证的契约，或实际出现两端差异时，才在正式构建发布后使用独立 Unity 缓存做一次检查：

```sh
python3 tools/camera-review/verify_unity.py --out experiments/巷战镜头穿墙检查/unity-import
```

此入口针对巷战 8 台机位，检查导入空间绑定、机位是否在空间内，以及共享旋转计算与 Unity 的约定是否一致；不进 Play Mode，不是实际攻击、返回或溶解的交互验收。普通独立 Stage 或空间声明沿用现有契约时也不重复跑它。首次可从已停止的正式预览缓存以 APFS clone 复用 Library；没有则正常建立缓存。检查工程仅保留 City.fbx，排除不参与此项验收的动画 FBX，避免整城动画导入阻塞语义机位核对。源工程和正式预览缓存不作删改。

## 证据边界

离线输入是作者机位，默认混合时长 2 秒、模型比例 1、16:9，未包括运行时拖动、切镜重定向、状态显隐或 Portal。镜头所在空间和可见几何应与正式场景一致；跨地点检查需打开完整装配，不能只查目标 Prefab。FOV 按 FBX 的 film height 取得导入角，再遵循当前导入器的旧水平角识别规则；本次已与 Unity 实际导入的 8 台相机逐一核对，不把 Blender 视口的裁切视角猜成运行时 FOV。

Blender 用于空间及画面检查；Unity 最终核对导出/导入和交互表现。两类证据分别报告。人物可见性应针对语义目标检查，不能拿地面兴趣点是否被墙挡住冒充人物遮挡判定。

### 悬空主体与平视镜头

主体不在地面时，为机位添加同级 Empty `FocusTarget_<机位名>`（对应 `Camera_<机位名>`），放在真实主体的视觉中心；Static、Pan、Orbit 均可使用。导入器绑定为 `focusTarget`，过渡优先使用它，再使用 OrbitPivot，最后才推算地面。不要使用 UI Anchor 代替主体焦点，也不要为满足地面求交而刻意把镜头朝下。源生成器创建机位时应同时保留已知的 target，避免丢掉作者意图。显式焦点不会被 Direct Approach 的地面投影覆盖；它不改变终点构图、不等于动画跟踪约束。
