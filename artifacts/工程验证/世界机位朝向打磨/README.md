# 世界机位朝向与预生成遮挡修复

2026-11-02。有效基准是世界相机的水平观看侧，不是 Blender 地理南向。上一轮地理南向探索已否决，曾写入的候选字段已撤回；雕像两份源已恢复原始文件。剧院和街角咖啡馆的有效朝向保持原样。

## 源改动

- `source-changes.json` 保存城市实例的前后角度。10 个偏向世界相机背侧的地标随建筑整体转向，辨识装饰、锚点和作者机位一起转；没有改运行时的 90° 背半边回退规则。
- 酒馆及马头随城市实例转向 -90°。没有采纳中途测试的加俯角、拉近或换镜头方案，作者相机与镜头参数保持原值。
- 码头保留沿岸布局，仅将主 Pan 相机转到世界观看侧，并同步平移 PanBounds；源码生成器与 Blender 源一致。靠岸演出机位保持原样。
- 新增 `city-box/pipeline/view_clearance.py`，在填充候选生成时，用真实外壳包围盒、作者主机位、固定世界起点及 Orbit 的世界侧候选观看点构成保守凸体。候选楼体侵入时跳过，后续窗光与屋顶也不会残留，不按易变的 B.xxx 名字删除。
- 这一装配拒绝 38 个背景候选（35 栋填充楼、3 个树候选）；填充楼从 1241 变成 1206。酒馆有 9 个候选被拒绝，警局有 4 个。按主体计数可重复，不能直接相加当总数。
- 生成器的视廊签名随完整报告保存。局部构建发现地标外壳／机位变化或基线没有视廊时直接拒绝，要求重新生成城市填充，防止更新了相机却复用不安全背景。

3. `防遮挡最终检查` 用共享 FocusTravelMath 检查 14 个主地点的进入与从实际到达机位开始的返回，共 28 条路线；每条 120 段。未检出机身分段穿插。
4. `防遮挡世界偏移西南` / `防遮挡世界偏移东北` 对酒馆、警局、诊所、码头再检查世界 PanBounds 两个对角起点及返回，共 16 条路线。酒馆、警局、诊所未检出外部遮挡采样；码头只保留主体包围盒探针落入道路／地形中的记录，未检出填充楼阻挡。地形记录不能当成需要删地面的证据。
5. `酒馆与警局同机位对照.png` 是 Blender Workbench 灰模，橙色为目标，灰色为城市。对照前后相机输入完全相同；前景遮挡的改善来自预生成过滤。酒馆马头和门面、警局台阶和低层立面已逐图审阅。
6. `city-box/tools/view_clearance_checks.py` 的 5 项空间回归通过：前景高楼阻挡、侧街保留、主体后方保留、低矮前景保留、相机后方保留；并检查源重载签名稳定、转动酒馆后签名变化。
