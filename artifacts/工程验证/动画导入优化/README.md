# 动画导入后处理优化

## 改动与接入

已优化主工程 `UnityClient/Assets/Editor/Pipeline/SSNoirModelImporter.cs` 的动画后处理：先统一判定删除项、收集修改项，最后用 `AnimationUtility.SetEditorCurves` 一次提交；已 broken + Linear 的关键帧不重复设置，整条未改曲线不提交。保留原有参与者过滤、刚性描线清理和线性缩放规则。

这是性能优化，已验证导入结果相同，因此正式 `GetVersion()` 保持 22，已有正确缓存继续有效。1022 / 1023 仅用于私有对照工程强制真实导入，不进入主工程。主工程文件以写入前哈希检查保护，没有覆盖其他并行修改。

## 实测

| 联合起吊 | 原版 | 优化版 |
|---|---:|---:|
| 单 FBX 导入 | 89.551 秒 | 3.434 秒 |
| 动画后处理合计 | 86.968 秒 | 1.362 秒 |
| 其中缩放曲线处理 | 82.717 秒 | 0.937 秒 |

独立工程基线的 7 次声明 clip 回调里，参与者过滤仅 0.072 秒，描线曲线删除 4.064 秒，缩放处理 82.717 秒；批量提交消除了逐条曲线反复触发 Unity 后处理的主要成本。优化版其余 110 次回调共 2.326 秒，该轮 AssetDatabase 刷新 10.258 秒。联合起吊沿用上轮缓存，其余资源实际导入；不能把这 10.258 秒称为全部资源从零导入时间。

## 等价性与验证

- 同一个 FBX、sidecar 与 Unity 2022.3 环境，计时副本只在私有缓存使用不同版本号及 Stopwatch 日志。
- 比较包括 8 个动画资产（含预览资产）、38,093 条浮点曲线、8,087,985 个关键帧。
- 所有绑定、时间、数值、左右切线、切线权重、weightedMode、切线模式、broken 状态及曲线 Wrap 属性逐位摘要完全相同；动画时长、帧率、Legacy、循环／Wrap、对象引用曲线与事件也一致。
- 其他 110 次回调只验证优化后的真实导入与耗时，不声称它们已逐键与原版比对。
- 主工程 `Assembly-CSharp-Editor.csproj` 编译通过，0 错误；4 条原有 CityNightEnvironment 未赋值字段警告。构建输出在 `/tmp/ssnoir-animation-import-build`，没有写正在运行编辑器的 Temp。
- 主工程 Unity 当时正在运行，因此没有重启或操作它；写入后尚未观察到该进程自动刷新。切回编辑器正常刷新后，后续导入使用新逻辑。
- 没有改 FBX 内容、重采样、压缩设置或运行时代码；未进行 Play Mode 视觉试玩，等价性证据是 Unity 实际导入后的完整曲线与动画属性。

## 文件

`comparison.json` 是逐曲线比较结果，`result.json` 是汇总；baseline/run 与 optimized/run 保留每条曲线摘要和 Unity 日志。约 618 MB 的生成二进制逐键转储在零差异确认后清理，摘要仍可重复比较。工具与使用说明在 `tools/animation-import-review/`；源副本与分段计时副本保留在本目录。
